<small>المرحلة 4 · ليه Frameworks</small>

انت رايح React، وده اختيار ممتاز. بس هتسمع الناس بتتخانق على Vue و Svelte و Angular، وهتشوف وظايف بتطلبهم. الفصل ده بيكتب نفس العداد بالأربعة، وكلهم اتعملوا Build فعلاً بنسخ أكتوبر 2026، وبيقارن الأفكار مش الـ Syntax: الـ State فين، والـ Template شكله إيه، وبيحدّثوا الـ DOM إزاي، وحجم الناتج كام. والهدف إنك تشوف إن اللي هتتعلمه في React بيتنقل لأي حاجة تانية.

:::note[بعد الفصل ده هتكون عارف]
- نفس الكومبوننت بالأربعة، واتعمله Build فعلاً
- فين الـ State: useState و ref و signal و $state
- شكل الـ Template: JSX ضد HTML بإضافات
- حجم الـ JavaScript اللي طلع للمتصفح لكل واحد (قسناه)
- مقارنة على مستوى الفلسفة: Library ضد Framework كامل
- إيه اللي بيتنقل معاك من Framework للتاني
- ليه React اختيار منطقي ليك
:::

## 12.1 العداد بالأربعة

أبسط Component ممكن: زرار مكتوب عليه العدد، وكل ضغطة تزوّده واحد. فيه **State** (العدد)، و**Event** (الضغطة)، و**عرض** (الرقم على الزرار). عملنا كل واحد في مشروع جديد (React و Vue و Svelte بـ `create-vite`، و Angular بـ `@angular/cli` 22)، وعملنالهم `build` فعلاً:

#### React 19.3

```jsx title="App.jsx"
import { useState } from 'react'

export default function App() {
  const [count, setCount] = useState(0)
  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  )
}
```

#### Vue 3.5

```vue title="App.vue"
<script setup>
import { ref } from 'vue'
const count = ref(0)
</script>

<template>
  <button @click="count++">Count: {{ count }}</button>
</template>
```

#### Svelte 5.57

```svelte title="App.svelte"
<script>
  let count = $state(0)
</script>

<button onclick={() => count++}>Count: {count}</button>
```

#### Angular 22.2

```ts title="app.ts"
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-root',
  template: `<button (click)="increment()">
    Count: {{ count() }}</button>`,
})
export class App {
  count = signal(0);
  increment() {
    this.count.update((c) => c + 1);
  }
}
```

## 12.2 نفصّص الفروق

**نفس الأفكار، أسماء مختلفة**

| الفكرة | React | Vue | Svelte 5 | Angular |
|---|---|---|---|---|
| الـ State | `useState(0)` بيرجّع القيمة + Function تغيّرها | `ref(0)`: Object جواه `.value` (والـ Template بيفكّه لوحده) | `$state(0)`: متغير عادي، بتغيّره بـ `count++` | `signal(0)`: تقراه كـ Function `count()`، وتغيّره بـ `set`/`update` |
| الـ Template | **JSX**: HTML جوه JavaScript | HTML بإضافات زي `@click` و`v-if` و`{{ }}` | HTML بإضافات زي `{ }` و`{#if}` | HTML بإضافات زي `(click)` و`@if` و`{{ }}` |
| الحدث | `onClick={…}` بحرف C كبير | `@click="…"` | `onclick={…}` زي HTML | `(click)="…"` |
| شكل الملف | `.jsx`: JavaScript | `.vue`: ملف واحد فيه script و template و style | `.svelte`: نفس فكرة Vue | `.ts` فيه Class، وممكن ملف HTML منفصل |
| تحديث الـ DOM | Virtual DOM + Diffing | Reactivity (Signals) + Virtual DOM خفيف | Compiler + Signals (Runes) | Signals + Change detection |

:::note[الـ $ في Svelte مش jQuery]
الـ `$state` في Svelte 5 اسمها **Rune**: إشارة للـ Compiler إن المتغير ده State. هو مش Function حقيقية بتتنده وقت التشغيل زي `useState`. الـ Compiler بيشوفها وقت الـ Build ويكتب الكود اللي يحدّث الـ DOM.
:::

## 12.3 حجم اللي وصل للمتصفح

نفس العداد بالظبط، من غير CSS، والأرقام من الـ Build الحقيقي (`vite build` للتلاتة الأولانيين و`ng build` لـ Angular). وزوّدنا نفس العداد بـ JavaScript عادي من غير أي Framework للمقارنة:

**حجم الـ JavaScript لعداد واحد (أكتوبر 2026)**

| الـ Framework | الحجم الخام | بعد الضغط (gzip) |
|---|---|---|
| JavaScript عادي | 0.83 kB | 0.47 kB |
| Svelte 5.57 | 25.30 kB | 10.15 kB |
| Vue 3.5 | 62.39 kB | 24.59 kB |
| Angular 22.2 | 97.14 kB | 29.32 kB (تقدير Angular CLI) |
| React 19.3 | 219.61 kB | 68.64 kB |

:::caution[متفهمش الجدول ده غلط]
الرقم ده هو "الثمن الثابت" اللي بتدفعه علشان تجيب الـ Framework نفسه. ومش معناه إن Svelte أحسن من React بـ 6 مرات. لما التطبيق يكبر، كود التطبيق نفسه بيبقى أكبر بكتير من الـ Framework، والفرق النسبي بيقل. والحجم معيار واحد من كذا معيار: الـ Ecosystem والوظايف والمكتبات والمجتمع بيفرقوا أكتر. بس الجدول بيوضح ليه صفحة بسيطة متحتاجش React (فصل 11)، وليه الـ Meta-frameworks بتحاول تقلل الـ JS اللي بيتبعت (فصل 22).
:::

## 12.4 الفلسفة: Library ضد Framework كامل

#### React: صغيرة ومعاها Ecosystem

بتعمل الـ Components والـ State وبس. الـ Routing؟ اختار مكتبة. البيانات؟ اختار مكتبة. الـ Forms؟ اختار. ده بيديك حرية، وبيديك قرارات كتير. وعلشان كده Next.js بقى مشهور: بيختارلك. ومن Meta (فيسبوك سابقاً)، وأكبر Ecosystem وأكتر وظايف.

#### Angular: كل حاجة في العلبة

Routing و Forms و HTTP و Testing، كلهم رسميين ومن Google. ومبني على TypeScript من الأول. بيتكلم بلغة "الشركات الكبيرة": قواعد واضحة، وكل المشاريع شبه بعض. منحنى التعلم أعلى في الأول.

#### Vue: النص الحلو

أسهل بداية لحد جاي من HTML. فيه Router و State رسميين (Vue Router و Pinia)، بس مش إجباريين. مشهور جداً في آسيا وأوروبا وفي مشاريع Laravel (PHP). ومؤسسه Evan You هو كمان اللي عمل Vite.

#### Svelte: الـ Compiler

أقل كود تكتبه وأصغر ناتج. الـ Syntax أقرب لـ HTML و JS العاديين. المجتمع أصغر، والوظايف أقل، بس الناس اللي بتستخدمه بتحبه جداً. و SvelteKit هو الـ Meta-framework بتاعه.

## 12.5 إيه اللي بيتنقل معاك؟

الخبر الحلو: لو اتعلمت React صح، هتفهم الباقيين في أيام. لأن الأفكار نفسها:

1. **Components** بتاخد Props وترجّع UI.
2. **State** بتتغير، والـ UI يتبعها لوحده.
3. **Derived state** بتتحسب (`useMemo` في React، و`computed` في Vue و Angular، و`$derived` في Svelte).
4. **Effects** للحاجات اللي برة الـ UI: طلب API أو Timer (`useEffect` و`watch` و`$effect` و`effect`).
5. **Lists** بـ Key لكل عنصر، و**Conditional rendering**.
6. نفس **الأدوات** تحتهم: npm و Vite و ESLint و TypeScript. ودي بالظبط اللي جاية في الكتاب.

:::tip[ليه React اختيار منطقي ليك دلوقتي]
أكبر سوق وظايف، وأكبر عدد مكتبات ودروس وإجابات على أي مشكلة، و Next.js لما تحتاج سيرفر، و React Native لو حبيت تعمل تطبيقات موبايل بنفس المعرفة. ومش هتخسر حاجة: الأفكار هتتنقل معاك لأي Framework تاني. متضيعش وقت في "أنهي أحسن". اختار واحد واتعمق.
:::

**المصادر الرسمية:** [React · Quick Start](https://react.dev/learn) · [Vue · Introduction](https://vuejs.org/guide/introduction.html) · [Svelte · Overview](https://svelte.dev/docs/svelte/overview) · [Svelte · $state](https://svelte.dev/docs/svelte/$state) · [Angular · Overview](https://angular.dev/overview) · [Angular · Signals](https://angular.dev/guide/signals)

:::tip[ملخص الفصل]
- الأربعة بيعملوا نفس الحاجة: Components + State + Declarative UI.
- الـ State: `useState` و`ref` و`$state` و`signal`.
- React بتكتب الـ UI بـ JSX جوه JS، والباقيين HTML بإضافات.
- الحجم الثابت لعداد واحد: من 10 كيلو (Svelte) لـ 69 كيلو (React) بعد الضغط، بس ده معيار واحد.
- React مكتبة ومعاها Ecosystem، و Angular كل حاجة جوه، و Vue في النص، و Svelte Compiler.
- الأفكار بتتنقل: لو فهمت React كويس، الباقيين سهلين.
:::

### صح ولا غلط؟

1. في Svelte 5 الـ `$state` Function بتتنده وقت التشغيل زي `useState`.
2. Angular فيه Routing و Forms رسميين جوه الـ Framework.
3. React أكبر في الحجم الثابت، فمعناه إن أي تطبيق React أبطأ من أي تطبيق Svelte.

### أسئلة مراجعة

1. اكتب مكان الـ State في الأربعة من الذاكرة.
2. إيه الفرق بين JSX والـ Templates في Vue و Svelte؟
3. ليه حجم الـ Framework مش المعيار الوحيد؟
4. اذكر 3 أفكار هتتنقل معاك من React لأي Framework تاني.

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** اعمل مشروع Vue بـ `npm create vite@latest my-vue -- --template vue`، وحط فيه العداد، وشغّله بـ `npm run dev`.
2. **[متوسط]** اعمل نفس الحاجة لـ Svelte و React، وقارن الـ `package.json` بتاع التلاتة: إيه في `dependencies` وإيه في `devDependencies`؟
3. **[صعب]** زوّد على العداد: زرار Reset، ورسالة "Big number!" لما العدد يعدّي 10 (Conditional rendering)، في اتنين Frameworks على الأقل. اكتب الفرق اللي حسيته.
