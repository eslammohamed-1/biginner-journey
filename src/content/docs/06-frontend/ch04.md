<small>المرحلة 2 · HTML بجد</small>

أغلب الناس بتكتب Form بـ input وزرار وبعدين تكتب 50 سطر JavaScript علشان تشيك إن الإيميل صح. بس المتصفح بيعرف يعمل ده لوحده من غير ولا سطر. الفصل ده بيشرح الـ Form من غير JavaScript الأول: إيه اللي بيتبعت وليه، وكل Attribute بيعمل إيه، ورسايل الـ Validation الحقيقية اللي Chrome بيطلعها، وبعدين إزاي تاخد الـ Form بـ JavaScript لما تحتاج.

:::note[بعد الفصل ده هتكون عارف]
- الـ Form بيبعت إيه وفين: action و method و name
- label مربوط بـ input، وليه placeholder مش label
- أنواع الـ input والكيبورد اللي بيظهر على الموبايل
- الـ Validation المدمج: required و minlength و pattern و min/max
- autocomplete وليه بيفرق مع الـ Password managers
- fieldset و legend للـ Radio
- FormData و preventDefault: الـ Form من JavaScript
- الـ Validation في المتصفح للراحة، والسيرفر للأمان
:::

## 4.1 Form من غير ولا سطر JavaScript

ده Form تسجيل حقيقي، مفيهوش أي JavaScript:

```html title="forms/index.html"
<form action="/thanks" method="get">
  <label for="name">Name</label>
  <input id="name" name="name" required minlength="3" autocomplete="name">

  <label for="email">Email</label>
  <input id="email" name="email" type="email" required autocomplete="email">

  <label for="age">Age</label>
  <input id="age" name="age" type="number" min="13" max="120">

  <label for="code">Code</label>
  <input id="code" name="code" pattern="[A-Z]{3}-[0-9]{3}" title="Like ABC-123">

  <fieldset>
    <legend>Plan</legend>
    <label><input type="radio" name="plan" value="free" checked> Free</label>
    <label><input type="radio" name="plan" value="pro"> Pro</label>
  </fieldset>

  <label><input type="checkbox" name="news" value="yes"> Newsletter</label>
  <input type="text" placeholder="no name attr">
  <button>Sign up</button>
</form>
```

ملينا الـ Form ده بـ Chrome (بـ Puppeteer، يعني متصفح حقيقي بنتحكم فيه بالكود)، وضغطنا Sign up. ده الـ URL اللي اتفتح بعدها بالحرف:

```text title="URL after submit"
http://localhost:8097/thanks?name=Sara+Ali&email=sara%40example.com&age=25&code=ABC-123&plan=pro&news=yes
```

```text title="الـ URL ده جه منين"
/thanks
?name=Sara+Ali&…
name= email= age= code=
plan=pro
news=yes
(no placeholder field)
```

1. `/thanks`: من `action`: العنوان اللي البيانات بتروحله. لو مكتبتهوش: نفس الصفحة.
2. `?name=Sara+Ali&…`: `method="get"` بيحط البيانات في الـ Query string (كتاب الإنترنت فصل 6). المسافة بقت `+` والـ `@` بقت `%40`: ده الـ URL encoding.
3. `name= email= age= code=`: المفتاح هو الـ <strong>`name` Attribute</strong>، مش الـ `id`. الـ `id` للـ label والـ CSS والـ JS، والـ `name` للبيانات اللي بتتبعت.
4. `plan=pro`: الـ Radio بيبعت `value` بتاع الواحد المختار بس. وكلهم نفس الـ `name` علشان يبقوا مجموعة واحدة (تختار واحد بس).
5. `news=yes`: الـ Checkbox بيتبعت **بس لو متعلّم**. لو مش متعلّم، المفتاح مش هيظهر خالص (مش `news=no`).
6. `(no placeholder field)`: الـ input اللي ملوش `name` **متبعتش خالص**. ودي غلطة شائعة جداً: "كتبت في الخانة والسيرفر مش شايفها".

:::caution[GET ولا POST؟]
`get` للبحث والفلترة (الـ URL ينفع يتحفظ ويتبعت). و`post` لأي حاجة بتغيّر بيانات أو فيها أسرار: التسجيل وتسجيل الدخول والدفع، لأن البيانات بتروح في الـ Body مش في الـ URL (فالـ Password ميتحفظش في الـ History). ده نفس كلام الـ Methods في كتاب APIs و JSON فصل 15.
:::

## 4.2 الـ label: مش ديكور

**تشريح الأمر**

```html
<label for="email">Email</label>
<input id="email" name="email" type="email">
```

1. `for="email"`: بيربط الـ label بالـ input اللي الـ `id` بتاعه `email`. الربط ده بيعمل حاجتين: قارئ الشاشة بيقول "Email, edit text" لما توصل للخانة، والضغط على كلمة Email نفسها بيحط الـ Focus في الخانة (هدف أكبر للصباع على الموبايل).
2. `id="email"`: لازم يبقى فريد في الصفحة كلها.

والطريقة التانية إنك تلف الـ input جوه الـ label: `<label><input type="checkbox"> Newsletter</label>`. ودي مريحة للـ Checkbox والـ Radio.

:::caution[الـ placeholder مش label]
الـ `placeholder` بيختفي أول ما تكتب، فتنسى الخانة دي كانت إيه. ولونه فاتح فصعب يتقري. استخدمه كـ **مثال** بس (`placeholder="sara@example.com"`)، وخلي الـ label موجود دايماً.
:::

## 4.3 أنواع الـ input: كل نوع بيديك حاجة ببلاش

**أهم الأنواع**

| النوع | بيديك إيه ببلاش |
|---|---|
| `email` | Validation للشكل، وكيبورد فيه `@` على الموبايل |
| `tel` | كيبورد أرقام التليفون (من غير Validation: أشكال الأرقام كتير) |
| `url` | Validation إنه URL، وكيبورد فيه `/` و`.com` |
| `number` | أسهم زيادة ونقص، و`min`/`max`/`step`. (لأرقام زي الكود البريدي أو الكارت استخدم `text` + `inputmode="numeric"`) |
| `password` | بيخبي الحروف، والـ Password manager بيعرفه |
| `date` / `time` | Date picker من المتصفح نفسه |
| `checkbox` / `radio` | اختيار متعدد / اختيار واحد من مجموعة |
| `search` | زرار مسح، وبعض الكيبوردات بتكتب "Search" بدل Enter |
| `file` | اختيار ملفات، و`accept="image/*"` و`multiple` |

وفيه كمان `<select>` (قايمة اختيار) و`<textarea>` (نص طويل). والاتنين بياخدوا `name` و`required` زي أي input.

## 4.4 الـ Validation المدمج: رسايل حقيقية من Chrome

دي الحتة اللي ناس كتير متعرفهاش. المتصفح بيشيك لوحده، وبيطلع رسالة، وبيمنع الإرسال. سألنا Chrome عن كل خانة (الخاصية `validationMessage`) مرتين: والـ Form فاضي، وبعد ما كتبنا قيم غلط:

```text title="Chrome · empty form"
name:  valid=false msg="Please fill out this field."
email: valid=false msg="Please fill out this field."
age:   valid=true  msg=""
code:  valid=true  msg=""
```

```text title="Chrome · after typing: Sa / sara@ / 10 / abc-12"
name:  valid=false msg="Please lengthen this text to 3 characters or more (you are currently using 2 characters)."
email: valid=false msg="Please enter a part following '@'. 'sara@' is incomplete."
age:   valid=false msg="Value must be greater than or equal to 13."
code:  valid=false msg="Please match the requested format."
```

| الأمر | بيعمل إيه |
|---|---|
| `required` | الخانة لازم تتملي. لاحظ إن `age` و`code` كانوا `valid=true` وهما فاضيين: من غير `required`، الفاضي مقبول، والقواعد التانية بتتشيك بس لما تكتب حاجة. |
| `minlength / maxlength` | أقل وأكتر عدد حروف. و`maxlength` بيمنعك تكتب أكتر أصلاً. |
| `type="email"` | شيك شكل الإيميل. الرسالة نفسها بتقولك إيه الناقص (`'sara@' is incomplete`). |
| `min / max / step` | للأرقام والتواريخ. |
| `pattern="[A-Z]{3}-[0-9]{3}"` | Regular expression لازم القيمة **كلها** تطابقه (كأن فيه `^…$` لوحده). هنا: 3 حروف Capital، شرطة، 3 أرقام. و`abc-12` فشلت في الاتنين. |
| `title="Like ABC-123"` | مع `pattern`، المتصفحات بتعرضه كتلميح يوضح الشكل المطلوب (وبعضها بيضيفه لفقاعة الخطأ). بس مش جزء من `validationMessage` في Chrome زي ما شفنا، فمتعتمدش عليه لوحده واكتب الشكل المطلوب جنب الخانة. |
| `novalidate` | على الـ `form`: "اقفل الـ Validation بتاعك". بتستخدمه لو هتعمل رسايلك بنفسك بـ JS. |

وتقدر تلوّن الخانات بالـ CSS حسب حالتها: `input:invalid` و`input:valid`. بس `:invalid` بتشتغل من أول ما الصفحة تفتح (الخانة الفاضية الـ required حمرا قبل ما تلمسها!). علشان كده فيه `:user-invalid`: بتشتغل بس بعد ما المستخدم يتعامل مع الخانة.

```css
input:user-invalid {
  border-color: crimson;
}
```

## 4.5 autocomplete: صاحبك اللي محدش بيكلمه

الـ `autocomplete` بيقول للمتصفح والـ Password manager (زي Passwords app على الماك) الخانة دي فيها إيه بالظبط، فيملاها صح:

**أشهر القيم**

| القيمة | للخانة |
|---|---|
| `name` / `email` / `tel` | الاسم والإيميل والتليفون |
| `username` | اسم المستخدم في تسجيل الدخول |
| `current-password` | الباسورد في تسجيل الدخول |
| `new-password` | الباسورد في التسجيل أو التغيير (المتصفح بيقترح باسورد قوي) |
| `one-time-code` | كود الـ SMS، والـ iPhone والماك بيقترحوه من الرسايل |
| `street-address` / `postal-code` | العنوان |

## 4.6 الـ Form من JavaScript

في التطبيقات الحديثة غالباً مش عايز الصفحة تتقلب. عايز تاخد البيانات وتبعتها بـ `fetch`. والطريقة الصح إنك تفضل مستخدم الـ `form` (علشان الـ Validation والـ Enter والـ Accessibility) وتمسك حدث `submit`:

```js
const form = document.querySelector('form')

form.addEventListener('submit', async (event) => {
  event.preventDefault()
  const data = Object.fromEntries(new FormData(form))
  const res = await fetch('/api/signup', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data),
  })
  if (!res.ok) showError(await res.json())
})
```

| الأمر | بيعمل إيه |
|---|---|
| `'submit'` | مش `'click'` على الزرار. الـ `submit` بيتنده بالزرار **وبـ Enter**، و**بعد** ما الـ Validation المدمج ينجح. لو فيه خانة غلط، الحدث مش هيتنده أصلاً. |
| `event.preventDefault()` | "متعملش السلوك الافتراضي" (اللي هو تقليب الصفحة لـ `/thanks`). |
| `new FormData(form)` | بيجمع كل الخانات اللي ليها `name`، بنفس قواعد الإرسال (الـ Checkbox بس لو متعلّم). طبعناه فعلاً: `[["name","Sara Ali"],["email","sara@example.com"],["age","25"],["code","ABC-123"],["plan","pro"],["news","yes"]]`. |
| `Object.fromEntries(…)` | بيحوّل الأزواج دي لـ Object عادي، فتعمله `JSON.stringify`. لاحظ إن كل القيم **Strings**، حتى `"25"`. |
| `fetch + res.ok` | بالظبط زي كتاب APIs و JSON فصل 10. |

:::tip[حاجة مشتركة: نفس الكلام في React]
في React هتكتب `<form onSubmit={handleSubmit}>` وجوه الـ Function `event.preventDefault()`. نفس الحدث بالظبط ونفس الـ Attributes (`required` و`type="email"`…). اللي هيتغير إن الخانات ممكن تبقى "Controlled" (القيمة في State). فكل اللي في الفصل ده هيفضل صح.
:::

:::caution[الـ Validation في المتصفح مش حماية]
أي حد يقدر يفتح DevTools ويشيل `required`، أو يبعت الطلب بـ curl من غير Form خالص (كتاب APIs فصل 8). فالـ Validation في المتصفح علشان **راحة المستخدم** (يعرف غلطته فوراً). أما **الأمان** فلازم السيرفر يشيك تاني على كل حاجة. ودي هتعملها في كورس Maximilian.
:::

**المصادر الرسمية:** [MDN · Your first form](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Your_first_form) · [MDN · Client-side form validation](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Form_validation) · [MDN · autocomplete](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/autocomplete) · [MDN · FormData](https://developer.mozilla.org/en-US/docs/Web/API/FormData) · [MDN · :user-invalid](https://developer.mozilla.org/en-US/docs/Web/CSS/:user-invalid)

:::tip[ملخص الفصل]
- `action` فين، و`method` إزاي (`get` في الـ URL، و`post` في الـ Body)، و`name` هو المفتاح.
- الخانة من غير `name` متتبعتش، والـ Checkbox بيتبعت بس لو متعلّم.
- كل input ليه `label` مربوط بـ `for`/`id`، والـ placeholder مثال مش label.
- الـ `type` الصح بيديك Validation وكيبورد موبايل مناسب.
- `required` و`minlength` و`pattern` و`min`/`max` بيشتغلوا من غير JS.
- من JS: اسمع `submit`، و`preventDefault()`، و`new FormData(form)`.
- الـ Validation في المتصفح للراحة، والسيرفر للأمان.
:::

### صح ولا غلط؟

1. الـ input اللي ليه `id` بس من غير `name` بيتبعت عادي.
2. خانة `pattern` من غير `required` وفاضية بتعتبر valid.
3. طالما عملت `required` في الـ HTML، السيرفر مش محتاج يشيك.

### أسئلة مراجعة

1. إيه الفرق بين `id` و`name` في الـ input؟
2. ليه بنسمع `submit` على الـ form بدل `click` على الزرار؟
3. إيه الفرق بين `:invalid` و`:user-invalid`؟
4. إمتى تستخدم `new-password` وإمتى `current-password`؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** اكتب Form تسجيل دخول فيه username و password بالـ `autocomplete` الصح، وجرّب Safari وهو بيقترحلك.
2. **[متوسط]** اعمل Form بحث بـ `method="get"` فيه خانة و`select` للترتيب، وشوف الـ URL بعد الإرسال. وبعدين حوّله يبعت بـ `fetch` من غير ما الصفحة تتقلب.
3. **[صعب]** اعمل خانتين Password و Confirm، واستخدم `setCustomValidity('Passwords do not match')` على التانية في حدث `input` علشان المتصفح نفسه يمنع الإرسال ويعرض رسالتك.
