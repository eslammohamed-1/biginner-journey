<small>المرحلة 6 · Modules و Vite</small>

رابط الـ API في التطوير غير رابطه في الموقع الحقيقي، واسم الموقع في نسخة التجربة غير الأصلية. فبدل ما تغيّر الكود كل مرة، بتحط الإعدادات دي في ملفات .env. بس فيه فخ كبير: في الـ Front end، أي حاجة بتحطها في الكود بتوصل لأي حد يفتح DevTools. الفصل ده بيوريك الفخ بعينك: مفتاح API سري لقيناه مكتوب جوه ملف الـ JS المبني.

:::note[بعد الفصل ده هتكون عارف]
- تعرف يعني إيه Environment variable
- تكتب ملفات .env و .env.local و .env.\[mode\] وتعرف مين بيكسب
- تستخدم import.meta.env و VITE\_ و MODE و DEV و PROD
- تستخدم %VITE\_X% جوه index.html
- تفهم ليه أي VITE\_ متغير عام، وتشوف التسريب بعينك
- تعرف مكان الأسرار الصح: السيرفر
- تستخدم process.env و node --env-file في كورس Node
:::

<a id="s19-1"></a>

## 19.1 يعني إيه Environment variable؟

متغير بيتحط في **البيئة** اللي البرنامج شغال فيها، مش في الكود نفسه. في الـ Terminal بتشوفها بـ `echo $HOME` (كتاب الـ Terminal). والفكرة: نفس الكود يتصرف مختلف حسب هو شغال فين، من غير ما تعدّله.

## 19.2 في Vite: .env و import.meta.env

جرّبنا على قالب Vite الـ Vanilla. تلات ملفات:

```sh title=".env"
VITE_APP_TITLE=My Links
VITE_COUNT=5
```

```sh title=".env.staging"
VITE_APP_TITLE=Staging Links
```

```sh title=".env.local"
VITE_API_KEY=sk-oops-123
SECRET_TOKEN=do-not-ship
```

```js title="src/main.js"
document.querySelector('#app').innerHTML = `
  <h1>${import.meta.env.VITE_APP_TITLE}</h1>
  <p>mode: ${import.meta.env.MODE}, dev: ${import.meta.env.DEV}, prod: ${import.meta.env.PROD}</p>
`
console.log(import.meta.env.VITE_API_KEY, import.meta.env.SECRET_TOKEN)
console.log(typeof import.meta.env.VITE_COUNT)
```

```html title="index.html (سطر واحد اتغير)"
<title>%VITE_APP_TITLE%</title>
```

وعملنا `npm run build`، وفتحنا ملف الـ JS اللي طلع (آخره):

```js title="dist/assets/index-CrYCwyUk.js (آخر الملف)"
document.querySelector(`#app`).innerHTML=`
  <h1>My Links</h1>
  <p>mode: production, dev: false, prod: true</p>
`,console.log(`sk-oops-123`,void 0),console.log(`string`);
```

| الأمر | بيعمل إيه |
|---|---|
| `My Links` | `import.meta.env.VITE_APP_TITLE` اتبدلت بالقيمة نفسها **وقت البناء**. مفيش متغير في المتصفح أصلاً، القيمة مكتوبة نص. |
| `mode: production` | `MODE` = `development` في `npm run dev` و`production` في `build`. و`DEV` و`PROD` Booleans جاهزين. ومعاهم `BASE_URL` (قيمة `base`). |
| `sk-oops-123` | **المفتاح "السري" مكتوب في الملف**، اللي أي زائر بينزّله. ده التسريب، تحت بالتفصيل. |
| `void 0` | = `undefined`. `SECRET_TOKEN` من غير `VITE_`، فـ Vite **رفض** يحطه. وده الحماية الوحيدة اللي Vite بيديهالك: البادئة. |
| `"string"` | `VITE_COUNT=5` وصل كنص `"5"` مش رقم. كل القيم نصوص. محتاج رقم؟ `Number(import.meta.env.VITE_COUNT)`. ومحتاج Boolean؟ قارن بـ `=== 'true'`. |
| `%VITE_APP_TITLE%` | جوه `index.html` بتتكتب كده، وطلعت `<title>My Links</title>`. |

<a id="s19-3"></a>

## 19.3 مين بيكسب؟

```sh title="Terminal"
$ npx vite build --mode staging
✓ built in 41ms
$ grep -o '<title>.*</title>' dist/index.html
<title>Staging Links</title>
$ VITE_APP_TITLE="From Shell" npx vite build
$ grep -o '<title>.*</title>' dist/index.html
<title>From Shell</title>
```

**ترتيب الملفات (الأقوى تحت)، من دوكيومنتيشن Vite**

| الملف | بيتحمّل إمتى | على Git؟ |
|---|---|---|
| `.env` | دايماً | أيوه (قيم عادية، مش أسرار) |
| `.env.local` | دايماً، على جهازك بس | لأ (`*.local` في `.gitignore`) |
| `.env.[mode]` | في الـ mode ده بس (`.env.production` و`.env.staging`…) | أيوه |
| `.env.[mode].local` | الـ mode ده، وعلى جهازك بس | لأ |
| متغير في الـ Shell | اللي كان موجود قبل ما Vite يشتغل | — |

الملف الخاص بالـ mode أقوى من العام، و`.local` أقوى من غيره، وأي متغير موجود في الـ Shell أقوى من كل الملفات (ودي اللي استخدمتها استضافات زي Vercel و Netlify: بتحط المتغيرات في البيئة وقت الـ Build، فصل 25).

:::danger[مشكلة: غيرت .env ومفيش حاجة اتغيرت]
**العَرَض**: عدّلت قيمة في `.env` والصفحة لسه بالقيمة القديمة.

**السبب**: Vite بيقرا ملفات `.env` مرة واحدة لما يبدأ.

**الحل**: وقّف `npm run dev` (`Ctrl+C`) وشغّله تاني. ولو المتغير لسه `undefined`: اتأكد إنه بادئ بـ `VITE_`، وإن الملف في جذر المشروع جنب `package.json` (مش جوه `src`).
:::

<a id="s19-4"></a>

## 19.4 القاعدة الذهبية: الـ Front end مفيهوش أسرار

:::caution[أي VITE_ = عام]
لو المتغير بادئ بـ `VITE_`، اعتبره **منشور على الإنترنت**. أي زائر يقدر يفتح DevTools ← Sources (كتاب 5 فصل 17) أو يعمل `curl` للملف ويلاقيه، زي ما لقينا `sk-oops-123`. البادئة مش "تشفير"، هي بالعكس: قرار منك إن ده **مسموح يتنشر**. و`.env.local` بيحمي المفتاح من Git بس، مش من الـ Bundle.
:::

**إيه ينفع يبقى VITE\_؟**

| ينفع (عام أصلاً) | ممنوع (سر) |
|---|---|
| رابط الـ API بتاعك (`VITE_API_URL`) | مفتاح OpenAI أو Stripe Secret Key |
| اسم الموقع، و Feature flags | باسورد قاعدة البيانات |
| Keys معمولة مخصوص للمتصفح (Publishable key بتاع Stripe، أو Key مقيّد بالدومين) | أي Token بيدّي صلاحيات كاملة |

طب لو محتاج تكلّم API بمفتاح سري؟ اعمل **سيرفر وسيط** (Backend صغير، أو Serverless function على Vercel أو Netlify): المتصفح يكلّم سيرفرك، وسيرفرك هو اللي معاه المفتاح ويكلّم الـ API. وده بالظبط اللي شرحناه في كتاب الـ APIs (فصل 22، Express)، وهتعمله في كورس Maximilian.

## 19.5 وفي Node: process.env

في السيرفر الوضع مختلف تماماً: الكود مش بيروح لحد، فالأسرار مكانها هنا. والقراية بـ `process.env`، و Node 24 بيقرا ملف `.env` بنفسه من غير أي Package:

```sh title="Terminal"
$ cat s.cjs
console.log(process.env.SECRET_TOKEN, process.env.VITE_APP_TITLE)
$ node s.cjs
undefined undefined
$ node --env-file=.env.local s.cjs
do-not-ship undefined
$ node --env-file=.env --env-file=.env.local s.cjs
do-not-ship My Links
$ node --env-file=missing.env s.cjs
node: missing.env: not found
$ node --env-file-if-exists=missing.env s.cjs
missing.env not found. Continuing without it.
undefined undefined
```

| الأمر | بيعمل إيه |
|---|---|
| `--env-file` | حمّل الملف ده. وتقدر تكرره لأكتر من ملف. |
| `--env-file-if-exists` | نفسه بس مش هيقف لو الملف مش موجود. |
| `في Node مفيش VITE_` | أي اسم ينفع. الـ `VITE_` قاعدة Vite بس، لأن Vite بيحط القيم في كود رايح للمتصفح. |
| `dotenv` | في كورسات Node هتلاقي `npm i dotenv` و`require('dotenv').config()`. نفس الفكرة قبل ما Node يدعمها، ولسه مستخدمة كتير. |

:::tip[عادات .env]
- الأسرار في `.env.local` (أو `.env` في مشروع Node بشرط يكون في `.gitignore`)، ومتعملهاش commit أبداً. ولو حصل: غيّر المفتاح فوراً، لأن الـ Git history بيفضل فاكره (كتاب Git).
- اعمل ملف `.env.example` فيه الأسامي من غير قيم، وارفعه، علشان زميلك يعرف محتاج إيه.
- على الاستضافة: المتغيرات بتتحط من الـ Dashboard، مش بملف (فصل 25).
:::

**المصادر الرسمية:** [Vite · Env Variables and Modes](https://vite.dev/guide/env-and-mode) · [Vite · HTML Constant Replacement](https://vite.dev/guide/env-and-mode#html-constant-replacement) · [Node.js Docs · --env-file](https://nodejs.org/api/cli.html#--env-filefile) · [Node.js Docs · process.env](https://nodejs.org/api/process.html#processenv) · [npm · dotenv](https://www.npmjs.com/package/dotenv)

:::tip[ملخص الفصل]
- Environment variables = إعدادات برة الكود، بتختلف حسب البيئة.
- Vite: `import.meta.env.VITE_X`، و`MODE` و`DEV` و`PROD`، و`%VITE_X%` في الـ HTML.
- القيم بتتكتب في الـ Bundle وقت البناء، وكلها نصوص.
- الترتيب: `.env` ثم `.local` ثم `.env.[mode]` ثم `.env.[mode].local`، والـ Shell فوق الكل. ولازم Restart بعد التعديل.
- أي `VITE_` عام. الأسرار مكانها السيرفر (`process.env` و`node --env-file`).
:::

### صح ولا غلط؟

1. حطيت المفتاح في `.env.local` باسم `VITE_SECRET`، فهو آمن لأنه مش على Git.
2. `import.meta.env.VITE_PORT` قيمته رقم لو كتبت `VITE_PORT=3000`.
3. `npm run build --mode staging` بيحمّل `.env.staging`.

### أسئلة مراجعة

1. ليه `SECRET_TOKEN` طلع `undefined` في المتصفح؟
2. عندك `VITE_X` في `.env` و`.env.production`. أنهي واحدة هتكسب في `build`؟ وفي `dev`؟
3. إزاي تستخدم API محتاج مفتاح سري من موقع React؟
4. إيه الفرق بين `import.meta.env` و`process.env`؟

### تحديات الفصل

2. **[متوسط]** اعمل `.env.staging` وscript اسمه `build:staging` بيبني بيه.
3. **[صعب]** كرر تجربة التسريب: حط `VITE_FAKE_KEY`، واعمل build، ولاقي القيمة بـ `grep -r` في `dist`، وبعدين لاقيها من DevTools على `preview`.
