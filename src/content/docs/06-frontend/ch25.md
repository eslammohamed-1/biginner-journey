<small>المرحلة 8 · الجودة والأداء والنشر</small>

الموقع شغال على localhost، ومحدش في الدنيا شايفه غيرك. النشر (Deploy) يعني ترفع فولدر dist على سيرفر ليه رابط عام. الفصل ده بيشرح إيه اللي بيحصل في أي Deploy، وتلات استضافات مجانية بخطواتهم من الدوكيومنتيشن الرسمي، و Workflow بتاع GitHub Actions سطر سطر، ومتغيرات البيئة على الاستضافة، وأشهر مشكلتين: صفحة بيضا و 404 لما تعمل Refresh.

:::note[بعد الفصل ده هتكون عارف]
- تفهم الـ Deploy: build ثم ارفع dist
- تعرف الفرق بين Static hosting وسيرفر
- تنشر على GitHub Pages بـ Actions وتشرح الـ Workflow
- تعرف خطوات Netlify و Vercel بالـ Git وبالـ CLI
- تفهم Preview deployments و Production
- تحط Environment variables على الاستضافة
- تحل الصفحة البيضا (base) و 404 بتاع الـ SPA
:::

:::note[قبل ما نبدأ: ماعملناش Deploy حقيقي]
النشر على الإنترنت حاجة **عامة** بحسابك، فالكتاب ماعملهاش نيابة عنك. كل اللي في الفصل ده: الخطوات من الدوكيومنتيشن الرسمي (Vite و GitHub و Netlify و Vercel)، والملفات اللي جهّزناها وجرّبناها محلياً (build و preview و lint). الـ Output بتاع النشر نفسه هتشوفه انت لما تعمله.
:::

## 25.1 الـ Deploy بيعمل إيه؟

![كل استضافة حديثة بتعمل نفس الخطوات أوتوماتيك مع كل push](./assets/ch25-fig1.png)

*كل استضافة حديثة بتعمل نفس الخطوات أوتوماتيك مع كل push*

موقع Vite + React (SPA) = ملفات ثابتة: HTML و CSS و JS وصور. مفيش سيرفر بيشغّل كود. فأي **Static hosting** ينفع، وأغلبهم مجاني للمشاريع الشخصية. أما Next.js بـ SSR (فصل 22) فمحتاج استضافة بتشغّل Node، زي Vercel.

**التلاتة**

|   | GitHub Pages | Netlify | Vercel |
|---|---|---|---|
| الرابط | `username.github.io/repo/` | `name.netlify.app` | `name.vercel.app` |
| الإعداد | Workflow في الـ repo + `base` | Import من GitHub | Import من GitHub (بيكتشف Vite لوحده) |
| Preview لكل PR | لأ | أيوه | أيوه |
| Serverless functions / SSR | لأ | أيوه | أيوه، والأفضل لـ Next.js |
| CLI | `gh` (كتاب Git فصل 17) | `netlify-cli` | `vercel` |

## 25.2 GitHub Pages بـ GitHub Actions

كتاب Git (فصل 17) شرح Pages و Actions. هنا التطبيق على Vite، من صفحة "Deploying a Static Site" في دوكيومنتيشن Vite:

1. <strong>اضبط `base`:</strong> في `vite.config.js`: `base: '/my-links/'` (اسم الـ repo بين شرطتين). لو الـ repo اسمه `username.github.io` أو عندك دومين خاص، سيبه `/`.
2. <strong>اعمل ملف الـ Workflow:</strong> `.github/workflows/deploy.yml` (تحت).
3. <strong>فعّل Pages:</strong> في الـ repo ← Settings ← Pages ← Source: **GitHub Actions**.
4. <strong>push على main:</strong> تاب Actions هيوريك الـ Workflow شغال، ولما يخلص الرابط هيظهر.

```yaml title=".github/workflows/deploy.yml (المشروع النهائي)"
name: Deploy to GitHub Pages

on:
  push:
    branches: ['main']
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: 'pages'
  cancel-in-progress: true

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v7
      - name: Set up Node
        uses: actions/setup-node@v7
        with:
          node-version: lts/*
          cache: 'npm'
      - name: Install dependencies
        run: npm ci
      - name: Lint
        run: npm run lint
      - name: Build
        run: npm run build
      - name: Setup Pages
        uses: actions/configure-pages@v6
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v5
        with:
          path: './dist'
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v5
```

| الأمر | بيعمل إيه |
|---|---|
| `on: push / workflow_dispatch` | يشتغل مع كل push على main، أو بزرار "Run workflow" من تاب Actions. |
| `permissions` | أقل صلاحيات لازمة: يقرا الكود، ويكتب على Pages، و`id-token` علشان يثبت هويته لـ Pages من غير Token تحطه انت. |
| `concurrency` | لو عملت push مرتين ورا بعض، الأقدم يتلغي. |
| `runs-on: ubuntu-latest` | جهاز Linux نضيف عند GitHub. علشان كده `node_modules` بتاع الماك مايترفعش أصلاً (فصل 13). |
| `node-version: lts/* و cache: 'npm'` | آخر LTS، وخزّن كاش npm بين التشغيلات (بيعتمد على `package-lock.json`). |
| `npm ci ثم lint ثم build` | نفس اللي بتعمله على جهازك بالظبط. لو ESLint لقى error، الـ Workflow يقف ومفيش نشر (فصل 23). الـ Lint خطوة احنا زودناها على مثال Vite. |
| `upload-pages-artifact: ./dist` | ارفع `dist` بس، و`deploy-pages` ينشره. |
| `@v7 / @v5` | نسخ الـ Actions. مثال Vite في الدوكيومنتيشن بيثبّتهم بـ **SHA** كامل (أأمن: الـ Tag ممكن يتنقل، الـ SHA لأ). احنا استخدمنا الـ Tags للقراية. لما تعمله، انسخ اللي في الدوكيومنتيشن وقتها. |

## 25.3 Netlify

#### بالـ Git (الأسهل)

1. ارفع الكود على GitHub.
2. في Netlify: Import project واختار الـ repo.
3. اختار الـ Branch، و Build command `npm run build`، و Publish directory `dist`، والـ Environment variables.
4. Deploy.

#### بالـ CLI

```sh title="Terminal"
$ npm install -g netlify-cli
$ netlify init
$ netlify deploy
# preview URL to check first
$ netlify deploy --prod
```

وبعد الربط: أي push على Branch تاني أو Pull request = **Preview deployment** برابط مختلف تجرّب عليه، وأي push على main = **Production**. ومع Netlify `base` يفضل `/` لأن الموقع على جذر الدومين.

<a id="s25-4"></a>

## 25.4 Vercel

#### بالـ Git

1. ارفع على GitHub.
2. Import في Vercel.
3. Vercel بيكتشف إن المشروع Vite ويظبط الإعدادات لوحده.
4. نفس فكرة Preview و Production.

#### بالـ CLI

```sh title="Terminal"
$ npm i -g vercel
$ vercel
# or without global install:
$ npx vercel
```

و Vercel هي الشركة اللي بتعمل Next.js، فـ SSR و ISR و Cache Components (فصل 22) شغالين عليها من غير إعداد.

## 25.5 Environment variables على الاستضافة

`.env.local` مش بيترفع على Git (فصل 19)، فالاستضافة مش هتشوفه. الحل: في Netlify أو Vercel، Project settings ← Environment variables ← زوّد `VITE_API_URL` بقيمته. الاستضافة بتحطها في البيئة وقت `npm run build`، و Vite بيقراها (وهي أقوى من ملفات `.env`، فصل 19). وفي GitHub Actions: Settings ← Secrets and variables ← Actions، وبعدين `env:` في خطوة الـ Build. وافتكر: أي `VITE_` هيبقى في الـ JS العام مهما كان مكانه.

## 25.6 أشهر مشكلتين

:::danger[مشكلة: صفحة بيضا على GitHub Pages و Console فيه 404]
**العَرَض**: الرابط بيفتح فاضي، و Network فيه `404` على `/assets/index-….js`.

**السبب**: الموقع على `/my-links/` بس الـ HTML بيطلب `/assets/…` من جذر الدومين، لأن `base` مش متظبط.

**الحل**: `base: '/my-links/'` بنفس اسم الـ repo بالظبط (Case-sensitive). واتأكد قبل الرفع: في المشروع النهائي كل مسارات `dist/index.html` بدأت بـ `/my-links/`.
:::

:::danger[مشكلة: Refresh على /about بيدّي 404]
**العَرَض**: الموقع شغال من الصفحة الرئيسية، والتنقل جوه شغال، بس Refresh على `/about` أو فتح الرابط مباشرة = 404.

**السبب**: في SPA مع React Router، مفيش ملف اسمه `about.html`. الـ Routing بيحصل بـ JS جوه `index.html`. فالسيرفر بيدوّر على الملف ومش لاقيه.

**الحل**: قول للاستضافة "أي مسار مش موجود، رجّع `index.html`". في Netlify: ملف `public/_redirects` فيه `/* /index.html 200`. في Vercel: `rewrites` في `vercel.json` (Vercel بتشرحها في صفحة Vite). وفي GitHub Pages مفيش طريقة رسمية، وده سبب إن ناس كتير بتستخدم Netlify أو Vercel لتطبيقات React.
:::

:::tip[ملخص الفصل]
- Deploy = `npm ci` ثم `build` ثم ارفع `dist`. أي SPA = ملفات ثابتة.
- GitHub Pages: `base: '/repo/'` + Workflow + Source: GitHub Actions.
- Netlify و Vercel: Import من GitHub، و Preview لكل PR، و Production من main. وفيه CLI.
- متغيرات البيئة تتحط في الاستضافة، و`VITE_` لسه عامة.
- صفحة بيضا = `base`. و 404 مع Refresh = محتاج Rewrite لـ `index.html`.
:::

### صح ولا غلط؟

1. موقع Vite + React محتاج سيرفر Node علشان يشتغل.
2. على Netlify، الـ `base` لازم يبقى اسم الـ repo.
3. الـ Workflow بيستخدم `npm ci` علشان يلتزم بالـ Lockfile.

### أسئلة مراجعة

1. رتّب خطوات أي Deploy.
2. إيه فايدة Preview deployment؟
3. الموقع بيفتح على GitHub Pages بس صفحة بيضا. هتعمل إيه خطوة بخطوة؟
