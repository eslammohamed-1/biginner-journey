<small>المرحلة 7 · CSS والـ Rendering و TypeScript</small>

في مشروع كبير، الـ CSS العادي بيوجع: اسم .title في ملف بيبوّظ .title في ملف تاني، وملف CSS بيكبر ومحدش بيجرؤ يمسح منه حاجة. الإيكوسيستم طلّع حلول مختلفة: Tailwind (Classes جاهزة في الـ HTML)، و CSS Modules (أسماء محلية لكل ملف)، و Sass (CSS بقدرات زيادة)، ومكتبات Components جاهزة. الفصل ده بيجرّب الأربعة في Vite ويوريك الـ CSS اللي بيطلع فعلاً.

:::note[بعد الفصل ده هتكون عارف]
- تعرف المشاكل اللي الأدوات دي بتحلها
- تسطّب Tailwind v4 في Vite: @import و @theme وتقرا الـ CSS اللي اتولّد
- تفهم ليه ملف Tailwind صغير مع إن فيه آلاف الـ Classes
- تستخدم CSS Modules وتشوف الأسماء المحلية
- تكتب Sass: متغيرات و Nesting و Mixins
- تعرف مكتبات Components (shadcn/ui و MUI و…) وإمتى تستخدمها
- تختار بينهم
:::

## 20.1 المشكلة

#### Global names

كل Class في CSS عام على الصفحة كلها. انت كتبت `.title` للكارت، وزميلك كتب `.title` للقايمة، واللي اتحمّل بعدين كسب (فصل 6: Source order).

#### كود ميت

Component اتمسح، والـ CSS بتاعه لسه موجود لأن محدش متأكد إن مفيش حاجة تانية بتستخدمه.

#### تكرار

نفس اللون `#1d63ed` مكتوب 40 مرة. (Custom properties حلّت ده جزئياً، فصل 10.)

#### التنقّل

علشان تعدّل زرار، بتفتح ملف HTML وملف CSS وتدوّر على الاسم.

## 20.2 Tailwind CSS v4

الفكرة: بدل ما تكتب CSS وتسمّي Classes، تستخدم Classes جاهزة صغيرة كل واحدة بتعمل حاجة واحدة (**Utility classes**) مباشرة في الـ HTML. التسطيب في Vite (من دوكيومنتيشن Tailwind، وده اللي عملناه في المشروع النهائي):

1. <strong>سطّب:</strong> `npm install tailwindcss @tailwindcss/vite` (عندنا: `added 17 packages`، النسخة 4.3.3).
2. **ضيف الـ Plugin** في `vite.config.js`: `plugins: [tailwindcss()]` (فصل 18).
3. <strong>سطر واحد في الـ CSS:</strong> `@import "tailwindcss";`. مفيش `tailwind.config.js` في v4 (لو فيديو قديم بيعمله، ده v3).

```css title="src/style.css (المشروع النهائي)"
@import 'tailwindcss';

@theme {
  --color-brand: #1d63ed;
}
```

```js title="src/main.js (جزء)"
`<h1 class="text-3xl font-bold text-brand">${title}</h1>`
`<a class="block rounded-xl bg-white p-4 shadow hover:shadow-lg
   focus-visible:outline-2 focus-visible:outline-brand" …>`
```

وده الـ CSS اللي Tailwind ولّده فعلاً في `dist`:

```css title="dist/assets/index-NALiIVJV.css (مقتطفات)"
.text-brand{color:var(--color-brand)}
.p-4{padding:calc(var(--spacing) * 4)}
.rounded-xl{border-radius:var(--radius-xl)}
--spacing:.25rem
--radius-xl:.75rem
--color-brand:#1d63ed
```

| الأمر | بيعمل إيه |
|---|---|
| `@theme { --color-brand }` | عرّفت لون اسمه `brand`، فـ Tailwind عمل لوحده `text-brand` و`bg-brand` و`outline-brand`… كل الـ Design tokens في v4 Custom properties عادية (فصل 10). |
| `p-4` | = `4 × --spacing` = 4 × 0.25rem = 1rem. كل المسافات مضاعفات رقم واحد، فالتصميم بيبقى متناسق. |
| `hover:shadow-lg` | Variant: الـ Class تشتغل في `:hover` بس. ولقيناها في الملف جوه `@media (hover:hover)`، يعني على الأجهزة اللي فيها ماوس بس (مش اللمس). وفيه `md:` للـ Breakpoints و`dark:` و`focus-visible:`. |
| `9.53 kB` | ملف الـ CSS كله 9533 بايت، مع إن Tailwind فيه آلاف الـ Classes. السر: Tailwind بيقرا ملفاتك ويولّد **بس** الـ Classes اللي لقاها مكتوبة. دوّرنا على `bg-red-500` (مش مستخدمة): 0 مرة. |
| `@layer` | الـ CSS جوه `@layer theme, base, components, utilities` (فصل 6)، فالـ Utilities دايماً تكسب. |

:::caution[فخ: أسماء Classes بتتركب]
Tailwind بيدوّر على الأسماء **كاملة** كنص في ملفاتك. فلو كتبت `` `text-${color}-500` ``، مش هيلاقي `text-red-500` في أي حتة، ومش هيولّدها، والـ Class هتبقى من غير ستايل. اكتب الاسم كامل: `color === 'red' ? 'text-red-500' : 'text-blue-500'`.
:::

:::note[الـ HTML بقى طويل ومزعج؟]
ده أكتر انتقاد لـ Tailwind. الرد: في React مش هتكرره، هتعمل Component `<LinkCard>` مرة واحدة. والميزة: الستايل جنب الـ HTML، ولو مسحت Component الـ CSS بتاعه بيختفي من الـ Build لوحده. وامتداد **Tailwind CSS IntelliSense** في VS Code بيكمّلك الأسماء ويوريك الـ CSS لما تقف عليها.
:::

## 20.3 CSS Modules

أي ملف اسمه `*.module.css`، Vite بيخلّي الـ Classes بتاعته **محلية**. جرّبنا ملفين فيهم نفس الاسم `.title`:

```css title="card.module.css"
.title {
  color: #1d63ed;
}
.btn {
  padding: 8px 16px;
}
```

```css title="list.module.css"
.title {
  color: crimson;
}
```

```js title="main.js"
import card from './card.module.css'
import list from './list.module.css'

document.querySelector('#app').innerHTML = `
  <h2 class="${card.title}">Card title</h2>
  <h2 class="${list.title}">List title</h2>
`
```

```css title="الـ CSS بعد build"
._title_1rm06_1{color:#1d63ed}._btn_1rm06_4{padding:8px 16px}._title_13fkz_1{color:#dc143c}
```

كل `.title` بقى اسم فريد (`_title_1rm06_1` و`_title_13fkz_1`)، و`card` في JS Object فيه `{ title: '_title_1rm06_1', btn: '_btn_1rm06_4' }`. مفيش تصادم ممكن. ولاحظ إن `crimson` اتحولت `#dc143c` (أقصر). في React بتكتبها `className={styles.title}`.

## 20.4 Sass

Sass = CSS بقدرات زيادة، بتتحول لـ CSS عادي. Vite بيدعمه لو سطبت `sass`: `npm i -D sass` (1.106.1)، وسمّي الملف `.scss`.

```css title="src/theme.scss"
$brand: #1d63ed;
$radius: 8px;

@mixin card-box($pad) {
  padding: $pad;
  border-radius: $radius;
}

.card {
  @include card-box(16px);
  border: 1px solid rgba($brand, 0.3);

  .title {
    color: $brand;
  }

  &:hover {
    background: rgba($brand, 0.05);
  }
}
```

```css title="الناتج"
.card{border:1px solid #1d63ed4d;border-radius:8px;padding:16px}.card .title{color:#1d63ed}.card:hover{background:#1d63ed0d}
```

| الأمر | بيعمل إيه |
|---|---|
| `$brand` | متغير وقت البناء (اختفى من الناتج واتبدل بالقيمة). على عكس `--brand` اللي بيفضل في المتصفح ويتغير بـ JS أو Media query. |
| `@mixin / @include` | حتة CSS بتتكرر بـ Parameters. |
| `Nesting و &` | `.title` جوه `.card` = `.card .title`. وده بقى موجود في CSS العادي (فصل 10)، فواحدة من أكبر أسباب Sass راحت. |
| `rgba($brand, 0.3)` | Function بتاعة Sass طلعت `#1d63ed4d` (لون بشفافية). |

ولاحظ حاجة وقت التسطيب: npm 11 طلّع `npm warn install-scripts 1 package has install scripts not yet covered by allowScripts: @parcel/watcher@2.6.0`. ده تحذير npm 12 بدري (فصل 16): Package بيستخدمه sass عنده Install script.

:::tip[Sass في 2026؟]
هتلاقيه في مشاريع كتير موجودة وفي Bootstrap. لكن مع Custom properties و Nesting و `color-mix()` في الـ CSS نفسه (فصل 10)، مشروع جديد غالباً مش محتاجه. اتعلّم تقراه، ومتبدأش بيه.
:::

## 20.5 مكتبات Components جاهزة

بدل ما تبني Modal و Dropdown و Date picker من الصفر (وتتعب في الـ Keyboard والـ ARIA، فصل 5)، فيه مكتبات جاهزة. أغلبها لـ React:

**أشهر الأنواع**

| النوع | أمثلة | الفكرة |
|---|---|---|
| Headless (من غير ستايل) | Radix UI و React Aria و Headless UI | السلوك والـ Accessibility جاهزين، والشكل عليك. |
| Copy-paste | shadcn/ui | مش Package: أمر بينسخ كود الـ Component في مشروعك (مبني على Radix و Tailwind)، فتعدّل فيه براحتك. |
| Styled كاملة | MUI (Material) و Chakra UI و Mantine و Ant Design | شكل جاهز ومتناسق وسريع، بس تغيير الشكل أصعب. |
| Classes فوق Tailwind | daisyUI | `btn` و`card` جاهزين. |
| من غير Framework | Bootstrap | CSS + JS. الأقدم، وفيه Templates كتير. |

## 20.6 تختار إيه؟

**مقارنة سريعة**

|   | CSS عادي | CSS Modules | Tailwind | Sass |
|---|---|---|---|---|
| تصادم الأسماء | ممكن | مستحيل | مفيش أسماء | ممكن |
| تسطيب | مفيش | مفيش (Vite) | Package + Plugin | Package |
| هتلاقيه في | كل حتة | React و Next.js | أغلب المشاريع الجديدة و shadcn/ui | مشاريع أقدم و Bootstrap |

نصيحتي ليك: اتعلّم CSS العادي كويس الأول (الفصول 6-10)، لأن كل الأدوات دي بتطلّع CSS في الآخر، ولما حاجة تبوظ هتفتح DevTools وتلاقي CSS عادي. وبعدها جرّب Tailwind في مشروع React، لأنه هيقابلك في أغلب الـ Tutorials والشغل الحديث.

**المصادر الرسمية:** [Tailwind CSS · Installing with Vite](https://tailwindcss.com/docs/installation/using-vite) · [Tailwind CSS · Theme variables (@theme)](https://tailwindcss.com/docs/theme) · [Tailwind CSS · Detecting classes in source files](https://tailwindcss.com/docs/detecting-classes-in-source-files) · [Tailwind CSS · Hover, focus and other states](https://tailwindcss.com/docs/hover-focus-and-other-states) · [Vite · CSS Modules](https://vite.dev/guide/features#css-modules) · [Vite · CSS Pre-processors](https://vite.dev/guide/features#css-pre-processors) · [Sass · Basics](https://sass-lang.com/guide/) · [shadcn/ui · Docs](https://ui.shadcn.com/docs) · [Radix Primitives](https://www.radix-ui.com/primitives) · [MUI · Getting started](https://mui.com/material-ui/getting-started/)

:::tip[ملخص الفصل]
- CSS عام وبيتراكم، والأدوات بتحل ده بطرق مختلفة.
- Tailwind v4: `@import "tailwindcss"` + `@theme` + Plugin، وبيولّد اللي انت استخدمته بس. واكتب أسماء الـ Classes كاملة.
- CSS Modules: `*.module.css` = أسماء فريدة لكل ملف.
- Sass: متغيرات و Mixins و Nesting، وبيطلع CSS عادي. أغلبه بقى في الـ CSS نفسه.
- مكتبات الـ Components: Headless و shadcn/ui و Styled كاملة.
:::

### صح ولا غلط؟

1. Tailwind v4 محتاج `tailwind.config.js`.
2. في CSS Modules، `.title` في ملفين مختلفين بيطلعوا نفس الاسم.
3. المتغير `$brand` بتاع Sass ممكن تغيّره بـ JS في المتصفح.

### أسئلة مراجعة

1. ليه ملف Tailwind النهائي صغير؟ وإيه الفخ اللي ممكن يخلّي Class متتولّدش؟
2. إيه الفرق بين متغير Sass و Custom property؟
3. إيه الفرق بين shadcn/ui و MUI؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** سطّب Tailwind في مشروع Vite بالتلات خطوات، واعمل كارت بـ `p-4 rounded-xl shadow`.
2. **[متوسط]** ضيف لون `brand` في `@theme` واستخدمه في `bg-brand` و`hover:bg-brand/80`. دوّر عليهم في الـ CSS بعد build.
3. **[صعب]** اعمل نفس الكارت 3 مرات: CSS Module و Tailwind و Sass، وقارن حجم الـ CSS في `dist` في كل حالة.
