<small>المرحلة 8 · الجودة والأداء والنشر</small>

الموقع شغال عندك على الماك وواي فاي البيت سريع. بس المستخدم الحقيقي على موبايل متوسط ونت 4G ضعيف، وفيه اللي بيستخدم Screen reader. إزاي تعرف تجربتهم؟ الفصل ده بيشرح Core Web Vitals (المقاييس اللي جوجل بتقيس بيها تجربة المستخدم)، وبيشغّل Lighthouse على مشروعنا وعلى صفحة سيئة عن قصد، ويقرا كل رقم، ويوريك حدود الفحص الأوتوماتيكي.

:::note[بعد الفصل ده هتكون عارف]
- تعرف LCP و INP و CLS والحدود بتاعتهم
- تفرق بين Lab data و Field data
- تشغّل Lighthouse من DevTools ومن الـ CLI
- تقرا التقرير: الـ Scores والـ Metrics والـ Insights
- تصلّح أشهر المشاكل
- تفحص الـ Accessibility أوتوماتيك وتعرف اللي الأداة مش هتلاقيه
:::

<a id="s24-1"></a>

## 24.1 Core Web Vitals: تلات أسئلة

**الحدود الرسمية (web.dev). «جيد» لازم يتحقق لـ 75% من الزيارات (p75)**

| المقياس | بيسأل | جيد | سيئ |
|---|---|---|---|
| **LCP** Largest Contentful Paint | أكبر حاجة في الشاشة (صورة أو عنوان) ظهرت إمتى؟ | ≤ 2.5 ثانية | \> 4 ثواني |
| **INP** Interaction to Next Paint | لما بدوس، الصفحة بترد بسرعة؟ | ≤ 200ms | \> 500ms |
| **CLS** Cumulative Layout Shift | الحاجات بتتنطط وهي بتحمّل؟ | ≤ 0.1 | \> 0.25 |

INP حل محل FID (First Input Delay) في مارس 2024، فلو مقال قديم بيتكلم عن FID، ده المقياس القديم. وكل واحد ليه أسباب مشهورة:

| الأمر | بيعمل إيه |
|---|---|
| `LCP بطيء` | صورة كبيرة مش متضغطة، أو CSR (الصفحة فاضية لحد ما JS يخلص، فصل 22)، أو سيرفر بطيء، أو CSS و JS بيعطّلوا الرسم (Render-blocking). |
| `INP عالي` | JS كتير شغال على الـ Main thread، فالمتصفح مشغول ومش قادر يرد على الضغطة. |
| `CLS عالي` | صورة من غير `width` و`height` (فالمتصفح مايعرفش يحجزلها مكان)، أو إعلان أو Banner بيظهر فوق المحتوى، أو خط بيتغير. |

<a id="s24-2"></a>

## 24.2 Lab ولا Field؟

#### Lab data

اختبار على جهاز واحد في ظروف ثابتة: Lighthouse. ممتاز علشان تلاقي المشاكل وتجرّب الحلول. بس مش بيقيس INP (مفيش مستخدم بيدوس)، فبيقيس **TBT** (Total Blocking Time) كبديل.

#### Field data

أرقام من زوار حقيقيين على Chrome (اسمها CrUX). بتظهر في **PageSpeed Insights** لو موقعك عليه زيارات كفاية. ده اللي جوجل بتعتمد عليه فعلاً.

<a id="s24-3"></a>

## 24.3 نشغّل Lighthouse

1. <strong>من Chrome:</strong> DevTools (`⌥⌘I`) ← تاب **Lighthouse** ← اختار Mobile والـ Categories ← Analyze page load. افتحه في نافذة Incognito علشان الـ Extensions ماتأثرش.
2. <strong>من الـ Terminal:</strong> `npx lighthouse <url>` (احنا استخدمنا 13.5.0 مع Output بصيغة JSON).
3. <strong>على الـ Build مش الـ Dev:</strong> شغّل `npm run build` و`npm run preview` واختبر الـ preview. الـ Dev server مش مضغوط وفيه HMR، فالأرقام هتطلع أوحش من الحقيقة.

شغّلناه على `preview` بتاع مشروع links-card (نسخة أولى من المشروع النهائي: Vite + Tailwind)، والإعدادات الافتراضية: `mobile` و`simulate` (بيحاكي موبايل متوسط ونت 4G بطيء):

**النتيجة الحقيقية (Lighthouse 13.5.0)**

| Category | Score | Metric | القيمة |
|---|---|---|---|
| Performance | 100 | FCP | 1.0 s |
| Accessibility | 100 | LCP | 1.0 s |
| Best Practices | 100 | TBT | 0 ms |
| SEO | 90 | CLS | 0 |
| Agentic Browsing | 100 | Speed Index | 1.0 s |

| الأمر | بيعمل إيه |
|---|---|
| `FCP 1.0 s` | First Contentful Paint: أول حاجة اترسمت. والـ LCP نفس الوقت لأن الصفحة صغيرة. |
| `TBT 0 ms` | مفيش JS تقيل بيعطّل (1.29 kB JS بس، فصل 26). قارن بـ 222 kB بتوع React (فصل 2). |
| `SEO 90` | نقص بسبب `meta-description`: "Document does not have a meta description". الحل سطر: `<meta name="description" content="…">`. |
| `Agentic Browsing` | Category جديدة في Lighthouse بتقيس: هل أدوات الـ AI اللي بتتصفح المواقع تقدر تفهم صفحتك وتتعامل معاها. (وصفها التفصيلي في دوكيومنتيشن Lighthouse؛ احنا بننقل الـ Score بس.) |
| `Insights` | طلع اتنين: `render-blocking-insight` (ملف الـ CSS بيوقف الرسم لحد ما ينزل) و`network-dependency-tree-insight` (سلسلة Requests ورا بعض). نصايح مش أخطاء، وأثرها هنا صغير جداً. |

:::caution[متعبدش الـ 100]
الـ Score بيتغير من تشغيلة للتانية حسب الجهاز. وبيقيس صفحة واحدة في ظروف معينة. استخدمه علشان تلاقي مشاكل وتقارن قبل وبعد، مش كهدف في حد ذاته.
:::

## 24.4 الـ Accessibility: صفحة سيئة عن قصد

فاكر فصل 5؟ كتبنا صفحة فيها كل الأخطاء المشهورة:

```html title="badpage/index.html"
<html>
  <head><meta charset="UTF-8" /><title>bad</title></head>
  <body>
    <div style="font-size:24px" onclick="go()">Welcome</div>
    <img src="data:image/gif;base64,…" width="200" height="100">
    <p style="color:#bbb;background:#fff">Light grey text that is hard to read</p>
    <input type="email" placeholder="Email">
    <button><svg width="16" height="16"></svg></button>
    <a href="/more">click here</a>
  </body>
</html>
```

Lighthouse (Accessibility بس) إداها **53**، والمشاكل اللي لقاها:

**اللي Lighthouse لقاه**

| Audit | الرسالة | الحل |
|---|---|---|
| `html-has-lang` | `<html>` element does not have a `[lang]` attribute | `<html lang="ar" dir="rtl">` |
| `image-alt` | Image elements do not have `[alt]` attributes | `alt` بيوصف الصورة، أو `alt=""` لو زينة |
| `color-contrast` | …do not have a sufficient contrast ratio | #bbb على أبيض نسبته أقل من 4.5:1. غمّق اللون |
| `button-name` | Buttons do not have an accessible name | `aria-label="Search"` أو نص مخفي |
| `landmark-one-main` | Document does not have a main landmark. | `<main>` حوالين المحتوى |

### واللي ماشافوش

:::caution[الأداة الأوتوماتيك بتلاقي جزء بس]
Lighthouse **مالقاش** اتنين من أسوأ المشاكل في الصفحة:

- `<div onclick>`: مش بيوصله Tab ولا بيشتغل بـ Enter (فصل 5). الأداة مش عارفة إن الـ div ده المفروض "زرار".
- `<input placeholder="Email">` من غير `<label>`: الـ Placeholder اتحسب كاسم فعدّى، مع إنه بيختفي وانت بتكتب (فصل 4).
- و"click here" كنص رابط مش بيقول الرابط رايح فين.

علشان كده لازم كمان تجرّب بنفسك: امشي في الصفحة بـ **Tab** بس، وشغّل **VoiceOver** على الماك (`⌘F5`)، وبص على الـ Accessibility tree في DevTools (فصل 3).
:::

وفيه أدوات زيادة مبنية على نفس المحرك (axe-core) اللي Lighthouse بيستخدمه: امتداد **axe DevTools**، وفي الـ Tests مكتبات زي `@axe-core/playwright`. وفي React، Plugin `eslint-plugin-jsx-a11y` بيمسك جزء من المشاكل وانت بتكتب.

## 24.5 أشهر الإصلاحات

1. <strong>الصور:</strong> صيغة حديثة (WebP أو AVIF)، ومقاس مناسب، و`width`/`height` دايماً (CLS)، و`loading="lazy"` للي تحت الشاشة بس (مش صورة الـ LCP).
2. <strong>JS أقل:</strong> Code splitting بـ `import()` (فصل 17)، وراجع الـ Packages الكبيرة قبل ما تسطّبها.
3. <strong>الخطوط:</strong> `font-display: swap`، وخطوط أقل.
4. <strong>Cache:</strong> الأسماء اللي فيها Hash بتتخزن (فصل 18)، والاستضافات الحديثة بتعمل ده لوحدها.
5. <strong>Semantic HTML:</strong> أغلب مشاكل الـ a11y بتتحل بإنك تستخدم العنصر الصح (الفصول 3-5).

:::tip[ملخص الفصل]
- LCP ≤ 2.5s، و INP ≤ 200ms، و CLS ≤ 0.1، على 75% من الزيارات.
- Lab (Lighthouse) للتشخيص، و Field (CrUX و PageSpeed Insights) للحقيقة.
- اختبر الـ preview مش الـ dev، وفي Incognito.
- Lighthouse لقى 5 مشاكل a11y، بس مالقاش الـ div اللي بيتداس ولا الـ input من غير label. جرّب بالكيبورد و VoiceOver.
:::

### صح ولا غلط؟

1. Lighthouse بيقيس INP مباشرة.
2. صورة من غير `width` و`height` ممكن تزوّد CLS.
3. Accessibility 100 في Lighthouse يعني الموقع Accessible تماماً.

### أسئلة مراجعة

1. ليه نختبر الـ preview مش الـ dev server؟
2. موقع CSR بـ React صفحته الرئيسية LCP 5 ثواني. اقترح 3 حلول.
3. اذكر مشكلتين a11y الأدوات الأوتوماتيك مش هتلاقيهم.

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** شغّل Lighthouse من DevTools على مشروع من الكورس، واكتب الـ 4 Scores.
2. **[متوسط]** اعمل الصفحة السيئة، وصلّحها لحد ما Accessibility تبقى 100، وبعدين صلّح الحاجتين اللي Lighthouse مالقاهمش.
3. **[صعب]** جرّب موقعك على PageSpeed Insights بعد ما تنشره. فيه Field data؟ لو لأ، ليه؟
