<small>المرحلة 8 · الجودة والأداء والنشر</small>

كتبت consol.log بدل console.log، ومحدش لاحظ لحد ما الصفحة ضربت في الإنتاج. وزميلك بيحب Double quotes وانت Single، وكل Pull request نصه تغييرات مسافات. أداتين بيحلوا المشكلتين: ESLint بيدوّر على الأخطاء والكود المشكوك فيه، و Prettier بيوحّد الشكل. الفصل ده بيعمل الاتنين في مشروع Vite ويشرح كل سطر في ملفات الإعدادات وكل Output.

:::note[بعد الفصل ده هتكون عارف]
- تفرق بين Linter و Formatter
- تسطّب ESLint 10 بالـ Flat config وتشرح كل سطر
- تقرا Output بتاع ESLint: السطر والعمود والـ Rule
- تستخدم --fix وتعرف إمتى بيصلّح
- تسطّب Prettier بـ --save-exact وتعرف .prettierrc و .prettierignore
- تخلّي ESLint و Prettier مايتخانقوش (eslint-config-prettier)
- تربطهم بـ VS Code وبالـ scripts وبالـ CI
:::

<a id="s23-1"></a>

## 23.1 اتنين مختلفين

#### ESLint = مصحح

بيقرا الكود ويدوّر على **مشاكل**: متغير مش معرّف، متغير مش مستخدم، كود مش هيتنفذ أبداً، Hooks متكتبة غلط في React. بيقولك "ده غالباً Bug".

#### Prettier = منسّق

مابيهتمش الكود صح ولا غلط. بياخده ويعيد كتابته **بشكل واحد ثابت**: مسافات، و Quotes، وطول السطر. مفيش نقاش في الفريق تاني.

<a id="s23-2"></a>

## 23.2 ESLint في المشروع النهائي

الطريقة الرسمية لمشروع جديد: `npm init @eslint/config@latest` (يعني `npx @eslint/create-config`، فصل 13)، وهيسألك أسئلة ويكتب الملف. ومحتاج Node `^20.19` أو `^22.13` أو `>=24`. احنا سطبناها بإيدنا علشان نفهم كل Package:

```sh title="Terminal"
$ npm install -D eslint @eslint/js globals eslint-config-prettier
added 80 packages, and audited 113 packages in 1s
```

| الأمر | بيعمل إيه |
|---|---|
| `eslint` | الأداة نفسها (10.13.0). |
| `@eslint/js` | الـ Rules الأساسية بتاعة JavaScript، ومنها `recommended`. |
| `globals` | لستة المتغيرات الموجودة جاهزة: `document` و`window` في المتصفح، أو `process` في Node. من غيرها ESLint هيقول `'document' is not defined`. |
| `eslint-config-prettier` | بيقفل أي Rule ليها علاقة بالشكل، علشان Prettier هو المسؤول عنه. |

```dockerfile
import js from '@eslint/js'
import globals from 'globals'
import { defineConfig, globalIgnores }
  from 'eslint/config'
import prettier from
  'eslint-config-prettier/flat'
export default defineConfig([
  globalIgnores(['dist']),
  {
    files: ['**/*.js'],
    extends: [js.configs.recommended,
              prettier],
    languageOptions:
      { globals: globals.browser },
    rules: {
      'no-unused-vars': 'warn',
    },
  },
])
```

1. `import js from '@eslint/js'`: الملف ES Module عادي (`eslint.config.js`). ده الـ **Flat config**، الوحيد في ESLint 10. لو شفت `.eslintrc.json` في فيديو قديم، دي الطريقة القديمة.
2. `export default defineConfig([`: متفحصش `dist` (كود مبني ومضغوط).
3. `{`: الإعدادات دي لكل ملفات `.js`.
4. `extends: [js.configs.recommended,`: ابدأ بالـ Rules الموصى بيها، وبعدين اقفل بتوع الشكل. `prettier` لازم **آخر واحد**.
5. `languageOptions:`: الكود ده بيشتغل في المتصفح.
6. `rules: {`: غيّرنا Rule واحدة: المتغير اللي مش مستخدم `warn` (أصفر) بدل `error`. القيم: `"off"` و`"warn"` و`"error"`.

### التجربة

زوّدنا آخر `src/main.js` تلات سطور فيهم غلطتين، وفعّلنا مؤقتاً Rule زيادة `'prefer-const': 'error'`:

```js
let count = 0
const unused = 42
consol.log("count is", count)
```

```sh title="Terminal"
$ npx eslint .

/tmp/lint/src/main.js
  24:5  error    'count' is never reassigned. Use 'const' instead  prefer-const
  25:7  warning  'unused' is assigned a value but never used       no-unused-vars
  26:1  error    'consol' is not defined                           no-undef

✖ 3 problems (2 errors, 1 warning)
  1 error and 0 warnings potentially fixable with the `--fix` option.
```

**تشريح الأمر**

```text
26:1  error    'consol' is not defined    no-undef
```

1. `26:1`: السطر 26، العمود 1.
2. `error`: الخطورة. أي error يخلّي الأمر يرجع exit 1 (فيوقف الـ CI).
3. `'consol'…`: الرسالة: الاسم ده مش معرّف في أي حتة. غلطة إملائية كانت هتبقى `ReferenceError` في المتصفح.
4. `no-undef`: اسم الـ Rule. دوّر عليه في `eslint.org/docs/latest/rules/no-undef` تعرف ليه وأمثلة.

```sh title="Terminal"
$ npx eslint . --fix

/tmp/lint/src/main.js
  25:7  warning  'unused' is assigned a value but never used  no-unused-vars
  26:1  error    'consol' is not defined                      no-undef

✖ 2 problems (1 error, 1 warning)
$ tail -3 src/main.js
const count = 0
const unused = 42
consol.log("count is", count)
```

`--fix` غيّر `let` لـ `const` لوحده (الحل واضح ومضمون)، بس **ماقدرش** يصلّح `consol` ولا يمسح `unused`: دول محتاجين قرار منك. وفي React هتلاقي Rules مهمة جداً من `eslint-plugin-react-hooks` (القالب بيجيبها مع `--eslint`، فصل 18).

:::note[وقوالب React الجديدة فيها Oxlint]
create-vite بقى بيدّي React **Oxlint** افتراضياً: Linter مكتوب بـ Rust، أسرع بكتير، وبيدعم أغلب Rules بتاعة ESLint، وإعداداته في `.oxlintrc.json` والأمر `"lint": "oxlint"`. الفكرة نفسها والـ Output شبهه. لو الكورس بيستخدم ESLint، اعمل المشروع بـ `--eslint`.
:::

## 23.3 Prettier

```sh title="Terminal"
$ npm install -D --save-exact prettier
added 1 package, and audited 114 packages in 397ms
```

ليه `--save-exact`؟ دوكيومنتيشن Prettier بيطلبها صريح: أي نسخة جديدة (حتى Patch) ممكن تغيّر شكل التنسيق شوية، فلو كل واحد في الفريق عنده نسخة، كل واحد هيعيد تنسيق الملفات بشكل مختلف. فـ `"prettier": "3.9.10"` بالظبط (فصل 15).

```json title=".prettierrc"
{
  "singleQuote": true,
  "semi": false
}
```

Single quotes ومن غير `;` (زي ستايل كتير من الكورسات). الدوكيومنتيشن بيقترح تبدأ بـ `{}` وتسيب الافتراضي.

```text title=".prettierignore"
dist
package-lock.json
```

ملفات ماتنسقهاش. (Prettier بيتجاهل `node_modules` لوحده، وبيقرا `.gitignore` كمان.)

```js title="قبل"
const user={name:"Sara",age:25,skills:["html","css","js"]}
function greet(u){return "Hi "+u.name+"!";}
if(user.age>18){console.log(greet(user))}
```

```js title="بعد npx prettier"
const user = { name: 'Sara', age: 25, skills: ['html', 'css', 'js'] }
function greet(u) {
  return 'Hi ' + u.name + '!'
}
if (user.age > 18) {
  console.log(greet(user))
}
```

### check ولا write؟

```sh title="Terminal"
$ npm run format:check
Checking formatting...
[warn] src/main.js
[warn] Code style issues found in the above file. Run Prettier with --write to fix.
$ echo $?
1
$ npm run format
.github/workflows/deploy.yml 14ms (unchanged)
…
src/main.js 8ms
src/style.css 12ms (unchanged)
$ diff before.js src/main.js
< consol.log("count is", count)
---
> consol.log('count is', count)
```

| الأمر | بيعمل إيه |
|---|---|
| `"format": "prettier . --write"` | نسّق كل الملفات واكتبها. السطر اللي مفيهوش `(unchanged)` هو اللي اتغير. |
| `"format:check": "prettier . --check"` | افحص بس ومتغيرش. بيرجع exit 1 لو فيه ملف مش متنسق. ده اللي يتحط في الـ CI. |
| `"lint": "eslint ."` | النقطة = الفولدر الحالي كله. |

:::caution[npx prettier من غير تسطيب]
دوكيومنتيشن Prettier بيحذّر: لو كتبت `npx prettier` في مشروع مش متسطب فيه، npx هينزّل **أحدث نسخة** (فصل 13)، اللي ممكن تنسّق غير نسخة الفريق. سطّبه في المشروع الأول.
:::

## 23.4 في VS Code وفي الـ CI

1. <strong>الامتدادات:</strong> "ESLint" (من Microsoft) بيحط خط تحت المشاكل وانت بتكتب، و"Prettier - Code formatter" (من Prettier).
2. <strong>Format on save:</strong> من Settings (`⌘,`) دوّر على `Format On Save` وفعّله، واختار Prettier في `Default Formatter`. كل `⌘S` = ملف متنسق.
3. <strong>الـ CI:</strong> في GitHub Actions بتاع المشروع النهائي فيه خطوة `npm run lint` قبل `npm run build` (فصل 25). أي error يوقف الـ Deploy.

**المصادر الرسمية:** [ESLint · Getting Started](https://eslint.org/docs/latest/use/getting-started) · [ESLint · Configuration Files (flat config)](https://eslint.org/docs/latest/use/configure/configuration-files) · [ESLint · Rules Reference](https://eslint.org/docs/latest/rules/) · [ESLint · CLI (--fix)](https://eslint.org/docs/latest/use/command-line-interface) · [Prettier · Install](https://prettier.io/docs/install) · [Prettier · Options](https://prettier.io/docs/options) · [Prettier · Integrating with Linters](https://prettier.io/docs/integrating-with-linters) · [GitHub · eslint-config-prettier](https://github.com/prettier/eslint-config-prettier) · [Oxc · Oxlint](https://oxc.rs/docs/guide/usage/linter)

:::tip[ملخص الفصل]
- ESLint بيدوّر على الأخطاء، و Prettier بيوحّد الشكل.
- Flat config في `eslint.config.js`: `recommended` + `globals` + `prettier` في الآخر.
- Output = سطر:عمود + الخطورة + الرسالة + اسم الـ Rule. و`--fix` بيصلّح المضمون بس.
- Prettier بـ `--save-exact`، و`--write` للتنسيق و`--check` للـ CI.
- Format on save في VS Code، و lint في الـ CI.
:::

### صح ولا غلط؟

1. Prettier هيقولك إن `consol` مش معرّف.
2. `eslint --fix` بيصلّح كل المشاكل.
3. `eslint-config-prettier` لازم يبقى آخر حاجة في `extends`.

### أسئلة مراجعة

1. إيه الفرق بين `warn` و`error` عملياً في الـ CI؟
2. ليه ESLint محتاج Package اسمه `globals`؟
3. ليه Prettier يتسطب بنسخة بالظبط؟
