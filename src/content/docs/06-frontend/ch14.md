<small>المرحلة 5 · npm بالتفصيل</small>

package.json هو «بطاقة الهوية» بتاعة أي مشروع JavaScript: اسمه، ونوعه، وأوامره، والحاجات اللي محتاجها. أول ملف تفتحه في أي مشروع جديد، ومنه تعرف المشروع بيتشغّل إزاي. الفصل ده بيشرحه مفتاح مفتاح، ويركّز على scripts (pre و post وتمرير الـ Arguments) و type (ليه import بيضرب Error) والأنواع الأربعة للـ dependencies و overrides.

:::note[بعد الفصل ده هتكون عارف]
- تقرا package.json أي مشروع وتعرف هو إيه وبيشتغل إزاي
- name و version و private و description
- type: module ولا commonjs، والـ Error اللي بيطلع لو غلط
- scripts: npm run و start و test و pre/post و --
- dependencies و devDependencies و peerDependencies و optionalDependencies
- engines و bin و exports (لما تبص على package.json بتاع مكتبة)
- overrides: تجبر نسخة جوه الشجرة
- npm pkg get/set: تعدّل من الـ Terminal
:::

## 14.1 نوعين package.json

هتقابل package.json بشكلين: بتاع **تطبيق** (مشروعك، مش هيتنشر على npm) وبتاع **مكتبة** (Package متنشر، زي vite). الأول بسيط. ده اللي عمله `create-vite` للقالب الـ Vanilla:

```dockerfile
{
  "name": "vanilla-app",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "devDependencies": {
    "vite": "^8.3.4"
  }
}
```

1. `{`: اسم المشروع. حروف صغيرة ومن غير مسافات. في التطبيق مش مهم أوي، في المكتبة هو اللي الناس بتكتبه في `npm i`.
2. `"version": "0.0.0",`: رقم النسخة بنظام SemVer (الفصل الجاي). 0.0.0 لأنه لسه بادئ.
3. `"private": true,`: "ممنوع يتنشر". لو كتبت `npm publish` بالغلط، npm هيرفض. أي تطبيق لازم يبقى فيه ده.
4. `"type": "module",`: ملفات `.js` هنا ES Modules (`import`/`export`). تحت بالتفصيل.
5. `"scripts": {`: الأوامر بتاعة المشروع: `npm run dev` و`npm run build` و`npm run preview`. فصل 18 بيشرح كل واحد بيعمل إيه.
6. `"devDependencies": {`: الأدوات. لاحظ إن القالب كاتب `^8.3.4`، والمتسطب فعلاً طلع 8.3.5 (الـ `^` سمحت بكده، فصل 15).

ومشروع React فيه نفس الشكل، بس فيه `dependencies` (react و react-dom) و`devDependencies` أكتر (فصل 2). ولو شفت أي مشروع على GitHub، أول حاجة تعملها: افتح package.json واقرا الـ scripts، تعرف بيشتغل إزاي.

## 14.2 type: ليه import بيضرب Error؟

JavaScript فيها نظامين Modules (فصل 17 بالتفصيل): القديم بتاع Node (**CommonJS**: `require` و`module.exports`) والرسمي (**ES Modules**: `import` و`export`). و Node بيعرف الملف من أنهي نوع من `type`. جرّبنا نفس الملف بتلات قيم:

```js title="a.js"
import { sep } from "node:path"; console.log("sep is", sep)
```

```sh title=""type": "commonjs""
! Warning: Failed to load the ES module: /tmp/ty/a.js. Make sure to set "type": "module" in the nearest package.json file or use the .mjs extension.
x SyntaxError: Cannot use import statement outside a module
```

```sh title="Terminal"
#  "type": "module"
$ node a.js
sep is /
```

```sh title="من غير type خالص"
! [MODULE_TYPELESS_PACKAGE_JSON] Warning: Module type of file:///tmp/ty/a.js is not specified and it doesn't parse as CommonJS.
! Reparsing as ES module because module syntax was detected. This incurs a performance overhead.
! To eliminate this warning, add "type": "module" to /tmp/ty/package.json.
> sep is /
```

:::caution[الفخ ده هيقابلك في كورس Node]
`npm init -y` في npm 11 بيكتب `"type": "commonjs"`. فلو عملت مشروع Node جديد وكتبت `import express from "express"`، هيضرب `Cannot use import statement outside a module`. الحل: غيّر لـ `"module"` (أو استخدم `require` زي ما الكورس بيعمل). وكل قوالب Vite بتكتب `"module"`. ونفس القاعدة بالامتداد: `.mjs` دايماً ES Module، و`.cjs` دايماً CommonJS، مهما كان الـ type.
:::

## 14.3 scripts بالتفصيل

في مشروع التجارب زوّدنا شوية scripts:

```json title="package.json (npm-play)"
"scripts": {
  "test": "echo \"Error: no test specified\" && exit 1",
  "hello": "echo Hello",
  "prehello": "echo before",
  "posthello": "echo after",
  "greet": "node args.js",
  "v": "vite --version"
}
```

`npm run` من غير اسم بيعرض الكل:

```sh title="Terminal"
$ npm run
Lifecycle scripts included in npm-play@1.0.0:
  test
    echo "Error: no test specified" && exit 1
available via `npm run`:
  hello
    echo Hello
  prehello
    echo before
…
```

### pre و post

```sh title="Terminal"
$ npm run hello

> npm-play@1.0.0 prehello
> echo before

before

> npm-play@1.0.0 hello
> echo Hello

Hello

> npm-play@1.0.0 posthello
> echo after

after
```

أي script اسمه `preX` بيشتغل تلقائياً قبل `X`، و`postX` بعده. وكل script بيطبع سطرين `>`: اسم المشروع@النسخة واسم الـ script، والأمر الحقيقي اللي بيتنفّذ. ولو أي خطوة فشلت (Exit code مش صفر، كتاب الـ Terminal)، الباقي بيقف.

### تمرير Arguments: الـ -- تاني

```js title="args.js"
console.log(process.argv.slice(2))
```

```sh title="Terminal"
$ npm run greet -- --name=Sara x

> npm-play@1.0.0 greet
> node args.js --name=Sara x

[ '--name=Sara', 'x' ]
$ npm run greet --name=Sara x

> npm-play@1.0.0 greet
> node args.js x

[ 'x' ]
```

من غير `--`، npm افتكر `--name=Sara` إعداد ليه هو وأكله، ووصل `x` بس. ودي فايدتها العملية: `npm run dev -- --host` علشان تفتح Vite من موبايلك على نفس الـ Wi-Fi (فصل 18)، و`npm run lint -- --fix`.

### أسماء ليها اختصار

| الأمر | بيعمل إيه |
|---|---|
| `npm test / npm t` | = `npm run test`. والقالب الافتراضي `exit 1` عن قصد: "لسه مفيش Tests". جرّبناه: طبع `Error: no test specified` ورجع exit 1. |
| `npm start` | = `npm run start`. ولو مفيش script اسمه start، npm بيشغّل `node server.js` لوحده لو الملف موجود (جرّبناه وطبع `> node server.js`). هتشوف `start` كتير في كورس Node. |
| `npm run dev / build` | مالهمش اختصار، لازم `run`. |

:::note[الـ script عارف هو مين]
npm بيحط متغيرات بيئة لأي script: جرّبنا `console.log(process.env.npm_package_name, process.env.npm_lifecycle_event)` في script اسمه `who`، وطبع `ty who`. مفيدة لو script واحد عايز يتصرف حسب اسمه.
:::

## 14.4 أربع أنواع dependencies

**مين بيروح فين**

| المفتاح | إمتى | مثال حقيقي |
|---|---|---|
| `dependencies` | كود هيشتغل مع التطبيق (يدخل الـ Bundle أو يشتغل على السيرفر) | `react` و`react-dom`، و`express` في كورس Node |
| `devDependencies` | أدوات وقت التطوير والبناء بس | `vite` و`eslint` و`prettier` و`typescript` |
| `peerDependencies` | (في المكتبات) "أنا محتاج X، بس **انت** اللي تسطّبه" | `@tailwindcss/vite` بيقول `vite: '^5.2.0 \|\| ^6 \|\| ^7 \|\| ^8'`، و`react-dom` بيقول `react: '^19.3.1'` |
| `optionalDependencies` | (في المكتبات) "لو فشل تسطيبه، كمّل عادي" | `lightningcss` فيه 11 نسخة لأنظمة مختلفة، واحدة بس اللي بتتسطب |

الـ **peer** مهم تفهمه: `react-dom` لازم يشتغل مع **نفس** نسخة `react` اللي في مشروعك، مش نسخة خاصة بيه. فبدل ما يسطّب واحدة لنفسه، بيعلن "أنا محتاج react 19.3.1 أو أحدث في 19". ولو مشروعك فيه React 18، npm هيضرب Error اسمه `ERESOLVE`.

:::danger[مشكلة: npm error ERESOLVE unable to resolve dependency tree]
**العَرَض**: `npm install` بيفشل، وفي الرسالة `peer` و`Could not resolve dependency`.

**السبب**: Package عايز peer بنسخة غير اللي عندك (مثلاً مكتبة قديمة عايزة React 18 ومشروعك React 19).

**الحل**: الأول دوّر على نسخة أحدث من المكتبة تدعم نسختك. والـ `--legacy-peer-deps` اللي هتلاقيه في Stack Overflow بيقول لـ npm "تجاهل الـ peers"، وده ممكن يشتغل بس ممكن كمان يطلع Bugs غريبة وقت التشغيل. استخدمه وانت فاهم.
:::

:::tip[ومتقلقش أوي من dev ولا لا]
في تطبيق Vite، الـ Bundler بياخد اللي انت عملتله `import` بس، بغض النظر هو في أنهي قسم. فلو حطيت `react` في devDependencies بالغلط، الموقع هيشتغل برضه. الفرق بيبان في سيرفرات Node (اللي ممكن تسطّب بـ `--omit=dev`) وفي المكتبات المنشورة. فخليك منظم: اللي بيشتغل مع التطبيق في dependencies، والأدوات في devDependencies.
:::

## 14.5 package.json بتاع مكتبة

افتح `node_modules/vite/package.json`، أو اسأل الـ Registry:

```sh title="Terminal"
$ npm view vite engines type
engines = { node: '^20.19.0 || >=22.12.0' }
type = 'module'
$ npm view vite bin license
bin = { vite: 'bin/vite.js' }
license = 'MIT'
```

| الأمر | بيعمل إيه |
|---|---|
| `engines` | نسخ Node اللي المكتبة بتشتغل عليها. لو نسختك أقدم، npm بيطلع تحذير `EBADENGINE`. لو شفته، حدّث Node. |
| `bin` | "لما حد يسطبني، اعمل أمر اسمه `vite` يشغّل `bin/vite.js`". ده اللي بيتحط في `node_modules/.bin` (الفصل اللي فات). |
| `exports / main` | لما تكتب `import x from "vite"`، الملف اللي بيتفتح. `main` القديم ملف واحد، و`exports` الأحدث بيحدد كل مسار مسموح (Vite عنده `"."` و`"./client"` و…) ويمنع الباقي. |
| `files / repository / license` | إيه اللي يتنشر، ورابط الكود على GitHub، والـ License (MIT في vite). شوف الـ License قبل ما تستخدم أي مكتبة في شغل. |

## 14.6 مفاتيح تانية هتقابلها

| الأمر | بيعمل إيه |
|---|---|
| `packageManager` | زي `"pnpm@10.30.3"`: "المشروع ده بيتسطب بـ pnpm النسخة دي". لقيناه جوه Packages في `node_modules` نفسها. (فصل 16) |
| `browserslist` | المتصفحات اللي عايز تدعمها (أدوات زي Autoprefixer بتقراها). |
| `overrides` | تجبر نسخة معينة لـ Package جوه الشجرة حتى لو مش انت اللي طالبه. تحت. |
| `allowScripts` | جديد في npm 12: مين مسموحله يشغّل Scripts وقت التسطيب (فصل 16). |

### overrides: لما الثغرة في Package انت ماطلبتوش

`debug@2.6.9` بيطلب `ms` بالظبط `2.0.0`. نفترض إن 2.0.0 فيها مشكلة وصاحب debug مش هيحدّث. تقدر تجبرها:

```sh title="Terminal"
$ npm ls --all
ov@1.0.0 /tmp/ov
└─┬ debug@2.6.9
  └── ms@2.0.0
$ npm pkg set overrides.ms=2.1.3
$ npm install
$ npm ls --all
ov@1.0.0 /tmp/ov
└─┬ debug@2.6.9
  └── ms@2.1.3 overridden
```

كلمة `overridden` بتفكّرك إنك انت اللي غيرت. واعرف إنك بكده بتشغّل debug على نسخة صاحبه ماجرّبهاش، فاختبر كويس.

## 14.7 npm pkg: عدّل من غير ما تفتح الملف

```sh title="Terminal"
$ npm pkg get name version type
{
  "name": "npm-play",
  "version": "1.0.0",
  "type": "commonjs"
}
$ npm pkg set type=module
$ npm pkg set scripts.lint="eslint ."
```

مفيد في الشرح والـ Scripts، ومفيش خوف من فاصلة ناقصة تبوّظ الـ JSON. وده حصل كتير: `package.json` JSON صارم، فممنوع Comments وممنوع فاصلة بعد آخر عنصر (كتاب الـ APIs فصل 3).

**المصادر الرسمية:** [npm Docs · package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json) · [npm Docs · scripts](https://docs.npmjs.com/cli/v11/using-npm/scripts) · [npm Docs · npm run](https://docs.npmjs.com/cli/v11/commands/npm-run) · [npm Docs · npm pkg](https://docs.npmjs.com/cli/v11/commands/npm-pkg) · [Node.js Docs · Modules: Packages (type, exports)](https://nodejs.org/api/packages.html)

:::tip[ملخص الفصل]
- package.json = بطاقة هوية المشروع. اقرا الـ scripts الأول.
- `private: true` لأي تطبيق، و`type: "module"` علشان `import` يشتغل في Node.
- `preX`/`postX` تلقائي، و`--` علشان تعدّي Flags للأمر، و`npm start`/`npm test` من غير run.
- dependencies للتطبيق، و devDependencies للأدوات، و peer = "سطّبه انت"، و optional = "لو فشل كمّل".
- `engines` و`bin` و`exports` في المكتبات، و`overrides` تجبر نسخة في الشجرة.
:::

### صح ولا غلط؟

1. لو مشروعك فيه `"type": "commonjs"`، `import` في ملف `.js` هيشتغل عادي.
2. `npm run build --minify` بيبعت `--minify` للأمر.
3. `react-dom` بيعلن `react` كـ peerDependency.

### أسئلة مراجعة

1. ليه أي تطبيق لازم يبقى فيه `"private": true`؟
2. عندك scripts فيها `prebuild` و`build`. إيه اللي هيحصل لما تكتب `npm run build`؟ ولو `prebuild` فشل؟
3. إيه الفرق بين dependency و peerDependency؟
4. إمتى تستخدم `overrides`؟ وإيه خطورتها؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** افتح package.json بتاع أي مشروع من كورس Jonas، وصنّف كل Package: تطبيق ولا أداة؟
2. **[متوسط]** اعمل script اسمه `clean` بيمسح `dist` (`rm -rf dist`)، وخليه يشتغل تلقائياً قبل `build` من غير ما تكتبه.
3. **[صعب]** اكتب ملف بـ `import` في مشروع عملته بـ `npm init -y`، وشوف الـ Error بعينك. حلّه بطريقتين مختلفتين (من غير ما تغيّر الكود).
