قبل ما نبني Images بتاعتنا، لازم نعرف نتعامل مع الـ Images الجاهزة: نجيبها منين، نعرف اللي عندنا، ونمسح اللي مش محتاجينه.

<a id="s3-1"></a>

## 3.1 يعني إيه Image؟

- زي ما فهمنا قبل كده، الـ Container زي VM شغال على الجهاز أو السيرفر، الفرق إنه شغال في هيئة process عادية. بس بتقدر تدخل عليه وهو شغال، تفتح shell وتكتب أوامر، وجواه ملفات تقدر تشوفها وتتعامل معاها، وتعمل run لـ app وهكذا.
- فبالتالي انت محتاج مواصفات وحاجات محددة خاصة بالـ environment دي، والـ **Image** هي اللي بيكون فيها الكلام ده، بس بتكون زي **template** مبني مسبقاً، بتعمله run يقوّملك container على طول.
- ممكن تتخيلها زي **قالب** لمجسّم، بتصب فيه مادة تتحول للمجسّم ده. تاخده تستخدمه وتنقله وتشاركه وتشغّله عند أي حد، وهيشتغل على طول ومش هيحصل مشاكل اختلاف الـ versions وغيرها.

:::caution[على الماك: Docker شغال جوه Linux صغير]
قلنا إن الـ Containers بتشارك الـ **Kernel** (قلب نظام التشغيل) بتاع Linux. طب الماك مش Linux! فـ **Docker Desktop** (أو OrbStack أو Colima) بيعمل VM صغيرة جداً فيها Linux من غير ما تحس، والـ Containers بتشتغل جواها. وده معناه كام حاجة:

- سطّبه بـ `brew install --cask docker` وافتح Docker Desktop مرة، أو حمّله من الرابط تحت. لازم يكون شغال (الحوت فوق في الشريط) قبل أي أمر `docker`.
- كل أوامر الكتاب زي ما هي بالظبط، و `-p 8080:80` و `localhost:8080` شغالين عادي.
- المسار `/var/lib/docker/...` اللي هتشوفه في فصل الـ Volumes موجود جوه الـ VM مش على الماك، فمش هتلاقيه في الـ Finder.
- اختار Images بتشتغل على معالجات Apple (`arm64`). الرسمية كلها بتدعمها.
:::

:::note[قبل أي حاجة: سطّب Docker]
لازم نسطّب Docker على الجهاز من الرابط ده: [docs.docker.com/get-started/get-docker](https://docs.docker.com/get-started/get-docker/)

وبعد التسطيب اتأكد إنه شغال بالأمرين دول: `docker --version` و `docker run hello-world`.
:::

<a id="s3-2"></a>

## 3.2 بنجيب الـ Image منين؟ (docker pull)

بنسحب الـ image من أي **Docker Registry** عليه images، زي **Docker Hub** (وفيه غيره عادي).

```sh title="Terminal"
docker pull [REGISTRY/REPOSITORY/]image_name[:TAG]
```

<strong>معناها:</strong> هات Image اسمها `image_name` بالـ version بتاعها `TAG`، من الـ Docker Registry اللي اسمها `REGISTRY`، الموجودة في Repository اسمها `REPOSITORY`، ونزّلها على جهازي.

![تشريح الاسم الكامل لأي Image.](./assets/ch03-fig1.png)

*تشريح الاسم الكامل لأي Image.*

```sh title="Terminal"
docker pull busybox
```

يعني: روح هات الـ Image اللي اسمها `busybox`، أحدث version منها، من Docker Hub. هيشوف لو موجودة عندي ممكن ميعملش حاجة، ولو مش موجودة يبدأ يسحبها.

#### القيم الافتراضية

- لو مكتبتش `:TAG` ← هياخد `latest` (أحدث version).
- لو مكتبتش `REGISTRY/REPOSITORY/` ← هيروح على Docker Hub: `docker.io/library/`

:::caution[خلي بالك]
لو هتسحب من موقع تاني، أو من Docker Hub برضه بس من **REPOSITORY خاصة**، فالموضوع بيكون مختلف، وهتحتاج تزوّد كام خطوة قبلها (زي `docker login`)، وهنشرحهم في فصل رفع الـ Images على Docker Hub.
:::

<a id="s3-3"></a>

## 3.3 أعرف إيه الـ Images اللي نازلة عندي؟

```sh title="Terminal"
docker images
```

هيوريك بيانات عن كل Image عندك: **REPOSITORY** (اسم الـ Image)، و **TAG**، و **IMAGE ID**، و **SIZE**. مثلاً:

```sh title="Terminal"
$ docker images
REPOSITORY   TAG       IMAGE ID       CREATED       SIZE
nginx        latest    a72860cb95fd   2 weeks ago   188MB
busybox      latest    6fd955f66c23   1 month ago   4.26MB
```

<a id="s3-4"></a>

## 3.4 حذف Image

| الأمر | بيعمل إيه |
|---|---|
| `docker rmi image-name` | بيحذف الـ Image.مش هتتحذف لو فيه Container بيستخدمها. |
| `docker rmi -f image-name` | بيحذفها بالإجبار.لكن ده خطر لو حد شغال عليها. |

:::tip[Best Practice]
قبل ما تمسح Image، اعرف مين بيستخدمها بـ `docker ps -a`، وامسح الـ Containers القديمة الأول بدل ما تستخدم `-f`.
:::

:::tip[ملخص الفصل]
- الـ Image قالب جاهز (template) بيتعمله run فيطلع Container.
- `docker pull` بيسحب Image من Registry، والافتراضي `docker.io/library` و `latest`.
- `docker images` بيعرض الـ Images اللي عندك.
- `docker rmi` بيمسح Image، و `-f` بالإجبار (بحذر).
:::

### أسئلة مراجعة

1. اكتب الاسم الكامل اللي Docker بيفهمه لما تكتب `docker pull nginx`.
2. إيه اللي هيحصل لو عملت pull لـ Image موجودة عندك فعلاً؟
3. ليه `docker rmi` ممكن يرفض يمسح Image؟
