لما بتكتب COPY . . انت بتنسخ كل حاجة في الفولدر، بما فيها node\_modules و .git وملفات الـ .env اللي فيها أسرار. ملف صغير اسمه .dockerignore بيحل المشكلة دي.

<a id="s11-1"></a>

## 11.1 المشكلة: الـ Build Context بيتبعت كله

فاكر النقطة اللي في آخر `docker build -t app .`؟ دي معناها إن الفولدر الحالي كله هو الـ **Build Context**، و Docker بيبعته للـ builder قبل ما يبدأ. ولما تكتب `COPY . .` في الـ Dockerfile، كل اللي في الفولدر بيتنسخ جوه الـ Image، ومن ضمنه حاجات انت مش عايزها خالص:

#### حاجات بتكبّر الحجم وتبطّأ الـ build

- `node_modules` (والـ Image هتعمل install لوحدها أصلاً)
- فولدر `.git` بكل تاريخ المشروع
- ملفات الـ logs والـ build القديمة

#### حاجات خطر تتسرّب

- ملفات `.env` فيها Passwords و API Keys
- مفاتيح SSH أو شهادات
- ملفات إعدادات الجهاز الشخصية

<a id="s11-2"></a>

## 11.2 الحل: ملف .dockerignore

ملف نصّي اسمه بالظبط `.dockerignore` (بالنقطة في الأول)، بتحطه في **جذر الـ Build Context** (جنب الـ Dockerfile غالباً)، وبتكتب فيه الملفات والفولدرات اللي Docker يتجاهلها. فكرته نفس فكرة `.gitignore` بالظبط.

```gitignore title=".dockerignore"
# dependencies (هتتسطّب جوه الـ Image)
node_modules
npm-debug.log

# git و إعدادات المحرر
.git
.gitignore
.vscode

# أسرار
.env
*.pem

# ناتج build قديم و logs
build
dist
*.log

# متتجاهلش الملف ده
!.env.example
```

<a id="s11-3"></a>

## 11.3 قواعد الكتابة

**الـ Patterns في ملف .dockerignore**

| الصيغة | معناها | مثال |
|---|---|---|
| `name` | تجاهل الملف أو الفولدر ده | `node_modules` |
| `*` | أي مجموعة حروف في نفس المستوى | `*.log` |
| `**` | أي عدد من الفولدرات | `**/*.tmp` |
| `!` | استثناء: متتجاهلش ده | `!.env.example` |
| `#` | تعليق | `# secrets` |

<a id="s11-4"></a>

## 11.4 المكاسب

- <strong>Build أسرع:</strong> الـ Context بيبقى صغير، فبيتبعت أسرع.
- <strong>Image أصغر:</strong> مفيش ملفات ملهاش لازمة جوه الـ Image.
- <strong>كاش أحسن:</strong> أي تعديل في `.git` أو ملف log مش هيبوّظ الكاش بتاع `COPY . .`.
- <strong>أمان:</strong> ملفات الأسرار متدخلش الـ Image أصلاً، فمتتسرّبش لما ترفعها على Docker Hub.

:::caution[خلي بالك]
الـ `.dockerignore` بيتقري من جذر الـ Build Context بس. لو حطيته في فولدر فرعي أو سمّيته غلط (زي `dockerignore` من غير نقطة) مش هيشتغل، ومش هيطلعلك أي Error.
:::

:::tip[Best Practice]
اعمل `.dockerignore` مع أول Dockerfile في أي مشروع، خصوصاً لو بتستخدم `COPY . .` زي مثال الـ React في الفصل اللي فات.
:::

:::tip[ملخص الفصل]
- الـ Build Context هو الفولدر اللي في آخر أمر `docker build`، وبيتبعت كله.
- `.dockerignore` بيستبعد ملفات من الـ Context، وصيغته شبه `.gitignore`.
- أهم حاجات تتجاهلها: `node_modules` و `.git` و `.env` وناتج الـ build القديم.
:::

### أسئلة مراجعة

1. ليه نتجاهل `node_modules` وإحنا محتاجين المكتبات؟
2. اكتب سطر يتجاهل كل ملفات `.md` ما عدا `README.md`.
3. إزاي ملف `.dockerignore` بيحسّن استخدام الكاش؟
