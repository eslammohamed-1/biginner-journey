<small>المرحلة 6 · DevTools والـ Debugging</small>

القايمة بتقولك فيه مشكلة. التفاصيل بتقولك المشكلة إيه. لما تدوس على أي طلب، بيفتح جنبه لوح فيه كل حاجة: الـ Headers اللي رايحة وجاية، والـ Body اللي اتبعت، والرد خام ومنسق، ومين طلبه، والكوكيز. وبعدين هنشوف الأدوات اللي بتخليك تتحكم: تنسخ الطلب لـ curl أو fetch، وتعدله وتبعته تاني، وتمنع طلبات، وتغير الرد نفسه من غير ما تلمس السيرفر، وتصدّر كل حاجة في ملف HAR.

:::note[بعد الفصل ده هتكون عارف]
- تابة Headers: General و Response و Request و Raw و Provisional headers
- تابة Payload: Query string و Form data و JSON
- Preview و Response: منسق مقابل خام
- Initiator: مين طلب الطلب ده، وسلسلته
- تابة Cookies: اللي اتبعت، واللي اتحط، واللي اتمنع وليه
- Copy as cURL و Copy as fetch، والتعديل وإعادة الإرسال
- Request conditions: تمنع طلب أو Domain
- Overrides: تغيّر الرد أو الـ Headers من جهازك
- HAR: تصدّر وتستورد، و sanitized مقابل sensitive
:::

<a id="s19-1"></a>

## 19.1 تابة Headers: الحوار كله

دوس على اسم أي طلب. هيفتح لوح فيه تابات، وأولهم **Headers**، ومقسوم 3 أجزاء:

```http title="Headers · users (طلب الـ 404 من رسمة الفصل 18)"
▼ General
Request URL:     https://api.shop.dev/users
Request Method:  GET
Status Code:     ● 404 Not Found
Remote Address:  104.21.48.3:443
Referrer Policy: strict-origin-when-cross-origin
▼ Response Headers
content-type: application/json; charset=utf-8
cache-control: no-store
access-control-allow-origin: http://localhost:5173
▼ Request Headers
:authority: api.shop.dev
:method: GET
:path: /users
accept: */*
authorization: Bearer eyJhbGciOi...
origin: http://localhost:5173
```

1. `▼ General`: **General**: الملخص. الـ URL الكامل (اتأكد إنه اللي انت فاكره، خصوصاً الـ Query)، والـ Method، والـ Status بلون، والـ IP اللي اتكلمنا معاه، وسياسة الـ Referer (الفصل 9).
2. `▼ Response Headers`: **Response Headers**: اللي السيرفر رد بيه. هنا تدور على `content-type` و`set-cookie` و`cache-control` و`access-control-*`.
3. `▼ Request Headers`: **Request Headers**: اللي المتصفح بعته فعلاً. اتأكد هنا إن الـ `authorization` اتبعت، وإن الـ `content-type` صح. ولاحظ الـ Pseudo-headers بتوع HTTP/2 (الفصل 9).

وجنب عنوان كل جزء فيه مفتاح **Raw**: يوريك الـ Headers بالشكل الخام زي ما هي في الـ HTTP (أو أقرب حاجة ليها في HTTP/2)، بترتيبها الحقيقي. مفيد لما تحب تنسخ أو تقارن مع curl.

:::caution[Provisional headers are shown]
ساعات هتلاقي تحذير أصفر فوق Request Headers بالجملة دي. معناها: "اللي قدامك مش الـ Headers الحقيقية اللي اتبعتت، دي اللي المتصفح كان ناوي يبعتها". بيحصل لما الطلب جه من الكاش (فمفيش طلب حقيقي اتبعت)، أو اتمنع (CORS أو Extension)، أو لسه مكملش. يعني لو شايف التحذير ده، اسأل نفسك الأول: الطلب ده وصل للسيرفر أصلاً؟
:::

<a id="s19-2"></a>

## 19.2 تابة Payload: اللي انت بعته

بتظهر بس لو الطلب فيه Query string أو Body. وفيها اللي كودك بعته بالظبط، وده أهم مكان تتأكد فيه إن البيانات وصلت بالشكل اللي السيرفر مستنيه:

| الأمر | بيعمل إيه |
|---|---|
| `Query String Parameters` | الـ `?key=value` متقسمة. وفيه زرار **view URL-encoded** يوريك الشكل المتشفّر (الفصل 6)، و**view decoded** العادي. |
| `Form Data` | فورم عادي (`urlencoded` أو `multipart`). كل حقل لوحده. |
| `Request Payload` | Body بـ JSON أو نص. بيتعرض كشجرة تقدر تفتحها، و**view source** يوريك النص زي ما اتبعت حرف حرف. |

:::danger[مشكلة: السيرفر بيقول 400: missing field 'email'، وأنا باعته!]
الـ Console مفيهاش حاجة، والكود شكله سليم: `body: {email, password}`.

افتح Payload و view source: هتلاقي `[object Object]`. نسيت `JSON.stringify`. أو هتلاقي الـ JSON صح، بس في Headers الـ `content-type` هو `text/plain` لأنك نسيت الـ Header، فالسيرفر مش بيقرا الـ Body كـ JSON (الفصل 7). الـ Payload والـ Request Headers مع بعض بيكشفوا المشكلتين في ثانية.
:::

<a id="s19-3"></a>

## 19.3 Preview و Response

#### Preview

الرد **منسق**: JSON كشجرة تفتحها، وصورة كصورة، و HTML معروض. للقراية السريعة.

#### Response

الرد **خام** زي ما جه. لو الـ JSON بايظ (فاصلة زيادة، أو جالك صفحة HTML بدل JSON)، Preview مش هيعرضه، و Response هيوريك الحقيقة.

:::note[مثال عملي: Unexpected token '<']
الكود عمل `await res.json()` وطلعلك في الـ Console: `SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON`. افتح الطلب ← Response: هتلاقي صفحة HTML. يعني الـ URL غلط والسيرفر رجّعلك صفحة 404 بتاعة الموقع، أو الـ Dev server رجّعلك `index.html`. الحرف `<` هو أول حرف في `<!DOCTYPE`. وده من أشهر الأخطاء في كورسات JS كلها.
:::

<a id="s19-4"></a>

## 19.4 تابة Initiator: مين طلب ده؟

لقيت طلب غريب ومش عارف جاي منين؟ تابة Initiator فيها جزئين:

- **Request call stack**: لو الطلب جه من JS، هتلاقي سلسلة الدوال اللي وصلت لحد الـ `fetch`، كل واحدة بملفها ورقم سطرها، ودوس عليها توديك للسطر. يعني "`loadUsers` في `app.js:12`، اتنادت من `init` في `app.js:50`".
- **Initiator chain**: السلسلة على مستوى الطلبات: الصفحة طلبت `app.js`، و`app.js` طلب `users`.

ونفس المعلومة بسرعة في القايمة: دوس <kbd>⇧</kbd> وحط الماوس على أي طلب، اللي طلبوه يتلونوا **أخضر**، واللي هو طلبهم **أحمر**.

<a id="s19-5"></a>

## 19.5 تابة Cookies: اتبعتت ولا اتمنعت؟

بتظهر لو الطلب فيه كوكيز رايحة أو جاية. فيها جدولين: **Request Cookies** (اللي المتصفح بعتها مع الطلب ده) و**Response Cookies** (اللي السيرفر حطها بـ `Set-Cookie`). وأهم حاجة فيها: لو كوكي **اتمنعت**، هتلاقيها مظللة بلون أصفر وجنبها علامة، وحط الماوس عليها يقولك السبب بالظبط. أمثلة على الأسباب:

| الأمر | بيعمل إيه |
|---|---|
| `This Set-Cookie didn't specify a "SameSite" attribute…` | اتعاملت `Lax`، فمش هتتبعت مع طلب Cross-site (الفصل 13). |
| `…had the "SameSite=None" attribute but did not have the "Secure" attribute` | `None` لازم معاها `Secure`. فالمتصفح رفض يحفظها خالص. |
| `…the "Secure" attribute but was not received over a secure connection` | سيرفر HTTP عادي بيحاول يحط كوكي `Secure`. |
| `…Domain attribute was invalid with regards to the current host url` | `api.shop.dev` بيحاول يحط كوكي لـ `other.com`. ممنوع. |

وفيه Checkbox اسمه **show filtered out request cookies**: يوريك الكوكيز اللي **كانت** موجودة بس المتصفح قرر ميبعتهاش مع الطلب ده وليه. ده بالظبط اللي محتاجه لما تقول "أنا عامل Login، ليه السيرفر بيقولي 401؟".

## 19.6 انسخ الطلب: cURL و fetch

ودي من أقوى الحاجات في DevTools كله. Right-click على أي طلب ← **Copy**، وهتلاقي:

| الأمر | بيعمل إيه |
|---|---|
| `Copy URL` | الـ URL بس. |
| `Copy as cURL` | أمر curl فيه نفس الـ Method والـ Headers والكوكيز والـ Body بالظبط. على الـ Mac بيتنسخ بصيغة bash/zsh. وعلى Windows فيه `Copy as cURL (cmd)` و`(bash)`. |
| `Copy as fetch` | كود `fetch(...)` جاهز تلزقه في الـ Console أو في كودك. |
| `Copy as fetch (Node.js)` | نفس اللي فوق، بس بيشيل حاجات خاصة بالمتصفح، ومعاه الكوكيز كـ Header. |
| `Copy as PowerShell` | لزمايلك على Windows. |
| `Copy response` | الـ Body بتاع الرد. |
| `Copy all as cURL / Copy all as HAR (sanitized)` | كل الطلبات اللي في القايمة (بعد الفلتر) مرة واحدة. |

وده شكل الناتج، ولاحظ إنك تعرف تقرا كل سطر فيه دلوقتي:

**تشريح الأمر**

```sh
curl 'https://api.shop.dev/orders' -H 'accept: application/json' -H 'authorization: Bearer eyJhbGc...' -H 'content-type: application/json' -H 'origin: http://localhost:5173' -b 'theme=dark' --data-raw '{"item":12,"qty":2}'
```

1. `curl 'https://api.shop.dev/orders'`: الـ URL بين Single quotes عشان zsh.
2. `-H 'accept: ...'`: كل Request header ليه `-H` لوحده، زي ما في تابة Headers بالظبط.
3. `-H 'authorization: Bearer ...'`: الـ Token اتنسخ **كمان**. خلي بالك وانت بتبعت الأمر ده لحد.
4. `-H 'origin: ...'`: curl مش هيطبّق CORS، بس السيرفر هيشوف نفس الـ Origin.
5. `-b 'theme=dark'`: الكوكيز (لو فيه).
6. `--data-raw '...'`: الـ Body. `--data-raw` زي `-d` بس مبيعاملش `@` في الأول كاسم ملف. ووجود Body بيخلي curl يعمل POST لوحده، فمش محتاج `-X POST`.

واستخدامه الأشهر هو الخطوة الأهم في أي Debugging: <strong>"هل المشكلة في المتصفح ولا في السيرفر؟"</strong>. انسخ الطلب اللي فاشل كـ cURL، ولزقه في الـ Terminal، وزوّد `-i`:

- لو فشل بنفس الشكل: المشكلة في **الطلب نفسه أو السيرفر**. عدّل في الأمر (شيل Header، غيّر الـ Body) لحد ما تلاقي السبب.
- لو نجح في curl بس فاشل في المتصفح: المشكلة في حاجة المتصفح بيضيفها: CORS، أو كوكي اتمنعت، أو كاش، أو Extension.

### عدّل وابعت تاني

عاوز تجرب نفس الطلب بقيمة مختلفة من غير ما تكتب كود؟ أسهل طريقة: **Copy as fetch**، وروح الـ Console، والزقه، وغيّر اللي عاوزه، و<kbd>↩</kbd>. الطلب الجديد هيظهر في Network زي أي طلب. وفي نسخ Chrome الحديثة فيه اختصار لده في نفس القايمة (Edit and resend أو حاجة قريبة)، وكمان **Replay XHR** بيعيد طلبات XHR زي ما هي. وفي Safari فيه Edit and resend من زمان.

:::caution[خلي بالك: الطلب المنسوخ فيه أسرارك]
Copy as cURL و fetch بينسخوا الكوكيز والـ `authorization` زي ما هي. يعني اللي يستلم الأمر ده يقدر يعمل اللي انت بتعمله بحسابك لحد ما الـ Session يخلص. قبل ما تبعته في Slack أو تحطه في Issue على GitHub، امسح الـ Tokens والكوكيز أو بدّلهم بـ `XXX`.
:::

<a id="s19-7"></a>

## 19.7 Request conditions: امنع طلب وشوف إيه اللي هيحصل

سؤال مهم: لو ملف Analytics ده وقع، الصفحة هتبوظ؟ لو الـ API ده مرجعش، الكود بتاعي هيتصرف إزاي؟ Right-click على الطلب ← **Block request URL** أو **Block request domain**. هيفتح في الـ Drawer تابة **Request conditions** وفيها القاعدة، وتقدر تكتب قواعد بنفسك بـ `*`، زي `*.analytics.com/*`. واعمل Reload: الطلبات دي هتظهر في Network بـ Status `(blocked:devtools)`.

وفي Chrome الحديث، نفس التابة دي بتسمحلك كمان تعمل **Throttling لطلبات معينة** بس، مش للصفحة كلها. يعني تخلي الـ API بتاعك بس بطيء وتشوف الـ Loading spinner بتاعك.

<a id="s19-8"></a>

## 19.8 Overrides: غيّر الرد من غير ما تلمس السيرفر

تخيل إن الـ Backend لسه مخلصش الـ API، أو بيرجع داتا غلط، وانت عاوز تشوف الـ Frontend هيعمل إيه لو الرد كان شكل تاني. أو عاوز تجرب تشيل Header معين. **Overrides** بيخلي DevTools يرد على المتصفح بنسخة على جهازك بدل الرد الحقيقي:

1. Right-click على الطلب ← **Override content** (للـ Body) أو **Override headers** (للـ Headers).
2. أول مرة هيطلب منك تختار **فولدر** على الـ Mac يحفظ فيه الملفات، ويطلب إذن. اعمل فولدر مخصوص زي `~/devtools-overrides`، ودوس Allow.
3. هيفتح الرد في Sources، عدّله زي ما تحب (مثلاً غيّر `"role":"user"` لـ `"role":"admin"`)، و<kbd>⌘</kbd><kbd>S</kbd>.
4. اعمل Reload. الطلب هيظهر في Network وعليه **علامة بنفسجي** تقولك إن ده رد معدل، مش الحقيقي.

:::note[ده بيتغير عندك انت بس]
Overrides جوه المتصفح بتاعك بس، وطول ما DevTools مفتوح والخاصية شغالة. السيرفر ماعرفش حاجة، واليوزرز مش شايفين حاجة. يعني مش ثغرة: لو غيّرت `role` لـ `admin` وظهرلك زرار Admin، السيرفر المفروض برضه يرفض أي طلب Admin منك، لأن الحماية الحقيقية لازم تبقى على السيرفر. ولو مرفضش، يبقى لقيت Bug أمني حقيقي في الـ Backend. ومتنساش تقفلها من Sources ← Overrides لما تخلص، عشان متقعدش تتجنن ليه التعديلات بتاعتك مش ظاهرة.
:::

## 19.9 HAR: الجلسة كلها في ملف

زميلك بيقول "الصفحة بايظة عندي" وانت مش عارف تكرر المشكلة. أو فريق الدعم الفني لشركة بتطلب منك تبعتلهم اللي حصل. الحل: **HAR** (HTTP Archive)، ملف JSON فيه كل الطلبات اللي في Network: الـ URLs والـ Headers والـ Bodies والتوقيت.

| الأمر | بيعمل إيه |
|---|---|
| `⤓ ← Export HAR (sanitized)` | الافتراضي: بيصدّر من **غير** `Cookie` و`Set-Cookie` و`Authorization`. ده اللي تبعته لحد. |
| `Export HAR (with sensitive data)` | بالأسرار كلها. مش ظاهر غير لو فعّلت "Allow to generate HAR with sensitive data" من Settings. استخدمه بحذر شديد. |
| `⤒ أو اسحب الملف على Network` | Import: تفتح HAR حد بعتهولك، وتشوف كل الطلبات كأنها حصلت عندك. |

:::caution[خلي بالك: حتى الـ sanitized ممكن يبقى فيه حاجات]
الـ Sanitized بيشيل الـ Headers دي بس. لكن الـ **Bodies** لسه فيها: لو فورم Login فيه الباسورد في الـ Payload، هيبقى في الملف. ولو فيه Token في الـ URL نفسه (`?token=...`)، هيبقى في الملف. افتح الملف في محرر وادوّر قبل ما تبعته.
:::

:::note[لو حابب تتعمق: تتحكم في الـ HAR بـ jq]
ملف HAR ده JSON عادي، فتقدر تحلله بـ `jq` (الفصل 10). مثلاً تطلع كل الطلبات اللي فشلت مع الـ Status بتاعها: `jq -r '.log.entries[] | select(.response.status >= 400) | "\(.response.status) \(.request.url)"' page.har`. الـ `.log.entries[]` = كل الطلبات، و`select` = فلتر زي `filter` في JS، والسطر الأخير بيطبع الرقم والعنوان.
:::

:::tip[ملخص الفصل]
- Headers: General (الملخص)، و Response (رد السيرفر)، و Request (اللي اتبعت فعلاً)، و Raw. و Provisional headers = الطلب غالباً موصلش.
- Payload: اللي كودك بعته. أول مكان تشوف فيه `[object Object]` أو JSON غلط.
- Preview منسق، و Response خام. و `Unexpected token '<'` = جالك HTML بدل JSON.
- Initiator: سلسلة الكود اللي عمل الطلب، و <kbd>⇧</kbd>+Hover في القايمة.
- Cookies: اللي اتبعت واللي اتحط، واللي اتمنع وسببه.
- Copy as cURL يفصل المتصفح عن السيرفر، و Copy as fetch للتعديل وإعادة الإرسال. وفيهم أسرارك.
- Block في Request conditions، و Overrides تغيّر الرد عندك بس، و HAR sanitized عشان تبعت الجلسة.
:::

### صح ولا غلط؟

1. Export HAR (sanitized) بيشيل الباسوردات اللي في الـ Body كمان.
2. Overrides بيغيّر الرد للمستخدمين كلهم.
3. لو الطلب المنسوخ كـ cURL نجح في الـ Terminal وفشل في المتصفح، فالمشكلة غالباً حاجة خاصة بالمتصفح زي CORS.

### أسئلة مراجعة

1. إيه معنى "Provisional headers are shown"؟ واذكر سببين ليها.
2. إزاي تلاقي `[object Object]` في طلب، وإيه سببه؟
3. إيه الفرق بين Preview و Response؟ وإمتى Preview ميكفيش؟
4. إيه اللي هيحصل لو بعت Copy as cURL في جروب عام؟
5. إزاي تتأكد إن الـ Frontend بتاعك بيتعامل صح لو ملف Analytics وقع؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** افتح `https://jsonplaceholder.typicode.com/` واعمل من الـ Console `fetch('/posts', {method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify({title:'hi'})})`. شوف الطلب في Headers و Payload و Preview و Response.
2. **[متوسط]** انسخ نفس الطلب كـ cURL، والزقه في الـ Terminal بـ `-i`، وقارن الرد. وبعدين انسخه كـ fetch وغيّر الـ title وابعته تاني.
3. **[صعب]** افتح `https://jsonplaceholder.typicode.com/posts/1` كصفحة، واعمل Override content للرد بتاعها، وخلي العنوان كلمة من عندك، واعمل Reload وشوف العلامة البنفسجي. وبعدين صدّر HAR sanitized، وافتحه بـ `jq` وطلّع منه كل الـ URLs.
