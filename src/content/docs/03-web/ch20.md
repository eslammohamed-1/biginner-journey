<small>المرحلة 6 · DevTools والـ Debugging</small>

الـ Console ليه وشين. وش بيكلمك: كل خطأ وتحذير ورسالة من كودك أو من المتصفح. ووش انت بتكلمه: تكتب JS يتنفذ على الصفحة نفسها حالاً. هنتعلم نقرا الاتنين: المستويات والفلاتر، وتفصيص الـ Stack trace، وكتالوج بأشهر رسايل الشبكة (CORS و 404 و 401 و 500 و Mixed content و net::ERR\_\*) ومعنى كل واحدة، وإزاي تعمل fetch صح من الـ Console، وأدوات صغيرة هتستخدمها كل يوم.

:::note[بعد الفصل ده هتكون عارف]
- مستويات الرسايل: Verbose و Info و Warnings و Errors، والفلاتر والإعدادات
- أكتر من console.log: table و group و time و count و assert و trace
- تقرا الـ Stack trace وتوصل للسطر
- كتالوج رسايل الشبكة: CORS و 404 و 401/403 و 500 و Mixed content و CSP
- عيلة net::ERR\_\* ومعنى كل واحد
- fetch من الـ Console بـ await، و res.ok و res.status
- أدوات: $0 و $\_ و $$ و copy()
- الـ Issues panel و Understand this error
:::

<a id="s20-1"></a>

## 20.1 وشين في مكان واحد

في كورس Jonas هتكتب `console.log` مئات المرات، وده الاستخدام الأول: كودك بيكلمك. بس الـ Console فيه كمان رسايل **المتصفح نفسه**: كل طلب فشل، وكل CORS، وكل تحذير أمان. ولو حد في فريقك قالك "بص في الـ Console"، غالباً يقصد دي، مش الـ logs بتاعتك. والوش التاني: السطر اللي تحت فيه `>`، تكتب فيه أي JS ويتنفذ **جوه الصفحة اللي انت فيها**، بنفس المتغيرات والـ DOM والكوكيز. يعني مش ملعب منفصل، انت جوه الموقع.

<a id="s20-2"></a>

## 20.2 المستويات والفلاتر

كل رسالة ليها مستوى، وكل مستوى ليه شكل:

```sh title="Terminal"
> console.log('عادي'); console.info('معلومة')
عادي
معلومة
> console.warn('تحذير')
! تحذير
> console.error('خطأ')
x خطأ
> console.debug('تفاصيل')
# مش هيظهر غير لو فعّلت Verbose
```

| الأمر | بيعمل إيه |
|---|---|
| `Default levels ▾` | اختار تشوف إيه: **Verbose** (`console.debug` ورسايل تفصيلية من المتصفح، مقفول افتراضياً)، و**Info**، و**Warnings** (أصفر)، و**Errors** (أحمر). لو مش لاقي رسالة متأكد إنها موجودة، بص هنا الأول. |
| `Filter` | زي Network: كلمة، أو `-كلمة` للعكس، أو `/regex/`، أو `url:app.js` رسايل ملف معين. |
| `☰ Console sidebar` | قايمة على الجنب بتقسم الرسايل: User messages (بتاعتك) و Errors و Warnings، ومين الملف اللي طلّعها. مفيد جداً لما الصفحة مليانة رسايل. |
| `top ▾` | الـ **Context**: الكود بتتنفذ فين. `top` = الصفحة الأساسية. لو الصفحة فيها iframe أو Extension، هتلاقيهم هنا. لو كتبت متغير وقالك مش موجود، اتأكد إنك في الـ Context الصح. |
| `⚙ Console settings` | **Preserve log** (متمسحش مع الـ Reload)، و**Hide network** (اخفي رسايل الشبكة)، و**Log XMLHttpRequests** (اطبع كل XHR/fetch)، و**Show CORS errors in console**، و**Group similar messages**، و**Eager evaluation** (يوريك النتيجة وانت بتكتب). |
| `⌘K` | امسح الـ Console. أو اكتب `clear()`. |

### أكتر من console.log

الـ `console` فيه أدوات كتير بتوفر عليك وقت، وكلها شغالة في كودك وفي الـ Console نفسه:

```js title="جرّبهم في الـ Console"
const users = [{id: 1, name: 'Sara', role: 'admin'}, {id: 2, name: 'Omar', role: 'user'}];

console.table(users);                  // جدول بأعمدة id و name و role
console.log({ users });                // اللوج بالاسم: { users: [...] } بدل [...] وخلاص

console.group('Login flow');           // كل اللي بعده متداخل تحت عنوان
console.log('step 1'); console.log('step 2');
console.groupEnd();

console.time('fetch users');           // ابدأ عداد
await fetch('https://jsonplaceholder.typicode.com/users');
console.timeEnd('fetch users');        // fetch users: 312.4 ms

console.count('render');               // render: 1، وبعدين render: 2 ...
console.assert(users.length > 5, 'users قليلين!');  // يطبع خطأ بس لو الشرط غلط
console.trace('مين نده عليا؟');         // يطبع سلسلة الدوال اللي وصلت هنا
```

:::caution[خلي بالك: الـ Object في اللوج بيتغير]
لو عملت `console.log(user)` وبعدها الكود غيّر `user.name`، وبعدين فتحت السهم جنب الـ Object في الـ Console، ممكن تشوف القيمة **الجديدة** مش اللي كانت وقت اللوج. ليه؟ لأن الـ Console بيحتفظ بـ **Reference** للـ Object، وبيقرا القيم لما تفتحه انت (وفيه أيقونة `i` صغيرة جنبه بتقولك ده). عشان تشوف القيمة في اللحظة دي بالظبط: `console.log(structuredClone(user))` أو `console.log(JSON.stringify(user))`.
:::

## 20.3 تقرا الخطأ والـ Stack trace

الخطأ الأحمر مش مجرد "فيه مشكلة". هو بيقولك **إيه** المشكلة، و**فين** بالظبط، و**إزاي** الكود وصل هناك:

```sh title="Terminal"
x Uncaught TypeError: Cannot read properties of undefined (reading 'name')
    at renderUser (app.js:22:31)
    at app.js:40:3
    at Array.forEach (<anonymous>)
    at loadUsers (app.js:39:9)
```

```sh title="فصّص الخطأ"
Uncaught
TypeError
Cannot read properties of undefined (reading 'name')
at renderUser (app.js:22:31)
at app.js:40:3 ... at loadUsers (app.js:39:9)
```

1. `Uncaught`: محدش عمله `catch`. لو لقيت `Uncaught (in promise)`، يبقى Promise اترفض (زي `fetch` أو `async` function) ومفيش `.catch` ولا `try`.
2. `TypeError`: نوع الخطأ. `TypeError` = استخدمت قيمة بشكل مش مناسب لنوعها. وفيه `ReferenceError` (متغير مش موجود) و`SyntaxError` (الكود أو الـ JSON مكتوب غلط).
3. `Cannot read properties of undefined (reading 'name')`: الرسالة: حاولت تقرا `.name` من حاجة قيمتها `undefined`. يعني في `x.name`، الـ `x` هو اللي undefined، مش `name`.
4. `at renderUser (app.js:22:31)`: أول سطر في الـ Stack = **مكان الخطأ**: دالة `renderUser`، ملف `app.js`، سطر 22، عمود 31. دوس عليه يفتحلك السطر في Sources.
5. `at app.js:40:3 ... at loadUsers (app.js:39:9)`: باقي السلسلة لتحت = **مين نده على مين**: `loadUsers` عملت `forEach`، وجواها Arrow function في سطر 40، وهي اللي نادت `renderUser`. اقرا من فوق لتحت تعرف إزاي الكود وصل للخطأ.

:::tip[الخطأ الأول هو المهم]
لو فيه 15 خطأ أحمر، متبدأش من آخرهم. غالباً الأول هو السبب، والباقي نتايج ليه (الـ `users` مجاش، فكل حاجة بتعتمد عليه وقعت). وفي حالة الخطأ اللي فوق، السؤال الحقيقي مش "ليه `renderUser` وقعت" لكن "ليه الـ user كان undefined؟"، والإجابة غالباً في Network: الـ API رجّع شكل غير اللي متوقعه.
:::

## 20.4 كتالوج رسايل الشبكة

دي الرسايل اللي المتصفح بيكتبها لوحده لما حاجة في الشبكة تبوظ. كل واحدة هتقابلها، فاحفظ شكلها ومعناها:

```sh title="Terminal"
x GET https://api.shop.dev/users 404 (Not Found)
x Failed to load resource: the server responded with a status of 401 ()
x POST https://api.shop.dev/orders 500 (Internal Server Error)
x Access to fetch at 'https://api.shop.dev/orders' from origin 'http://localhost:5173' has been blocked by CORS policy: ...
x Mixed Content: The page at 'https://shop.dev/' was loaded over HTTPS, but requested an insecure resource 'http://cdn.old.com/x.js'. This request has been blocked; the content must be served over HTTPS.
x Refused to connect to 'https://evil.com/' because it violates the following Content Security Policy directive: "connect-src 'self'".
x GET https://apii.shop.dev/users net::ERR_NAME_NOT_RESOLVED
x GET http://localhost:3000/api net::ERR_CONNECTION_REFUSED
```

**معنى كل رسالة وتبص فين**

| الرسالة | معناها | تبص فين |
|---|---|---|
| `404 (Not Found)` | السيرفر رد، بس العنوان ده مش موجود | الـ URL في Headers ← General: غلطة إملائية؟ `/api` ناقصة؟ `/` زيادة؟ |
| `401` | مين انت؟ مفيش Login أو الـ Token غلط أو خلص | Request Headers: الـ `authorization` اتبعت؟ تابة Cookies: الكوكي اتبعتت ولا اتمنعت؟ |
| `403` | عارفك، بس مش مسموحلك | صلاحيات الحساب على السيرفر، مش الـ Frontend |
| `500` | السيرفر نفسه وقع | Response: ساعات فيها رسالة الخطأ. والحل في Logs السيرفر |
| `blocked by CORS policy` | السيرفر مدّاش إذن للـ Origin بتاعك | سطر الـ preflight في Network، والفصل 14 |
| `Mixed Content` | صفحة HTTPS بتطلب حاجة `http://` | حوّل الرابط لـ `https://` (الفصل 12) |
| `Content Security Policy` | الموقع نفسه حاطط قايمة بالأماكن المسموح يكلمها (بـ Header اسمه `content-security-policy`)، والطلب ده مش فيها | Response Headers بتاعة الصفحة. لو الموقع بتاعك: ضيف الدومين للقايمة |

### عيلة net::ERR\_\*: لما مفيش رد أصلاً

دي أهم رسايل لأنها بتقولك إن المشكلة **قبل** HTTP. السيرفر ماردش بأي Status، لأن الطلب ماوصلش أو الاتصال مااكتملش. والاسم نفسه بيقولك المحطة اللي وقع فيها من رحلة الفصل 2:

**أشهر أخطاء net::ERR\_\***

| الخطأ | وقع فين | السبب غالباً |
|---|---|---|
| `ERR_NAME_NOT_RESOLVED` | DNS | الاسم غلط (`apii`)، أو الدومين مش موجود. جرب `dig` |
| `ERR_CONNECTION_REFUSED` | TCP | مفيش حد شغال على الـ Port ده. السيرفر بتاعك مش شغال؟ Port غلط؟ جرب `lsof -i :3000` |
| `ERR_CONNECTION_TIMED_OUT` | TCP | محدش رد خالص: Firewall، أو IP غلط، أو السيرفر واقع |
| `ERR_CONNECTION_RESET` | الاتصال | الطرف التاني قفل فجأة. ساعات Proxy أو VPN |
| `ERR_INTERNET_DISCONNECTED` | جهازك | مفيش نت (أو Offline في Throttling!) |
| `ERR_CERT_*` / `ERR_SSL_PROTOCOL_ERROR` | TLS | مشكلة شهادة (الفصل 12) |
| `ERR_TOO_MANY_REDIRECTS` | HTTP | Redirect loop: أ بيحوّل لـ ب وب بيحوّل لـ أ. جرب `curl -sIL` |
| `ERR_BLOCKED_BY_CLIENT` | المتصفح | Ad blocker أو Extension منع الطلب. جرب Incognito |
| `ERR_ABORTED` | المتصفح | الطلب اتلغى (الصفحة اتغيرت، أو `AbortController`). غالباً طبيعي |
| `ERR_EMPTY_RESPONSE` | HTTP | السيرفر قفل من غير ما يبعت حاجة. غالباً كراش في السيرفر |

:::tip[حاجة مشتركة: نفس المحطات، نفس الأدوات]
كل خطأ هنا بيقابله أداة في الـ Terminal من الكتاب ده: DNS ← `dig`، و TCP ← `nc -zv` و`lsof`، و TLS ← `openssl s_client` و`curl -v`، و Redirects ← `curl -sIL`، و HTTP ← `curl -i`. يعني لما الـ Console يقولك "وقعت هنا"، تروح للـ Terminal وتختبر المحطة دي لوحدها.
:::

## 20.5 fetch من الـ Console

الـ Console بيقبل `await` مباشرة (Top-level await)، فتقدر تجرب أي API في سطر:

```sh title="Terminal"
> const res = await fetch('https://jsonplaceholder.typicode.com/users/99')
> res.status
404
> res.ok
false
> res.headers.get('content-type')
'application/json; charset=utf-8'
> await res.json()
{}
# مفيش Error! fetch مبيرفضش على 404. لازم تشيك على res.ok بنفسك
```

وده الشكل اللي تكتبه في كودك عشان تتعامل مع النوعين: الشبكة وقعت، أو السيرفر رد بخطأ:

```js title="getUser.js"
async function getUser(id) {
  try {
    const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);   // 404 و 500 هنا
    return await res.json();
  } catch (err) {
    console.error('getUser failed:', err.message);          // الشبكة أو اللي فوق
    return null;
  }
}
```

:::note[الـ Origin بتاع الـ Console هو الصفحة]
الـ `fetch` اللي بتكتبه في الـ Console بيتعامل كأنه من الصفحة اللي انت فيها: نفس الـ Origin ونفس الكوكيز ونفس قواعد CORS و CSP. عشان كده لو فتحت الـ Console على `jsonplaceholder.typicode.com` نفسه وعملت `fetch('/users')`، هتشتغل بعنوان نسبي ومفيش CORS خالص. ولو جربت من صفحة تانية، ممكن تتمنع حسب الموقع.
:::

## 20.6 أدوات الـ Console الصغيرة

| الأمر | بيعمل إيه |
|---|---|
| `$0` | العنصر اللي انت مختاره في Elements دلوقتي. اختار زرار، وروح الـ Console، واكتب `$0.textContent` أو `$0.click()`. |
| `$_` | نتيجة آخر سطر اتنفذ. عملت `await res.json()` ونسيت تحفظه؟ `const data = $_`. |
| `$('css') / $$('css')` | اختصار لـ `querySelector` و`querySelectorAll`، بس `$$` بيرجع Array حقيقية. مثلاً: `$$('a').length`. (لو الصفحة فيها jQuery، `$` هيبقى بتاعها.) |
| `copy(x)` | انسخ أي قيمة للـ Clipboard. `copy(data)` بيحوّل الـ Object لـ JSON منسق وينسخه. تلزقه في محرر على طول. |
| `↑ / ↓` | الأوامر اللي كتبتها قبل كده. |
| `⇧↩` | سطر جديد من غير تنفيذ، لو بتكتب كود أطول. |

:::caution[خلي بالك: Self-XSS]
لو حد قالك "الزق الكود ده في الـ Console وهتاخد هدية"، **متعملش**. الكود ده هيتنفذ جوه حسابك بكوكيزك، ويقدر يعمل أي حاجة انت تقدر تعملها. عشان كده لو فتحت Console بتاع Facebook مثلاً هتلاقي تحذير كبير. وChrome بيطلب منك تكتب "allow pasting" قبل ما يسيبك تلزق أول مرة، وده لنفس السبب.
:::

## 20.7 الـ Issues panel و Understand this error

فوق في الـ Console ممكن تلاقي عداد صغير بأيقونة. ده بيفتح Panel اسمه **Issues**: المتصفح بيجمع فيه المشاكل اللي لقاها وشرحها بالتفصيل، بدل ما يملا بيها الـ Console. زي كوكيز اتمنعت بسبب SameSite، و Mixed content، ومشاكل CORS، ومشاكل Accessibility. وكل Issue فيه شرح ولينك للطلب المتأثر في Network. ارجعله لما يكون الـ Console هادي والحاجة مش شغالة.

وجنب الأخطاء هتلاقي أيقونة **Understand this error** لو الخدمة متاحة عندك (الشروط في الفصل 17). بتشرحلك الخطأ بالـ AI بناءً على الكود. جربها **بعد** ما تقرا الخطأ بنفسك، عشان تقارن فهمك بشرحها، مش بداله.

:::tip[ملخص الفصل]
- الـ Console فيه رسايل كودك ورسايل المتصفح، ومكان تشغّل فيه JS جوه الصفحة.
- المستويات: Verbose و Info و Warnings و Errors. والـ Context (`top`) بيحدد الكود بيتنفذ فين.
- `console.table` و`group` و`time` و`count` و`assert` و`trace`. والـ Object في اللوج بيتقري لما تفتحه.
- الـ Stack trace: أول سطر = مكان الخطأ، والباقي = مين نده على مين. والخطأ الأول هو المهم.
- 404 و 401 و 403 و 500 = السيرفر رد. CORS و Mixed content و CSP = المتصفح منع.
- `net::ERR_*` = مفيش رد HTTP، والاسم بيقولك المحطة: DNS أو TCP أو TLS.
- `fetch` مبيرفضش على 404، فشيك على `res.ok`. و`$0` و`$_` و`$$` و`copy()` أدوات يومية.
:::

### صح ولا غلط؟

1. `net::ERR_CONNECTION_REFUSED` معناه إن السيرفر رد بـ 403.
2. في الـ Stack trace، أول سطر تحت الرسالة هو المكان اللي الخطأ حصل فيه.
3. `fetch` بيعمل Reject لو السيرفر رد بـ 404.

### أسئلة مراجعة

1. في `Cannot read properties of undefined (reading 'name')`، إيه اللي undefined بالظبط؟
2. إيه الفرق بين `ERR_NAME_NOT_RESOLVED` و`ERR_CONNECTION_REFUSED`؟ وتختبر كل واحد بأنهي أمر؟
3. إيه الفرق بين خطأ CORS وخطأ CSP؟ ومين اللي "منع" في كل واحد؟
4. ليه ممكن تشوف قيمة في Object في الـ Console غير اللي كانت وقت `console.log`؟
5. اكتب سطرين في الـ Console يجيبوا `/users/1` ويطبعوا الإيميل بس.

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** جرب كل دوال `console` اللي في الفصل على بيانات `/users` من jsonplaceholder: `table` و`time` و`group`.
2. **[متوسط]** ولّد بنفسك 3 أخطاء شبكة من الـ Console: `fetch('https://doesnotexist.invalid')` و`fetch('http://localhost:3999')` و`fetch('https://jsonplaceholder.typicode.com/nope')`. اكتب الرسالة ونوعها والمحطة اللي وقعت فيها.
3. **[صعب]** اعمل خطأ متعمد في صفحة صغيرة: Array فيها Object ناقص خاصية، و`forEach` بتقرا الخاصية دي. اقرا الـ Stack trace، ودوس عليه لحد السطر، وصلّح.
