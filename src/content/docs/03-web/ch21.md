<small>المرحلة 6 · DevTools والـ Debugging</small>

في الفصل 13 فهمنا الكوكيز و localStorage نظرياً. Application Panel هو المكان اللي تشوفهم فيه بعينك وتعدلهم وتمسحهم. هنمشي على جدول الكوكيز عمود عمود، ونعدّل التخزين، ونمسح بيانات الموقع كلها لما حاجة تعلق، ونلمس الـ Service Workers. وفي الآخر، بما إنك على Mac: إزاي تفتح Web Inspector في Safari ونفس الأفكار فيه.

:::note[بعد الفصل ده هتكون عارف]
- خريطة Application Panel
- جدول الكوكيز: كل عمود، والتعديل والمسح، والكوكيز اللي فيها مشكلة
- localStorage و sessionStorage: تشوف وتعدل وتضيف
- Storage و Clear site data: البداية من الصفر
- Service Workers والـ Cache storage باختصار
- Safari Web Inspector: تفعّله وتستخدمه، والفروق المهمة
:::

<a id="s21-1"></a>

## 21.1 فين كل حاجة

افتح DevTools ← **Application** (لو مش ظاهر، في `»`). على الشمال فيه شجرة بأقسام:

| الأمر | بيعمل إيه |
|---|---|
| `Application` | **Manifest** (لو الموقع PWA)، و**Service workers**، و**Storage** (ملخص المساحة وزرار المسح). |
| `Storage` | **Local storage** و**Session storage** و**IndexedDB** و**Cookies** و**Cache storage**، وحاجات تانية أقل استخدام. كل واحد تحته الـ Origins اللي ليها بيانات. |
| `Background services` | تسجيل لحاجات بتحصل في الخلفية زي الـ Push notifications. مش هنحتاجه. |
| `Frames` | الصفحة وأي iframes جواها، ومعلومات أمان عن كل واحد. |

<a id="s21-2"></a>

## 21.2 جدول الكوكيز

Storage ← Cookies ← اختار الـ Origin. هتلاقي جدول، وكل عمود فيه هو Attribute من اللي فصّصناهم في الفصل 13:

**أعمدة جدول الكوكيز**

| العمود | بيقولك |
|---|---|
| Name / Value | الاسم والقيمة. ودوس على أي صف تشوف القيمة كاملة تحت، ومعاها Checkbox **Show URL-decoded** لو القيمة متشفرة (`%7B%22...`) |
| Domain | بتتبعت لمين. لو بتبدأ بـ `.` (زي `.shop.com`)، يبقى للـ Subdomains كمان |
| Path | المسار |
| Expires / Max-Age | هتخلص إمتى. لو مكتوب `Session`، يبقى Session cookie |
| Size | الاسم + القيمة بالـ Bytes. لو قربت من 4096، فيه مشكلة |
| HttpOnly ✓ | الـ JS ميشوفهاش. لو فيه علامة، مش هتلاقيها في `document.cookie` |
| Secure ✓ | HTTPS بس |
| SameSite | `Strict` أو `Lax` أو `None`، أو فاضي (يعني اتعاملت Lax في Chrome) |
| Partition Key | لو `Partitioned` (CHIPS): مربوطة بأنهي موقع أب |
| Priority | Low و Medium و High: لو المتصفح اضطر يمسح كوكيز عشان المساحة، يبدأ بأنهي |

| الأمر | بيعمل إيه |
|---|---|
| `Double-click على خانة` | عدّلها. غيّر القيمة، أو الـ Expires، أو حتى شيل الـ HttpOnly. مفيد تجرب "لو الكوكي دي اتغيرت، السيرفر هيعمل إيه؟". |
| `Double-click على صف فاضي` | ضيف كوكي جديدة بإيدك. |
| `اختار صف + Delete (⌫)` | امسح الكوكي دي. أسرع طريقة تعمل "Logout" وتجرب الصفحة كأنك زائر. |
| `🚫 Clear all cookies` | امسح كوكيز الـ Origin ده كلها. |
| `Only show cookies with an issue` | فلتر للكوكيز اللي فيها مشكلة (اتمنعت أو هتتمنع). هتلاقيها متلونة، وحط الماوس على العلامة يقولك السبب. |

:::tip[حاجة مشتركة: نفس الكوكي، 3 أماكن تشوفها]
تابة **Cookies** جوه طلب في Network بتقولك الكوكي دي **اتبعتت مع الطلب ده** ولا لأ وليه (الفصل 19). جدول **Application** بيقولك الكوكيز **المحفوظة** عند المتصفح دلوقتي. و`document.cookie` في الـ Console بيقولك اللي **الـ JS شايفه** (من غير HttpOnly). لو الكوكي موجودة في Application ومش في الطلب، يبقى المتصفح قرر ميبعتهاش (Domain أو Path أو SameSite أو Secure). ولو مش موجودة في Application خالص، يبقى السيرفر محطهاش أو المتصفح رفضها.
:::

<a id="s21-3"></a>

## 21.3 localStorage و sessionStorage

Storage ← Local storage ← الـ Origin. جدول بسيط: Key و Value. والـ Value لو JSON، دوس عليه يتعرض كشجرة تحت.

| الأمر | بيعمل إيه |
|---|---|
| `Double-click` | عدّل أي Key أو Value. |
| `صف فاضي في الآخر` | ضيف Key جديد. |
| `⌫ / 🚫` | امسح واحد، أو امسح الكل. |
| `⟳` | حدّث الجدول. لو الكود غيّر حاجة ومش ظاهرة، دوس عليه. |

:::note[مثال عملي: الثيم بيرجع Light كل مرة]
عملت زرار Dark mode بيعمل `localStorage.setItem('theme','dark')`. ولما تعمل Reload بيرجع Light. افتح Local storage: لو `theme` موجودة بقيمة `dark`، يبقى المشكلة في الكود اللي **بيقرا** القيمة وقت التحميل. ولو مش موجودة، يبقى المشكلة في اللي **بيكتب**. ولو موجودة تحت Origin تاني (Port تاني)، فاكر الفصل 13؟ كده نصيت المشكلة في ثانية بدل ما تقرا الكود كله.
:::

<a id="s21-4"></a>

## 21.4 Clear site data: ابدأ من الصفر

ساعات الموقع "يعلق" في حالة غريبة: Login قديم، أو كاش قديم، أو بيانات اتخزنت غلط من نسخة قديمة من كودك. بدل ما تمسح كل حاجة لوحدها: Application ← **Storage**. هتلاقي رسمة بالمساحة المستخدمة، وتحتها Checkboxes (Cookies و Local and session storage و IndexedDB و Cache storage و Unregister service workers)، وزرار **Clear site data**. ده بيرجّع الموقع ده عندك كأنك أول مرة تفتحه، من غير ما يلمس باقي المواقع.

وفيه طريقة أسرع: Right-click على زرار Reload في Chrome و DevTools مفتوح ← **Empty cache and hard reload** للكاش بس. وفيه طريقة من السيرفر نفسه: Header اسمه `Clear-Site-Data: "cache", "cookies", "storage"` ممكن يتبعت في رد الـ Logout عشان يمسح كل حاجة عند اليوزر.

<a id="s21-5"></a>

## 21.5 Service Workers باختصار

**Service Worker** = ملف JS الموقع بيسجله في المتصفح، وبيقف **بين الصفحة والشبكة**. أي طلب الصفحة بتعمله بيعدي عليه الأول، ويقدر يرد من كاش بتاعه (اسمه Cache storage) من غير ما يروح للنت. ده اللي بيخلي مواقع تشتغل Offline. بس ليه أثر جانبي مزعج وانت بتطور: ممكن يفضل يديك نسخة قديمة من الموقع حتى بعد ما تغيّر الكود.

| الأمر | بيعمل إيه |
|---|---|
| `Update on reload` | مع كل Reload، حمّل نسخة الـ Service Worker الجديدة. فعّله وانت بتطور. |
| `Bypass for network` | خلي الطلبات تروح للشبكة على طول، كأن مفيش Service Worker. |
| `Unregister` | امسحه خالص. |
| `Offline` | جرب الموقع كأن مفيش نت. |

وفي Network، الطلبات اللي الـ Service Worker رد عليها هتلاقي في Size بتاعها `(ServiceWorker)`، وعليها ترس صغير ⚙ جنب الاسم لو هو اللي عملها.

## 21.6 Safari Web Inspector

انت على Mac، ويوزرز كتير هيفتحوا موقعك من Safari أو من iPhone (وكل المتصفحات على الـ iPhone جواها محرك Safari). ومحرك Safari (WebKit) مختلف عن Chrome في حاجات، خصوصاً الكوكيز والخصوصية. فلازم تعرف تفتح أدواته:

1. Safari ← **Settings** (<kbd>⌘</kbd><kbd>,</kbd>) ← **Advanced** ← فعّل **Show features for web developers**. هيظهرلك قايمة جديدة فوق اسمها **Develop**.
2. افتح Web Inspector: Develop ← Show Web Inspector، أو <kbd>⌥</kbd><kbd>⌘</kbd><kbd>I</kbd> (نفس اختصار Chrome تقريباً)، أو Right-click ← Inspect Element.

نفس الأفكار اللي اتعلمناها موجودة، بأسماء قريبة:

**Chrome DevTools مقابل Safari Web Inspector**

| Chrome | Safari | ملاحظة |
|---|---|---|
| Network | Network | نفس الفكرة: قايمة وتفاصيل وفلاتر و Export HAR، وفيه Preserve log و Disable caches في الشريط |
| Console | Console | نفس الرسايل تقريباً، بس النصوص مختلفة شوية |
| Application | Storage | Cookies و Local/Session storage و IndexedDB |
| Sources | Sources | الـ Breakpoints والـ Debugger |
| Performance | Timelines | تسجيل لكل اللي حصل |
| Device mode | Responsive Design Mode | Develop ← Enter Responsive Design Mode |

| الأمر | بيعمل إيه |
|---|---|
| `Develop ← Empty Caches` | امسح كاش Safari كله. (<kbd>⌥</kbd><kbd>⌘</kbd><kbd>E</kbd>) |
| `Develop ← [اسم الـ iPhone]` | وصّل الـ iPhone بالكابل، وفعّل Web Inspector على الموبايل (Settings ← Apps ← Safari ← Advanced)، وهتقدر تفتح Web Inspector على الـ Mac لصفحة مفتوحة على الموبايل. أقوى طريقة تعمل Debug لموقع على موبايل حقيقي. |
| `Network ← Edit and resend` | Right-click على طلب: عدّله وابعته تاني من جوه Web Inspector. |

:::note[ليه موقعك ممكن يشتغل في Chrome ويبوظ في Safari؟]
أشهر سبب في الشبكة: Safari بيمنع الـ Third-party cookies من سنين (الفصل 13)، وبيحدد عمر الكوكيز اللي الـ JS بيكتبها في حالات معينة. فلو الـ Login بتاعك معتمد على كوكي من دومين تاني، أو جوه iframe، هيشتغل في Chrome ويفشل في Safari. افتح Storage ← Cookies في Safari وقارن بـ Chrome. والسبب التاني: الـ CSS والـ JS بيختلفوا شوية بين المحركات، وده بتشوفه في Console و Elements.
:::

:::tip[ملخص الفصل]
- Application: Storage فيها Cookies و Local/Session storage و IndexedDB و Cache storage.
- جدول الكوكيز = الـ Attributes كلها: Domain و Path و Expires و HttpOnly و Secure و SameSite و Partition Key.
- Double-click للتعديل، و ⌫ للمسح، و Only show cookies with an issue للمشاكل.
- نفس الكوكي في 3 أماكن: المحفوظة (Application)، واللي اتبعتت (Network ← Cookies)، واللي الـ JS شايفها (`document.cookie`).
- Storage ← Clear site data يرجّع الموقع كأنها أول زيارة.
- Service Worker بيقف بين الصفحة والشبكة، و Update on reload و Bypass for network وانت بتطور.
- Safari: فعّل Show features for web developers، وبعدين <kbd>⌥</kbd><kbd>⌘</kbd><kbd>I</kbd>. و Storage = Application.
:::

### صح ولا غلط؟

1. الكوكي اللي عليها HttpOnly مش هتظهر في جدول Application.
2. Clear site data بيمسح بيانات كل المواقع في المتصفح.
3. قايمة Develop في Safari بتظهر لوحدها من غير ما تفعّلها.

### أسئلة مراجعة

1. الكوكي موجودة في Application بس مش في Request Cookies لطلب معين. إيه الأسباب المحتملة؟
2. إمتى تستخدم Clear site data بدل إنك تمسح كوكي واحدة؟
3. إيه المشكلة اللي Service Worker ممكن يعملها وانت بتطور؟ وتحلها إزاي؟
4. ليه مهم تجرب موقعك في Safari وانت على Mac؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** افتح أي موقع عامل فيه Login، ولاقي كوكي الـ Session في Application. هي HttpOnly؟ و Secure؟ و SameSite إيه؟
2. **[متوسط]** امسح كوكي الـ Session بس، واعمل Reload. حصل إيه؟ وبعدين جرب Clear site data على موقع تاني.
3. **[صعب]** فعّل Develop في Safari، وافتح نفس الموقع في Chrome و Safari، وقارن الكوكيز في الاتنين. لو عندك iPhone، جرب Develop ← \[الـ iPhone\].
