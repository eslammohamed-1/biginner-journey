<small>المرحلة 3 · لغة الويب: HTTP</small>

استخدمنا curl في كل فصل لحد دلوقتي بشكل متفرق. الفصل ده بقى نجمع فيه كل حاجة: نعمل كل أنواع الطلبات على API حقيقي للتجارب، ونبعت JSON وفورمز وملفات، ونحفظ كوكيز، ونقيس الوقت بالملي ثانية لكل مرحلة من مراحل الرحلة، ونعمل طلبات بتفشل بصوت عالي في الـ Scripts. كل Flag متشرّح.

:::note[بعد الفصل ده هتكون عارف]
- ليه curl أداة أساسية جنب DevTools مش بديل ليها
- قراية الرد: -i و -I و -v والفرق بينهم
- CRUD كامل على API: -X و -H و -d و --json
- رفع الملفات بـ -F، والـ Query بـ -G و --data-urlencode
- التحويلات والملفات: -L و -o و -O
- الهدوء والفشل الصريح: -s و -S و -f و --fail-with-body
- قياس الوقت بـ -w (DNS و Connect و TLS و TTFB)
- الكوكيز والـ Login و -u و -k والـ Timeouts و --resolve
:::

<a id="s10-1"></a>

## 10.1 ليه curl لما عندي متصفح؟

سؤال منطقي. المتصفح بيعمل طلبات طول اليوم، و DevTools بيوريك كل حاجة. ليه أتعب نفسي بالـ Terminal؟ عشان المتصفح بيعمل حاجات كتير من ورا ضهرك: بيبعت كوكيز لوحده، وبيستخدم الكاش، وبيطبّق CORS، وعنده Extensions ممكن تعدّل الطلبات، وبيتبع الـ Redirects من غير ما يقولك. فلما حاجة تبوظ، صعب تعرف هل المشكلة في السيرفر ولا في حاجة من دول. والحل: <strong>تجرب الطلب "عريان"</strong>، من غير أي حاجة زيادة. لو اشتغل بـ curl ومش شغال في المتصفح، يبقى المشكلة في الحاجات اللي المتصفح بيضيفها (غالباً CORS أو كوكيز أو كاش). ولو مش شغال بـ curl كمان، يبقى المشكلة في السيرفر أو في طلبك نفسه.

وكمان curl بيتكتب في Scripts، وبيتبعت لزميلك في رسالة، وتوثيق أي API في الدنيا بيكتب أمثلته بـ curl. وأحلى حاجة: DevTools يقدر يحوّلك أي طلب لأمر curl بزرار (Copy as cURL، الفصل 19). فاتعلمه كويس، هتستخدمه كل أسبوع.

:::note[الـ API اللي هنجرب عليه]
هنستخدم `jsonplaceholder.typicode.com`: API مجاني للتجارب فيه `/posts` و`/users` و`/todos`، وبيقبل كل الـ Methods. بس خلي بالك: هو بيرد كأنه نفّذ (يرجعلك 201 والبيانات)، لكنه **مش بيحفظ** حاجة فعلاً. ومعاه `httpbin.org` اللي بيرجعلك طلبك كمراية.
:::

<a id="s10-2"></a>

## 10.2 تقرا الرد: -i و -I و -v

من غير أي Flags، curl بيطبع الـ Body بس. بس انت غالباً محتاج تشوف الـ Status والـ Headers. وفيه تلات درجات:

| الأمر | بيعمل إيه |
|---|---|
| `curl -i URL` | `-i` = Include: اطبع Headers الرد **وبعدها** الـ Body. الطلب نفسه عادي (GET). |
| `curl -I URL` | `-I` = Head: ابعت طلب `HEAD`، فالرد Headers بس. أسرع، بس خلي بالك إن سيرفرات قليلة بترد على HEAD بشكل مختلف عن GET. |
| `curl -v URL` | `-v` = Verbose: كل حاجة: الـ DNS والاتصال والـ TLS، والطلب اللي اتبعت (`>`)، والرد (`<`)، والـ Body. ده اللي بتستخدمه في الـ Debugging. |

:::tip[حاجة مشتركة: i صغيرة و I كبيرة]
زي كتير من أدوات Unix، الحرف الصغير والكبير ممكن يبقوا حاجتين مختلفين خالص في نفس الأداة: `-i` (ضمّن الـ Headers) و`-I` (HEAD بس)، و`-o` (احفظ باسم أنا بختاره) و`-O` (احفظ بنفس اسم الملف)، و`-s` (اسكت) و`-S` (بس قولي الأخطاء). فلو أمر طلع ناتج غريب، أول حاجة تشيك عليها حالة الحرف.
:::

<a id="s10-3"></a>

## 10.3 CRUD كامل: اقرا واعمل وعدّل وامسح

**اقرا**: GET هو الافتراضي، فمش محتاج تكتب Method:

```sh title="Terminal"
$ curl -s https://jsonplaceholder.typicode.com/posts/1
{
  "userId": 1,
  "id": 1,
  "title": "sunt aut facere repellat provident occaecati excepturi optio reprehenderit",
  "body": "quia et suscipit\nsuscipit recusandae consequuntur ..."
}
```

**اعمل**: POST بـ JSON. ودي الصيغة اللي هتكتبها كتير، فخلينا نفصّصها كويس:

**تشريح الأمر**

```sh
curl -i -X POST https://jsonplaceholder.typicode.com/posts -H 'Content-Type: application/json' -d '{"title":"First post","userId":1}'
```

1. `curl -i`: اطلب، واطبع Headers الرد مع الـ Body عشان نشوف الـ Status.
2. `-X POST`: `-X` = Request method: استخدم الـ Method ده. (الحقيقة: لما تستخدم `-d`، curl بيعمل POST لوحده، فـ `-X POST` هنا للوضوح بس.)
3. `https://jsonplaceholder.typicode.com/posts`: الـ Collection: "ضيف بوست جديد للبوستات".
4. `-H 'Content-Type: application/json'`: قول للسيرفر إن الـ Body JSON. فاكر الغلطة المشهورة في الفصل 7؟ هنا نفس الكلام.
5. `-d`: `-d` = Data: الـ Body. من غير الـ Header اللي فوق، curl بيبعته على إنه `application/x-www-form-urlencoded`.
6. `'{"title":"First post","userId":1}'`: الـ JSON نفسه بين Single quotes، عشان الـ Double quotes اللي جوه JSON متتلخبطش مع الـ zsh.

```sh title="Terminal"
HTTP/2 201
content-type: application/json; charset=utf-8
location: https://jsonplaceholder.typicode.com/posts/101
etag: W/"3e-Jwo8gJL384l8HW9eGTvv/o+Y2dI"

{
  "title": "First post",
  "userId": 1,
  "id": 101
}
```

شوف الحاجات اللي اتعلمناها كلها في رد واحد: `201` لأن حاجة اتعملت، و`location` فيه عنوان الحاجة الجديدة، و`id: 101` اتعمل من السيرفر. وفيه اختصار أحدث بيعمل الـ Header والـ Body مع بعض:

**تشريح الأمر**

```sh
curl --json '{"title":"First post","userId":1}' https://jsonplaceholder.typicode.com/posts
```

1. `curl`: اطلب.
2. `--json`: اختصار (من curl 7.82) بيعمل 3 حاجات مرة واحدة: `-d` للـ Body، و`Content-Type: application/json`، و`Accept: application/json`. والـ POST تلقائي.
3. `'{"title":"First post","userId":1}'`: الـ JSON.
4. `https://jsonplaceholder.typicode.com/posts`: العنوان. لاحظ إن ترتيب الـ Flags والـ URL في curl مش مهم.

**عدّل وامسح**: نفس الفكرة بـ Methods تانية:

| الأمر | بيعمل إيه |
|---|---|
| `curl -X PATCH --json '{"title":"New title"}' https://jsonplaceholder.typicode.com/posts/1` | عدّل جزء. و`-X` هنا لازم، عشان `--json` لوحده بيعمل POST. |
| `curl -X PUT --json '{"id":1,"title":"x","userId":1}' https://jsonplaceholder.typicode.com/posts/1` | استبدل كله. لاحظ إن PUT بيبعت الـ Object كامل. |
| `curl -i -X DELETE https://jsonplaceholder.typicode.com/posts/1` | امسح. الرد `200` ببوست فاضي `{}` هنا، وفي APIs تانية `204`. |

### JSON من ملف بدل ما تكتبه

لو الـ JSON طويل، اكتبه في ملف `post.json` وابعته بـ `@`:

**تشريح الأمر**

```sh
curl --json @post.json https://jsonplaceholder.typicode.com/posts
```

1. `curl --json`: ابعت JSON.
2. `@post.json`: الـ `@` في curl معناها "اقرا القيمة من الملف ده" بدل ما تكون مكتوبة. بتشتغل مع `-d` و`--json` و`-F`. و`@-` = اقرا من الـ stdin (اللي جاي من Pipe).
3. `https://jsonplaceholder.typicode.com/posts`: العنوان.

:::note[مثال عملي: JSON مقروء بـ jq]
ردود الـ APIs بتيجي JSON في سطر واحد طويل أحياناً. أداة `jq` (موجودة في macOS 15 وطالع، ولو مش عندك: `brew install jq`) بتنسقه وتلونه وتطلع منه اللي انت عاوزه: `curl -s https://jsonplaceholder.typicode.com/users | jq '.[0].email'`. الـ `.` = الـ JSON كله، و`[0]` = أول عنصر في الـ Array، و`.email` = خاصية الإيميل. يعني نفس اللي بتكتبه في JS: `data[0].email`.
:::

## 10.4 فورمز وملفات و Query

مش كل حاجة JSON. لو بتجرب فورم قديم، أو بترفع ملف، أو عاوز تبني Query string بأمان:

**تشريح الأمر**

```sh
curl -F 'name=Sara' -F 'avatar=@me.png;type=image/png' https://httpbin.org/post
```

1. `curl`: اطلب.
2. `-F 'name=Sara'`: `-F` = Form: ابعت `multipart/form-data` (زي فورم فيه ملفات). وكل `-F` حقل.
3. `-F 'avatar=@me.png;type=image/png'`: حقل اسمه `avatar` قيمته **محتوى** الملف `me.png` (الـ `@` تاني)، و`;type=` بتحدد الـ Content-Type بتاع الجزء ده. لو مكتبتهاش curl بيخمّن من الامتداد.
4. `https://httpbin.org/post`: هيرجعلك الـ `form` والـ `files` اللي استلمها.

**تشريح الأمر**

```sh
curl -G https://httpbin.org/get --data-urlencode 'q=rock & roll' --data-urlencode 'lang=ar'
```

1. `curl -G`: `-G` = Get: "خد أي `-d` أو `--data-urlencode` وحطهم في الـ Query string بدل الـ Body، والطلب يبقى GET".
2. `https://httpbin.org/get`: العنوان من غير `?`. curl هيضيفها.
3. `--data-urlencode 'q=rock & roll'`: اعمل Percent-encoding للقيمة لوحدك (فاكر الفصل 6؟). الناتج `q=rock%20%26%20roll` (وممكن تشوف `+` مكان المسافة، والاتنين صح في الـ Query string). المهم إن الـ `&` بقت `%26` فمش هتتفهم إنها فاصل بين Parameters. وكده مش محتاج تحسب الأكواد بإيدك.
4. `--data-urlencode 'lang=ar'`: Parameter تاني. curl هيحط `&` بينهم.

## 10.5 التحويلات والتحميل: -L و -o و -O

| الأمر | بيعمل إيه |
|---|---|
| `curl -L http://github.com` | `-L`: اتبع الـ Redirects لحد الآخر (الفصل 8). من غيرها هتاخد الـ 301 وبس. |
| `curl -L -o logo.svg https://example.com/a/b/logo.svg` | `-o file`: احفظ الـ Body في ملف بالاسم ده. |
| `curl -LO https://example.com/files/report.pdf` | `-O`: احفظ بنفس اسم الملف اللي في الـ URL (`report.pdf`) في الفولدر الحالي. |
| `curl -C - -LO https://example.com/big.zip` | `-C -`: كمّل تحميل اتقطع من مكان ما وقف. ده بيستخدم `Range` و`206` اللي في الفصل 8. والـ `-` بعد `-C` معناها "احسب انت وقفت فين". |

## 10.6 الـ Scripts: اسكت، بس افشل بصوت عالي

لما تحط curl في Script، فيه مشكلتين. الأولى: شريط التقدم بيبوظ الناتج. والتانية أخطر: curl بيعتبر أي رد من السيرفر نجاح (زي `fetch` بالظبط!)، يعني لو السيرفر رد 500، curl هيطبع صفحة الخطأ ويخرج بـ Exit code صفر، والـ Script هيكمّل كأن كل حاجة تمام. والحل في تلات Flags:

**تشريح الأمر**

```sh
curl -sSf https://httpbin.org/status/500 -o data.json || echo "فشل"
```

1. `-s`: Silent: مفيش شريط تقدم ولا رسايل.
2. `S`: الـ `-S` = Show error: "حتى لو ساكت، لو حصل خطأ اطبعه". من غيرها `-s` بتخبي الأخطاء كمان.
3. `f`: الـ `-f` = Fail: لو الـ Status 400 أو أكتر، متطبعش الـ Body واخرج بـ Exit code غير صفر (22). ده اللي بيخلي الـ Script يعرف إن فيه مشكلة.
4. `-o data.json`: احفظ الناتج لو نجح.
5. `|| echo "فشل"`: الـ `||` = "لو اللي قبلي فشل (Exit code مش صفر)، نفّذ اللي بعدي". نفس الـ `||` اللي في كتاب الـ Terminal.

```sh title="Terminal"
$ curl -sSf https://httpbin.org/status/500 -o data.json || echo "فشل"
curl: (22) The requested URL returned error: 500
فشل
$ echo $?
0
```

<small>الـ `echo $?` طبع 0 لأنه بيطبع Exit code آخر أمر، وآخر أمر هنا كان `echo "فشل"` اللي نجح.</small>

:::tip[--fail-with-body: احسن الاتنين]
مشكلة `-f` إنها بترمي Body الرد، وغالباً السيرفر كاتب فيه سبب الخطأ. من curl 7.76 فيه `--fail-with-body`: يفشل زي `-f` بالظبط، بس يطبعلك الـ Body. وده اللي تستخدمه وانت بتجرب API ومش فاهم ليه بيرجّع 400.
:::

## 10.7 قيس الرحلة بالملي ثانية

فاكر رحلة الطلب في الفصل 2؟ curl يقدر يقيسلك كل محطة فيها، ودي نفس الأرقام اللي هتشوفها في تابة Timing في DevTools. اعمل ملف اسمه `timing.txt` فيه:

```sh title="timing.txt"
      dns:  %{time_namelookup}s\n
  connect:  %{time_connect}s\n
      tls:  %{time_appconnect}s\n
     ttfb:  %{time_starttransfer}s\n
    total:  %{time_total}s\n
   status:  %{http_code}  ·  %{size_download} bytes  ·  http/%{http_version}\n
```

**تشريح الأمر**

```sh
curl -s -o /dev/null -w @timing.txt https://example.com
```

1. `curl -s -o /dev/null`: اسكت، وارمي الـ Body.
2. `-w`: اطبع بعد ما تخلص.
3. `@timing.txt`: نفس الـ `@` اللي فوق: "الشكل اللي تطبعه موجود في الملف ده". أسهل من كتابة سطر طويل.
4. `https://example.com`: العنوان اللي هنقيسه.

```sh title="Terminal"
$ curl -s -o /dev/null -w @timing.txt https://example.com
      dns:  0.012s
  connect:  0.031s
      tls:  0.074s
     ttfb:  0.118s
    total:  0.119s
   status:  200  ·  577 bytes  ·  http/2
```

```sh title="الأرقام دي بتقيس إيه بالظبط"
time_namelookup
time_connect
time_appconnect
time_starttransfer
time_total
```

1. `time_namelookup`: من البداية لحد ما الـ DNS خلص. لو الرقم ده كبير، المشكلة في الـ DNS.
2. `time_connect`: لحد ما الـ TCP Handshake خلص. الفرق بينه وبين اللي قبله ≈ RTT واحد.
3. `time_appconnect`: لحد ما الـ TLS خلص (للـ HTTPS بس). الفرق عن connect = وقت التشفير.
4. `time_starttransfer`: الـ **TTFB** (Time To First Byte): لحد ما أول Byte من الرد وصل. الفرق عن appconnect = وقت السيرفر وهو بيفكر + RTT. لو الرقم ده الكبير، السيرفر بطيء.
5. `time_total`: كله. الفرق عن starttransfer = وقت تحميل الـ Body.

:::caution[خلي بالك: الأرقام تراكمية]
كل رقم من دول محسوب **من بداية الطلب**، مش مدة المرحلة لوحدها. يعني وقت الـ TLS لوحده = `tls - connect` = 0.043 ثانية في المثال. وفي DevTools، تابة Timing بتوريك كل مرحلة لوحدها، فخلي بالك وانت بتقارن.
:::

## 10.8 حاجات تانية هتحتاجها

| الأمر | بيعمل إيه |
|---|---|
| `curl -c jar.txt -b jar.txt URL` | `-c file` = Cookie jar: احفظ أي `Set-Cookie` في الملف ده. و`-b file` = ابعت الكوكيز اللي فيه. الاتنين مع بعض = curl بيفتكر الـ Login زي المتصفح. و`-b 'sid=abc'` تبعت كوكي بإيدك. |
| `curl -u sara:s3cret URL` | `-u` = User: بيعمل `Authorization: Basic` لوحده. لو كتبت `-u sara` بس، هيسألك عن الباسورد من غير ما يظهر في تاريخ الأوامر. |
| `curl -H "Authorization: Bearer $TOKEN" URL` | Token من متغير. هنا لازم **Double** quotes عشان zsh يحط قيمة `$TOKEN`. وده أأمن من إنك تلزق الـ Token في الأمر نفسه. |
| `curl --max-time 10 --connect-timeout 3 URL` | متستناش للأبد: الطلب كله 10 ثواني بالكتير، وفتح الاتصال 3 ثواني. مهمين في الـ Scripts. |
| `curl --http1.1 URL / curl --http2 URL` | أجبره على نسخة معينة من HTTP (الفصل 11). مفيد لما حاجة شغالة في نسخة ومش شغالة في التانية. |
| `curl --resolve shop.test:443:127.0.0.1 https://shop.test` | "لما تدور على `shop.test` على Port 443، استخدم الـ IP ده". زي `/etc/hosts` بس للأمر ده بس، ومن غير sudo. |
| `curl -k https://localhost:8443` | `-k` = Insecure: متتحققش من الشهادة. **للتجربة على جهازك بس** (شهادة Self-signed). على أي موقع حقيقي، ده بيلغي الحماية كلها (الفصل 12). |

:::caution[خلي بالك: الأسرار في تاريخ الـ zsh]
أي أمر بتكتبه بيتحفظ في `~/.zsh_history`. يعني لو كتبت `curl -H 'Authorization: Bearer sk-live-...'`، الـ Token بقى محفوظ في ملف نصي على جهازك. الأحسن تحطه في متغير بيتقرا من مكان آمن، أو تبدأ الأمر بمسافة (لو مفعّل `setopt HIST_IGNORE_SPACE` في `~/.zshrc`، الأمر اللي بيبدأ بمسافة مبيتحفظش).
:::

:::tip[ملخص الفصل]
- curl = الطلب من غير إضافات المتصفح، فبيفصل مشاكل السيرفر عن مشاكل المتصفح.
- `-i` Headers + Body، و`-I` طلب HEAD، و`-v` كل حاجة.
- `-X` للـ Method، و`-H` للـ Header، و`-d` للـ Body، و`--json` اختصار JSON، و`@file` من ملف.
- `-F` للفورمز والملفات، و`-G --data-urlencode` للـ Query المتشفّر.
- `-L` اتبع التحويلات، و`-o`/`-O` احفظ، و`-sSf` أو `--fail-with-body` في الـ Scripts.
- `-w` بالمتغيرات `time_*` بيقيس كل محطة، والأرقام تراكمية من البداية.
- `-c`/`-b` للكوكيز، و`-u` للـ Basic، و`--resolve` بدل hosts، و`-k` للتجربة المحلية بس.
:::

### صح ولا غلط؟

1. من غير `-f`، curl بيرجّع Exit code صفر حتى لو السيرفر رد 500.
2. `-I` و`-i` نفس الحاجة.
3. في `-w`، قيمة `time_appconnect` هي وقت الـ TLS لوحده.

### أسئلة مراجعة

1. إمتى تقول "المشكلة في المتصفح مش في السيرفر" بعد ما تجرب بـ curl؟
2. إيه التلات حاجات اللي `--json` بيعملهم؟ وليه محتاج `-X PATCH` معاه في التعديل؟
3. إيه الفرق بين `-d 'q=a b'` مع `-G` و`--data-urlencode 'q=a b'` مع `-G`؟
4. عندك `dns 0.010` و`connect 0.040` و`tls 0.090` و`ttfb 1.900`. المشكلة فين؟
5. ليه في `-H "Authorization: Bearer $TOKEN"` استخدمنا Double quotes مش Single؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** اعمل CRUD كامل على `/todos` في jsonplaceholder: GET لـ todo رقم 5، و POST لواحدة جديدة، و PATCH يخليها `completed: true`، و DELETE. اكتب الـ Status بتاع كل واحد.
2. **[متوسط]** اعمل ملف `timing.txt` وقيس 3 مواقع: واحد في مصر، و `example.com`، وواحد في آسيا. قارن الـ TTFB والـ TLS.
3. **[صعب]** استخدم `-c` و`-b` مع `https://httpbin.org/cookies/set?name=sara` وبعدين `https://httpbin.org/cookies`: اثبت إن curl فاكر الكوكي في الطلب التاني. (تلميح: الأول بيعمل Redirect، فمحتاج `-L`.)
