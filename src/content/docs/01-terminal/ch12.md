<small>المرحلة 5 · الأتمتة والتخصيص</small>

إنت كمبرمج JavaScript عارف القاعدة الذهبية: لو كتبت نفس الكود 3 مرات، حطه في Function. الـ Terminal نفس الكلام بالظبط. كل يوم الصبح بتفتح المشروع، وتعمل git pull، وتشغل Postgres، وتشغل npm run dev، وتفتح VS Code؟ 5 أوامر كل يوم، 300 يوم في السنة. الـ Script هو الـ Function بتاعة الـ Terminal: ملف فيه نفس الأوامر اللي اتعلمتها، ومعاها متغيرات وشروط ولوبات ودوال، وتشغله بكلمة واحدة. ومش برمجة معقدة: لو فهمت الفصول اللي فاتت، إنت عملياً عارف 80% منه. الفصل ده بيبني معاك Scripts حقيقية خطوة خطوة، ويعلمك إزاي تخليها آمنة متكسرش في نص الشغل، وإزاي تكتبها بحيث تشتغل على الماك (bash 3.2 والأدوات الـ BSD) وعلى السيرفر Linux من غير مفاجآت.

:::note[بعد الفصل ده هتكون عارف]
- الـ Shebang وتشغيل الـ Script، وإيه اللي بيحصل مع bash 3.2 على الماك
- المتغيرات والـ Quoting والحساب
- test و \[ \] و \[\[ \]\] والمقارنات
- if و case و for و while
- الدوال و local و return
- ‎$1 و $@ و $# و shift
- set -euo pipefail و trap
- Scripts عملية كاملة تشتغل على الماك و Linux (date -v و stat -f و sed -i '')
- جدولة الـ Scripts بـ launchd و cron
:::

## 12.1 أول Script: الـ Shebang

خلينا نبدأ صغير خالص. افتح VS Code (أو `nano hello.sh`) واكتب 3 سطور. السطر الأول غريب شوية، وده أهم سطر في الملف كله:

```sh title="hello.sh"
#!/usr/bin/env bash
# أول Script
echo "Hello, $USER! Today is $(date +%A)."
```

**تشريح الأمر**

```sh
#!/usr/bin/env bash
```

1. `#!`: Shebang (hash + bang): لازم يكون أول حرفين في الملف. بيقول للـ Kernel "شغّل الملف ده بالبرنامج اللي بعدي".
2. `/usr/bin/env`: برنامج بيدوّر على اللي بعده في الـ PATH ([↩ 1.4](../ch01/#s1-4 "الـ PATH: إزاي الـ Shell بيلاقي البرنامج؟")). أحسن من `#!/bin/bash` لأن bash ممكن يكون في مكان تاني. على الماك ده مهم جداً: لو سطبت bash 5 من Homebrew، `env` هيلاقيه في `/opt/homebrew/bin/bash` الأول، أما `#!/bin/bash` فهيشغّل دايماً bash 3.2 القديم ([↩ 3.4](../ch03/#s3-4 "ليه الماك ساب bash وراح لـ zsh؟")).
3. `bash`: المفسّر. لو كتبت `sh` هيبقى POSIX بس من غير مميزات bash ([↩ 3.2](../ch03/#s3-2 "الجد الكبير: sh و POSIX")).

:::caution[بتكتب لأنهي bash؟]
جوه الـ Script اكتب `echo "$BASH_VERSION"` مرة وشوف: على ماك مفيهوش brew bash هيقولك `3.2.57(1)-release`، وعلى Ubuntu `5.x`. الفصل ده بيعلّم bash العادي اللي شغال في الاتنين، ولما حاجة تحتاج bash 4 أو أحدث هنقولك صراحة. والقاعدة: لو الـ Script هيتشغل على ماكات ناس تانية، اكتبه لـ bash 3.2، أو اطلب منهم `brew install bash`. ولو هو ليك إنت بس، ممكن كمان تكتبه لـ zsh بـ `#!/bin/zsh`، بس الـ Syntax بيختلف في حاجات (زي الـ Arrays تحت).
:::

**تشريح الأمر**

```sh
chmod +x hello.sh && ./hello.sh
```

1. `chmod +x hello.sh`: اديله صلاحية التشغيل ([↩ 6.2](../ch06/#s6-2 "chmod: تغيير الصلاحيات")). من غيرها: `Permission denied` (Exit 126).
2. `&&`: لو نجح.
3. `./hello.sh`: شغّله. الـ `./` لازمة لأن المجلد الحالي مش في الـ PATH. وبديلها: `bash hello.sh` (ساعتها مش محتاج x ولا Shebang).

:::tip[ShellCheck]
سطّب `shellcheck` بـ `brew install shellcheck` ([↩ 11.3](../ch11/#s11-3 "brew كل يوم: install و upgrade و info"))، وفيه Extension لـ VS Code بيعلّم على الغلط وإنت بتكتب زي ESLint بالظبط. وشغّله على أي Script: `shellcheck hello.sh`. بيلقط 90% من الغلطات الشائعة (Quotes ناقصة، متغيرات مش متعرفة...) قبل ما تكسر حاجة.
:::

## 12.2 المتغيرات والحساب

في JavaScript بتكتب `let name = "Ahmed"`. في bash الفكرة نفسها، بس فيه قاعدة واحدة هتوقعك أول أسبوع لحد ما تتعود عليها: **ممنوع المسافات** حوالين الـ `=`. خلينا نشوف ليه:

**تشريح الأمر**

```sh
name="Ahmed"; count=3; echo "${name}_backup $((count * 2))"
```

1. `name="Ahmed"`: تعريف متغير: **من غير مسافات** حوالين `=`. لو كتبت `name = "Ahmed"`، الـ Shell هيفهم إنك عايز تشغل أمر اسمه name.
2. `;`: فاصل أوامر ([↩ 7.7](../ch07/#s7-7 "الـ Exit Codes و && و || و ;")).
3. `count=3`: كل حاجة في bash نص؛ الرقم بيتعامل كرقم بس جوه الحساب.
4. `"${name}_backup`: الأقواس `{}` بتحدد اسم المتغير بالظبط؛ من غيرها `$name_backup` هيدوّر على متغير اسمه name\_backup.
5. `$((count * 2))`: Arithmetic expansion: حساب أرقام صحيحة (`+ - * / %`)، وجواها المتغير من غير `$` عادي. النتيجة `Ahmed_backup 6`.

**توسيعات المتغيرات المفيدة**

| الشكل | بيرجع | مثال (f=photo.jpg) |
|---|---|---|
| `${var:-def}` | القيمة، أو def لو فاضي | `${PORT:-8080}` |
| `${var:?msg}` | اقفل الـ Script بالرسالة لو فاضي | `${1:?need a file}` |
| `${#var}` | الطول | `9` |
| `${var%.*}` | شيل أقصر نهاية تطابق | `photo` |
| `${var##*.}` | شيل أطول بداية تطابق | `jpg` |
| `${var/old/new}` | استبدال أول تطابق (و `//` للكل) | `${f/jpg/png}` |
| `${var^^}` / `${var,,}` | كابيتال / سمول (bash 4+، **مش** في bash الماك 3.2) | `PHOTO.JPG` |

طب على الماك بـ bash 3.2، أعمل Uppercase إزاي؟ بأداة خارجية بتشتغل في كل مكان: `upper=$(printf '%s' "$f" | tr '[:lower:]' '[:upper:]')` ([↩ 8.5](../ch08/#s8-5 "tr: بدّل الحروف")). وفي zsh فيه شكل خاص بيه: `${(U)f}` و `${(L)f}`.

**تشريح الأمر**

```sh
read -rp "Your name: " user
```

1. `read`: Builtin: اقرا سطر من stdin وحطه في متغير.
2. `-rp`: `-r` Raw: متفهمش `\` كـ Escape (استخدمها دايماً)، و `-p` Prompt: اطبع السؤال ده الأول. (و `-s` Silent للباسوردات).
3. `"Your name: "`: نص السؤال.
4. `user`: اسم المتغير (من غير `$` وإنت بتعرّفه).

:::note[Arrays]
`files=(a.txt "my file.txt" c.txt)` ثم `"${files[@]}"` = كل العناصر كل واحد Argument، و `${#files[@]}` = العدد، و `${files[0]}` = الأول. (الـ Index بيبدأ من 0 في bash ومن 1 في zsh!، يعني نفس السطر `echo ${files[1]}` بيطبع `my file.txt` في bash و `a.txt` في zsh). الـ Arrays العادية دي شغالة في bash 3.2، أما الـ Associative arrays (زي Object في JS: `declare -A user`) فمحتاجة bash 4+ ([↩ 3.4](../ch03/#s3-4 "ليه الماك ساب bash وراح لـ zsh؟")).
:::

## 12.3 الشروط: test و \[ \] و \[\[ \]\]

هنا أول مكان الـ bash هيستغرب فيه مخك الـ JavaScript. في JS بتكتب `if (size > 100)` والـ `>` عملية مقارنة. في bash `>` معناها Redirection ([↩ 7.2](../ch07/#s7-2 "الـ Redirection: وجّه الـ Streams"))، وهتعمل ملف اسمه 100! السبب إن `if` في bash بتشتغل بطريقة مختلفة خالص من جذورها: `if` مش بتقيّم "صح وغلط" زي اللغات التانية: هي بتشغّل أمر وتشوف الـ **Exit code** (0 = صح، [↩ 7.7](../ch07/#s7-7 "الـ Exit Codes و && و || و ;")). و `[` نفسها **أمر** (اسم تاني لـ `test`)، وعشان كده المسافات حواليها إجبارية.

**تشريح الأمر**

```sh
size=$(stat -f%z "$file"); if [[ -f "$file" && $size -gt 100 ]]; then echo big; fi
```

1. `size=$(stat -f%z "$file")`: حجم الملف بالبايت. `stat -f%z` دي صيغة الماك (BSD)؛ على Linux بتبقى `stat -c%s` ([↩ 2.6](../ch02/#s2-6 "ليه أوامر من النت مبتشتغلش على الماك؟ BSD ضد GNU")). ولو عايز سطر يشتغل في الاتنين: `wc -c < "$file"`.
2. `if`: شغّل اللي بعدي، ولو رجع 0 نفّذ الـ then.
3. `[[`: الـ Test المطوّر في bash/zsh: أأمن من `[` (مش بيعمل Word splitting ولا Glob للمتغيرات، وبيفهم `&&` و `||` و `=~` جواه). مسافة بعده إجباري.
4. `-f "$file"`: الملف موجود وملف عادي.
5. `&&`: AND جوه الـ `[[ ]]`. (في `[ ]` القديمة: `] && [`).
6. `$size -gt 100`: Greater Than: مقارنة **أرقام**.
7. `]]`: النهاية، بمسافة قبلها.
8. `; then`: الـ `;` بدل سطر جديد، و then = نفّذ لو صح.
9. `echo big; fi`: الأمر، و `fi` (if بالمقلوب) = النهاية.

**اختبارات test و \[\[ \]\]**

| الاختبار | صح لو | الاختبار | صح لو |
|---|---|---|---|
| `-e f` | موجود (أي نوع) | `-z "$s"` | النص فاضي (Zero) |
| `-f f` | ملف عادي | `-n "$s"` | النص مش فاضي |
| `-d f` | مجلد | `"$a" == "$b"` | نصين متساويين (`=` في `[`) |
| `-L f` | Symlink | `"$a" != "$b"` | مختلفين |
| `-r` / `-w` / `-x` | تقدر تقرا / تكتب / تشغّل ([↩ 6.1](../ch06/#s6-1 "الفكرة: 3 أسئلة × 3 أنواع ناس")) | `$s =~ ^[0-9]+$` | Regex (في `[[` بس، [↩ 8.1](../ch08/#s8-1 "grep: دوّر على سطور")) |
| `-s f` | موجود وحجمه أكبر من صفر | `-eq -ne` | أرقام: يساوي / لا يساوي |
| `f1 -nt f2` | f1 أحدث (Newer Than) | `-lt -le -gt -ge` | أقل / أقل أو يساوي / أكبر / أكبر أو يساوي |

:::caution[== و -eq مش زي بعض]
`[[ 10 == 010 ]]` غلط (نصوص مختلفة)، و `[[ 10 -eq 010 ]]` صح (أرقام). و `<` و `>` جوه `[[ ]]` مقارنة **أبجدية** مش أرقام، وجوه `[ ]` هتبقى Redirection وهتعمل ملف! للأرقام استخدم `-lt` أو `(( a < b ))`.
:::

**تشريح الأمر**

```sh
case "$1" in start|up) run ;; stop) halt ;; *) echo "usage" ;; esac
```

1. `case "$1" in`: قارن قيمة أول Argument بالأنماط اللي جاية.
2. `start|up)`: نمط (Glob مش Regex) و `|` = أو، و `)` نهاية النمط.
3. `run ;;`: الأوامر، و `;;` = خلصنا الحالة دي.
4. `stop) halt ;;`: حالة تانية.
5. `*)`: أي حاجة تانية (Default).
6. `esac`: case بالمقلوب = النهاية.

## 12.4 اللوبات: for و while

نقلت 200 صورة من الـ iPhone للماك، ولقيتها كلها `.heic`، والموقع اللي عايز ترفع عليه مبيقبلش غير JPG. هتفتح كل صورة في Preview وتعمل Export؟ 200 مرة؟ دي بالظبط وظيفة اللوب، والماك فيه أداة صور جاهزة اسمها `sips`:

**تشريح الأمر**

```sh
for f in *.heic; do sips -s format jpeg "$f" --out "${f%.heic}.jpg"; done
```

1. `for f in`: لكل عنصر في القائمة، حطه في المتغير `f`. (زي `for (const f of files)` في JS).
2. `*.heic`: القائمة: الـ Glob بيتوسع لأسماء الملفات ([↩ 7.4](../ch07/#s7-4 "الـ Globbing: النجمة وأخواتها")). ينفع `{1..10}` أو `"$@"` أو `$(cat list)`. خلي بالك إن الماك مش حساس لحالة الحروف في أسامي الملفات، بس الـ Glob حساس: `*.heic` مش هيلقط `IMG_1.HEIC`؛ اكتب `*.[hH][eE][iI][cC]` أو فعّل `shopt -s nocaseglob`.
3. `; do`: بداية الجسم.
4. `sips -s format jpeg "$f" --out "${f%.heic}.jpg"`: Scriptable Image Processing System: أداة جاية مع الماك. `-s format jpeg` = غيّر الصيغة، و `--out` = احفظ هنا، و `${f%.heic}` = الاسم من غير الامتداد. (على Linux المقابل `convert` أو `magick` من ImageMagick، وموجودة على الماك كمان بـ `brew install imagemagick`).
5. `; done`: النهاية.

**تشريح الأمر**

```sh
while IFS= read -r line; do echo "> $line"; done < urls.txt
```

1. `while`: كرر طول ما الأمر بعدي بيرجع 0.
2. `IFS=`: Internal Field Separator فاضي **للأمر ده بس**: متشيلش المسافات من أول وآخر السطر.
3. `read -r line`: اقرا سطر في `line`. لما الملف يخلص بيرجع 1 فاللوب يقف.
4. `; do echo "> $line"; done`: الجسم.
5. `< urls.txt`: الـ stdin بتاع اللوب كله من الملف ([↩ 7.2](../ch07/#s7-2 "الـ Redirection: وجّه الـ Streams")). ده الطريقة الصح لقراية ملف سطر سطر، مش `for l in $(cat f)` اللي بتقطع على المسافات.

| الأمر | بيعمل إيه |
|---|---|
| `for ((i=1; i<=5; i++)); do …; done` | لوب بعداد على طريقة C. |
| `until ping -c1 -W1000 host &>/dev/null; do sleep 2; done` | `until` = كرر لحد ما ينجح: "استنى لحد ما السيرفر يرد". (`-W1000` = ثانية على الماك بالملي، وعلى Linux `-W1`، [↩ 10.1](../ch10/#s10-1 "التشخيص: ping و ip")). |
| `break / continue` | اخرج من اللوب / روح للّفة الجاية. |

## 12.5 الدوال

الدوال في bash هي نفس فكرة الـ Functions في JS: كود بتكتبه مرة وتنادي عليه كتير. بس فيه 3 فروق هتلاحظها: مفيش Parameters بالاسم (بتوصلها بـ `$1` و `$2`)، والمتغيرات Global افتراضياً (عكس `let`)، و `return` مبترجّعش قيمة. خلينا نعمل دالة `log` هتستخدمها في كل Script بعد كده:

```sh title="Terminal"
log() {
    local level="$1"; shift
    printf '[%s] %s: %s\n' "$(date +%T)" "$level" "$*" >&2
}
log INFO "Backup started"
```

**تشريح الأمر**

```sh
log() { local level="$1"; shift; printf '%s\n' "$*" >&2; }
```

1. `log()`: تعريف دالة اسمها log. الأقواس فاضية دايماً (الـ Arguments مش بتتكتب هنا).
2. `{`: بداية الجسم (مسافة بعدها، و `;` قبل `}` لو على سطر واحد).
3. `local level="$1"`: `local` = المتغير ده جوه الدالة بس، ومن غيرها بيبقى Global ويخبط في باقي الـ Script. و `$1` هنا = أول Argument **للدالة** مش للـ Script.
4. `shift`: زقّ الـ Arguments: الـ `$2` يبقى `$1`... (تحت).
5. `printf '%s\n' "$*"`: اطبع كل الباقي كنص واحد. `printf` أدق وأضمن من `echo` في الـ Scripts.
6. `>&2`: = `1>&2`: ودّي الناتج لـ stderr، عشان رسايل اللوج متتخلطش بالبيانات ([↩ 7.1](../ch07/#s7-1 "الـ Streams التلاتة")).
7. `}`: النهاية.

:::note[return مقابل echo]
`return N` بترجّع **Exit code** بس (0 لـ 255). عشان ترجّع قيمة، اطبعها واستلمها بـ `$()`: `result=$(get_ip)` ([↩ 7.6](../ch07/#s7-6 "الـ Command Substitution: ‎$()‎")).
:::

## 12.6 الـ Arguments: ‎$1 و $@ و $#

لما تكتب `ls -la ~/Downloads`، الـ `-la` و `~/Downloads` دول Arguments بيوصلوا لبرنامج ls. والـ Script بتاعك نفس الكلام: أي حاجة تكتبها بعد اسمه بتوصله في متغيرات جاهزة (زي `process.argv` في Node):

**متغيرات الـ Arguments (لـ `./deploy.sh prod "v 2" -f`)**

| المتغير | القيمة | المعنى |
|---|---|---|
| `$0` | `./deploy.sh` | اسم الـ Script |
| `$1` `$2` `$3` | `prod` و `v 2` و `-f` | كل Argument برقمه (و `${10}` بأقواس بعد 9) |
| `$#` | `3` | العدد |
| `"$@"` | `"prod" "v 2" "-f"` | كلهم، كل واحد لوحده (**ده اللي هتستخدمه**) |
| `"$*"` | `"prod v 2 -f"` | كلهم كنص واحد |

**تشريح الأمر**

```sh
[[ $# -lt 1 ]] && { echo "usage: $0 <env>" >&2; exit 2; }
```

1. `[[ $# -lt 1 ]]`: لو عدد الـ Arguments أقل من 1...
2. `&&`: ...نفّذ اللي بعده.
3. `{ echo "usage: $0 <env>" >&2;`: اطبع طريقة الاستخدام لـ stderr. الـ `<env>` جوه Quotes فمش Redirection.
4. `exit 2; }`: اقفل الـ Script بـ Exit code 2 (استخدام غلط). والـ `{ ;}` بتجمع الأمرين ([↩ 7.7](../ch07/#s7-7 "الـ Exit Codes و && و || و ;")).

:::note[Options زي الأوامر الحقيقية]
عايز الـ Script بتاعك ياخد `-v` و `-o file` زي `ls`؟ استخدم `getopts` Builtin: `while getopts "vo:" opt; do case $opt in v) verbose=1;; o) out=$OPTARG;; esac; done`. الـ `:` بعد o = "بتاخد قيمة" ([↩ 2.2](../ch02/#s2-2 "أنواع الـ Options")).
:::

## 12.7 الوضع الصارم: set -euo pipefail و trap

أغرب حاجة في bash للي جاي من JavaScript: لو أمر فشل في نص الـ Script، bash **بيكمل عادي** على السطر اللي بعده! مفيش Exception بيوقف كل حاجة. تخيل Script بيعمل `cd build` (وفشل لأن الفولدر مش موجود) وبعدين `rm -rf *`. هيمسح الفولدر اللي إنت فيه دلوقتي. السطر الجاي هو "الـ Strict mode" بتاع bash، وبيتكتب في أول أي Script جاد:

**تشريح الأمر**

```sh
set -euo pipefail
```

1. `set`: Builtin بيغير سلوك الـ Shell.
2. `-e`: Errexit: أول أمر يفشل، اقفل الـ Script فوراً بدل ما تكمّل على أساس غلط.
3. `u`: Nounset: لو استخدمت متغير مش متعرّف (غلطة في الاسم)، اعتبره خطأ واقفل. ده بيمنع كارثة `rm -rf "$DIR/"` لما DIR يطلع فاضي ([↩ 15.1](../ch15/#s15-1 "rm -rf: المسح من غير رجعة")). وفخ خاص بالماك: في bash أقدم من 4.4 (يعني 3.2 بتاع الماك)، `"${arr[@]}"` لـ Array **فاضية** بيعتبرها مش متعرّفة ويقفل بـ `unbound variable`. الحل الآمن هناك: `${arr[@]+"${arr[@]}"}`.
4. `o pipefail`: الـ Pipe يعتبر فاشل لو **أي** أمر فيه فشل، مش آخر واحد بس (افتراضياً `false | true` = نجاح!).

:::caution[-e مش سحر]
`set -e` مبيشتغلش جوه شرط `if` أو قبل `&&` و `||`، ومبيقفلش لو الأمر الفاشل جوه `$()` في بعض الحالات. اعتبره شبكة أمان، مش بديل إنك تفحص الأوامر المهمة بنفسك. والأمر اللي متوقع يفشل عادي: `grep x f || true`.
:::

**تشريح الأمر**

```sh
tmp=$(mktemp -d); trap 'rm -rf "$tmp"' EXIT
```

1. `tmp=$(mktemp -d)`: اعمل مجلد مؤقت باسم عشوائي آمن واحفظ مساره (`-d` = Directory).
2. `;`: بعدها.
3. `trap`: Builtin: "لما يحصل الحدث ده، نفّذ الأمر ده".
4. `'rm -rf "$tmp"'`: الأمر، في Single quotes عشان يتفك وقت التنفيذ مش دلوقتي.
5. `EXIT`: الحدث: خروج الـ Script بأي طريقة (نجاح أو فشل أو Ctrl+C). وينفع `INT` و `TERM` ([↩ 9.3](../ch09/#s9-3 "الـ Signals و kill")).

## 12.8 Scripts عملية كاملة

كفاية قطع غيار، خلينا نركّب العربية. أول Script: كل يوم عايز نسخة من فولدر المشروع متضغطة وعليها التاريخ، ومش عايز الـ Backups تاكل الهارد، فنسيب آخر 7 بس. ده كان شغل 10 دقايق يدوي كل يوم، وهيبقى سطر واحد:

```sh title="backup.sh: باك أب بتاريخ ويمسح القديم"
#!/usr/bin/env bash
set -euo pipefail

SRC="${1:?usage: backup.sh <dir> [dest]}"
DEST="${2:-$HOME/backups}"
KEEP=7
stamp=$(date +%F_%H%M)
name="$(basename "$SRC")_$stamp.tar.gz"

mkdir -p "$DEST"
tar -czf "$DEST/$name" -C "$(dirname "$SRC")" "$(basename "$SRC")"
echo "saved: $DEST/$name ($(du -h "$DEST/$name" | cut -f1))"

# keep newest $KEEP only
ls -1t "$DEST"/*.tar.gz | tail -n +$((KEEP + 1)) | while IFS= read -r old; do rm -v -- "$old"; done
```

كل سطر فيه حاجة اتعلمتها: `${1:?}` (فوق)، و `tar -C` ([↩ 10.8](../ch10/#s10-8 "tar: أرشف واضغط"))، و `du -h | cut -f1` ([↩ 8.4](../ch08/#s8-4 "cut: قص الأعمدة"))، و `tail -n +8` = من السطر التامن للآخر، و `while IFS= read -r` ([↩ 12.4](#s12-4 "اللوبات: for و while")). ليه مش `xargs -r rm` زي ما هتلاقي في شروحات Linux؟ لأن الـ `-r` دي GNU بس، و xargs بتاع الماك ممكن يرفضها، واللوب بـ while شغال في الاتنين، ولو مفيش ولا ملف قديم مش بيعمل حاجة ([↩ 8.9](../ch08/#s8-9 "xargs: من سطور لـ Arguments")). والـ `ls -1t` هنا آمن لأن إحنا اللي عاملين الأسماء (من غير مسافات). والـ Script ده كله اتكتب عشان يشتغل على الماك و Linux من غير تعديل: `date +%F` و `tar -czf` و `du -h` نفس الشكل في الاتنين.

**تشريح الأمر**

```sh
days_ago() { date -v-"$1"d +%F 2>/dev/null || date -d "$1 days ago" +%F; }
```

1. `days_ago()`: دالة بترجع تاريخ من N يوم. محتاجينها لأن حساب التواريخ هو أكتر مكان الماك و Linux بيختلفوا فيه ([↩ 2.6](../ch02/#s2-6 "ليه أوامر من النت مبتشتغلش على الماك؟ BSD ضد GNU")).
2. `date -v-"$1"d`: صيغة الماك (BSD): `-v` = Adjust value، و `-7d` = اطرح 7 أيام. وتقدر تجمع: `date -v-1m -v+2d` (شهر لورا ويومين لقدام). وعلى Linux `-v` مش موجودة فهتفشل.
3. `+%F`: الشكل `2026-10-15`، نفسه في الاتنين.
4. `2>/dev/null ||`: لو فشلت (يعني إحنا على Linux)، اخفي رسالة الخطأ وجرّب اللي بعدها ([↩ 7.7](../ch07/#s7-7 "الـ Exit Codes و && و || و ;")).
5. `date -d "$1 days ago"`: صيغة GNU على Linux: `-d` = Date string بالإنجليزي.

**التواريخ والملفات في الـ Scripts: الماك قصاد Linux**

تاني Script: عندك لستة مواقع (موقعك، الـ API، صفحة الـ Docs) وعايز تعرف كلهم شغالين ولا لأ في ثانية:

```sh title="sitecheck.sh: افحص قائمة مواقع"
#!/usr/bin/env bash
set -uo pipefail
fail=0
while IFS= read -r url; do
    [[ -z "$url" || "$url" == \#* ]] && continue
    code=$(curl -s -o /dev/null -m 10 -w '%{http_code}' "$url")
    if [[ "$code" == 2* || "$code" == 3* ]]; then
        printf '%-40s OK  %s\n' "$url" "$code"
    else
        printf '%-40s BAD %s\n' "$url" "$code"; fail=1
    fi
done < "${1:-sites.txt}"
exit "$fail"
```

هنا مستخدمين `-e` لأ عن قصد، عشان موقع واقع ميوقفش الفحص. و `\#*` = سطر بيبدأ بـ # (كومنت)، و `-m 10` = استنى 10 ثواني بالكتير، و `%-40s` = نص بعرض 40 متساوي على الشمال. وفي الآخر الـ Exit code بيقول لو فيه فشل، فينفع تحطه في cron أو CI ([↩ 10.2](../ch10/#s10-2 "curl و wget: كلّم السيرفرات")).

### شغّله أوتوماتيك: launchd (و cron)

الـ Script جاهز، بس لسه إنت اللي بتشغله. الخطوة الأخيرة إنه يشتغل لوحده كل يوم. على الماك الطريقة اللي Apple بتوصي بيها هي LaunchAgent ([↩ 9.5](../ch09/#s9-5 "الخدمات على الماك: launchd و launchctl و brew services")) بمفتاح `StartCalendarInterval`:

```text title="جزء من ~/Library/LaunchAgents/com.ahmed.backup.plist"
<key>ProgramArguments</key>
<array>
  <string>/Users/ahmed/bin/backup.sh</string>
  <string>/Users/ahmed/projects/app</string>
</array>
<key>StartCalendarInterval</key>
<dict>
  <key>Hour</key>   <integer>3</integer>
  <key>Minute</key> <integer>0</integer>
</dict>
<key>StandardOutPath</key>  <string>/Users/ahmed/backup.log</string>
<key>StandardErrorPath</key><string>/Users/ahmed/backup.log</string>
```

الميزة الكبيرة على cron: لو الماك كان نايم أو مقفول الساعة 3، launchd بيشغّل الـ Script أول ما يصحى، و cron كان هيفوّتها خالص. (كمّل الملف بـ `Label` زي المثال في فصل العمليات، وسجّله بـ `launchctl bootstrap gui/$(id -u) ...`).

:::note[cron: على السيرفر (وشغال على الماك كمان)]
`crontab -e` وضيف سطر: `0 3 * * * /home/ahmed/bin/backup.sh /home/ahmed/docs >> /home/ahmed/backup.log 2>&1`. الخمس خانات: دقيقة، ساعة، يوم الشهر، الشهر، يوم الأسبوع (0 = الأحد). يعني كل يوم الساعة 3 الفجر. استخدم مسارات مطلقة لأن cron بيشتغل بـ PATH صغير جداً ([↩ 13.5](../ch13/#s13-5 "الـ PATH: ضيف مجلد صح")). وعلى الأنظمة اللي فيها systemd فيه بديل اسمه systemd timers. و cron لسه شغال على الماك بنفس الشكل (بمسارات `/Users/...`)، بس عشان يوصل لفولدرات زي Documents و Desktop لازم تدي `/usr/sbin/cron` صلاحية **Full Disk Access** ([↩ 6.8](../ch06/#s6-8 "SIP و Full Disk Access: حتى root ليه حدود"))، وده من أسباب إن launchd أريح.
:::

## 12.9 مشاكل شائعة

:::danger[مشكلة: bad interpreter: /bin/bash^M]
الملف اتكتب على Windows (أو زميلك بعتهولك منه) ونهاية كل سطر فيها `\r\n` بدل `\n`.

<strong>الحل:</strong> على الماك: `sed -i '' $'s/\r$//' script.sh`، والـ `$'...'` لازمة لأن sed بتاع الماك مبيفهمش `\r` لوحده، فالـ Shell هو اللي بيحولها. على Linux: `sed -i 's/\r$//' script.sh`. أو `brew install dos2unix`. وظبط VS Code على LF من الشريط اللي تحت ([↩ 8.5](../ch08/#s8-5 "tr: بدّل الحروف")).
:::

:::danger[مشكلة: declare: -A: invalid option أو bad substitution]
الـ Script شغال على السيرفر، ولما شغلته على الماك وقع عند `declare -A` أو `${var,,}` أو `mapfile`.

<strong>الحل:</strong> دي مميزات bash 4+ والماك بيشغّل 3.2. يا إما `brew install bash` واستخدم `#!/usr/bin/env bash` (مش `#!/bin/bash`)، يا إما اكتبها بطريقة 3.2 ([↩ 3.4](../ch03/#s3-4 "ليه الماك ساب bash وراح لـ zsh؟")).
:::

:::danger[مشكلة: date: illegal option -- d]
نسخت سطر `date -d yesterday` من شرح على النت والماك رفضه.

<strong>الحل:</strong> على الماك `date -v-1d`، أو استخدم دالة `days_ago` اللي فوق عشان تشتغل في الاتنين، أو `brew install coreutils` واستخدم `gdate -d yesterday`.
:::

:::danger[مشكلة: [: too many arguments]
كتبت `[ $name == "Ahmed Ali" ]` والمتغير فيه مسافة فاتقسم لكلمتين.

<strong>الحل:</strong> `"$name"` بالـ Quotes، أو استخدم `[[ ]]` ([↩ 7.5](../ch07/#s7-5 "الـ Quoting: إمتى الـ Shell يفهم الرموز وإمتى لأ")).
:::

:::tip[ملخص الفصل]
- `#!/usr/bin/env bash` + `chmod +x` + `./script`.
- `var=value` من غير مسافات، و `"$var"` و `${var:-default}` و `$(( ))`.
- `if` بتشوف الـ Exit code، و `[[ ]]` أأمن، و `-eq` للأرقام و `==` للنصوص.
- `for f in *` و `while IFS= read -r line; done < file`.
- الدوال بـ `local`، و `"$@"` لكل الـ Arguments، و `$#` عددهم.
- `set -euo pipefail` و `trap ... EXIT` و shellcheck.
- على الماك: `#!/usr/bin/env bash`، وخلي بالك من bash 3.2 (مفيش `declare -A` ولا `${v,,}`)، و `date -v` و `stat -f` و `sed -i ''`. واجدول بـ LaunchAgent أو cron.
:::

### صح ولا غلط؟

1. `name = "Ali"` طريقة صحيحة لتعريف متغير.
2. `[` أمر حقيقي وعشان كده محتاج مسافات حواليه.
3. `return` في bash ممكن ترجّع نص.
4. من غير `pipefail`، فشل أول أمر في Pipe مش بيأثر على الـ Exit code.

### أسئلة مراجعة

1. إيه الفرق بين `"$@"` و `"$*"`؟
2. اكتب شرط يتأكد إن أول Argument مجلد موجود، ولو لأ يقفل بـ Exit code 1.
3. ليه `for line in $(cat file)` غلط؟ وإيه البديل؟
4. اشرح كل حرف في `set -euo pipefail`.
5. إمتى تستخدم `trap`؟
6. اكتب سطر بيطبع تاريخ امبارح ويشتغل على الماك و Linux.

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** Script بياخد اسم ويطبع "أهلاً يا NAME"، ولو مفيش اسم يسأل بـ read.
2. **[متوسط]** Script بيرتب ملفات مجلد `~/Downloads` في مجلدات حسب الامتداد (pdf و jpg و zip و dmg...). جرّبه الأول على نسخة في `/tmp`.
3. **[صعب]** Script فيه Options بـ getopts: `-n` Dry run و `-d dir`، بيمسح الملفات الأقدم من 30 يوم في المجلد، ويطبع الإجمالي.
