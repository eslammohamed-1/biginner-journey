<small>المرحلة 4 · النظام والشبكة</small>

قاعد في كافيه، والماك واصل بالـ Wi-Fi، وعلامة النت مليانة، بس الموقع اللي شغال عليه مش بيفتح. تعمل Refresh عشر مرات. تقفل الـ Wi-Fi وتفتحه. ولا حاجة. طب المشكلة فين؟ في الكافيه؟ في الـ DNS؟ في السيرفر؟ في البورت؟ المحترفين مبيخمنوش، بيمشوا بالترتيب ويسألوا كل طبقة سؤال. والفصل ده هيعلمك الترتيب ده، وبعدين هياخدك للخطوة اللي هتعملها قريب جداً كمطوّر: إنك تأجر أول سيرفر (VPS) وتدخل عليه من الماك بـ ssh بالمفاتيح، وتنقل ملفاتك بـ scp و rsync و tar، وتعرف مين فاتح أنهي بورت بـ lsof.

:::note[بعد الفصل ده هتكون عارف]
- ping و ifconfig و networksetup لتشخيص الاتصال على الماك
- curl و wget وكل Flags بتاعتهم المهمة
- DNS بـ dig و scutil و dscacheutil، و mDNS والـ .local
- ssh بالمفاتيح (Ed25519) وملف ~/.ssh/config والـ Keychain
- نقل الملفات بـ scp و rsync (و openrsync بتاع الماك) و tar
- البورتات و lsof على الماك (و ss على Linux)
:::

:::note[كلمات هتقابلها في الفصل ده (والشرح الكامل في كتاب الإنترنت)]
الفصل ده بيستخدم كلمات شبكات ممكن تكون أول مرة تسمعها، فخد معناها في سطر، والحكاية كاملة في **كتاب الإنترنت والويب و DevTools** (الكتاب 03):

- **IP**: رقم عنوان الجهاز على الشبكة، زي `192.168.1.23` (كتاب الإنترنت فصل 3).
- **Port**: رقم "الباب" اللي البرنامج بيسمع عليه جوه الجهاز، زي `3000` أو `443`. الـ IP = العمارة، والـ Port = رقم الشقة.
- **DNS**: اللي بيحوّل `google.com` لـ IP (فصل 5 هناك).
- **Request / Response**: إنت بتبعت طلب فيه **Method** (زي GET = هات، POST = خد) و **Headers** (معلومات على الظرف) و **Body** (المحتوى)، والسيرفر يرد برقم اسمه **Status code** (200 = تمام، 404 = مش موجود، 500 = السيرفر وقع). فصول 7 لـ 9 هناك.
- **TLS / HTTPS**: التشفير اللي بيحمي الكلام (فصل 12 هناك). و **Token**: "كارنيه" نصي بيثبت إنت مين، وبيتبعت في Header اسمه Authorization.
- **JSON**: شكل نصي للبيانات شبه الـ Object في JavaScript: `{"name": "Ali", "age": 30}`.

مش لازم تفهمهم 100% دلوقتي. نفّذ الأوامر، ولما تخلص كتاب الإنترنت ارجع للفصل ده، هتلاقيه بقى سهل جداً.
:::

## 10.1 التشخيص: ping و ip

خلينا نرجع للكافيه. الدكتور الشاطر مبيقولش "إنت عيان" وخلاص، بيكشف بالترتيب: الحرارة، الضغط، النبض. والشبكة نفس الكلام، فيه "سلم" وبتطلعه درجة درجة، وأول درجة تفشل هي مكان المشكلة:

1. <strong>عندي IP أصلاً؟</strong> (الماك واخد عنوان من راوتر الكافيه؟)
2. <strong>أوصل للراوتر؟</strong>
3. <strong>أوصل للنت؟</strong> (`ping 8.8.8.8`)
4. <strong>الـ DNS شغال؟</strong> (الاسم بيتحول لـ IP؟)
5. <strong>السيرفر بيسمع على البورت؟</strong> (`curl`)

أول أداة على السلم هي `ping`: زي ما تنادي على حد في أوضة تانية "إنت هناك؟" وتستنى يرد، وتقيس هو رد في قد إيه:

**تشريح الأمر**

```sh
ping -c 4 -W 2000 8.8.8.8
```

1. `ping`: ابعت رسايل ICMP صغيرة واستنى الرد، وقيس الوقت.
2. `-c 4`: Count: 4 مرات بس. على الماك و Linux من غيرها بيفضل شغال لحد `Ctrl+C` (على Windows بيبعت 4 افتراضياً).
3. `-W 2000`: Wait: استنى الرد لكل رسالة 2000 **ملي ثانية** (ثانيتين) بالكتير. خلي بالك: على الماك الرقم بالملي ثانية، وعلى Linux بالثواني (`-W 2`). لو كتبت `-W 2` على الماك هيستنى 2 ملي ثانية بس وكل حاجة هتبان فاشلة! ولو عايز حد أقصى للأمر كله: `-t 5` (ثواني).
4. `8.8.8.8`: الهدف (IP أو اسم). لو IP شغال والاسم لأ، المشكلة في الـ DNS.

طب الدرجتين الأولانيين؟ "عندي IP؟" و"الراوتر فين؟". على الماك كل كارت شبكة ليه اسم قصير: الـ Wi-Fi غالباً `en0`، والـ Ethernet أو الـ Adapter `en1` أو أكتر، و `lo0` هو الماك بيكلم نفسه (`127.0.0.1`). وعشان تتأكد مين مين:

**تشريح الأمر**

```sh
networksetup -listallhardwareports
```

1. `networksetup`: أداة الماك الرسمية لإعدادات الشبكة من الـ Terminal (هي نفسها اللي ورا System Settings ← Network). كتير من أوامرها محتاجة sudo لو هتغيّر حاجة.
2. `-listallhardwareports`: اعرض كل كروت الشبكة: الاسم اللي إنت تعرفه (Wi-Fi) قصاد اسم الجهاز (`en0`) والـ MAC address.

```sh title="Terminal"
$ networksetup -listallhardwareports
Hardware Port: Wi-Fi
Device: en0
Ethernet Address: a4:83:e7:12:34:56

$ ipconfig getifaddr en0
192.168.1.23
```

| الأمر | بيعمل إيه |
|---|---|
| `ipconfig getifaddr en0` | الـ IP بتاعي على الـ Wi-Fi، سطر واحد ومن غير زحمة. (مش `ipconfig` بتاع Windows، نفس الاسم بس أداة تانية). |
| `ifconfig en0` | كل تفاصيل الكارت: `inet` = IPv4، و `inet6` = IPv6، و `status: active`. على الماك ifconfig لسه هي الأداة الأساسية. |
| `route -n get default` | الـ Default gateway (الراوتر) فين: سطر `gateway: 192.168.1.1`. و `netstat -rn` بيعرض جدول الـ Routing كله. |
| `networksetup -getinfo Wi-Fi` | الـ IP والـ Router والـ Subnet بتوع الـ Wi-Fi، وهل جايين من DHCP ولا يدوي. |
| `traceroute google.com` | الطريق خطوة خطوة لحد السيرفر (أو `mtr` لايف بعد `brew install mtr`، و `tracert` على Windows). |
| `networkQuality` | Speed test رسمي من Apple جوه الـ Terminal: سرعة الرفع والتنزيل والـ Responsiveness. (بالـ Q كبيرة). |

:::note[على Linux: الأداة اسمها ip]
على أغلب السيرفرات الحديثة `ifconfig` مش متسطبة أصلاً، وبدلها `ip`:

| الأمر | بيعمل إيه |
|---|---|
| `ip -br addr` | عناويني إيه؟ `-br` = Brief: سطر لكل كارت. (بديل `ifconfig` القديم). أسامي الكروت هناك زي `eth0` أو `ens3`. |
| `ip route` | الـ Default gateway (الراوتر) فين: السطر اللي بيبدأ بـ `default via`. |
:::

:::note[ping مش دليل]
سيرفرات كتير بتقفل ICMP، فممكن ping يفشل والموقع شغال عادي. الاختبار الأدق للخدمة نفسها هو `curl` للبورت (تحت).
:::

## 10.2 curl و wget: كلّم السيرفرات

إنت كمطوّر JavaScript أكيد كتبت `fetch("https://api.example.com/users")` قبل كده. طب لو الـ API مش راجع البيانات اللي متوقعها، المشكلة في الكود بتاعك ولا في السيرفر نفسه؟ أسرع طريقة تعرف: تسأل السيرفر بنفسك، من غير متصفح ولا كود. وده `curl`: هو حرفياً `fetch` بس من الـ Terminal، وجاي جاهز مع الماك. وكل Flag فيه بيقابل حاجة إنت عارفها: `-X` هي الـ `method`، و `-H` هي الـ `headers`، و `-d` هي الـ `body`.

وهتشوف curl كمان في كل صفحة "Install" تقريباً، زي سطر تثبيت Homebrew نفسه ([↩ 11.3](../ch11/#s11-3 "brew كل يوم: install و upgrade و info")). فخلينا نفهم الشكل المشهور ده حرف حرف:

**تشريح الأمر**

```sh
curl -fsSL -o get.sh https://example.com/install.sh
```

1. `curl`: Client URL: ابعت طلب لـ URL واطبع الرد على stdout. بيدعم HTTP و HTTPS و FTP وغيرهم.
2. `-fsSL`: أربعة مدموجين ومشهورين جداً: `-f` Fail (لو السيرفر رجع 404 أو 500 افشل بـ Exit code بدل ما تطبع صفحة الخطأ)، و `-s` Silent (من غير شريط التقدم)، و `-S` Show error (بس اطبع الأخطاء رغم -s)، و `-L` Location (اتبع الـ Redirects).
3. `-o get.sh`: Output: احفظ في الملف ده بدل الشاشة. (و `-O` كبيرة = احفظ بنفس اسم الملف اللي في الـ URL).
4. `https://example.com/install.sh`: الـ URL. لو فيه `&` أو `?` حطه في Quotes ([↩ 7.5](../ch07/#s7-5 "الـ Quoting: إمتى الـ Shell يفهم الرموز وإمتى لأ")).

**أهم Flags بتاعة curl**

| Flag | المعنى | مثال |
|---|---|---|
| `-I` | Head: الـ Headers بس | `curl -I https://site.com` |
| `-i` | Include: الـ Headers + الـ Body |   |
| `-v` | Verbose: كل تفاصيل الاتصال (TLS و Headers) | للتشخيص |
| `-X POST` | الـ Method | `-X DELETE` |
| `-H "..."` | Header | `-H "Authorization: Bearer $TOKEN"` |
| `-d '...'` | Data: Body (وبيخلي الطلب POST تلقائياً) | `-d 'name=ali'` |
| `--json '...'` | JSON body + الـ Headers المناسبة (curl 7.82+) | `--json '{"a":1}'` |
| `-u user:pass` | Basic auth |   |
| `-k` | تجاهل أخطاء الشهادة (للتجربة بس!) |   |
| `-w '%{http_code}'` | اطبع معلومة بعد الطلب | تحت |
| `-C -` | كمّل تحميل اتقطع |   |

**تشريح الأمر**

```sh
curl -s -o /dev/null -w '%{http_code}\n' https://example.com
```

1. `curl -s`: من غير شريط تقدم.
2. `-o /dev/null`: ارمي الـ Body في الثقب الأسود ([↩ 7.1](../ch07/#s7-1 "الـ Streams التلاتة")).
3. `-w '%{http_code}\n'`: Write-out: اطبع الـ Status code بس وسطر جديد. أسرع فحص "الموقع شغال؟".
4. `https://example.com`: الـ URL.

**تشريح الأمر**

```sh
wget -c -O ubuntu.iso https://releases.ubuntu.com/ubuntu.iso
```

1. `wget`: Web get: متخصص في التحميل (curl متخصص في الطلبات). مش جاي مع الماك: `brew install wget`. ولو مش عايز تسطبه، `curl -C - -L -o ubuntu.iso URL` بيعمل نفس الشغلانة.
2. `-c`: Continue: كمّل التحميل من مكان ما وقف.
3. `-O ubuntu.iso`: اسم الملف. خد بالك: `-O` الكبيرة في wget = اسم ملف تختاره، وفي curl = استخدم اسم الـ URL. نفس الحرف بمعنيين!
4. `https://...`: الـ URL (هنا مسار توضيحي).

:::tip[-o و -O و -v بين الأوامر]
`-o` = Output في curl و sort (`sort -o`) و gcc، و `-v` = Verbose في curl و ssh و rsync و cp، و `-q` = Quiet في wget و grep و apt. ولما تشوف Flag مش فاهمه في سكربت حد، `man curl` ثم `/` واكتب الـ Flag ([↩ 2.4](../ch02/#s2-4 "إزاي تجيب المساعدة لأي أمر")).
:::

## 10.3 الـ DNS: dig و nslookup

الكمبيوترات بتكلم بعض بالأرقام (`142.250.185.78`)، وإحنا بنحفظ أسامي (`google.com`). اللي بيترجم بينهم هو الـ **DNS**: دليل التليفونات بتاع النت. ولما الـ DNS يقع، النت يبان "واقع" رغم إنه شغال تمام؛ `ping 8.8.8.8` شغال، بس `ping google.com` بيقولك `cannot resolve`. وده أشهر سبب لمشكلة الكافيه بتاعتنا.

**تشريح الأمر**

```sh
dig +short MX gmail.com @1.1.1.1
```

1. `dig`: Domain Information Groper: اسأل الـ DNS. جاي مع الماك. (على Debian/Ubuntu في حزمة `dnsutils` أو `bind9-dnsutils`).
2. `+short`: الـ Options بتاعة dig بتبدأ بـ `+` مش `-`! معناها: الإجابة بس من غير التفاصيل.
3. `MX`: نوع السجل: `A` (IPv4، الافتراضي)، و `AAAA` (IPv6)، و `MX` (إيميل)، و `CNAME` (اسم مستعار)، و `TXT`، و `NS`.
4. `gmail.com`: الدومين.
5. `@1.1.1.1`: اسأل الـ DNS server ده بالذات بدل الافتراضي. لو الإجابة اختلفت، يبقى الـ DNS عندك هو المشكلة.

| الأمر | بيعمل إيه |
|---|---|
| `nslookup example.com` | أبسط وموجود على Windows و macOS و Linux. |
| `dscacheutil -q host -a name example.com` | بيحل الاسم زي ما البرامج على الماك بتحله فعلاً (بيقرا `/etc/hosts` والـ Cache كمان). `dig` بيسأل الـ DNS server على طول ومبيبصش على `/etc/hosts`، فممكن الاتنين يختلفوا! |
| `scutil --dns \| grep nameserver` | الـ DNS servers اللي الماك بيستخدمها فعلاً دلوقتي (اللي جاية من الراوتر أو من الـ VPN). |
| `networksetup -setdnsservers Wi-Fi 1.1.1.1 8.8.8.8` | غيّر الـ DNS بتاع الـ Wi-Fi (و `Empty` مكان الأرقام = رجّع الافتراضي). ممكن يطلب باسورد الأدمن. |
| `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder` | امسح الـ DNS cache. محتاجها لما تغيّر سجل DNS لموقعك والماك لسه فاكر القديم ([↩ 6.6](../ch06/#s6-6 "sudo و su")). |

:::note[الأسامي اللي بتنتهي بـ .local]
عندك ماك تاني أو طابعة على نفس الشبكة؟ مش محتاج تعرف الـ IP: `ping ahmeds-macbook.local`. ده اسمه **mDNS** (أو Bonjour): الأجهزة على نفس الشبكة بتعلن عن نفسها بأساميها من غير DNS server. اسم الماك بتاعك تشوفه بـ `scutil --get LocalHostName`، وتتفرج على الخدمات المعلنة حواليك بـ `dns-sd -B _ssh._tcp` (<kbd>Ctrl+C</kbd> للخروج). وده نفس اللي بيخلي AirDrop و AirPlay يلاقوا الأجهزة.
:::

:::note[على Linux: getent و resolvectl]
| الأمر | بيعمل إيه |
|---|---|
| `getent hosts example.com` | بيحل الاسم زي ما البرامج بتحله فعلاً (بيقرا `/etc/hosts` كمان). المقابل لـ dscacheutil. |
| `resolvectl status` | الـ DNS servers اللي الجهاز بيستخدمها (systemd-resolved). المقابل لـ `scutil --dns`. |
:::

## 10.4 ssh: ادخل على سيرفر بعيد

جه اليوم الكبير: خلّصت مشروع Node وعايز تنزله على النت. أجّرت VPS صغير بـ 5 دولار في الشهر من DigitalOcean أو Hetzner، وجالك إيميل فيه حاجتين: IP زي `203.0.113.10` واسم مستخدم. مفيش شاشة، مفيش ماوس، مفيش Finder. السيرفر ده جهاز في Data center في بلد تانية، والطريقة الوحيدة إنك تكلمه هي إنك تفتح Terminal على الماك وتعمل `ssh`. ساعتها الـ Terminal بتاعك يبقى "شباك" على جهاز تاني خالص: كل أمر تكتبه بيتنفذ هناك.

والحلو إن `ssh` جاي مع الماك، وكل اللي جاي في الجزء ده بيشتغل بنفس الشكل على الماك و Linux لأنه نفس البرنامج (OpenSSH):

**تشريح الأمر**

```sh
ssh -p 2222 -i ~/.ssh/id_ed25519 deploy@203.0.113.10
```

1. `ssh`: Secure SHell: افتح Shell على جهاز تاني، والاتصال كله متشفر.
2. `-p 2222`: Port: البورت (الافتراضي 22). وخد بالك إن scp بيستخدم `-P` كبيرة لنفس الحاجة!
3. `-i ~/.ssh/id_ed25519`: Identity: المفتاح الخاص اللي هتدخل بيه (لو مش الافتراضي).
4. `deploy@203.0.113.10`: `user@host`: المستخدم على السيرفر، والسيرفر (IP أو اسم). من غير `user@` بيستخدم اسمك المحلي.

```sh title="Terminal"
$ ssh deploy@203.0.113.10 'df -h /'
Filesystem  Size  Used Avail Use% Mounted on
/dev/sda1    40G   18G   20G  48% /
```

لو حطيت أمر بعد العنوان، ssh بينفذه هناك ويرجعلك الناتج ويقفل. والـ Quotes بتحدد إن الـ `df -h /` يتنفذ **هناك** مش عندك. ولاحظ إن الناتج شكل Linux (`/dev/sda1`) مش شكل الماك، لأن الأمر اتنفذ على السيرفر.

طب كل مرة هتكتب باسورد؟ لأ. الباسوردات بتتسرق وبتتخمن، وفيه بوتات على النت بتجرب آلاف الباسوردات على أي سيرفر جديد في أول ساعة. الحل اللي المحترفين بيستخدموه: **المفاتيح**. تخيلها كده: إنت بتعمل "قفل" و"مفتاح" مع بعض. القفل (المفتاح العام `.pub`) بتركّبه على باب كل سيرفر عايز تدخله، وتوزعه براحتك. والمفتاح (الخاص) بيفضل في جيبك، على الماك بتاعك بس، ومحدش يشوفه أبداً.

### المفاتيح: ادخل من غير باسورد (وبأمان أكتر)

**تشريح الأمر**

```sh
ssh-keygen -t ed25519 -C "ahmed@laptop"
```

1. `ssh-keygen`: اعمل زوج مفاتيح: خاص (يفضل عندك ومحدش يشوفه) وعام (`.pub`، بيتحط على السيرفرات).
2. `-t ed25519`: Type: نوع Ed25519 (حديث وصغير وسريع). من OpenSSH 9.5 هو الافتراضي أصلاً، بس كتابته بتضمن النوع على النسخ الأقدم.
3. `-C "ahmed@laptop"`: Comment: تعليق في آخر المفتاح العام عشان تعرف بتاع مين. هيسألك على مكان الحفظ (Enter = `~/.ssh/id_ed25519`) و Passphrase (حط واحدة!).

**تشريح الأمر**

```sh
ssh-copy-id -i ~/.ssh/id_ed25519.pub deploy@203.0.113.10
```

1. `ssh-copy-id`: انسخ المفتاح العام لملف `~/.ssh/authorized_keys` على السيرفر وظبط صلاحياته ([↩ 6.2](../ch06/#s6-2 "chmod: تغيير الصلاحيات")). موجود على نسخ الماك الحديثة؛ لو مش لاقيه: `brew install ssh-copy-id`، أو انسخ محتوى الـ `.pub` يدوي (`pbcopy < ~/.ssh/id_ed25519.pub` وتلزقه في لوحة تحكم السيرفر).
2. `-i ~/.ssh/id_ed25519.pub`: المفتاح العام (`.pub`) اللي هيتنسخ.
3. `deploy@203.0.113.10`: السيرفر، وهيطلب الباسورد آخر مرة.

:::caution[المفتاح الخاص = مفتاح الشقة]
عمرك ما تبعت `id_ed25519` (من غير .pub) لحد ولا ترفعه على GitHub. وصلاحياته `600` والمجلد `700` وإلا ssh هيرفضه ([↩ 6.2](../ch06/#s6-2 "chmod: تغيير الصلاحيات")).
:::

**تشريح الأمر**

```sh
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```

1. `ssh-add`: حمّل المفتاح في الـ **ssh-agent** (برنامج صغير شغال في الخلفية بيفتكر المفاتيح المفتوحة)، عشان متكتبش الـ Passphrase مع كل اتصال.
2. `--apple-use-keychain`: ميزة خاصة بالماك: احفظ الـ Passphrase في الـ **Keychain** (نفس المكان اللي Safari بيحفظ فيه الباسوردات)، فتكتبها مرة واحدة في عمرك. (في نسخ قديمة كانت `-K`).
3. `~/.ssh/id_ed25519`: المفتاح الخاص.

<a id="s10-5"></a>

## 10.5 ملف ~/.ssh/config: اختصر كل ده

```text title="~/.ssh/config"
Host prod
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Host *
    ServerAliveInterval 60
    AddKeysToAgent yes
    UseKeychain yes
```

ملف `~/.ssh/config` ده "دفتر العناوين" بتاعك: بدل ما تحفظ IP وبورت واسم مستخدم ومكان مفتاح لكل سيرفر، تديله اسم قصير. وبعد كده `ssh prod` = الأمر الطويل كله. والسطرين الأخيرين خاصين بالماك: حمّل المفاتيح في الـ Agent تلقائياً، وخد الـ Passphrase من الـ Keychain. وكمان `scp` و `rsync` و `git` بيفهموا `prod` نفس الاسم.

**مفاتيح ~/.ssh/config**

| المفتاح | بيساوي |
|---|---|
| `Host prod` | الاسم المختصر اللي هتكتبه (و `*` = كل السيرفرات) |
| `HostName` | العنوان الحقيقي |
| `User` / `Port` / `IdentityFile` | `user@` و `-p` و `-i` |
| `ProxyJump bastion` | `-J`: ادخل عن طريق سيرفر وسيط |
| `LocalForward 5433 localhost:5432` | `-L`: افتح بورت عندك يوصل لبورت هناك |
| `ServerAliveInterval 60` | ابعت نبضة كل دقيقة عشان الاتصال ميقطعش |
| `UseKeychain yes` | على الماك بس: خد الـ Passphrase من الـ Keychain (على Linux السطر ده بيعمل Error، فلو بتنقل الملف لسيرفر حط قبله `IgnoreUnknown UseKeychain`) |

**تشريح الأمر**

```sh
ssh -N -L 5433:localhost:5432 prod
```

1. `ssh`: اتصل.
2. `-N`: No command: متفتحش Shell، أنا عايز النفق بس.
3. `-L 5433:localhost:5432`: Local forward: `بورتي:العنوان_من_ناحية_السيرفر:بورته`. أي حاجة توصل لـ localhost:5433 عندك تعدي في النفق المتشفر لـ PostgreSQL على السيرفر.
4. `prod`: الاسم من ملف الـ config.

<a id="s10-6"></a>

## 10.6 scp: انسخ من وإلى السيرفر

دخلت السيرفر. تمام. بس الكود لسه على الماك بتاعك. محتاج تنقله. الـ Finder مش هيساعدك هنا، ومفيش Drag & Drop لسيرفر في بلد تانية. هنا بييجي دور `scp`: هو `cp` اللي إنت عارفه، بس عرف يسافر:

**تشريح الأمر**

```sh
scp -P 2222 -r ./site deploy@203.0.113.10:/var/www/
```

1. `scp`: Secure CoPy: زي `cp` بالظبط بس أحد الطرفين (أو الاتنين) على جهاز تاني ([↩ 5.4](../ch05/#s5-4 "النسخ والنقل والمسح: cp و mv و rm")).
2. `-P 2222`: البورت، بـ **P كبيرة** (عشان `-p` الصغيرة في scp = Preserve التواريخ زي cp).
3. `-r`: Recursive: مجلد بكل اللي فيه، نفس `cp -r`.
4. `./site`: المصدر المحلي.
5. `deploy@203.0.113.10:/var/www/`: الوجهة: `user@host:path`. الـ <strong>:</strong> هي اللي بتقول "ده على جهاز تاني". من غير مسار بعدها = الـ home هناك. وعشان تنزّل من السيرفر اعكس الترتيب.

:::note[scp من جوه]
من OpenSSH 9.0، الأمر `scp` بيستخدم بروتوكول SFTP من جوه بدل البروتوكول القديم (والـ `-O` بترجّع القديم لو سيرفر قديم). الاستخدام زي ما هو، بس للنسخ الكبير والمتكرر `rsync` أحسن.
:::

<a id="s10-7"></a>

## 10.7 rsync: المزامنة الذكية

تخيل إن عندك 2000 ملف على السيرفر، وغيرت سطر واحد في ملف واحد. scp هينقل الـ 2000 تاني كل مرة. ده زي ما تنقل عفش الشقة كله كل ما تشتري كرسي جديد. `rsync` أذكى: بيقارن الطرفين وينقل **الفرق بس**:

**تشريح الأمر**

```sh
rsync -avzP --delete --dry-run ./site/ prod:/var/www/site/
```

1. `rsync`: Remote sync: بينقل **الفرق بس**. أول مرة بينسخ كله، والمرات الجاية الملفات اللي اتغيرت بس.
2. `-avzP`: `-a` Archive (= `-rlptgoD`: Recursive و Links و Permissions و Times و Group و Owner و Devices؛ يعني نسخة طبق الأصل)، و `-v` Verbose، و `-z` اضغط في الطريق، و `-P` = `--partial --progress` (شريط تقدم ويكمل لو اتقطع).
3. `--delete`: امسح من الوجهة أي حاجة اتمسحت من المصدر (مرآة كاملة). خطيرة لو المسار غلط!
4. `--dry-run`: (= `-n`) جرّب: اعرض اللي هيحصل من غير ما تعمل حاجة. شيلها لما تتأكد.
5. `./site/`: المصدر. **الـ / في الآخر مهمة**: `site/` = "محتويات site"، و `site` = "المجلد site نفسه" (هيبقى `/var/www/site/site`).
6. `prod:/var/www/site/`: الوجهة على السيرفر باسم الـ config (rsync بيستخدم ssh تلقائياً).

المقارنة بين cp و mv و rsync في [↩ 5.4](../ch05/#s5-4 "النسخ والنقل والمسح: cp و mv و rm"). وبورت مختلف مع rsync: `-e "ssh -p 2222"` (أو حطه في الـ config وخلاص).

:::caution[الـ rsync اللي جاي مع الماك مش rsync!]
لسنين طويلة Apple كانت شايلة rsync نسخة `2.6.9` من سنة 2006 (لنفس سبب bash 3.2: رخصة GPLv3، [↩ 3.4](../ch03/#s3-4 "ليه الماك ساب bash وراح لـ zsh؟")). ومن macOS 15.4 الأمر `/usr/bin/rsync` بقى في الحقيقة **openrsync**، نسخة بترخيص BSD بتدعم جزء بس من الـ Options. جرّب `rsync --version`: هيقولك `openrsync: protocol version 29`. الأوامر اللي في الكتاب ده شغالة عليه، بس لو سكربت من النت فيه Option غريب وقالك `unrecognized option`، سطّب الأصلي: `brew install rsync`. والـ Homebrew بيحطه في `/opt/homebrew/bin` قبل `/usr/bin` في الـ PATH، فيكسب ([↩ 13.5](../ch13/#s13-5 "الـ PATH: ضيف مجلد صح")).
:::

<a id="s10-8"></a>

## 10.8 tar: أرشف واضغط

إنت عارف الـ Zip: كليك يمين في الـ Finder ← Compress. طب ليه كل حاجة على السيرفرات وفي GitHub Releases بتبقى `.tar.gz`؟ لأن `tar` أقدم من الـ Zip، وبيحافظ على الصلاحيات والـ Owners والـ Links (اللي اتكلمنا عنهم في [↩ 6.2](../ch06/#s6-2 "chmod: تغيير الصلاحيات")) وده مهم جداً على السيرفر. الفكرة على مرحلتين: tar بيلم الملفات في "شنطة" واحدة، و gzip بيضغط الشنطة:

**تشريح الأمر**

```sh
tar -czvf backup.tar.gz --exclude="node_modules" project/
```

1. `tar`: Tape ARchive: اجمع ملفات كتير في ملف واحد.
2. `-czvf`: `-c` Create: اعمل أرشيف، و `-z` اضغطه بـ gzip، و `-v` Verbose (اعرض الأسماء)، و `-f` File: اسم الأرشيف **جاي بعدها على طول**، فلازم `f` تبقى آخر حرف.
3. `backup.tar.gz`: اسم الأرشيف (Argument بتاع `-f`).
4. `--exclude="node_modules"`: متدخلش ده.
5. `project/`: اللي هيتأرشف.

**حروف tar**

| الحرف | المعنى |
|---|---|
| `c` / `x` / `t` | Create / eXtract / lisT (اعرض من غير فك) |
| `z` / `j` / `J` | gzip `.gz` / bzip2 `.bz2` / xz `.xz` (و tar بتاع الماك، bsdtar، بيعرف لوحده وقت الفك، و GNU tar كمان) |
| `f` | اسم الأرشيف بعدها |
| `-C dir` | فك في المجلد ده: `tar -xzf a.tar.gz -C /tmp` |

**تشريح الأمر**

```sh
tar -czf - project/ | ssh prod 'tar -xzf - -C /srv'
```

1. `tar -czf -`: أرشف واضغط، والـ `-` مكان اسم الملف = اكتب على stdout (اصطلاح مشترك بين أوامر كتير: `-` = stdin أو stdout).
2. `project/`: المجلد.
3. `|`: Pipe لـ ssh ([↩ 7.3](../ch07/#s7-3 "الـ Pipe |: ركّب الأوامر")).
4. `ssh prod`: ادخل على السيرفر، والـ stdin بتاعك يتنقل لهناك.
5. `'tar -xzf - -C /srv'`: هناك: فك (`-x`) من stdin (`-f -`) في `/srv`. نسخ مجلد كامل من غير ملف وسيط.

:::caution[ملفات ._ الغريبة على السيرفر]
عملت `tar` على الماك وفكيته على Linux، ولقيت جنب كل ملف ملف تاني اسمه `._index.js`؟ ده tar بتاع الماك بيحفظ الـ Extended attributes ([↩ 6.7](../ch06/#s6-7 "حماية الماك الزيادة: الـ Extended attributes والـ Quarantine")) في ملفات "AppleDouble" دي. السيرفر مش محتاجها. امنعها كده: `COPYFILE_DISABLE=1 tar -czf backup.tar.gz project/` (أو `--no-mac-metadata`). ونفس القصة مع `.DS_Store`: ضيف `--exclude=".DS_Store"`.
:::

## 10.9 البورتات و lsof

فكر في الـ IP على إنه عنوان عمارة، والـ **Port** (رقم من 0 لـ 65535) هو رقم الشقة جوه العمارة. الماك بتاعك عمارة واحدة، بس فيها "سكان" كتير: سيرفر الـ React على شقة 3000، و Postgres على 5432، و AirPlay على 5000. ولما متصفحك يروح لـ `localhost:3000` فهو بيخبط على شقة معينة. البورتات تحت 1024 محتاجة root عشان برنامج يسمع عليها.

**بورتات مشهورة**

| البورت | الخدمة | البورت | الخدمة |
|---|---|---|---|
| `22` | SSH | `3306` | MySQL |
| `53` | DNS | `5432` | PostgreSQL |
| `80` / `443` | HTTP / HTTPS | `6379` | Redis |
| `25` / `587` | SMTP | `3000` / `8000` / `8080` | سيرفرات تطوير |

والسؤال اللي هيقابلك كل أسبوع تقريباً: "مين اللي قاعد في شقة 3000؟". على الماك الأداة اسمها `lsof` (List Open Files)، لأن في Unix كل حاجة ملف، حتى الاتصال بالشبكة:

**تشريح الأمر**

```sh
lsof -nP -iTCP -sTCP:LISTEN
```

1. `lsof`: List Open Files: اعرض الملفات المفتوحة ومين فاتحها. والـ Sockets بتاعة الشبكة بتتعد ملفات كمان.
2. `-nP`: `-n` No DNS: متحولش الـ IPs لأسامي، و `-P` Port numbers: اعرض `3000` مش اسمه (`hbci`). الاتنين بيخلوه أسرع بكتير وأوضح.
3. `-iTCP`: Internet: الاتصالات الـ TCP بس. ممكن `-i :3000` لبورت معين، أو `-iUDP`.
4. `-sTCP:LISTEN`: State: اللي في حالة LISTEN بس، يعني اللي مستني حد يكلمه (السيرفرات)، مش الاتصالات الطالعة بتاعة Chrome.

```sh title="Terminal"
$ lsof -nP -iTCP -sTCP:LISTEN
COMMAND     PID  USER   FD   TYPE  DEVICE SIZE/OFF NODE NAME
ControlCe   612 ahmed   10u  IPv4  0x1a2b      0t0  TCP *:5000 (LISTEN)
node       4433 ahmed   23u  IPv6  0x3c4d      0t0  TCP *:3000 (LISTEN)
postgres    901 ahmed    7u  IPv4  0x5e6f      0t0  TCP 127.0.0.1:5432 (LISTEN)
```

عمود `NAME` هو المهم: `*:3000` = بيسمع على كل الكروت، و `127.0.0.1:5432` = من الماك نفسه بس (الفرق ده مشروح تحت). ومن غير `sudo` هتشوف عملياتك إنت بس؛ ضيف `sudo` قبله لو عايز تشوف خدمات النظام والـ root كمان.

| الأمر | بيعمل إيه |
|---|---|
| `lsof -nP -i :3000` | مين بيستخدم البورت ده (سامع أو متصل). |
| `lsof -t -i :3000` | `-t` Terse: الـ PID بس، عشان تديه لـ kill: `kill $(lsof -t -i :3000)` ([↩ 9.3](../ch09/#s9-3 "الـ Signals و kill")). |
| `netstat -an -p tcp \| grep LISTEN` | الطريقة القديمة، شغالة على الماك بس من غير أسامي البرامج (netstat بتاع الماك مفيهوش `-p` بمعنى Process، هنا `-p tcp` معناها Protocol). |

:::note[على Linux: ss]
على السيرفر `lsof` ممكن متكونش متسطبة، والأداة الأساسية هي `ss`:

**تشريح الأمر**

```sh
sudo ss -tulnp
```

1. `sudo`: عشان تشوف أسماء عمليات المستخدمين التانيين.
2. `ss`: Socket Statistics: البديل الحديث لـ `netstat` (اللي في حزمة net-tools القديمة، وبنفس الحروف تقريباً: `netstat -tulnp`).
3. `-tulnp`: `-t` TCP، و `-u` UDP، و `-l` Listening (اللي مستني اتصالات بس)، و `-n` Numeric (أرقام البورتات مش أسماءها، أسرع وأوضح؛ نفس `-n` بتاعة ping و ls -n)، و `-p` Process (مين البرنامج والـ PID، [↩ 9.1](../ch09/#s9-1 "ps: صورة للعمليات دلوقتي")).

```sh title="Terminal"
L$ sudo ss -tlnp
State   Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
LISTEN  0      511          0.0.0.0:80         0.0.0.0:*     users:(("nginx",pid=812,fd=6))
LISTEN  0      128        127.0.0.1:5432       0.0.0.0:*     users:(("postgres",pid=901,fd=5))
```
:::

:::note[0.0.0.0 مقابل 127.0.0.1]
`0.0.0.0:80` (أو `*:80` في lsof) = بيسمع من أي حد على الشبكة. و `127.0.0.1:5432` = من الجهاز نفسه بس. لو قاعدة بياناتك على `0.0.0.0` ومفيش Firewall، الدنيا كلها تقدر تجرب تدخلها، ونفس الكلام على الماك وإنت في الكافيه: أي حد على نفس الـ Wi-Fi يقدر يوصل لسيرفر التطوير بتاعك لو سامع على `*`. (الماك عنده Firewall في System Settings ← Network ← Firewall، وبيبقى مقفول افتراضياً). وعشان تختبر بورت على جهاز تاني: `nc -zv host 443` (`-z` افحص بس، و `-v` قولي النتيجة).
:::

<a id="s10-10"></a>

## 10.10 مشاكل شائعة

:::danger[مشكلة: Permission denied (publickey)]
السيرفر مش لاقي مفتاحك في `authorized_keys`، أو بتدخل بمستخدم غلط، أو الصلاحيات واسعة.

<strong>الحل:</strong> `ssh -v prod` واقرا هو جرّب أنهي مفتاح (سطور `Offering public key`). اتأكد من الـ User، ومن `chmod 700 ~/.ssh` و `600 authorized_keys` على السيرفر.
:::

:::danger[مشكلة: WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!]
بصمة السيرفر اختلفت عن اللي محفوظة في `~/.ssh/known_hosts`. ده طبيعي لو السيرفر اتعمله Reinstall، وخطير لو مفيش سبب (ممكن حد في النص).

<strong>الحل:</strong> لو متأكد إن السيرفر اتغير فعلاً: `ssh-keygen -R 203.0.113.10` يشيل البصمة القديمة، وادخل تاني وراجع البصمة الجديدة.
:::

:::danger[مشكلة: ssh بيسألني على الـ Passphrase كل مرة]
عملت Restart للماك، ورجع ssh يسألك على الـ Passphrase مع كل اتصال.

<strong>الحل:</strong> مرة واحدة: `ssh-add --apple-use-keychain ~/.ssh/id_ed25519`، وحط `AddKeysToAgent yes` و `UseKeychain yes` تحت `Host *` في `~/.ssh/config`. بعدها الماك هيفتكرها من الـ Keychain.
:::

:::danger[مشكلة: الموقع بيفتح من موبايلي ومش بيفتح من الماك]
غالباً الماك فاكر IP قديم للموقع (DNS cache)، أو فيه سطر قديم في `/etc/hosts` إنت نسيته من مشروع فات.

<strong>الحل:</strong> `grep example /etc/hosts` وشيل السطر لو موجود (`sudo nano /etc/hosts`)، وبعدين امسح الـ Cache: `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`. وقارن `dig +short example.com` بـ `dscacheutil -q host -a name example.com`.
:::

:::tip[ملخص الفصل]
- شخّص من تحت لفوق: `ipconfig getifaddr en0` و `route -n get default` ثم `ping` ثم `dig` ثم `curl` ثم `lsof -i`. وعلى Linux: `ip` و `ss`.
- `curl -fsSL` للتحميل في Scripts، و `-I` للـ Headers، و `-w '%{http_code}'` للفحص.
- `ssh-keygen -t ed25519` و `ssh-copy-id`، و `ssh-add --apple-use-keychain`، وملف `~/.ssh/config` بيختصر كل حاجة.
- `ssh -p` صغيرة و `scp -P` كبيرة، و rsync بالـ `/` في آخر المصدر وجرّب بـ `--dry-run`.
- rsync الماك = openrsync؛ للنسخة الكاملة `brew install rsync`.
- `tar -czf` للضغط و `-xzf` للفك (و `COPYFILE_DISABLE=1` عشان ملفات `._`)، و `lsof -nP -iTCP -sTCP:LISTEN` مين بيسمع على إيه.
- DNS الماك: `scutil --dns` و `dscacheutil -flushcache`، والأجهزة القريبة بـ `.local`.
:::

### صح ولا غلط؟

1. لو ping فشل يبقى الموقع أكيد واقع.
2. `scp -p 2222` بتحدد البورت.
3. `rsync -a src/ dst/` و `rsync -a src dst/` بيدوا نفس النتيجة.
4. المفتاح اللي بينتهي بـ `.pub` هو اللي بيتحط على السيرفر.

### أسئلة مراجعة

1. موقع مش بيفتح: رتّب الأوامر اللي هتستخدمها للتشخيص وقول كل واحد بيختبر إيه.
2. اشرح كل حرف في `curl -fsSL`.
3. اكتب Host في ssh config لسيرفر على بورت 2200 بمستخدم admin.
4. إيه وظيفة كل جزء في `lsof -nP -iTCP -sTCP:LISTEN`؟ وإيه المقابل على سيرفر Linux؟
5. ليه `ping -W 2` على الماك ممكن يخلي كل الردود تبان فاشلة؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** اعرف الـ IP بتاع `github.com` بـ dig من DNS server تاني غير الافتراضي، واعرف الـ DNS servers اللي الماك بيستخدمها دلوقتي.
2. **[متوسط]** اكتب سطر يطبع "UP" لو موقع رجع 200 و "DOWN" غير كده، باستخدام curl و `&&` و `||`.
3. **[صعب]** اعمل مفتاح Ed25519 جديد، وحطه في ssh config باسم `lab` لسيرفر، أو للماك نفسه: فعّل **Remote Login** من System Settings ← General ← Sharing، واستخدم `HostName localhost`. وانسخ مجلد بـ rsync مع `--dry-run` الأول.
