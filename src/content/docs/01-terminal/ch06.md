<small>المرحلة 2 · الملفات والصلاحيات</small>

أشهر رسالة هتشوفها في حياتك: Permission denied. وأول مرة تشوفها غالباً هتبقى وانت بتسطب حاجة بـ npm install -g، فتدوّر على النت وتلاقي حد بيقولك "حط sudo قبلها وخلاص". وفعلاً بتشتغل، وبعدها بأسبوع كل حاجة في npm تبوظ ومش فاهم ليه. الفصل ده بيشرح نظام الصلاحيات من الأساس: مين يقدر يعمل إيه، إزاي تقرا وتكتب الصلاحيات بالحروف والأرقام، والمستخدمين والجروبات و sudo صح. وكمان طبقات الحماية الزيادة اللي الماك بيضيفها: الـ Extended attributes والـ Quarantine والـ ACL و SIP و Full Disk Access.

:::note[بعد الفصل ده هتكون عارف]
- نظام r و w و x للمالك والجروب والباقي
- الفرق بين الصلاحيات على الملف وعلى المجلد
- chmod بالحروف وبالأرقام (755 و 644 و 600)
- chown و chgrp و umask
- المستخدمين والجروبات على الماك (dscl و admin) ومقارنتها بـ /etc/passwd
- الفرق بين sudo و su وليه \<code\>sudo echo &gt; file\</code\> مبتشتغلش
- حماية الماك الزيادة: xattr و com.apple.quarantine و ACL و SIP و Full Disk Access
:::

## 6.1 الفكرة: 3 أسئلة × 3 أنواع ناس

تخيل إنك ساكن في شقة مع عيلتك، وعندك أوضة خاصة بيك. إنت تقدر تدخل أوضتك وتقرا الكتب اللي فيها وتغيّر ترتيبها. إخواتك (الجروب) ممكن يدخلوا يقروا بس، من غير ما يحركوا حاجة. والضيوف (الباقي) ملهمش دعوة بأوضتك خالص. ده بالظبط نظام الصلاحيات في Unix، والماك ماشي عليه زي Linux بالظبط.

طب ليه النظام ده موجود أصلاً على جهاز إنت بس اللي بتستخدمه؟ لأن الماك من جوه فيه "مستخدمين" كتير غيرك: كل خدمة في النظام شغالة باسم مستخدم خاص بيها. والصلاحيات هي اللي بتمنع برنامج اتخرّب إنه يلمس ملفاتك، وبتمنعك إنت كمان إنك تبوّظ النظام بالغلط.

كل ملف ليه **مالك** (Owner) و**جروب** (Group). ولكل ملف، النظام بيسأل 3 أسئلة لـ 3 فئات:

#### r · Read = 4

تقدر تقرا المحتوى؟

#### w · Write = 2

تقدر تعدّل؟

#### x · eXecute = 1

تقدر تشغّله كبرنامج؟

![-rwxr-x--- = ملف عادي بصلاحيات 750 .](./assets/ch06-fig1.png)

*-rwxr-x--- = ملف عادي بصلاحيات 750.*

يعني `-rwxr-x---` معناها: ملف عادي (`-`)، المالك يقرا ويكتب ويشغّل، الجروب يقرا ويشغّل بس، والباقي ملهمش أي حاجة.

**نفس الحرف معناه إيه على الملف وعلى المجلد**

| الحرف | على ملف | على مجلد |
|---|---|---|
| `r` | تقرا المحتوى | تعرض الأسماء اللي جواه (`ls`) |
| `w` | تعدّل المحتوى | تعمل وتمسح وتغير أسماء ملفات **جواه** |
| `x` | تشغّله كبرنامج أو Script | تدخله (`cd`) وتوصل للملفات اللي جواه |

:::note[معلومة بتفاجئ الناس]
مسح ملف بيعتمد على صلاحية **w على المجلد** اللي فيه، مش على الملف نفسه. يعني ممكن تمسح ملف مش من حقك تعدّله لو المجلد بتاعك! (وعشان كده `/tmp` عليه Sticky bit، تحت).
:::

## 6.2 chmod: تغيير الصلاحيات

أول مرة هتحتاج الأمر ده غالباً هتبقى كتبت Script صغير، وحاولت تشغله بـ `./backup.sh`، والـ Terminal قالك `zsh: permission denied`. الملف موجود والكلام اللي جواه صح، بس محدش قال للماك إن الملف ده "برنامج" ينفع يتشغل. وهنا بييجي دور `chmod`. وليه طريقتين للكتابة: بالحروف (أوضح) وبالأرقام (أسرع):

### بالحروف (Symbolic)

**تشريح الأمر**

```sh
chmod u+x,g-w,o= deploy.sh
```

1. `chmod`: CHange MODe: غيّر الصلاحيات.
2. `u+x`: `u` = User (المالك)، `+` = ضيف، `x` = تشغيل. يعني "ضيف للمالك صلاحية التشغيل".
3. `,`: فاصلة من غير مسافة: اعمل كذا تغيير في نفس الأمر.
4. `g-w`: `g` = Group، `-` = شيل، `w` = كتابة.
5. `o=`: `o` = Others، `=` = خليها بالظبط كده، ومفيش حاجة بعدها = ملهمش أي صلاحية. (وفيه `a` = All للتلاتة).
6. `deploy.sh`: الملف.

### بالأرقام (Octal)

كل فئة رقم واحد = مجموع (r=4، w=2، x=1). فـ 7 = rwx، 6 = rw-، 5 = r-x، 4 = r--، 0 = ---. والأرقام التلاتة بالترتيب: المالك، الجروب، الباقي.

**أشهر الصلاحيات بالأرقام**

| الرقم | بالحروف | الاستخدام |
|---|---|---|
| `755` | `rwxr-xr-x` | Scripts وبرامج ومجلدات عامة |
| `644` | `rw-r--r--` | ملفات عادية (الافتراضي) |
| `700` | `rwx------` | مجلد خاص بيك بس (`~/.ssh`) |
| `600` | `rw-------` | ملفات سرية: مفاتيح SSH، ملفات `.env` |
| `640` | `rw-r-----` | إعدادات الجروب يقراها والباقي لأ |
| `775` | `rwxrwxr-x` | مجلد شغل مشترك لفريق |
| `777` | `rwxrwxrwx` | **تقريباً أبداً**: أي حد على الجهاز يعدّل ويشغّل |

**تشريح الأمر**

```sh
chmod -R 750 ~/projects/app
```

1. `chmod`: غيّر الصلاحيات.
2. `-R`: Recursive (حرف كبير بس في chmod/chown!): طبّق على المجلد وكل اللي جواه.
3. `750`: المالك rwx، الجروب r-x، الباقي ولا حاجة.
4. `~/projects/app`: المجلد.

:::caution[فخ chmod -R على ملفات ومجلدات مع بعض]
`chmod -R 755` هيخلي **كل الملفات** قابلة للتشغيل كمان، وده مش مطلوب. الأصح إنك تفرق بين المجلدات والملفات باستخدام `find` ([↩ 8.10](../ch08/#s8-10 "find و mdfind: دوّر على ملفات")):

```sh title="Terminal"
find ~/projects/app -type d -exec chmod 755 {} +   # المجلدات
find ~/projects/app -type f -exec chmod 644 {} +   # الملفات
```

وفيه حل أسهل بالحروف: `chmod -R a+rX dir`، الـ `X` الكبيرة معناها "x للمجلدات بس (واللي عليه x أصلاً)".
:::

### الصلاحيات الخاصة (رقم رابع في الأول)

**Setuid و Setgid و Sticky**

| الاسم | الرقم | بيظهر | بيعمل إيه | مثال |
|---|---|---|---|---|
| setuid | `4`xxx | `s` مكان x المالك | البرنامج يشتغل بصلاحيات **صاحبه** مش اللي شغّله | `/usr/bin/sudo` = `-r-s--x--x` |
| setgid | `2`xxx | `s` مكان x الجروب | على مجلد: أي ملف جديد ياخد جروب المجلد | مجلدات الفرق |
| sticky | `1`xxx | `t` في الآخر | على مجلد: محدش يمسح غير ملفاته | `/private/tmp` = `drwxrwxrwt` |

## 6.3 chown و chgrp: مين المالك؟

فاكر حكاية `sudo npm install -g` اللي في أول الفصل؟ تعالى نفهم إيه اللي حصل بالظبط. لما كتبت `sudo`، الـ npm اشتغل كـ **root**، فكل الملفات اللي عملها في الـ Cache بتاعه (`~/.npm`) بقى مالكها root مش إنت. وبعد كده لما تشغّل npm عادي من غير sudo، يحاول يكتب في ملفات مش بتاعتك، فيطلعلك `EACCES: permission denied`. الحل مش إنك تفضل تحط sudo، الحل إنك ترجّع الملفات لصاحبها:

**تشريح الأمر**

```sh
sudo chown -R $(whoami):staff ~/.npm
```

1. `sudo`: نفّذ الأمر كـ root، لأن تغيير المالك لملف مش بتاعك محتاج صلاحيات Admin (تحت).
2. `chown`: CHange OWNer: غيّر المالك.
3. `-R`: Recursive: المجلد وكل اللي جواه (نفس chmod).
4. `$(whoami)`: Command Substitution: نفّذ `whoami` وحط ناتجه (اسمك، زي `ahmed`) مكانه ([↩ 7.6](../ch07/#s7-6 "الـ Command Substitution: ‎$()‎")).
5. `:staff`: `user:group`. و `staff` هو الجروب الافتراضي لكل مستخدم على الماك. لو كتبت `ahmed` بس يتغير المالك بس. ولو `:staff` (من غير user) يتغير الجروب بس، زي `chgrp staff`.
6. `~/.npm`: المسار.

:::tip[Best Practice]
متستخدمش `sudo` مع `npm install -g` خالص. على الماك، الأحسن إنك تسطّب Node عن طريق أداة زي `nvm` أو `fnm` أو `brew install node`، وكلهم بيسطبوا في أماكن بتاعتك إنت، فمش هتحتاج sudo أصلاً.
:::

:::note[على Linux]
على السيرفر هتشوف كتير `sudo chown -R ahmed:www-data /var/www/site`: الجروب `www-data` هو اللي nginx شغال بيه على Ubuntu، فلازم يقدر يقرا ملفات الموقع.
:::

## 6.4 umask: الصلاحيات الافتراضية

ليه أي ملف جديد بتعمله بيطلع `644` وأي مجلد `755`؟ بسبب **umask**: "قناع" بيتشال من الصلاحيات الكاملة. الملفات بتبدأ من 666 والمجلدات من 777، وبيتشال منهم الـ umask.

```sh title="Terminal"
$ umask
0022
# files: 666 - 022 = 644   dirs: 777 - 022 = 755
```

**تشريح الأمر**

```sh
umask 027
```

1. `umask`: Builtin: من غير Argument بيعرض القيمة، ومعاه بيغيرها للـ Shell الحالي بس (حطها في `~/.zshrc` عشان تفضل، [↩ 13.1](../ch13/#s13-1 "مين بيقرا إيه وإمتى؟")).
2. `027`: شيل w من الجروب (2)، وشيل كله من الباقي (7). النتيجة: ملفات `640` ومجلدات `750`. (الحساب الدقيق مش طرح، ده "شيل البتات دي"، بس الطرح بيوصل لنفس النتيجة في الحالات المشهورة).

## 6.5 المستخدمين والجروبات

لما فتحت الماك أول مرة عملت حساب باسمك، وده كل اللي شفته. بس جوه النظام فيه عشرات المستخدمين التانيين اللي مبيظهروش في شاشة الدخول: مستخدم للـ Spotlight، ومستخدم للطباعة، ومستخدم لكل خدمة تقريباً. خلينا نتعرف على نفسنا الأول:

```sh title="Terminal"
$ whoami
ahmed
$ id
uid=501(ahmed) gid=20(staff) groups=20(staff),12(everyone),61(localaccounts),80(admin),701(com.apple.sharepoint.group.1),33(_appstore),98(_lpadmin),100(_lpoperator),204(_developer)
```

<small>الجروبات عندك ممكن تكون أكتر أو أقل حسب إعدادات جهازك.</small>

- كل مستخدم ليه رقم **UID**، و root دايماً UID = 0. على الماك أول مستخدم عادي رقمه **501** (على Linux بيبدأوا من 1000).
- الجروب الأساسي **staff** (رقمه 20)، وده مشترك بين كل المستخدمين العاديين.
- أهم جروب في اللستة: **admin** (80). اللي فيه هو اللي يقدر يستخدم `sudo` ويسطب برامج. لو حسابك "Administrator" في System Settings، يبقى إنت فيه.
- المستخدمين بتوع النظام أساميهم بتبدأ بـ `_` زي `_www` و `_spotlight`.

### فين متخزنة بيانات المستخدمين؟

على Linux كل ده متخزن في ملف نصي اسمه `/etc/passwd`. الماك عنده الملف ده برضه، بس للزينة تقريباً: الماك بيستخدم قاعدة بيانات اسمها **Directory Services**، وبتسألها بأمر اسمه `dscl`:

**تشريح الأمر**

```sh
dscl . -read /Users/ahmed UniqueID PrimaryGroupID NFSHomeDirectory UserShell
```

1. `dscl`: Directory Service Command Line: اسأل (أو عدّل) قاعدة بيانات المستخدمين.
2. `.`: النقطة هنا معناها "الجهاز ده" (الـ Local directory)، مش المجلد الحالي.
3. `-read`: اقرا سجل.
4. `/Users/ahmed`: السجل: المستخدم ahmed. (ده مسار جوه قاعدة البيانات، مش مجلد الـ home، رغم إن شكلهم واحد).
5. `UniqueID PrimaryGroupID NFSHomeDirectory UserShell`: المفاتيح اللي عايزها: الـ UID، والجروب الأساسي، والـ home، والـ Login Shell. من غيرهم هيطبعلك كل حاجة.

```sh title="Terminal"
$ dscl . -read /Users/ahmed UniqueID PrimaryGroupID NFSHomeDirectory UserShell
NFSHomeDirectory: /Users/ahmed
PrimaryGroupID: 20
UniqueID: 501
UserShell: /bin/zsh
```

وعلى سيرفر Linux نفس المعلومات دي في سطر واحد في `/etc/passwd`، مفصولة بـ `:`. الجدول ده بيقطّع السطر ده عمود عمود، وقصاد كل عمود اسمه في dscl:

```sh title="Terminal"
L$ grep ahmed /etc/passwd
ahmed:x:1000:1000:Ahmed Ali,,,:/home/ahmed:/bin/bash
```

**أعمدة /etc/passwd على Linux وقصادها في dscl على الماك**

| # | العمود على Linux | الماك (dscl) | المعنى |
|---|---|---|---|
| 1 | `ahmed` | `RecordName` | اسم المستخدم |
| 2 | `x` | متخزن متشفر في مكان محمي | الباسورد مش هنا؛ على Linux في `/etc/shadow` (اللي root بس يقراه) |
| 3 | `1000` | `UniqueID` = 501 | الـ UID |
| 4 | `1000` | `PrimaryGroupID` = 20 | الـ GID: الجروب الأساسي |
| 5 | `Ahmed Ali,,,` | `RealName` | الاسم الكامل (GECOS) |
| 6 | `/home/ahmed` | `NFSHomeDirectory` | الـ home |
| 7 | `/bin/bash` | `UserShell` | الـ Login Shell (اللي بيتغير بـ `chsh`، [↩ 3.8](../ch03/#s3-8 "إنت شغال على أنهي Shell؟ وإزاي تغيره؟")) |

### تضيف مستخدم لجروب

على الماك غالباً هتعمل ده من **System Settings ← Users & Groups**. بس لو عايز تعمله بالأمر (مثلاً تخلي مستخدم Admin):

**تشريح الأمر**

```sh
sudo dseditgroup -o edit -a sara -t user admin
```

1. `dseditgroup`: عدّل جروب في Directory Services.
2. `-o edit`: Operation: العملية هي "تعديل" (فيه كمان `read` و `create` و `delete`).
3. `-a sara`: Add: ضيف sara. (و `-d` = امسحها من الجروب).
4. `-t user`: Type: اللي بنضيفه نوعه مستخدم (ممكن يبقى جروب جوه جروب).
5. `admin`: اسم الجروب. ولو عايز تتأكد: `dseditgroup -o checkmember -m sara admin`.

:::note[على Linux: usermod]
**تشريح الأمر**

```sh
sudo usermod -aG docker ahmed
```

1. `usermod`: USER MODify: عدّل مستخدم موجود. (و `useradd` تعمل جديد، و `passwd` تغير الباسورد).
2. `-aG`: `-G` = الجروبات الإضافية، و `-a` = Append: **ضيف** عليهم. من غير `-a` المستخدم هيتشال من كل الجروبات التانية (حتى sudo!).
3. `docker`: اسم الجروب. (على الماك Docker Desktop مش محتاج الجروب ده أصلاً).
4. `ahmed`: اسم المستخدم. والتغيير بيبان بعد ما تعمل Log out و Log in (أو `newgrp docker`).

وعلى Linux جروب الأدمن اسمه `sudo` (Ubuntu) أو `wheel` (Fedora)، مش `admin`. وبيانات المستخدمين في `/etc/passwd` اللي بتقراه بـ `grep ahmed /etc/passwd`.
:::

## 6.6 sudo و su

فكّر في `sudo` كإنه "الكارنيه الأحمر" اللي بتطلّعه للأمن علشان يدخلك أماكن ممنوعة. مش بتمشي بيه طول اليوم، بتطلعه للحظة وتشيله. كل مرة تكتب `sudo` قبل أمر، الماك بيسألك على باسوردك (أو بصمتك لو ظبطتها تحت) علشان يتأكد إن إنت فعلاً اللي عايز تعمل الحاجة الخطيرة دي.

**sudo مقابل su**

|   | `sudo cmd` | `su -` |
|---|---|---|
| بيعمل إيه | ينفّذ أمر **واحد** كـ root | يفتح Shell كامل كمستخدم تاني (root افتراضياً) |
| باسورد مين | باسوردك إنت | باسورد المستخدم التاني (root) |
| مين يقدر | اللي في جروب `admin` على الماك (مكتوب في `/etc/sudoers`)، أو `sudo`/`wheel` على Linux | أي حد عارف الباسورد. وعلى الماك حساب root **مقفول** افتراضياً، فـ `su -` لوحدها مش هتشتغل |
| تسجيل | كل أمر بيتسجل في الـ Logs | أقل تتبع |
| النصيحة | استخدمه دايماً | نادراً |

| الأمر | بيعمل إيه |
|---|---|
| `sudo dscacheutil -flushcache` | أمر واحد كـ root (هنا: امسح كاش الـ DNS، [↩ 10.3](../ch10/#s10-3 "الـ DNS: dig و nslookup")). |
| `sudo -i` | Shell كامل كـ root بإعداداته (زي `su -` بس بباسوردك). اخرج بـ `exit`. |
| `sudo -u nobody ls` | `-u` = User: نفّذ كمستخدم تاني مش root (هنا `nobody`: مستخدم ملوش صلاحيات خالص، ممتاز للتجارب). |
| `su - sara` | ادخل كـ sara (محتاج باسوردها). الـ `-` معناها Login shell: حمّل الـ home والمتغيرات بتاعتها. |
| `sudo !!` | أعد آخر أمر بـ sudo ([↩ 14.4](../ch14/#s14-4 "الـ History: متكتبش حاجة مرتين")). |
| `sudo visudo` | عدّل ملف sudoers بأمان (بيتأكد من الكتابة قبل الحفظ). متعدلوش بـ nano مباشرة. |

:::note[خلّي بصمتك هي اللي تعمل sudo]
لو الماك بتاعك فيه Touch ID، تقدر تخلي `sudo` يطلب البصمة بدل الباسورد. من macOS Sonoma فيه ملف جاهز للتعديل ده ومبيتمسحش مع التحديثات:

```sh title="Terminal"
sudo cp /etc/pam.d/sudo_local.template /etc/pam.d/sudo_local
sudo nano /etc/pam.d/sudo_local   # شيل علامة # من أول سطر auth sufficient pam_tid.so
```

الـ `pam.d` هو المكان اللي فيه قواعد "إزاي النظام يتأكد إنك إنت"، و `pam_tid.so` هو الجزء اللي بيكلم Touch ID. افتح تابة جديدة وجرّب `sudo -v` (الـ `-v` = Validate: اتأكد مني بس من غير ما تشغل أمر).
:::

:::note[على Linux: sudo على Ubuntu الحديث]
من Ubuntu 25.10، الأمر `sudo` بقى بيتنفذ افتراضياً بـ **sudo-rs** (نسخة مكتوبة بـ Rust)، والـ sudo الأصلي لسه موجود باسم `sudo.ws`. الاستخدام اليومي زي ما هو، بس لو حاجة متقدمة في sudoers مشتغلتش، ده ممكن يكون السبب.
:::

:::tip[Least Privilege]
اشتغل كمستخدم عادي، واستخدم `sudo` للأمر اللي محتاجه بس. ولو حاجة "مش شغالة غير بـ sudo" وهي المفروض متحتاجش (زي ملف في الـ home بتاعك)، المشكلة غالباً في المالك: صلّحها بـ `chown` بدل ما تفضل تستخدم sudo.
:::

## 6.7 حماية الماك الزيادة: الـ Extended attributes والـ Quarantine

أكيد حصلك الموقف ده: نزّلت برنامج من النت، دبل كليك عليه، وطلعتلك رسالة "<em>can't be opened because Apple cannot check it for malicious software</em>". أو نزّلت أداة CLI من GitHub، وأول ما شغلتها الماك قالك إنها "from an unidentified developer". طب الماك عرف منين إن الملف ده جاي من النت؟ ده مش في الصلاحيات `rwx` خالص.

هنا بقى بييجي دور الـ **Extended attributes** (أو xattr): معلومات زيادة الماك بيلزقها في الملف من غير ما تغيّر محتواه، زي "استيكر" على الكرتونة. ولما المتصفح ينزّل ملف، بيلزق عليه استيكر اسمه `com.apple.quarantine` فيه "الملف ده جه من النت، من موقع كذا، يوم كذا". وبعد كده نظام اسمه **Gatekeeper** بيشوف الاستيكر ده ويقرر يفتح الملف ولا يحذّرك. وده نفس سبب علامة `@` اللي شفناها في `ls -l`.

**تشريح الأمر**

```sh
xattr -l ~/Downloads/tool.zip
```

1. `xattr`: اعرض أو عدّل الـ Extended attributes.
2. `-l`: Long: اعرض اسم كل Attribute وقيمته. (من غيرها بيعرض الأسماء بس).
3. `~/Downloads/tool.zip`: الملف.

```sh title="Terminal"
$ xattr -l ~/Downloads/tool.zip
com.apple.macl:
com.apple.quarantine: 0083;6717a2c1;Safari;9E1A4C3B-...
$ ls -l@ ~/Downloads/tool.zip
-rw-r--r--@ 1 ahmed  staff  48211 Oct 22 10:30 tool.zip
	com.apple.macl	     72
	com.apple.quarantine	     57
```

الـ `-@` مع `ls -l` بيعرض أسماء الـ Attributes وحجمها تحت الملف. ولو إنت **متأكد** إن الملف ده من مصدر موثوق، تقدر تشيل الاستيكر:

**تشريح الأمر**

```sh
xattr -dr com.apple.quarantine ~/Applications/Tool.app
```

1. `xattr`: نفس الأمر.
2. `-dr`: اتنين مدموجين: `-d` (Delete: امسح Attribute معين) و `-r` (Recursive: على المجلد وكل اللي جواه، ومهمة مع الـ `.app` لأنه مجلد).
3. `com.apple.quarantine`: اسم الـ Attribute اللي هيتمسح.
4. `~/Applications/Tool.app`: البرنامج. (وفيه `xattr -c` بتمسح **كل** الـ Attributes، وده أوسع من اللي محتاجه).

:::caution[خلي بالك]
الاستيكر ده موجود علشان يحميك. متشيلوش غير من حاجة إنت عارف مصدرها كويس. والطريقة الأأمن من غير Terminal: كليك يمين على البرنامج ← **Open**، أو **System Settings ← Privacy & Security** وانزل لتحت هتلاقي زرار **Open Anyway**. ولاحظ إن الملفات اللي بتنزلها بـ `curl` من الـ Terminal مبيتلزقش عليها الاستيكر ده أصلاً، فإنت مسؤول عنها بالكامل ([↩ 15.6](../ch15/#s15-6 "curl | sh: تشغيل Script من النت")).
:::

### الـ ACL: صلاحيات أدق من rwx

الـ `rwx` بيقسم الناس لـ 3 فئات بس. طب لو عايز تقول "سارة بالذات تقدر تقرا الملف ده"؟ هنا بييجي دور الـ **ACL** (Access Control List): لستة قواعد زيادة على الملف. والماك بيستخدمها فعلاً على مجلداتك، وده سبب علامة `+` على الـ home:

```sh title="Terminal"
$ ls -led ~/Desktop
drwx------+ 5 ahmed  staff  160 Oct 22 09:00 /Users/ahmed/Desktop
 0: group:everyone deny delete
```

الـ `-e` بتعرض الـ ACL تحت الملف (ماك بس)، و `-d` المجلد نفسه. والقاعدة دي معناها "أي حد، حتى إنت، ممنوع يمسح مجلد Desktop نفسه". وتقدر تضيف قاعدة بـ `chmod +a`:

**تشريح الأمر**

```sh
chmod +a "user:sara allow read" report.pdf
```

1. `chmod`: نفس الأمر بتاع الصلاحيات.
2. `+a`: Add ACL entry: ضيف قاعدة. (و `-a` تمسح قاعدة، و `-N` تمسح كل الـ ACL).
3. `"user:sara allow read"`: القاعدة بين علامات تنصيص لأن فيها مسافات: مين (`user:sara`)، مسموح ولا ممنوع (`allow`/`deny`)، وإيه (`read`، `write`، `delete`...).
4. `report.pdf`: الملف.

## 6.8 SIP و Full Disk Access: حتى root ليه حدود

على Linux الـ root هو الملك، يقدر يعمل أي حاجة في أي حتة. على الماك لأ. Apple قالت: "طب لو برنامج خبيث خد صلاحيات root، كده هيبوظ النظام كله؟" فعملت طبقتين حماية فوق الصلاحيات العادية:

#### SIP · System Integrity Protection

بيمنع **أي حد**، حتى root بـ `sudo`، إنه يعدّل ملفات النظام في `/System` و `/bin` و `/sbin` و `/usr` (ما عدا `/usr/local`). علشان كده عمرك ما هتسطب حاجة في `/usr/bin`، وده سبب إن Homebrew بيستخدم `/opt/homebrew`. اعرف حالته بـ `csrutil status`.

#### TCC · Privacy & Full Disk Access

بيحمي **خصوصيتك**: كل برنامج لازم ياخد إذن صريح منك علشان يوصل لـ Desktop و Documents و Downloads والكاميرا و Mail و Photos. والـ Terminal برنامج زي أي برنامج، فلو عايزه يوصل لكل حاجة: **System Settings ← Privacy & Security ← Full Disk Access** وفعّل Terminal.

```sh title="Terminal"
$ csrutil status
System Integrity Protection status: enabled.
$ sudo touch /usr/bin/test
touch: /usr/bin/test: Operation not permitted
```

:::caution[خلي بالك]
هتلاقي شروحات قديمة بتقولك "اقفل SIP" علشان تعمل حاجة. متعملش كده: ده محتاج تدخل Recovery Mode، وبيفتح الجهاز لأي برنامج خبيث. في 2026 مفيش تقريباً أي حاجة عادية محتاجة كده. ولاحظ إن `Operation not permitted` رسالة مختلفة عن `Permission denied`: الأولى غالباً معناها SIP أو TCC، والتانية معناها `rwx`.
:::

## 6.9 مشاكل شائعة

:::danger[مشكلة: <code>sudo echo "..." > /etc/file</code> بيقول Permission denied]
عايز تخلي `myapp.test` يفتح على جهازك وانت بتجرب مشروع، فكتبت `sudo echo "127.0.0.1 myapp.test" > /etc/hosts` وفشل! ليه؟ لأن الـ `>` بيعملها **الـ Shell بتاعك** (مستخدم عادي) قبل ما الأمر يشتغل ([↩ 1.2](../ch01/#s1-2 "إيه اللي بيحصل لما تدوس Enter؟")). الـ sudo بيطبّق على `echo` بس.

<strong>الحل:</strong> خلي برنامج شغال بـ sudo هو اللي يكتب: `echo "127.0.0.1 myapp.test" | sudo tee -a /etc/hosts`. (الـ `tee -a` بيضيف في آخر الملف، [↩ 8.8](../ch08/#s8-8 "tee: شوف واحفظ في نفس الوقت")). وبعدها على الماك امسح كاش الـ DNS علشان التغيير يبان: `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`.
:::

:::danger[مشكلة: npm: EACCES permission denied]
بعد ما استخدمت `sudo npm ...` مرة، بقى npm بيطلع `EACCES` كل شوية.

<strong>الحل:</strong> رجّع الملفات لصاحبها: `sudo chown -R $(whoami):staff ~/.npm`، ومتستخدمش sudo مع npm تاني ([↩ 6.3](#s6-3 "chown و chgrp: مين المالك؟")).
:::

:::danger[مشكلة: Bad permissions لمفتاح SSH]
SSH بيرفض المفتاح ويقول `UNPROTECTED PRIVATE KEY FILE!` لأن صلاحياته مفتوحة لغيرك.

<strong>الحل:</strong> `chmod 700 ~/.ssh` و `chmod 600 ~/.ssh/id_ed25519` ([↩ 10.4](../ch10/#s10-4 "ssh: ادخل على سيرفر بعيد")).
:::

:::tip[ملخص الفصل]
- r=4، w=2، x=1، لـ 3 فئات: المالك والجروب والباقي.
- على المجلد: r = تعرض، w = تعمل وتمسح جواه، x = تدخله.
- `chmod u+x` بالحروف أو `chmod 755` بالأرقام، و `-R` كبيرة للـ Recursive.
- `chown user:group`، و `umask` بيحدد الافتراضي.
- على الماك: أول UID = 501، الجروب الأساسي `staff`، والأدمن جروب `admin`، والبيانات في `dscl` مش `/etc/passwd`. وعلى Linux `usermod -aG` بالـ `-a` دايماً.
- sudo لأمر واحد أحسن من su، و root مقفول على الماك افتراضياً.
- الماك بيضيف: `xattr` و `com.apple.quarantine` للملفات اللي من النت، والـ ACL (`ls -le`، `chmod +a`)، و SIP اللي بيحمي النظام حتى من root، و Full Disk Access.
:::

### صح ولا غلط؟

1. صلاحية 640 معناها الجروب يقدر يكتب في الملف.
2. عشان تدخل مجلد بـ cd لازم يكون عليه x.
3. `sudo echo hi > /etc/test.txt` بتشتغل لأن sudo بيشمل الـ Redirection.
4. بـ `sudo` تقدر تعدّل أي ملف في `/usr/bin` على الماك.

### أسئلة مراجعة

1. حوّل `rwxr-x---` و `rw-rw-r--` لأرقام.
2. إيه الصلاحية المناسبة لمفتاح SSH الخاص؟ وللـ Script اللي هيتشغل؟
3. إيه اللي هيحصل على سيرفر Linux لو كتبت `usermod -G docker ahmed` من غير `-a`؟
4. نزّلت أداة من GitHub بالمتصفح والماك رافض يشغلها. إيه السبب؟ واذكر طريقتين للحل.
5. اشرح ليه `/tmp` صلاحياتها `drwxrwxrwt`.

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** اعمل Script فيه `echo hi`، وجرّب تشغله قبل وبعد `chmod +x`.
2. **[متوسط]** اعمل مجلد `secret` بصلاحية 700 وجواه ملف 600، وجرّب تقراه بمستخدم تاني (`sudo -u nobody cat ...`).
3. **[متوسط]** نزّل أي ملف من المتصفح، واعرض الـ Attributes بتاعته بـ `xattr -l`، وقارنها بملف نزلته بـ `curl -O`.
4. **[صعب]** غيّر الـ umask لـ 077 في Shell مؤقت، اعمل ملف ومجلد، وتوقع صلاحياتهم قبل ما تعمل `ls -l`.
