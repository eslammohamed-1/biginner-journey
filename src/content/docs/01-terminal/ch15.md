<small>المرحلة 6 · الاحتراف بأمان</small>

لما تمسح ملف من الـ Finder بيروح الـ Trash وتقدر ترجعه، لكن في الـ Terminal مفيش رجوع والأمر بيتم في ثانية من غير ما يرمش. الفصل ده هيعرّفك على الأوامر الخطيرة وإزاي تحمي نفسك ونظامك.

:::note[بعد الفصل ده هتكون عارف]
- rm -rf وأشهر الطرق اللي بيمسح بيها حاجات مش قصدك، وإيه اللي SIP بيحميه وإيه لأ
- dd و diskutil وليه dd اسمه Disk Destroyer
- chmod -R 777 و chown -R على مسارات النظام
- الـ Fork bomb وتشريحها رمز رمز
- ‎\> اللي بيمسح الملف من غير ما يسأل
- تشغيل Scripts من النت بـ curl و sh بأمان
- قائمة حماية عملية
:::

:::caution[متجربش الأوامر دي على الماك بتاعك]
كل الأمثلة الخطيرة هنا للقراية والفهم. لو عايز تجرب، جرّب جوه Container (`docker run --rm -it ubuntu` مع Docker Desktop أو OrbStack) أو Virtual Machine (زي UTM) مش مهم تبوظ. ولو مفيش، اعمل فولدر تجارب في `/tmp` واشتغل جواه بس، واستخدم `echo` قبل أي أمر عشان تشوف هيعمل إيه.
:::

## 15.1 rm -rf: المسح من غير رجعة

حكاية حقيقية بتتكرر كل يوم: واحد عايز يمسح فولدر `node_modules` القديم من مشروع عشان يوفر مساحة (أي حد اشتغل JavaScript عارف إن الفولدر ده ممكن يبقى 800 ميجا). كتب الأمر بسرعة، وإيده سبقت مخه، وحط مسافة واحدة زيادة:

**تشريح الأمر**

```sh
rm -rf ~/projects/ my-app/node_modules
```

1. `rm`: امسح ([↩ 5.4](../ch05/#s5-4 "النسخ والنقل والمسح: cp و mv و rm")). ومن غير Trash: الملف مش بيروح أي حتة، المكان بتاعه بيتعلّم "فاضي" وخلاص.
2. `-rf`: `-r` كل اللي جوه، و `-f` Force: متسألش ومتشتكيش لو حاجة مش موجودة. الاتنين مع بعض = ولا سؤال ولا تحذير.
3. `~/projects/`: المصيبة: **مسافة** بالغلط قبل my-app، فبقى عندنا Argumentين ([↩ 2.1](../ch02/#s2-1 "الشكل العام لأي أمر")). الأول هو `~/projects/` كله! كل مشاريعك.
4. `my-app/node_modules`: والتاني ده (نسبي للفولدر الحالي، وغالباً مش موجود، و `-f` هتسكت عنه). القصد كان `~/projects/my-app/node_modules` بس.

ومفيش `sudo` هنا خالص! ملفاتك إنت ملكك، فـ rm مش محتاج أي صلاحية زيادة عشان يمسحها. ونفس الغلطة على سيرفر بـ sudo: `sudo rm -rf /var/www/ site` = الموقع كله.

**طرق rm -rf بيمسح حاجات مش قصدك**

| الأمر | ليه خطير |
|---|---|
| `rm -rf "$DIR/"` | لو `DIR` فاضي أو اسمه غلط، بقى `rm -rf /` (حصلت فعلاً في Script تسطيب Steam على Linux سنة 2015 ومسحت ملفات ناس). الحل: `set -u` و `${DIR:?}` ([↩ 12.7](../ch12/#s12-7 "الوضع الصارم: set -euo pipefail و trap")) |
| `rm -rf ~ /tmp/x` | مسافة بعد `~` = الـ home كله: Desktop و Documents و Photos و ~/Library |
| `cd /x ; rm -rf *` | لو الـ cd فشل، المسح حصل في المجلد الحالي. استخدم `&&` ([↩ 7.7](../ch07/#s7-7 "الـ Exit Codes و && و \|\| و ;")) |
| `rm -rf .*` | قديماً كان بيطابق `..` ويطلع للأب؛ الإصدارات الحديثة من bash و rm بتمنعها، بس متعتمدش على كده |
| `rm -rf /*` | rm بيرفض `rm -rf /` على الماك و Linux، لكن `/*` بيتوسع لـ `/Applications /Users /bin ...` فالحماية **مبتشتغلش** ([↩ 7.4](../ch07/#s7-4 "الـ Globbing: النجمة وأخواتها")) |

:::note[طب و SIP مش بيحميني؟]
SIP ([↩ 6.8](../ch06/#s6-8 "SIP و Full Disk Access: حتى root ليه حدود")) ومعاه الـ System volume اللي للقراية بس ([↩ 4.6](../ch04/#s4-6 "الديسكات والمساحة")) بيحموا **macOS نفسه**: `/System` و `/bin` و `/usr` (ماعدا `/usr/local`). فلو حد عمل `sudo rm -rf /*` على الماك، الماك نفسه غالباً هيفضل يقوم. بس كل حاجة **بتاعتك**: `/Users` و `/Applications` و `/opt/homebrew` و `/Library`، مش محمية خالص وهتتمسح. يعني SIP بيحمي البيت، مش العفش. والعفش حمايته الوحيدة **Backup**: فعّل Time Machine (تحت).
:::

:::note[--preserve-root على Linux]
GNU coreutils من سنين بيرفض `rm -rf /` إلا لو كتبت `--no-preserve-root` صراحة. وعلى Ubuntu 25.10 وما بعده اللي بقى بيستخدم rust-coreutils (uutils) لأوامر كتير، الحماية دي موجودة برضه، بس الفكرة: **الحماية بتغطي حالة واحدة بس**، وعادة الأمان عندك أهم.
:::

## 15.2 dd: الـ Disk Destroyer

يوم ما هتحتاج تعمل فلاشة Ubuntu عشان تسطبه على لابتوب قديم أو Raspberry Pi، هتلاقي الشرح بيقولك استخدم `dd`. وهنا لازم تبقى صاحي جداً، لأن dd أخطر أمر في الكتاب ده: بيكتب على Disk كامل، Byte بـ Byte، من غير ما يسأل ومن غير ما يفهم إنت بتكتب على إيه. أول خطوة على الماك: اعرف الفلاشة اسمها إيه بالظبط.

```sh title="Terminal"
$ diskutil list external
/dev/disk4 (external, physical):
   #:                       TYPE NAME                    SIZE       IDENTIFIER
   0:     FDisk_partition_scheme                        *32.0 GB    disk4
   1:             Windows_FAT_32 USBSTICK                32.0 GB    disk4s1
```

شوف كلمة `external, physical` والحجم (32 جيجا = الفلاشة). الـ SSD الداخلي بتاع الماك غالباً `disk0`، وحواليه حاجات زي `disk3` (`synthesized`) دي الـ APFS Containers بتاعة النظام. أي رقم غير الفلاشة = متلمسوش. والأحسن: اعمل `diskutil list` من غير الفلاشة، وبعدين ركّبها واعمله تاني، وشوف إيه الجديد.

**تشريح الأمر**

```sh
diskutil unmountDisk /dev/disk4 && sudo dd if=ubuntu.iso of=/dev/rdisk4 bs=4m
```

1. `diskutil unmountDisk /dev/disk4`: فك ربط كل الـ Partitions بتاعة الفلاشة (من غير ما تطلّعها)، لأن الماك مش هيسيب dd يكتب على Disk مفتوح.
2. `dd`: انسخ Bytes خام من مكان لمكان. أسلوب الـ Arguments قديم `key=value` من غير شَرطة خالص.
3. `if=ubuntu.iso`: Input File: المصدر.
4. `of=/dev/rdisk4`: Output File: الوجهة، وهنا **Disk كامل**. الـ `r` قبل disk = Raw: طريق مباشر للجهاز من غير Cache الماك، وبيخلي الكتابة أسرع بكتير. لو كتبت رقم غلط، الـ Disk ده اتمسح في ثواني ومفيش سؤال. عشان كده اسمه الشعبي Disk Destroyer.
5. `bs=4m`: Block size: اقرا واكتب 4 ميجا كل مرة. على الماك بحرف صغير `m` (و GNU dd بيكتبها `4M`).

dd ساكت تماماً وهو شغال. عايز تعرف وصل لفين؟ اضغط <kbd>Ctrl+T</kbd>: ده بيبعت Signal اسمها `SIGINFO` (موجودة في BSD والماك ومش في Linux)، و dd بيرد بيطبع وصل كام Byte. ولما يخلص: `diskutil eject /dev/disk4`.

:::note[dd على Linux]
**تشريح الأمر**

```sh
sudo dd if=ubuntu.iso of=/dev/sdb bs=4M status=progress conv=fsync
```

1. `dd`: انسخ Bytes خام من مكان لمكان. أسلوب الـ Arguments قديم `key=value` من غير شَرطة خالص.
2. `if=ubuntu.iso`: Input File: المصدر.
3. `of=/dev/sdb`: Output File: الوجهة، وهنا **جهاز تخزين كامل** (فلاشة). لو كتبت `/dev/sda` بالغلط (غالباً القرص الأساسي)، النظام كله اتمسح في ثواني، ومفيش سؤال. عشان كده اسمه الشعبي Disk Destroyer.
4. `bs=4M`: Block size: اقرا واكتب 4 ميجا كل مرة (أسرع من الافتراضي 512 Byte).
5. `status=progress`: اعرض التقدم (GNU dd).
6. `conv=fsync`: اتأكد إن البيانات اتكتبت فعلاً على الجهاز قبل ما تخلص.

وقبلها: `lsblk -o NAME,SIZE,MODEL,MOUNTPOINTS` عشان تعرف أي جهاز هو الفلاشة بالحجم والموديل (المقابل لـ `diskutil list`).
:::

:::tip[قبل أي dd]
اعرف الفلاشة بالحجم و `external`، ويُفضّل تشيلها وترجعها وتشوف أنهي اسم اختفى وظهر. وفكّر في أداة برسومات (balenaEtcher، `brew install --cask balenaetcher`) لو مش مضطر، بتمنعك تختار الـ Disk الداخلي أصلاً.
:::

## 15.3 chmod -R 777 و chown -R على النظام

**تشريح الأمر**

```sh
sudo chmod -R 777 /
```

1. `sudo chmod`: غيّر الصلاحيات كـ root ([↩ 6.2](../ch06/#s6-2 "chmod: تغيير الصلاحيات")).
2. `-R`: على كل حاجة جوه.
3. `777`: أي حد يقرا ويكتب ويشغّل أي حاجة. وكمان بيشيل الـ setuid من أوامر زي `sudo` و `passwd`.
4. `/`: النظام كله. النتيجة على Linux: sudo يرفض يشتغل (<em>/etc/sudoers is world writable</em>)، و SSH يرفض المفاتيح، وفي حالات كتير الحل الوحيد إعادة تسطيب. وعلى الماك SIP هيمنعه من ملفات النظام المحمية، بس كل اللي مش محمي (`/Users` و `/Library` و `/private/etc` و `/opt/homebrew`) هيتبهدل، وحاجات زي sudo و ssh هتبدأ ترفض تشتغل.

والنسخة "الماكية" الأشهر من الغلطة دي: نصايح قديمة على النت بتقول `sudo chown -R $(whoami) /usr/local` أو `sudo chmod -R 777 /usr/local` عشان Homebrew يشتغل. على ماك Apple Silicon ده ملوش أي لازمة أصلاً (Homebrew في `/opt/homebrew`، [↩ 11.2](../ch11/#s11-2 "تسطيب Homebrew نفسه"))، والـ 777 خطر في أي حتة.

و `777` حتى على مجلد واحد غلط: أي برنامج أو مستخدم على الجهاز (أو أي ثغرة في موقعك) يقدر يعدّل ملفاتك. لو حاجة "مش شغالة غير بـ 777"، المشكلة في **المالك** غالباً، صلّحها بـ `chown` وصلاحية مناسبة ([↩ 6.3](../ch06/#s6-3 "chown و chgrp: مين المالك؟")). ونفس الخطر في `sudo chown -R ahmed /usr`: هيكسر برامج النظام.

## 15.4 الـ Fork Bomb

ده "أمر" مشهور بيتبعت كنكتة في المنتديات. شكله رموز بريئة، بس بيخلي الجهاز يقف في ثواني.

**تشريح الأمر**

```sh
:(){ :|:& };:
```

1. `:`: اسم دالة! الـ `:` حرف مسموح في أسماء الدوال في bash. يعني ده زي `bomb` بالظبط.
2. `()`: تعريف دالة ([↩ 12.5](../ch12/#s12-5 "الدوال")).
3. `{`: بداية جسم الدالة.
4. `:|:`: الدالة بتنادي نفسها، وتعمل Pipe لنسخة تانية من نفسها ([↩ 7.3](../ch07/#s7-3 "الـ Pipe |: ركّب الأوامر")). يعني كل نسخة بتعمل نسختين.
5. `&`: في الخلفية، عشان الـ Shell ميستناش ([↩ 9.4](../ch09/#s9-4 "الخلفية: & و jobs و fg و bg و nohup")).
6. `};`: نهاية الدالة.
7. `:`: شغّلها. 1 ← 2 ← 4 ← 8 … لحد ما جدول العمليات يتملي والجهاز ميقدرش يشغّل ولا حتى `kill`.

بالشكل المقروء: `bomb() { bomb | bomb & }; bomb`. الحماية: حد أقصى لعدد العمليات لكل مستخدم. على الماك الحد ده موجود أصلاً من الـ Kernel: `sysctl kern.maxprocperuid` بيقولك الرقم (غالباً بضعة آلاف)، و `ulimit -u` بيعرض الحد في الـ Shell بتاعك. فالماك مش هيموت خالص، بس هيبقى بطيء جداً ومش هتقدر تفتح ولا برنامج لحد ما تعمل Restart. وعلى Linux: `ulimit -u 4096`، أو `nproc` في `/etc/security/limits.conf`، و systemd بيحط حد افتراضي للـ Tasks لكل مستخدم في توزيعات كتير.

## 15.5 ‎\> اللي بيمسح من غير ما يسأل

قعدت ساعة تظبط `~/.zshrc` بتاعك: Aliases ودوال و Prompt بالألوان. وبعدين عايز تضيف alias واحد بسرعة، فكتبت `echo "alias gs='git status'" > ~/.zshrc`. علامة `>` واحدة بدل اتنين. وكل شغل الساعة راح، والملف فيه سطر واحد بس. ومفيش Undo.

**Redirection ممكن تمسح ملف**

| الأمر | اللي بيحصل |
|---|---|
| `echo "x" > ~/.zshrc` | كنت عايز تضيف سطر، الملف كله اتمسح وبقى فيه x. الصح `>>` |
| `sort f > f` | الملف بيتفضى قبل ما يتقري ([↩ 7.2](../ch07/#s7-2 "الـ Redirection: وجّه الـ Streams")) |
| `> important.log` | سطر لوحده = فضّي الملف فوراً |
| `cmd > /dev/disk4` | كتابة على القرص الخام زي dd (على Linux `/dev/sda`) |
| `crontab -r` | مش Redirection بس جنب `-e` على الكيبورد: بيمسح كل مهام cron من غير سؤال |

**تشريح الأمر**

```sh
setopt noclobber
```

1. `setopt`: Builtin في zsh: فعّل Option (و `unsetopt` تقفلها). حطه في `~/.zshrc` ([↩ 13.1](../ch13/#s13-1 "مين بيقرا إيه وإمتى؟")).
2. `noclobber`: خلي `>` ترفض تكتب فوق ملف موجود: zsh هيقولك `zsh: file exists: notes.txt`. ولو قاصد تكتب فوقه: `>|` أو `>!` ([↩ 7.2](../ch07/#s7-2 "الـ Redirection: وجّه الـ Streams")).

:::note[في bash]
**تشريح الأمر**

```sh
set -o noclobber
```

1. `set -o`: فعّل Option في الـ Shell (و `set +o` تقفلها؛ الـ `+` هنا عكس المتوقع: يعني "اقفل").
2. `noclobber`: خلي `>` ترفض تكتب فوق ملف موجود: `cannot overwrite existing file`. ولو قاصد: `>|`.
:::

## 15.6 curl | sh: تشغيل Script من النت

افتكر سطر تسطيب Homebrew في فصل الحزم ([↩ 11.2](../ch11/#s11-2 "تسطيب Homebrew نفسه")): `/bin/bash -c "$(curl -fsSL ...)"`. ونفس الشكل هتلاقيه في تسطيب oh-my-zsh و nvm و Bun و Deno و Rust. سطر واحد، تلزقه، ويتسطب كل حاجة. سهل جداً. وده بالظبط اللي بيخليه خطير لو المصدر مش موثوق:

**تشريح الأمر**

```sh
curl -fsSL https://example.com/install.sh | sudo bash
```

1. `curl -fsSL https://...`: نزّل الـ Script ([↩ 10.2](../ch10/#s10-2 "curl و wget: كلّم السيرفرات")).
2. `|`: وابعته على طول...
3. `sudo bash`: ...لـ bash بصلاحيات root ينفذه **من غير ما تشوفه**. أي حد يتحكم في الموقع (أو في الطريق لو مش HTTPS) يقدر يعمل أي حاجة في جهازك. ولو التحميل اتقطع في النص، ممكن يتنفذ نص سطر (`rm -rf /usr/local/x` يتقطع لـ `rm -rf /usr`).

```sh title="الطريقة الآمنة"
curl -fsSLo install.sh https://example.com/install.sh
less install.sh                      # اقراه
shasum -a 256 install.sh             # قارنه بالـ Checksum المنشور (على Linux: sha256sum)
bash install.sh                      # من غير sudo لو ينفع
```

:::caution[curl بيعدّي من Gatekeeper]
افتكر علامة `com.apple.quarantine` ([↩ 6.7](../ch06/#s6-7 "حماية الماك الزيادة: الـ Extended attributes والـ Quarantine")): المتصفح بيحطها على أي حاجة بتنزل، فالماك يفحصها ويسألك قبل أول تشغيل. أما `curl` فمبيحطهاش. يعني أي حاجة بتنزل بـ curl وتشغلها، الماك **مش هيفحصها ولا هيسألك**. إنت لوحدك المسؤول. وده سبب زيادة إنك تقرا قبل ما تشغّل.
:::

:::note[مش كل curl | sh شر]
مشاريع معروفة كتير بتستخدمه (Homebrew و oh-my-zsh و rustup)، والـ Scripts بتاعتهم عادة بتتحط جوه دالة بتتنادى في آخر سطر عشان مشكلة التحميل الناقص. الفكرة: اعرف المصدر، و HTTPS، واقرا لو تقدر، و **متلزقش أوامر من مواقع مش معروفة في الـ Terminal**. حتى اللصق نفسه ممكن يخدعك (نص مخفي في الصفحة)، فالـ Terminals الحديثة بتدعم Bracketed paste اللي بيمنع التنفيذ لحد ما تدوس Enter.
:::

## 15.7 قائمة الحماية

**عادات وأدوات بتحميك**

| الحماية | إزاي |
|---|---|
| شوف قبل ما تنفذ | `echo rm *.log`، و `ls` بنفس الـ Glob الأول ([↩ 7.4](../ch07/#s7-4 "الـ Globbing: النجمة وأخواتها")) |
| Dry run | `rsync -n` و `find` من غير `-delete` و `sed` من غير `-i` و `brew cleanup -n` (وعلى السيرفر `apt -s`) |
| اسأل قبل المسح | `alias rm='rm -I' cp='cp -i' mv='mv -i'` ([↩ 13.2](../ch13/#s13-2 "الـ Aliases: اختصارات")) |
| سلة مهملات | على الماك `brew install trash` وبعدين `trash file` بدل rm، والملف يروح الـ Trash بتاع Finder وترجعه من هناك ([↩ 5.4](../ch05/#s5-4 "النسخ والنقل والمسح: cp و mv و rm")). على Linux `trash-put` (trash-cli) أو `gio trash` |
| Scripts آمنة | `set -euo pipefail` و `"$var"` و `${var:?}` و shellcheck ([↩ 12.7](../ch12/#s12-7 "الوضع الصارم: set -euo pipefail و trap")) |
| Prompt واضح | اسم الجهاز ولون أحمر لما تكون root أو على Production ([↩ 13.6](../ch13/#s13-6 "الـ Prompt على مزاجك")) |
| أقل صلاحيات | sudo للأمر اللي محتاجه بس، ومتشتغلش كـ root |
| Backups | على الماك **Time Machine** على Disk خارجي (System Settings ← General ← Time Machine)، ومن الـ Terminal: `tmutil startbackup` و `tmutil listbackups`، و `tmutil localsnapshot` بياخد APFS Snapshot في ثانية قبل أي حاجة خطيرة. والقاعدة العامة: نسخ **مجرّبة** (3-2-1: 3 نسخ، على 2 نوع وسائط، 1 بره المكان)، وعلى السيرفرات Snapshots (Btrfs و ZFS و LVM) |
| مسارات مطلقة | في الأوامر الخطيرة اكتب المسار كامل بدل الاعتماد على المجلد الحالي |
| استنى ثانية | قبل Enter على أي أمر فيه `rm` أو `dd` أو `>` أو `-R` أو `sudo`: اقرا السطر تاني |

:::tip[ملخص الفصل]
- `rm -rf` مفيهوش رجعة ولا Trash: خاف من المسافات والمتغيرات الفاضية و `;`. و SIP بيحمي النظام مش ملفاتك.
- `dd of=` غلط = قرص كامل اتمسح؛ `diskutil list` الأول (و `lsblk` على Linux)، و `/dev/rdiskN` و <kbd>Ctrl+T</kbd> للتقدم.
- 777 مش حل أبداً؛ صلّح المالك.
- الـ Fork bomb دالة بتنادي نفسها مرتين في الخلفية؛ الحماية `ulimit -u`.
- `>` بيمسح، و `setopt noclobber` بيحميك.
- نزّل ← اقرا ← شغّل، بدل `curl | sudo bash`، وافتكر إن curl بيعدّي من Gatekeeper. و Time Machine هو شبكة الأمان الأخيرة.
:::

### صح ولا غلط؟

1. GNU rm بيرفض `rm -rf /*` زي ما بيرفض `rm -rf /`.
2. `set -u` ممكن يمنع مسح بسبب متغير فاضي.
3. الـ `:` في الـ Fork bomb هي اسم دالة.
4. SIP بيحمي ملفاتك في `~/Documents` من `rm -rf`.

### أسئلة مراجعة

1. اشرح بالظبط ليه `rm -rf "$DIR/"*` خطير، واكتب نسخة آمنة منه.
2. إزاي تتأكد من اسم الفلاشة قبل `dd` على الماك؟ وإيه الفرق بين `/dev/disk4` و `/dev/rdisk4`؟
3. واحد قالك "اعمل chmod 777 والموقع هيشتغل"، إيه ردك وإيه البديل؟
4. اكتب خطوات تشغيل Script تسطيب من الإنترنت بأمان.

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** فعّل `setopt noclobber` وجرّب `>` على ملف موجود، وبعدين `>|`.
2. **[متوسط]** شوف بعينك التوسيع من غير خطر: اكتب `DIR=""; echo rm -rf "$DIR/"*` (بـ `echo` بس!)، وبعدين جرّب نفس السطر بعد `set -u` و `unset DIR`، وبعدين بـ `"${DIR:?}"`.
3. **[صعب]** اكتب دالة `saferm` بتنقل الملفات لـ `~/.trash/التاريخ/` بدل ما تمسحها، وترفض تشتغل على `/` أو `$HOME`. (ولو حابب: خليها تنقل لـ `~/.Trash` عشان تظهر في Trash بتاع Finder).
