<small>المرحلة 1 · البداية</small>

قبل أول Commit، Git محتاج يعرف إنت مين، والـ Branch الأولاني اسمه إيه، ويفتحلك أنهي Editor لما يحتاج منك تكتب رسالة. الإعدادات دي بتتعمل مرة واحدة في العمر، ولو اتعملت غلط هتفضل تزعجك. خلينا نسطّب ونظبط صح من أول يوم.

:::note[بعد الفصل ده هتكون عارف]
- تسطيب Git على الـ Mac بـ Homebrew والفرق بينه وبين نسخة Apple
- مستويات الإعداد التلاتة: system و global و local
- ضبط user.name و user.email والإيميل الخاص بتاع GitHub
- ضبط اسم الـ Branch الافتراضي main
- ضبط الـ Editor (VS Code) والخروج من Vim لو اتحبست فيه
- إعدادات مفيدة تانية، وإزاي تجيب المساعدة لأي أمر
:::

<a id="s2-1"></a>

## 2.1 التسطيب على الـ Mac: هل Git عندك أصلاً؟

فيه احتمال كبير إن Git موجود على الـ Mac بتاعك من غير ما تعرف. Apple بتحطه ضمن حاجة اسمها **Command Line Tools** (أدوات المطورين). فقبل ما نسطّب أي حاجة، خلينا نسأل الـ Terminal (الـ zsh اللي اتعودت عليه من كتاب الـ Terminal):

**تشريح الأمر**

```sh
git --version
```

1. `git`: البرنامج.
2. `--version`: Option طويلة (زي ما اتعلمنا، الـ `--` قبل كلمة كاملة). بتطبع رقم النسخة وتخرج.

هيحصل واحد من 3 حاجات. لو طلعلك رقم زي `git version 2.50.1 (Apple Git-155)`، يبقى Git موجود، والكلمة `Apple Git` معناها إنه نسخة Apple اللي جاية مع Command Line Tools، وغالباً أقدم شوية من آخر نسخة. ولو طلعلك شباك بيقولك إن الأمر محتاج Command Line Developer Tools ويعرض تسطّبها، دوس **Install** واستنى كام دقيقة، وده نفس اللي بيعمله الأمر `xcode-select --install`. ولو طلع `command not found` (نادر على الـ Mac)، يبقى نسطّبه بنفسنا.

الطريقة اللي أنصحك بيها: تسطّب Git من **Homebrew**، مدير الحزم اللي شفناه في كتاب الـ Terminal. ميزته إنك بتاخد آخر نسخة، وبتحدّثها بأمر واحد مع باقي أدواتك:

**تشريح الأمر**

```sh
brew install git
```

1. `brew`: Homebrew: مدير الحزم على macOS.
2. `install`: سطّب.
3. `git`: اسم الحزمة (اسمها في Homebrew اسمه `Formula`).

```sh title="Terminal"
$ brew install git
$ which -a git
/opt/homebrew/bin/git
/usr/bin/git
$ git --version
git version 2.56.0
```

لاحظ إن `which -a` لقى نسختين: نسخة Homebrew في `/opt/homebrew/bin` (على أجهزة Apple Silicon، وعلى Intel بتبقى في `/usr/local/bin`)، ونسخة Apple في `/usr/bin`. والـ Shell بيشغّل أول واحدة يلاقيها في الـ `PATH`، وده نفس الكلام اللي شرحناه في أول فصل في كتاب الـ Terminal. لو `git --version` لسه بيقول `Apple Git` بعد التسطيب، يبقى `/opt/homebrew/bin` مش قبل `/usr/bin` في الـ PATH: اتأكد إن السطر `eval "$(/opt/homebrew/bin/brew shellenv)"` موجود في `~/.zprofile`، وافتح Terminal جديد.

:::tip[حدّث Git كل فترة]
`brew upgrade git` بيجيب آخر نسخة. Git بيطلع نسخة جديدة كل 3 شهور تقريباً، وفيها تحسينات وإصلاحات أمنية.
:::

**لو هتسطّب على جهاز تاني (للمرجع)**

| النظام | الأمر | ملاحظة |
|---|---|---|
| macOS | `brew install git` | المفضّل، أو `xcode-select --install` لنسخة Apple |
| Windows | `winget install --id Git.Git -e --source winget` | بييجي معاه Git Bash و Git Credential Manager |
| Ubuntu / Debian | `sudo apt install git` | بعد `sudo apt update` |
| Fedora | `sudo dnf install git` |   |

:::note[لو حابب تتعمق: آخر نسخة وأرقامها]
آخر نسخة مستقرة من Git وقت كتابة الكتاب (أكتوبر 2026) هي **2.56.0**، ونزلت 28 سبتمبر 2026. Git ماشي على أرقام `2.x` من سنة 2014، وكل نسخة Minor جديدة كل حوالي 12 أسبوع. أي نسخة 2.40 أو أحدث فيها كل اللي في الكتاب، والأوامر `git switch` و `git restore` محتاجة 2.23 على الأقل (2019). ونسخة Apple بتتأخر عن الأصلية كام شهر، وعشان كده بنفضّل Homebrew.
:::

## 2.2 git config: 3 مستويات للإعدادات

قبل ما نكتب أول إعداد، محتاجين نفهم حاجة صغيرة: الإعدادات دي بتتحفظ فين؟ تخيل إنك بتشتغل على مشاريعك الشخصية بإيميلك العادي، وفي يوم بدأت تشتغل على مشروع للشغل، وعاوز الـ Commits فيه تبقى بإيميل الشركة. لو الإعداد مكان واحد، هتفضل تغيّره رايح جاي. عشان كده Git بيقرا إعداداته من 3 أماكن متداخلة، زي الدواير جوه بعض، والأقرب للمشروع هو اللي بيكسب:

![مستويات الإعداد: المشروع جوه المستخدم جوه الجهاز.](./assets/ch02-fig1.png)

*مستويات الإعداد: المشروع جوه المستخدم جوه الجهاز.*

**مستويات git config**

| المستوى | الـ Flag | الملف | بيأثر على |
|---|---|---|---|
| System | `--system` | `/etc/gitconfig` | كل المستخدمين على الجهاز (نادراً ما بنلمسه) |
| Global | `--global` | `~/.gitconfig` | إنت، في كل الـ Repos. **ده اللي هنستخدمه دلوقتي** |
| Local | `--local` (الافتراضي) | `.git/config` | Repo واحد بس |

## 2.3 إنت مين؟ user.name و user.email

فاكر لما قلنا إن كل Commit جواه مين عمله؟ الاسم والإيميل دول Git بياخدهم من الإعدادات. ولو معندوش، هيرفض يعمل Commit خالص، أو أسوأ: هيخمّن حاجة زي `sara@Saras-MacBook-Air.local`، وتلاقي تاريخ مشروعك على GitHub باسم غريب ومن غير صورتك. فأول إعدادين في حياتك:

**تشريح الأمر**

```sh
git config --global user.name "Sara Ahmed"
```

1. `git config`: الـ Subcommand اللي بيقرا ويكتب الإعدادات.
2. `--global`: اكتب الإعداد في `~/.gitconfig`، فيتطبق على كل مشاريعك.
3. `user.name`: اسم الإعداد: `section.key`. هنا الـ Section اسمه `user` والمفتاح `name`.
4. `"Sara Ahmed"`: القيمة. الـ Quotes لازمة عشان فيه مسافة.

**تشريح الأمر**

```sh
git config --global user.email "sara@example.com"
```

1. `git config --global`: نفس الكلام: إعداد عام.
2. `user.email`: الإيميل اللي هيتكتب في كل Commit. GitHub بيستخدمه يربط الـ Commit بحسابك ويحط صورتك جنبه.
3. `"sara@example.com"`: القيمة.

:::tip[خصوصية: إيميل noreply بتاع GitHub]
الإيميل ده بيبقى **علني** في تاريخ أي Repo public. لو مش عاوز إيميلك الحقيقي يظهر، GitHub بيديك إيميل خاص من **Settings ← Emails** شكله `12345678+sara@users.noreply.github.com`، استخدمه في `user.email`، وفعّل "Keep my email address private".
:::

عشان تتأكد:

```sh title="Terminal"
$ git config user.name
Sara Ahmed
$ git config --list --show-origin
file:/home/sara/.gitconfig   user.name=Sara Ahmed
file:/home/sara/.gitconfig   user.email=sara@example.com
```

**تشريح الأمر**

```sh
git config --list --show-origin
```

1. `git config`: الإعدادات.
2. `--list`: اعرض كل الإعدادات اللي Git شايفها دلوقتي (من التلات مستويات). اختصارها `-l`.
3. `--show-origin`: جنب كل إعداد، اكتب جاي من أنهي ملف. مفيد جداً لما إعداد "مش راضي يتغير" وتكتشف إنه متعرّف في مكان تاني.

:::tip[حاجة مشتركة: أمر واحد يقرا ويكتب]
`git config key` من غير قيمة = **اقرا**. و `git config key value` = **اكتب**. نفس الفكرة هتشوفها في `git branch` (من غير اسم يعرض، وباسم يعمل) و `git remote` و `git tag` و `git stash`: الأمر من غير Arguments بيعرض، ومعاه بيعمل.
:::

## 2.4 اسم الـ Branch الأولاني: main

لسه مشرحناش الـ Branches (الفصل 7)، بس كفاية دلوقتي تعرف إن كل Repo بيبدأ بـ Branch واحد. زمان اسمه الافتراضي كان `master`، ودلوقتي GitHub ومعظم الأدوات بتستخدم `main` (GitHub غيّره من أكتوبر 2020). خلي Git على جهازك يمشي على نفس الاسم:

**تشريح الأمر**

```sh
git config --global init.defaultBranch main
```

1. `git config --global`: إعداد عام.
2. `init.defaultBranch`: الإعداد اللي `git init` بيقراه عشان يعرف يسمي أول Branch إيه. Section `init` ومفتاح `defaultBranch` (الإعدادات مش حساسة لحالة الحروف، بس بنكتبها كده عشان تتقري).
3. `main`: الاسم.

:::note[دقة: Git 3.0 و main]
من غير الإعداد ده، Git 2.x لسه بيسمي أول Branch `master` وبيطبعلك تنبيه. Git أعلن إن **Git 3.0** هيخلي `main` هو الافتراضي، بس Git 3.0 لسه منزلش. فالإعداد ده لسه مهم.
:::

## 2.5 الـ Editor: افتح VS Code مش Vim

فيه نكتة مشهورة بين المبرمجين: "إزاي تولّد كلام عشوائي؟ حط مبتدئ قدام Vim واطلب منه يخرج". الموضوع ده هيحصلك أول مرة تكتب `git commit` من غير `-m`: Git بيحتاج منك تكتب رسالة، فبيفتح الـ Editor الافتراضي، وعلى الـ Mac ده غالباً **Vim**. وتلاقي شاشة سودا غريبة، والكتابة مش بتظهر، و `Ctrl+C` مش بيعمل حاجة. خلينا نتجنب الموقف ده من الأول، ونخلي Git يفتح VS Code:

**تشريح الأمر**

```sh
git config --global core.editor "code --wait"
```

1. `git config --global`: إعداد عام.
2. `core.editor`: البرنامج اللي Git يفتحه لما يحتاج منك نص.
3. `"code --wait"`: الأمر بتاع VS Code. على الـ Mac لازم تحطه في الـ PATH مرة واحدة: افتح VS Code، و `Cmd+Shift+P`، واكتب `Shell Command: Install 'code' command in PATH`. و `--wait` أهم حتة: بتخلي الـ Terminal **يستنى** لحد ما تقفل التاب. من غيرها Git هيفتكر إنك خلصت وانت لسه بتكتب.

**قيم core.editor الشائعة**

| الـ Editor | القيمة |
|---|---|
| VS Code | `"code --wait"` |
| Cursor | `"cursor --wait"` |
| nano (بسيط جوه الـ Terminal) | `nano` |
| Vim | `vim` |

:::danger[مشكلة: اتحبست في Vim ومش عارف أخرج!]
عملت `git commit` من غير `-m` ولقيت شاشة غريبة ومفيش حاجة بتتكتب.

<strong>الحل:</strong> دوس `Esc` (عشان تخرج لوضع الأوامر)، وبعدين: `i` عشان تبدأ تكتب الرسالة، وبعد ما تخلص `Esc` ثم `:wq` و Enter = Write و Quit (احفظ واخرج). ولو عاوز تلغي الـ Commit: `Esc` ثم `:q!` = اخرج من غير حفظ. وبعدها اضبط `core.editor` عشان متتحبسش تاني.
:::

## 2.6 إعدادات تانية مفيدة

### نهايات السطور (Windows مقابل Mac/Linux)

Windows بينهي السطر بحرفين (`CRLF`)، و macOS و Linux بحرف واحد (`LF`). لو فريق فيه الاتنين، كل ملف هيبان "متغير بالكامل" من غير سبب.

انت على Mac، فالافتراضي عندك LF وكله تمام. بس لو زميل على Windows ابعتلك ملف بـ CRLF، الإعداد ده بيخلي Git يحوّله لـ LF وهو داخل الـ Repo:

**تشريح الأمر**

```sh
git config --global core.autocrlf input
```

1. `core.autocrlf`: تحويل نهايات السطور تلقائياً.
2. `input`: على **macOS و Linux**: حوّل CRLF لـ LF وانت بتحفظ في Git بس، ومتلمسش الملفات وهي طالعة. (وعلى Windows القيمة المناسبة `true`: حوّل لـ LF وانت داخل، ورجّعها CRLF وانت طالع).

:::tip[الأحسن: .gitattributes في المشروع]
الحل اللي بيمشي على الفريق كله مهما كانت إعدادات كل واحد: ملف اسمه `.gitattributes` في المشروع فيه سطر `* text=auto`. Git بيتعامل مع كل الملفات النصية صح تلقائياً.
:::

### سلوك git pull

هنفهم `pull` في الفصل 10، بس Git الحديث بيرفض يعمل `pull` لو الفروع اتفرعت ومقلتلوش يعمل إيه. اختار الأبسط للمبتدئين:

**تشريح الأمر**

```sh
git config --global pull.rebase false
```

1. `pull.rebase`: لما `git pull` يلاقي شغل جديد عندك وعلى السيرفر، يدمجهم إزاي؟
2. `false`: بالـ Merge (الطريقة الأوضح). هنشوف `true` (Rebase) في الفصل 15.

### اختصارات (Aliases)

**تشريح الأمر**

```sh
git config --global alias.lg "log --oneline --graph --all"
```

1. `alias.lg`: اعمل Subcommand جديد اسمه `lg`. زي الـ `alias` في الـ Shell اللي اتعلمناه في كتاب الـ Terminal، بس جوه Git.
2. `"log --oneline --graph --all"`: اللي هيتنفذ لما تكتب `git lg`. (هنشرح كل Flag هنا في الفصل 4).

### ملف ~/.gitconfig بعد كل ده

كل الأوامر اللي فوق كتبت في ملف نصي عادي. تقدر تفتحه بـ `git config --global --edit`:

```ini title="~/.gitconfig"
[user]
    name = Sara Ahmed
    email = 12345678+sara@users.noreply.github.com
[init]
    defaultBranch = main
[core]
    editor = code --wait
    autocrlf = input
[pull]
    rebase = false
[alias]
    lg = log --oneline --graph --all
    st = status -sb
```

1. `[user]`: اسمك وإيميلك (هنا إيميل GitHub الخاص). الـ `[user]` هو الـ Section، و `name` و `email` المفاتيح.
2. `[init]`: أي `git init` يبدأ بـ Branch اسمه main.
3. `[core]`: افتح VS Code واستنى، وظبّط نهايات السطور (input على Mac/Linux).
4. `[pull]`: pull يدمج بالـ Merge.
5. `[alias]`: اختصاراتك: `git lg` و `git st`.

:::note[لو حابب تتعمق: صيغة git config الجديدة]
من **Git 2.46** (يوليو 2024)، `git config` بقى ليه Subcommands واضحة: `git config set --global user.name "Sara"` و `git config get user.name` و `git config list`. الصيغة القديمة اللي في الكتاب لسه شغالة عادي، وهي اللي هتلاقيها في أغلب الشروحات.
:::

## 2.7 إزاي تجيب المساعدة

| الأمر | بيعمل إيه |
|---|---|
| `git help commit` | الشرح الكامل لـ `commit` (نفس `man git-commit`، و `q` للخروج زي `less`). |
| `git commit --help` | نفس اللي فوق. |
| `git commit -h` | ملخص سريع للـ Options في الـ Terminal نفسه (أسرع حاجة لما تنسى Flag). |
| `git help -g` | قايمة بـ Guides مفيدة، زي `git help everyday`. |

:::tip[حاجة مشتركة: -h و --help]
زي ما اتعلمنا في كتاب الـ Terminal: `-h` = ملخص قصير، و `--help` = الدليل الكامل. نفس القاعدة في كل Subcommands بتاعة Git.
:::

:::tip[رسايل Git بتقولك الحل]
أهم عادة هتتعلمها: **اقرا رسايل Git**. معظمها فيها سطر بيبدأ بـ `(use "git ..." to ...)` أو `hint:` بيقولك الأمر اللي محتاجه بالظبط. هنشوف ده في كل فصل.
:::

:::tip[ملخص الفصل]
- `git --version` للتأكد، و `brew install git` على الـ Mac، و `which -a git` يوريك أنهي نسخة بتشتغل.
- الإعدادات على 3 مستويات: system و global و local، والأقرب بيكسب.
- أول 3 إعدادات: `user.name` و `user.email` و `init.defaultBranch main`.
- `core.editor "code --wait"` عشان متتحبسش في Vim (ولو اتحبست: `Esc` ثم `:wq`).
- `git config --list --show-origin` يوريك كل إعداد جاي منين، و `-h` / `--help` للمساعدة.
:::

### صح ولا غلط؟

1. الإعداد اللي بـ `--local` بيغلب اللي بـ `--global`.
2. من غير `--wait`، الـ `code` هيشتغل كـ Editor لـ Git عادي.
3. الإيميل في الـ Commits بيبقى ظاهر لأي حد في الـ Repos الـ public.

### أسئلة مراجعة

1. عاوز إيميل الشغل يظهر في Repo الشغل بس، وإيميلك الشخصي في الباقي. تعمل إيه؟
2. ليه بنضبط `init.defaultBranch` لـ main؟
3. إيه الفرق بين `git commit -h` و `git commit --help`؟
4. إعداد مش راضي يتغير رغم إنك غيرته بـ `--global`. إيه الأمر اللي هيكشف السبب؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** اضبط الإعدادات الأساسية التلاتة وبعدين اعرضهم بـ `git config --global --list`.
2. **[متوسط]** اضبط `core.editor` للـ Editor بتاعك، وجرّب `git config --global --edit`. لازم الملف يتفتح في الـ Editor والـ Terminal يستنى.
3. **[صعب]** اعمل 2 Aliases: `git st` لـ `status -sb`، و `git last` يعرض آخر Commit (`log -1 HEAD --stat`). جرّبهم بعد ما تعمل أول Repo في الفصل الجاي.
