<small>المرحلة 7 · GitHub والـ AI والإنقاذ</small>

الفصل ده مش هتقراه مرة واحدة. ده الفصل اللي هترجعله الساعة 2 بالليل وقلبك بيدق. كل غلطة فيه حصلت لكل واحد اشتغل بـ Git، وكلها ليها حل. هنبدأ ببروتوكول الهدوء، وبعدين الغلطات متقسمة حسب الموقف، وكل واحدة بالرسالة اللي هتشوفها والحل خطوة بخطوة.

:::note[بعد الفصل ده هتكون عارف]
- بروتوكول أول 60 ثانية لما حاجة تبوظ
- Commit على Branch غلط، أو رسالة أو Author غلط
- Detached HEAD، وشغل ضاع، و Merge أو Rebase نص نص
- رسائل الـ push والـ pull المشهورة وحلها
- ملف كبير، .DS\_Store، ومشكلة git init في الـ Home
:::

<a id="s19-1"></a>

## 19.1 أول 60 ثانية: متعملش حاجة

أكتر حاجة بتبوّظ Repos مش الغلطة الأولى، دي الغلطة التانية: تتخض، تنسخ أول أمر من أول نتيجة في Google فيه `--force` أو `reset --hard`، وتشغّله. الخبر الحلو اللي اتعلمناه في [↩ 16.2](../ch16/#s16-2 "git reflog: دفتر تحركات HEAD"): أي حاجة اتعملها Commit تقريباً مستحيل تضيع. فخد نفس، وامشي بالترتيب ده:

1. <strong>اقرا `git status` كويس.</strong> Git بيقولك انت فين (أنهي Branch، في نص Merge ولا Rebase)، وغالباً بيقولك الأمر اللي يطلّعك.
2. **اعمل نسخة احتياطي من الفولدر كله** لو قلقان: `cp -R weather weather-backup`. كده أي حاجة تجرّبها مفيهاش مخاطرة.
3. <strong>شوف التاريخ:</strong> `git log --oneline --graph --all -10` و `git reflog -10`.
4. **دوّر على حالتك في الفصل ده** بالرسالة اللي ظاهرة لك.
5. <strong>أي أمر فيه `--hard` أو `--force` أو `clean -f`</strong>، افهمه الأول. التلاتة دول بيمسحوا حاجات مش متسجّلة.

:::tip[الحاجة الوحيدة اللي ممكن تضيع بجد]
التعديلات اللي **عمرها ما اتعملها Commit ولا add**. دي Git مش شايفها أصلاً، فلو `restore` أو `reset --hard` مسحها، مفيش reflog يرجّعها. عشان كده: Commit كتير، حتى لو "wip". تقدر تنضّفهم بعدين بـ `rebase -i`.
:::

<a id="s19-2"></a>

## 19.2 غلطات في الـ Commits

أشهر موقف: عملت 3 Commits لـ Feature جديدة وانت فاكر إنك على `feature/search`، وبصيت لقيت نفسك على `main`. ولسه ماعملتش push. الفكرة إن الـ Branch مجرد لافتة ([↩ 7.2](../ch07/#s7-2 "الـ Branch = لافتة على Commit")): نحط لافتة جديدة على الـ Commits دي، ونرجّع لافتة main مكانها.

:::danger[مشكلة: عملت Commits على main بدل Branch جديدة (مفيش push)]
الـ Commits المفروض تكون في Branch لوحدها.

<strong>الحل:</strong>

```sh title="Terminal"
git branch feature/search        # لافتة جديدة على الـ commits دي
git reset --hard origin/main     # رجّع main لمكانه على GitHub
git switch feature/search        # كمّل شغلك هنا
```

الـ Working directory لازم يكون نضيف قبل `reset --hard`. ولو main مالوش origin، بدل `origin/main` استخدم `HEAD~3` (عدد الـ Commits).
:::

:::danger[مشكلة: عملت Commit على Branch غلط (موجودة)]
Commit واحد المفروض يروح `feature/nav` بس اتعمل على `feature/search`.

<strong>الحل:</strong> انقله بـ cherry-pick ([↩ 15.7](../ch15/#s15-7 "git cherry-pick: Commit واحد بعينه")) وبعدين شيله من المكان الغلط:

```sh title="Terminal"
git log --oneline -1             # خد الـ SHA، مثلاً a1b2c3d
git switch feature/nav
git cherry-pick a1b2c3d
git switch feature/search
git reset --hard HEAD~1
```
:::

:::danger[مشكلة: رسالة الـ Commit غلط، أو نسيت ملف]
آخر Commit رسالته `fix` بس، أو نسيت تضيف `style.css`.

<strong>الحل:</strong> `git commit --amend -m "fix(search): trim city input"`. ولو ملف ناقص: `git add style.css` ثم `git commit --amend --no-edit` ([↩ 6.3](../ch06/#s6-3 "git commit --amend: صلّح آخر Commit")). ولو Commit أقدم: `git rebase -i HEAD~3` واختار `reword` أو `fixup`. ولو اتعمله push، هتحتاج `git push --force-with-lease`، وعلى Branch بتاعتك بس.
:::

:::danger[مشكلة: الـ Commits طالعة باسم أو إيميل غلط]
على GitHub الـ Commits مش مربوطة بحسابك، أو طالعة باسم الـ Laptop.

<strong>الحل:</strong> الأول صلّح الإعداد ([↩ 2.3](../ch02/#s2-3 "إنت مين؟ user.name و user.email")) والإيميل لازم يكون مضاف لحسابك على GitHub. وبعدين صلّح آخر Commit:

```sh title="Terminal"
git commit --amend --reset-author --no-edit
```

ولآخر 5 Commits مرة واحدة:

```sh title="Terminal"
git rebase --exec "git commit --amend --reset-author --no-edit" HEAD~5
```

`--reset-author` = خد الاسم والإيميل من الإعدادات الحالية، و `--exec` = شغّل الأمر ده بعد كل Commit في الـ Rebase.
:::

:::danger[مشكلة: عملت push لـ Commit بايظ على main]
الموقع باظ، والـ Commit على GitHub، وزمايلك عملوا pull.

<strong>الحل:</strong> متعملش reset ولا force push على main. اعمل `git revert <sha>` ([↩ 6.5](../ch06/#s6-5 "git revert: الإلغاء الآمن")): Commit جديد بيلغي التاني، و push عادي. التاريخ بيفضل صادق ومحدش يتأذي.
:::

<a id="s19-3"></a>

## 19.3 "شغلي ضاع!"

جملة بتتقال كتير، ومعظم المرات مش حقيقية. الشغل غالباً مستخبي في حتة من التلاتة دول: Commit مش عليه لافتة، أو Stash، أو Branch تانية.

:::danger[مشكلة: HEAD detached وعملت Commits]
`git status` بيقول `HEAD detached at 3f2a1bc` وانت عملت شغل.

<strong>الحل:</strong> حط لافتة على مكانك قبل ما تتحرك: `git switch -c save-my-work` ([↩ 7.6](../ch07/#s7-6 "الـ Detached HEAD: متتخضش")). ولو اتحركت خلاص وقفلت الـ Commits: Git طبع لك تحذير فيه الـ SHA، أو دوّر عليه في `git reflog`، وبعدين `git branch save-my-work <sha>`.
:::

:::danger[مشكلة: reset --hard أو مسحت Branch بالغلط]
كان فيه Commits وراحت.

<strong>الحل:</strong> `git reflog`، دوّر على السطر اللي قبل الغلطة، و `git reset --hard HEAD@{1}` أو `git branch rescue <sha>` ([↩ 16.2](../ch16/#s16-2 "git reflog: دفتر تحركات HEAD")). Branch اتمسحت؟ Git طبع الـ SHA وقت المسح: `Deleted branch x (was 9c1e2d4)`، فـ `git branch x 9c1e2d4`.
:::

:::danger[مشكلة: عملت stash ومش لاقي التعديلات]
الملفات رجعت قديمة والتعديلات مش موجودة.

<strong>الحل:</strong> `git stash list`، وبعدين `git stash show -p stash@{0}` تتأكد إنه هو، و `git stash pop`. وبتاخد بالك إنك على نفس الـ Branch اللي عملت عليها الـ Stash ([↩ 14.2](../ch14/#s14-2 "أوامر الـ Stash")).
:::

## 19.4 محبوس في نص عملية

الـ Prompt عندك في zsh ممكن يكتب `main|MERGING` أو `REBASE 2/5`، أو `git status` يقول `You have unmerged paths`. انت في نص عملية، وليك طريقين: تكمّل أو تلغي. والإلغاء دايماً بيرجّعك لحالة ما قبل البداية بالظبط.

**طرق الخروج من كل عملية**

| انت في نص | تكمّل (بعد حل الـ Conflicts و add) | تلغي |
|---|---|---|
| merge | `git commit` | `git merge --abort` |
| rebase | `git rebase --continue` | `git rebase --abort` |
| cherry-pick | `git cherry-pick --continue` | `git cherry-pick --abort` |
| revert | `git revert --continue` | `git revert --abort` |
| stash pop بـ Conflict | حل، `add`، ثم `git stash drop` | `git reset --merge` (الـ Stash لسه موجود) |
| bisect | — | `git bisect reset` |

:::danger[مشكلة: error: Your local changes would be overwritten by checkout]
بتحاول `switch` أو `pull` وعندك تعديلات مش متسجّلة هتتلخبط.

<strong>الحل:</strong> يا Commit، يا `git stash` ثم العملية ثم `git stash pop`. ولو التعديلات دي مش عاوزها: `git restore .`.
:::

## 19.5 رسائل الـ push والـ pull

الجزء ده بالرسالة اللي هتشوفها، عشان تدوّر عليها بعينك على طول.

:::danger[مشكلة: ! [rejected] main -> main (fetch first)]
زميل (أو انت من جهاز تاني أو من موقع GitHub) عمل push قبلك.

<strong>الحل:</strong> `git pull` (أو `git pull --rebase`)، وحل أي Conflict، وبعدين `git push` ([↩ 10.7](../ch10/#s10-7 "لما الـ push يترفض")). متعملش `--force` هنا: هيمسح شغل زميلك.
:::

:::danger[مشكلة: fatal: Need to specify how to reconcile divergent branches]
الـ pull رفض يشتغل لأن فيه Commits عندك وعلى GitHub الاتنين.

<strong>الحل:</strong> Git عاوزك تختار مرة واحدة: `git config --global pull.rebase false` (merge، اللي ظبطناه في [↩ 2.6](../ch02/#s2-6 "إعدادات تانية مفيدة")) أو `true` (rebase). أو للمرة دي بس: `git pull --no-rebase` أو `git pull --rebase`.
:::

:::danger[مشكلة: fatal: refusing to merge unrelated histories]
عملت Repo على GitHub بـ README، وعملت `git init` عندك كمان، وحاولت تعمل pull. الاتنين ملهمش أصل مشترك.

<strong>الحل:</strong> `git pull origin main --allow-unrelated-histories`، حل أي Conflict في README، و push. والمرة الجاية: يا تعمل Repo فاضي على GitHub (من غير README)، يا تبدأ بـ `clone`.
:::

:::danger[مشكلة: error: src refspec main does not match any]
بتعمل `git push -u origin main` والـ Branch "مش موجودة".

<strong>الحل:</strong> يا إما مفيش أي Commit لسه (اعمل واحد)، يا إما الـ Branch اسمها `master`: شوف بـ `git branch`، وغيّر الاسم بـ `git branch -m main` ([↩ 2.4](../ch02/#s2-4 "اسم الـ Branch الأولاني: main")).
:::

:::danger[مشكلة: git@github.com: Permission denied (publickey)]
الـ SSH مش شغال.

<strong>الحل:</strong> اختبر: `ssh -T git@github.com`. لو فشل: اتأكد إن المفتاح موجود (`ls ~/.ssh`)، وإنه في الـ Agent (`ssh-add --apple-use-keychain ~/.ssh/id_ed25519`)، وإن الـ Public key متضاف في GitHub ← Settings ← SSH keys ([↩ 9.4](../ch09/#s9-4 "الطريق 1: مفتاح SSH")). وتأكد إن الـ Remote بـ SSH: `git remote -v`.
:::

:::danger[مشكلة: remote: Support for password authentication was removed]
كتبت باسوورد GitHub في الـ Terminal.

<strong>الحل:</strong> من 2021 مينفعش باسوورد. استخدم `gh auth login` أو Token ([↩ 9.5](../ch09/#s9-5 "الطريق 2: HTTPS على الـ Mac بالـ Keychain")). ولو الـ Keychain حافظ حاجة قديمة غلط، امسحها من Keychain Access (ابحث عن github.com) وجرّب تاني.
:::

:::danger[مشكلة: Updates were rejected because the tip of your current branch is behind (بعد rebase)]
عملت rebase لـ Branch كان ليها push قبل كده.

<strong>الحل:</strong> لو الـ Branch بتاعتك لوحدك: `git push --force-with-lease` ([↩ 15.3](../ch15/#s15-3 "القاعدة الذهبية")). لو حد تاني شغال عليها: اتكلم معاه الأول.
:::

## 19.6 مشاكل الملفات

:::danger[مشكلة: File is 120.00 MB; this exceeds GitHub's file size limit of 100.00 MB]
GitHub بيرفض أي ملف أكبر من 100 MB (وبيحذّر من 50 MB). غالباً فيديو أو ملف Build أو Database.

<strong>الحل:</strong> المشكلة إن الملف في Commit، فمسحه في Commit جديد مش كفاية (الـ push بيبعت التاريخ كله). لو في آخر Commit: `git rm --cached demo.mp4` ثم `git commit --amend --no-edit`. لو أقدم: `git reset --soft origin/main` (يرجّع كل الـ Commits اللي ماتبعتتش للـ Staging)، وشيل الملف بـ `git rm --cached`، وضيفه للـ .gitignore، واعمل Commit من جديد.
:::

:::note[لو حابب تتعمق: Git LFS]
لو محتاج فعلاً ملفات كبيرة في الـ Repo (فيديوهات، تصميمات)، فيه **Git LFS** (Large File Storage): `brew install git-lfs` ثم `git lfs install` و `git lfs track "*.mp4"`. الـ Repo بيحفظ ملف صغير فيه "مؤشر"، والملف الحقيقي بيترفع على سيرفر LFS. GitHub بيدي مساحة LFS محدودة مجاناً.
:::

:::danger[مشكلة: .DS_Store في كل حتة]
macOS بيعمل ملف `.DS_Store` في كل فولدر بتفتحه في Finder، وظهر في `git status` أو اتعمله Commit.

<strong>الحل:</strong> مرة واحدة على جهازك: ضيفه للـ Global ignore ([↩ 5.4](../ch05/#s5-4 ".gitignore عام لكل مشاريعك")). ولو اتعمله Commit: `git rm --cached -r --ignore-unmatch '*.DS_Store'` ثم Commit.
:::

:::danger[مشكلة: غيرت Logo.png لـ logo.png و Git مش شايف]
نظام ملفات الـ Mac مبيفرقش بين الحروف الكبيرة والصغيرة، بس GitHub Pages و Linux بيفرقوا، فالصورة تبوظ على الموقع.

<strong>الحل:</strong> غيّر الاسم من خلال Git: `git mv Logo.png logo.png` ثم Commit ([↩ 5.7](../ch05/#s5-7 "git rm و git mv")).
:::

:::danger[مشكلة: git status بيعرض كل ملفات الـ Mac!]
كتبت `git status` في فولدر عادي، وطلع لك `Desktop/` و `Documents/` و `Library/` كلهم Untracked. معناها إنك عملت `git init` مرة في الـ Home بالغلط، والـ Home كله بقى Repo.

<strong>الحل:</strong> اتأكد الأول: `git rev-parse --show-toplevel`. لو طبع `/Users/sara` (الـ Home نفسه) يبقى هو ده. امسح الـ `.git` اللي هناك بس: `rm -rf ~/.git`. اقرا الأمر ده مرتين قبل Enter، وتأكد إنه `~/.git` بالظبط مش حاجة تانية. ده بيمسح تتبع Git بس، ملفاتك سليمة.
:::

:::danger[مشكلة: fatal: not a git repository (or any of the parent directories): .git]
بتشغّل أمر Git في فولدر مش Repo.

<strong>الحل:</strong> `pwd`، وادخل فولدر المشروع بـ `cd`. ولو ده المشروع فعلاً ومحتاج Repo: `git init`.
:::

:::tip[ملخص الفصل]
- متتخضش: `status`، ونسخة احتياطي، و `log --graph` و `reflog`، وبعدين الحل.
- اللي اتعمله Commit مبيضيعش. اللي عمره ما اتسجّل هو اللي يضيع.
- Branch غلط = لافتة جديدة + `reset`، أو `cherry-pick`.
- في نص عملية: `--continue` أو `--abort`.
- على main المشتركة: `revert` مش reset و force.
:::

### صح ولا غلط؟

1. تعديلات عمرها ما اتعملها add ممكن ترجّعها بـ reflog.
2. `git merge --abort` بيرجّعك لحالة ما قبل الـ Merge.
3. لو ملف كبير اتعمله Commit، كفاية تمسحه في Commit جديد عشان الـ push ينجح.

### أسئلة مراجعة

1. عملت 2 Commits على main بدل Branch ومفيش push. اكتب الأوامر بالترتيب.
2. إيه الفرق بين إصلاح Commit بايظ على main اتعمله push، وواحد لسه محلي؟
3. ليه `refusing to merge unrelated histories` بتحصل، وإزاي تتجنبها؟
4. الـ Branch اتمسحت بـ `-D`. إزاي ترجّعها؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** في Repo تجريبي، اعمل Commit على main، وانقله لـ Branch جديدة بالطريقة اللي في الفصل.
2. **[متوسط]** اعمل Merge فيه Conflict، واخرج منه بـ `--abort`، وبعدين اعمله تاني وحله.
3. **[صعب]** امسح Branch فيها Commits بـ `-D`، وارجّعها من غير ما تبص على الرسالة اللي Git طبعها (استخدم reflog بس).
