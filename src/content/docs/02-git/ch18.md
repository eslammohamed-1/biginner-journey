<small>المرحلة 7 · GitHub والـ AI والإنقاذ</small>

انت بتبني مشاريع بمساعدة الـ AI، وده ممتاز. بس الـ AI ساعات بيعدّل عشر ملفات وانت طالب منه سطر، وساعات بيحط API Key في الكود كأنه حاجة عادية. Git هو حزام الأمان بتاعك هنا: Checkpoint قبل أي تعديل، و Branch لكل تجربة، و diff تقراه قبل ما تقبل، وقواعد صارمة للأسرار.

:::note[بعد الفصل ده هتكون عارف]
- Commit قبل ما الـ AI يلمس الكود، وليه
- Branch لكل تجربة AI، والرجوع منها في ثانية
- تقرا تعديلات الـ AI بـ diff --stat و add -p
- .env و .env.example وليه الأسرار مكانها مش Git
- تعمل إيه لو Secret اتسرّب، و Push protection
:::

<a id="s18-1"></a>

## 18.1 الـ AI عدّل 14 ملف

الساعة 2 بالليل. مشروع الـ Weather app شغال تمام، وناقص بس إن الـ Search يقبل اسم المدينة بالعربي. كتبت للـ AI: "خلّي الـ search يدعم العربي". رد بثقة: "تم! عملت بعض التحسينات كمان". فتحت المتصفح... الصفحة بيضا. الـ Console فيه 3 Errors. والـ AI "حسّن" ملف الـ CSS، وغيّر اسم Function بتستخدمها في 4 أماكن، وحدّث `package.json`.

تطلب منه يصلّح؟ هيصلّح حاجة ويبوّظ حاجة تانية، وانت مش فاكر الكود كان شكله إيه. السيناريو ده بيحصل لكل اللي بيشتغلوا مع AI، والفرق الوحيد بين اللي بيخسر ساعتين واللي بيخسر 3 ثواني هو سطر واحد كان المفروض يتكتب **قبل** ما يطلب من الـ AI أي حاجة.

<a id="s18-2"></a>

## 18.2 القاعدة الأولى: Commit قبل الـ AI

قبل ما تدّي الـ AI أي مهمة بتعدّل كود، خلّي الـ Working directory نضيف: `git status` يقول `nothing to commit, working tree clean`. كده أي حاجة هتتغير بعد كده هي تعديل الـ AI **بس**، وتقدر تشوفه كله وترجع منه كله.

```sh title="Terminal"
git status
git add -A
git commit -m "chore: checkpoint before AI arabic search"
```

ولو الـ AI بوّظ الدنيا؟ ترجع لآخر Commit بأمر واحد (افتكر [↩ 6.2](../ch06/#s6-2 "git restore: ارجع ملف في الورشة أو الـ Staging") و [↩ 6.6](../ch06/#s6-6 "git clean: الملفات الجديدة Untracked")):

**تشريح الأمر**

```sh
git restore . && git clean -fd
```

1. `git restore .`: رجّع كل الملفات المتتبَّعة لحالة آخر Commit.
2. `&&`: ولو نجح، كمّل (من كتاب الـ Terminal).
3. `git clean -fd`: امسح الملفات الجديدة اللي الـ AI عملها ومش متتبَّعة: `-f` تأكيد و `-d` الفولدرات كمان. جرّب `-n` الأول تشوف هيمسح إيه.

:::note[مش لازم Commit؟]
لو مش حابب تعمل Commit لنص شغلك، فيه حل تاني: `git stash` ([↩ 14.2](../ch14/#s14-2 "أوامر الـ Stash"))، أو على الأقل `git add -A` من غير Commit. كده الـ Staging area فيها نسختك، و `git diff` (من غير `--staged`) يوريك تعديلات الـ AI بس، و `git restore .` يرجّع للنسخة اللي في الـ Staging. بس الـ Commit أوضح وأأمن.
:::

<a id="s18-3"></a>

## 18.3 Branch لكل تجربة

لو المهمة كبيرة ("اعمل Refactor للمشروع كله لـ Modules")، خليها في Branch لوحدها. لو التجربة نجحت، تدمجها. لو فشلت، تمسح الـ Branch ولا كأن حاجة حصلت، و main عمره ما اتلمس.

```sh title="Terminal"
git switch -c ai/modules-refactor
# ... الـ AI يشتغل، وانت تعمل commits صغيرة بعد كل خطوة ناجحة
git switch main
git merge --squash ai/modules-refactor   # نجحت: Commit واحد نضيف
git branch -D ai/modules-refactor        # فشلت: امسحها بالـ D الكبيرة
```

:::tip[Commits صغيرة أثناء الشغل مع الـ AI]
كل ما الـ AI يعمل خطوة شغالة، اعمل Commit. لو الخطوة الخامسة باظت، ترجع للرابعة مش للأول خالص. و `merge --squash` في الآخر بيجمعهم في Commit واحد على main لو مش عاوز التاريخ ده يظهر ([↩ 11.4](../ch11/#s11-4 "طرق الدمج على GitHub")).
:::

:::note[لو حابب تتعمق: git worktree]
عاوز تخلّي أداة AI تشتغل على Branch في نفس الوقت اللي انت شغال فيه على main؟ `git worktree add ../weather-ai ai/try` بيعمل فولدر تاني فيه نفس الـ Repo على Branch تانية، من غير clone جديد. الاتنين بيشاركوا نفس `.git`. و `git worktree list` تشوفهم و `git worktree remove ../weather-ai` تمسحه. أدوات AI كتير بتستخدم الفكرة دي عشان تشغّل أكتر من Agent على المشروع.
:::

## 18.4 اقرا قبل ما تقبل

الـ AI مش زميل بتثق فيه ثقة عمياء. هو زميل شاطر جداً وسريع جداً، وساعات بيكدب بثقة. فتعامل مع تعديلاته زي PR من حد جديد في الفريق: تراجعها. والمراجعة ليها 3 مستويات:

**تشريح الأمر**

```sh
git diff --stat
```

1. `--stat`: ملخص: أنهي ملفات اتغيرت، وكام سطر اتضاف (`+`) واتشال (`-`) في كل واحد. أول نظرة: لو طلبت تعديل في `search.js` ولقيت 14 ملف، فيه حاجة غلط.

```sh title="Terminal"
 package.json   |   4 +-
 src/search.js  |  23 +++++++---
 src/style.css  | 112 ++++++------------------
 3 files changed, 48 insertions(+), 91 deletions(-)
```

هنا تسأل: ليه `style.css` اتغير 112 سطر وانا ماطلبتش؟ وليه `package.json`؟ بعد كده `git diff src/search.js` تقرا التعديل اللي طلبته فعلاً سطر سطر. والمستوى التالت إنك تقبل حتة حتة:

**تشريح الأمر**

```sh
git add -p
```

1. `-p`: (`--patch`) يعرض كل تعديل (Hunk) لوحده ويسألك: `y` ضيفه، `n` لأ، `s` قسّمه أصغر، `q` خلاص ([↩ 13.5](../ch13/#s13-5 "git add -p: اختار حتت من الملف")). تقبل تعديل الـ search، وترفض الـ CSS.

وبعد ما تعمل Commit للي قبلته، ترمي الباقي بـ `git restore .`. وبكده خدت من الـ AI اللي انت عاوزه بالظبط.

:::caution[بصّ على package.json و lock files كويس]
لو الـ AI ضاف مكتبة جديدة، اتأكد إنها موجودة فعلاً وإن اسمها مظبوط على npmjs.com. الـ AI ساعات بيخترع أسماء مكتبات مش موجودة، وفيه ناس بتسجّل الأسماء دي بالظبط بكود خبيث، مستنية حد ينزّلها.
:::

**الـ Workflow الكامل مع الـ AI**

| إمتى | الأمر |
|---|---|
| قبل | `git status` نضيف، أو `git commit` Checkpoint، أو `git switch -c ai/...` |
| بعد، نظرة أولى | `git diff --stat` |
| بعد، قراية | `git diff path/file.js` |
| قبول جزئي | `git add -p` ثم `git commit` |
| رفض الباقي | `git restore .` و `git clean -fd` |
| Commit اتعمل وطلع غلط | `git reset --hard HEAD~1` (محلي) أو `git revert` (اتعمله push) |

## 18.5 الأسرار: القاعدة اللي مفيهاش هزار

الـ Weather app محتاج API Key. الـ AI كتب لك الكود كده:

```js title="src/api.js (غلط)"
const API_KEY = "sk_live_9f3a7c2e81b4d6..."; // متعملش كده
fetch(`https://api.weather.dev/v1?q=${city}&key=${API_KEY}`);
```

عملت Commit و push على Repo Public. خلال دقايق، فيه Bots بتلف على GitHub 24 ساعة بتدوّر على مفاتيح زي دي. ولو المفتاح ده لخدمة بتدفع فيها (AWS، OpenAI...)، ممكن تصحى على فاتورة بآلاف الدولارات. وحتى لو مسحت السطر في Commit جديد، المفتاح لسه في الـ **History**: أي حد يعمل `git log -p` يلاقيه. Git مصمم إنه ما ينساش، وده هنا ضدك.

الحل المعروف: ملف `.env` للأسرار، متجاهَل في Git، وملف `.env.example` متتبَّع فيه أسماء المتغيرات بس:

#### .env (في .gitignore)

```ini title=".env"
WEATHER_API_KEY=sk_live_9f3a7c2e81b4d6
MAPS_TOKEN=pk_83hd92
```

#### .env.example (يتعمله commit)

```ini title=".env.example"
WEATHER_API_KEY=your_key_here
MAPS_TOKEN=your_token_here
```

```gitignore title=".dockerignore"
.env
.env.*
!.env.example
```

الـ `!` بتعمل استثناء ([↩ 5.2](../ch05/#s5-2 "قواعد الـ Patterns")): تجاهل كل ملفات `.env` ما عدا الـ example. وقبل أول Commit في أي مشروع، اتأكد: `git check-ignore -v .env` لازم يطبع القاعدة ([↩ 5.5](../ch05/#s5-5 "git check-ignore: ليه الملف ده متجاهَل؟")).

:::caution[مهم جداً لـ Frontend]
أي مفتاح بتستخدمه في كود بيشتغل في المتصفح (حتى لو جاي من `.env` بـ `import.meta.env.VITE_KEY` في Vite)، بيتحط جوه ملفات الـ Build، وأي حد يفتح DevTools يشوفه. الـ `.env` بيحميه من Git، مش من المتصفح. المفاتيح الحساسة فعلاً مكانها Backend أو Serverless function. والمفاتيح اللي معمولة للمتصفح (Public keys) اعمل لها قيود من لوحة الخدمة (Domains مسموحة مثلاً).
:::

:::tip[قول للـ AI القواعد]
لما تطلب من الـ AI كود فيه API، قوله صراحة: "استخدم متغير بيئة من `.env`، وماتكتبش أي مفتاح في الكود، وضيف `.env.example`". ومتلصقش مفاتيحك الحقيقية في الـ Chat أصلاً: اديله `your_key_here`.
:::

## 18.6 المفتاح اتسرّب. اعمل إيه؟

حصل. ماتتكسفش، بيحصل لناس بخبرة سنين. الترتيب هنا مهم جداً:

1. <strong>الغي المفتاح فوراً (Revoke / Rotate)</strong> من لوحة الخدمة واعمل واحد جديد. ده أهم خطوة وأول خطوة. افترض إن المفتاح القديم اتشاف خلاص، حتى لو الـ Repo Private، وحتى لو مسحته بعد دقيقة.
2. حط الجديد في `.env`، وتأكد إن `.env` في الـ .gitignore.
3. شيل المفتاح من الكود واعمل Commit.
4. <strong>لو لسه ماعملتش push:</strong> صلّح الـ Commit نفسه: `git commit --amend` لو هو آخر واحد، أو `git rebase -i` لو أقدم ([↩ 15.5](../ch15/#s15-5 "الـ Interactive rebase: نضّف تاريخك")). كده المفتاح مش في الـ History خالص.
5. <strong>لو اتعمله push:</strong> تنظيف الـ History ممكن (بأداة زي `git filter-repo`)، بس معقد ومحتاج force push، والنسخ اللي اتعملها clone أو fork لسه فيها المفتاح. عشان كده الخطوة 1 هي اللي بتحميك فعلاً، مش التنظيف.

:::note[GitHub بيساعدك: Secret scanning و Push protection]
GitHub بيعمل **Secret scanning** على الـ Repos الـ Public: بيدوّر على أنواع مفاتيح معروفة، وكتير من الشركات (زي AWS) بتبلّغها GitHub فتلغي المفتاح بنفسها. وفيه كمان **Push protection**: لو حاولت تعمل push لـ Commit فيه مفتاح معروف، الـ push يترفض برسالة زي `GH013: Repository rule violations found` و `Push cannot contain secrets`، وبيقولك المفتاح في أنهي ملف وأنهي سطر. ساعتها ماتعملش "Allow" وتكمّل: صلّح الـ Commit (خطوة 4) وغيّر المفتاح. تقدر تتأكد إنها شغالة على حسابك من **Settings ← Code security**. بس دي شبكة أمان، مش بديل عن الـ .gitignore.
:::

:::tip[ملخص الفصل]
- Working directory نضيف أو Commit Checkpoint قبل أي مهمة للـ AI.
- التجارب الكبيرة في `ai/...` Branch: تدمجها أو تمسحها.
- `diff --stat` ثم `diff file` ثم `add -p`، والباقي `restore .` و `clean -fd`.
- الأسرار في `.env` (متجاهَل)، والأسماء في `.env.example`.
- مفتاح اتسرّب = Rotate الأول، وبعدين نضّف.
:::

### صح ولا غلط؟

1. لو مسحت المفتاح في Commit جديد وعملت push، المشكلة اتحلت.
2. `.env.example` المفروض يكون فيه المفاتيح الحقيقية عشان الفريق.
3. `git diff --stat` بيوريك أنهي ملفات اتغيرت وكام سطر.

### أسئلة مراجعة

1. ليه الـ Working directory النضيف قبل الـ AI بيسهّل المراجعة والرجوع؟
2. إزاي تقبل جزء من تعديلات الـ AI وترفض الباقي؟
3. اكتب قواعد .gitignore تتجاهل كل ملفات .env ما عدا .env.example.
4. رتّب خطوات التعامل مع مفتاح اتعمله push.

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** في مشروع، اعمل Checkpoint، واطلب من الـ AI تعديل، واقرا `git diff --stat` قبل ما تفتح الكود.
2. **[متوسط]** اطلب من الـ AI تعديلين في نفس الملف، واقبل واحد بس بـ `git add -p`.
3. **[صعب]** في Repo تجريبي، اعمل Commit فيه مفتاح وهمي (مش push)، وبعدين شيله من الـ History بـ `rebase -i` واتأكد بـ `git log -p` إنه مش موجود.
