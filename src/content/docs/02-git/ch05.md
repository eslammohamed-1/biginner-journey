<small>المرحلة 2 · الأساس على جهازك</small>

مش كل حاجة في فولدر المشروع مكانها Git. node\_modules فيها آلاف الملفات اللي بتتعمل بـ npm install، و .env فيه مفاتيح وباسوردات، وملفات النظام زي .DS\_Store ملهاش لازمة. الفصل ده عن ملف .gitignore: قواعده، وقالب جاهز لمشاريع JavaScript، وإزاي تشيل ملف من Git لو اتضاف بالغلط.

:::note[بعد الفصل ده هتكون عارف]
- ليه بنتجاهل ملفات ومين أشهرهم في مشاريع JS
- قواعد الـ Patterns: \* و \*\* و / و ! و #
- قالب .gitignore جاهز لمشاريع JavaScript
- الـ .gitignore العام لكل مشاريعك
- git check-ignore عشان تعرف ليه ملف متجاهَل
- git rm --cached لملف اتضاف قبل ما تتجاهله، و git rm و git mv
:::

:::note[فاكر node_modules و npm install؟]
الفصل ده بيتكلم كتير عن `node_modules` و `npm install` وفولدرات الـ Build (`dist` و `build`) وملف `.env`. لو الكلمات دي جديدة عليك، بص على صندوق "npm و node\_modules و package.json في دقيقة" في كتاب الـ Terminal (فصل 11، Homebrew ومديري الحزم). وباختصار: `node_modules` = المكتبات اللي npm نزّلها، وبتتعمل تاني بـ `npm install`. والـ Build = نسخة نهائية متولّدة من الكود. و `.env` = ملف نصي فيه إعدادات وأسرار زي الـ API Key (مفتاح سري بيدّيهولك أي موقع علشان برنامجك يستخدم خدماته). الحاجات دي كلها يا بتتولّد يا سرية، فمكانها مش Git.
:::

<a id="s5-1"></a>

## 5.1 ليه نتجاهل ملفات؟

أول مرة هتعمل `npm install` لمكتبة صغيرة في مشروعك وتكتب `git status`، هتتخض: فولدر اسمه `node_modules` ظهر، وجواه حرفياً آلاف الملفات، لمكتبات انت عمرك ما سمعت عنها (لأن كل مكتبة جايبة معاها مكتبات). وفيه نكتة مشهورة إن `node_modules` أتقل حاجة في الكون، وهي مش بعيدة عن الحقيقة. وجنبه ملف صغير بريء اسمه `.env` انت حاطط فيه الـ API Key بتاع خدمة الطقس اللي بتستخدمها في المشروع.

لو عملت `git add .` وCommit و push، هيحصل حاجتين وحشين. الأولى إن الـ Repo هيبقى تقيل جداً، وكل `npm install` هيعمل تغييرات مالهاش معنى. وأخطر من كده: ملف `.env` فيه الـ API Key بتاعك، ولو اتعمله Push على GitHub public، فيه Bots بتمسح GitHub بتدوّر على المفاتيح دي.

#### حاجات بتتولّد

`node_modules/` (بترجع بـ `npm install`)، و `dist/` و `build/` (ناتج الـ Build).

#### أسرار

`.env` و `.env.local` وأي مفاتيح أو شهادات (`*.pem`).

#### ملفات النظام والـ Editor

`.DS_Store` (macOS)، `Thumbs.db` (Windows)، و `.idea/`.

#### Logs ومؤقت

`*.log` و `npm-debug.log*` و `.cache/` و `coverage/`.

:::note[القاعدة الذهبية]
الـ Repo فيه **اللي إنت كتبته** (الكود، والإعدادات من غير أسرار) + **اللي يلزم عشان أي حد يبني المشروع** (`package.json` و `package-lock.json`). أي حاجة بتتولّد من حاجة تانية أو سرية = `.gitignore`.
:::

<a id="s5-2"></a>

## 5.2 قواعد الـ Patterns

`.gitignore` ملف نصي عادي في أول المشروع، كل سطر فيه Pattern. لو ملف طابق Pattern وكان Untracked، Git هيعمل نفسه مش شايفه.

**قواعد الكتابة في .gitignore**

| الـ Pattern | بيطابق إيه |
|---|---|
| `.env` | أي ملف أو فولدر اسمه `.env` في أي مكان في المشروع |
| `*.log` | `*` = أي حروف: كل الملفات اللي بتنتهي بـ `.log` |
| `node_modules/` | الـ `/` في الآخر = فولدرات بس بالاسم ده (في أي مكان) |
| `/dist` | الـ `/` في الأول = في أول المشروع بس، مش `src/dist` |
| `docs/*.pdf` | ملفات pdf جوه `docs` مباشرة (مش في فولدرات جواه) |
| `**/temp` | `**` = أي عمق من الفولدرات |
| `logs/**/*.log` | أي log في أي مكان جوه `logs` |
| `img?.png` | `?` = حرف واحد بالظبط |
| `!keep.log` | `!` = **استثناء**: متتجاهلش ده رغم إن اللي فوق تجاهله |
| `# comment` | تعليق |

:::tip[حاجة مشتركة: نفس رموز الـ Globbing]
`*` و `?` و `[abc]` هنا نفس معانيها في الـ Globbing اللي اتعلمناه في كتاب الـ Terminal. الفرق إن Git هو اللي بيفكها مش الـ Shell، وإن `**` شغالة على طول (في bash محتاجة `globstar`). ونفس الـ Patterns دي بتستخدمها في `git add '*.js'`.
:::

:::caution[فخ الاستثناء جوه فولدر متجاهَل]
لو كتبت `logs/` وبعدين `!logs/keep.log`، الاستثناء **مش هيشتغل**: Git مش بيدخل جوه فولدر متجاهَل أصلاً. الحل: تجاهل المحتوى مش الفولدر: `logs/*` وبعدين `!logs/keep.log`.
:::

<a id="s5-3"></a>

## 5.3 قالب جاهز لمشاريع JavaScript

```gitignore title=".gitignore"
# dependencies
node_modules/
# build output
dist/
build/
.parcel-cache/
# secrets
.env
.env.*
!.env.example
# logs
*.log
npm-debug.log*
# OS / editor
.DS_Store
Thumbs.db
.vscode/*
!.vscode/extensions.json
```

1. `# dependencies`: المكتبات اللي `npm install` بيجيبها. بترجع من `package.json` و `package-lock.json` (ودول **لازم** يتعملهم Commit).
2. `# build output`: ناتج الـ Build (Parcel أو Vite)، بيتولّد من الكود.
3. `# secrets`: كل ملفات `.env`، ما عدا `.env.example`: نسخة من غير قيم حقيقية عشان اللي بعدك يعرف المتغيرات المطلوبة.
4. `# logs`: Logs بتتعمل وانت بتشغّل.
5. `# OS / editor`: ملفات النظام، وإعدادات VS Code الشخصية، مع استثناء ملف الإضافات المقترحة للفريق.

:::tip[متكتبهوش من الصفر]
GitHub عنده قوالب جاهزة لكل لغة: لما تعمل Repo جديد على الموقع اختار **Add .gitignore ← Node**. ولو بتستخدم Vite (`npm create vite@latest`) فهو بيعملك `.gitignore` جاهز. واعمل الملف ده **قبل أول** `git add`.
:::

<a id="s5-4"></a>

## 5.4 .gitignore عام لكل مشاريعك

ملفات زي `.DS_Store` دي بتاعة جهازك إنت، مش بتاعة المشروع. حطها مرة واحدة في ملف عام:

**تشريح الأمر**

```sh
git config --global core.excludesFile ~/.gitignore_global
```

1. `git config --global`: إعداد عام ([↩ 2.2](../ch02/#s2-2 "git config: 3 مستويات للإعدادات")).
2. `core.excludesFile`: "فيه ملف تجاهل إضافي، طبّقه على كل الـ Repos".
3. `~/.gitignore_global`: مسار الملف في الـ Home (الـ `~` من كتاب الـ Terminal). اعمله واكتب فيه `.DS_Store` و `Thumbs.db`.

**أماكن قواعد التجاهل**

| المكان | بيتشارك مع الفريق؟ | استخدمه لـ |
|---|---|---|
| `.gitignore` في المشروع | أيوه (بيتعمله Commit) | حاجات المشروع: node\_modules و dist و .env |
| `~/.gitignore_global` | لأ | حاجات جهازك: .DS\_Store و Editor |
| `.git/info/exclude` | لأ | حاجة خاصة بيك في Repo واحد |

<a id="s5-5"></a>

## 5.5 git check-ignore: ليه الملف ده متجاهَل؟

**تشريح الأمر**

```sh
git check-ignore -v .env keep.log
```

1. `git check-ignore`: قولّي الملفات دي متجاهَلة ولا لأ.
2. `-v`: Verbose: قولّي كمان **أنهي ملف وأنهي سطر** هو السبب.
3. `.env keep.log`: الملفات اللي بنسأل عليها.

```sh title="Terminal"
$ git check-ignore -v .env keep.log
.gitignore:2:.env	.env
.gitignore:4:!keep.log	keep.log
```

كل سطر: `الملف:رقم السطر:الـ Pattern` ثم اسم الملف. السطر التاني بيبدأ بـ `!` يعني آخر قاعدة طابقت كانت **استثناء**، فـ keep.log مش متجاهَل. ولو عاوز تشوف كل المتجاهَل: `git status --ignored` (المتجاهَل بيظهر بـ `!!` في `-s`).

<a id="s5-6"></a>

## 5.6 اتضاف بالغلط قبل الـ .gitignore

:::danger[مشكلة: ضفت .env لـ .gitignore وبرضه بيظهر متعدل!]
الـ `.gitignore` بيأثر على الملفات **Untracked** بس. لو الملف اتعمله Commit قبل كده، Git بيفضل يتابعه عادي.

<strong>الحل:</strong> شيله من متابعة Git من غير ما تمسحه من جهازك:

```sh title="Terminal"
git rm --cached .env
git commit -m "chore: stop tracking .env"
```

ولو فولدر: `git rm -r --cached node_modules`.
:::

**تشريح الأمر**

```sh
git rm -r --cached node_modules
```

1. `git rm`: امسح من Git.
2. `-r`: Recursive: الفولدر وكل اللي جواه (نفس `-r` بتاعة `rm` و `cp` في كتاب الـ Terminal).
3. `--cached`: أهم حتة: امسحه من الـ **Index** (الـ Staging) بس، وسيبه على الديسك. من غيرها الملفات هتتمسح فعلاً من جهازك.
4. `node_modules`: المسار.

:::caution[لو السر اتعمله Push خلاص]
`git rm --cached` بيشيل الملف من الـ Commits **الجاية** بس. لو `.env` اتعمله Push قبل كده، المفتاح لسه موجود في التاريخ وأي حد يقدر يشوفه. الحل الحقيقي: **غيّر المفتاح فوراً** (Revoke و Rotate) من الموقع اللي عمله. التفاصيل في الفصل 18.
:::

<a id="s5-7"></a>

## 5.7 git rm و git mv

**المسح وتغيير الأسماء**

| الأمر | بيعمل إيه |
|---|---|
| `git rm file.js` | يمسح الملف من الديسك ويجهّز المسح في الـ Staging (خطوتين في واحدة: `rm` + `git add`) |
| `git rm --cached file.js` | يبطّل يتابعه بس، والملف يفضل |
| `git mv old.js new.js` | يغيّر الاسم ويجهّزه (= `mv` + `git add` للاتنين) |
| `git mv app.js src/` | ينقل لفولدر |

:::note[لو مسحت أو غيرت الاسم من VS Code]
عادي جداً. Git هيشوف ملف اتمسح وملف جديد اتعمل، ولما تعمل `git add -A` هيفهم إنه Rename لوحده (`R` في status) لو المحتوى قريب. `git mv` مجرد اختصار.
:::

:::tip[ملخص الفصل]
- بنتجاهل: اللي بيتولّد (node\_modules و dist)، والأسرار (.env)، وملفات النظام.
- `*` أي حروف، `**` أي عمق، `/` في الآخر فولدر، في الأول من الجذر، `!` استثناء.
- `.gitignore` للمشروع، و `core.excludesFile` لجهازك.
- `git check-ignore -v` يقولك أنهي قاعدة هي السبب.
- الـ .gitignore مبيأثرش على ملف متابَع: `git rm --cached`. والسر اللي اتعمله Push لازم يتغير.
:::

### صح ولا غلط؟

1. إضافة ملف لـ `.gitignore` بتشيله من Git لو كان متعمله Commit.
2. `package-lock.json` المفروض يتحط في `.gitignore`.
3. `git rm --cached file` بيمسح الملف من جهازك.

### أسئلة مراجعة

1. إيه الفرق بين `dist/` و `/dist` و `dist` في .gitignore؟
2. ليه بنعمل Commit لـ `.env.example` ومش `.env`؟
3. كتبت `logs/` و `!logs/keep.log` والاستثناء مشتغلش. ليه؟ وإزاي تصلحه؟
4. إيه الخطوات لو اكتشفت إن `node_modules` متعمله Commit؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** في مشروع npm (`npm init -y` و `npm i lodash`)، اعمل `.gitignore` بالقالب، وتأكد بـ `git status` إن `node_modules` اختفى.
2. **[متوسط]** اعمل `.env` و `.env.example`، واتأكد بـ `git check-ignore -v` إن الأول متجاهَل والتاني لأ.
3. **[صعب]** اعمل Commit لملف `debug.log` عمداً، وبعدين ضيف `*.log` للـ .gitignore، وخلّي Git يبطّل يتابعه من غير ما تمسحه. اتأكد بـ `git ls-files`.
