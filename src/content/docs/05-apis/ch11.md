<small>المرحلة 3 · تتكلم مع API</small>

أول ما تفتح دوكيومنتيشن API كبير زي GitHub أو Stripe، بتلاقي مئات الصفحات. تبدأ منين؟ الفصل ده بيديك ترتيب قراية ثابت، ويشرّح صفحة Reference واحدة حتة حتة، وبعدين يفتح ملف OpenAPI حقيقي (بتاع Frankfurter اللي استخدمناه في أول فصل) ويقراه بـ jq، علشان تعرف إن الصفحات الحلوة دي كلها طالعة من ملف JSON واحد.

:::note[بعد الفصل ده هتكون عارف]
- ترتيب قراية ثابت لأي API: من Getting started لحد Changelog
- تشريح صفحة Endpoint: Method و Path و Parameters و Body و Responses
- الفرق بين Path و Query و Header و Body parameters
- يعني إيه OpenAPI و Swagger، وإيه الفرق
- تقرا ملف OpenAPI حقيقي بـ jq: servers و paths و parameters و components
- Swagger UI و Redoc و Scalar: الدوكيومنتيشن اللي بتتولد من الملف
- توليد Client و Types من الملف
:::

<a id="s11-1"></a>

## 11.1 ترتيب القراية: 8 محطات

الغلطة الشائعة إنك تروح على طول لصفحة الـ Endpoint اللي عايزه وتنسخ المثال. وبعدين تتفاجئ بـ 401، أو تاخد أول 30 عنصر بس ومتعرفش إن في صفحات، أو تخبط في الـ Rate limit. فاقرا بالترتيب ده، ولو بسرعة:

1. **Overview / Getting started**: الـ API بيعمل إيه، و**الـ Base URL** (زي `https://api.github.com`)، وأول طلب.
2. **Authentication**: محتاج Key؟ Token؟ OAuth؟ وبيتبعت فين (فصل 12 و 13).
3. **Versioning**: في `/v2`؟ ولا Header؟ ولو مبعتّوش إيه اللي بيحصل (فصل 19).
4. **Errors**: شكل الغلط، والـ Codes الثابتة (فصل 17).
5. **Rate limits**: الحد كام، والـ Headers اسمها إيه، وبتعمل إيه لما تخبط.
6. **Pagination**: `page`؟ `cursor`؟ `Link` header؟ والحد الأقصى للصفحة.
7. **Reference**: صفحة الـ Endpoint اللي عايزه (تحت).
8. **Changelog**: إيه اللي اتغير قريب، وإيه اللي هيتشال.

:::tip[Best Practice: اعمل كارت للـ API]
بعد ما تقرا، اكتب كارت من 8 سطور: الـ Base URL، والـ Auth Header، والنسخة، وشكل الغلط، والحد، والـ Pagination، وأهم 3 Endpoints. الكارت ده هو اللي هتحطه في `README` بتاع مشروعك، وهو بالظبط نفس الأقسام اللي هتكتبها لما تعمل API بتاعك.
:::

## 11.2 تشريح صفحة Reference

خلينا ناخد صفحة "Get a repository" في GitHub (اللي جربناها في فصل 3). أي صفحة Reference محترمة فيها نفس الأجزاء دي، حتى لو الترتيب مختلف:

```http title="رأس الصفحة"
GET /repos/{owner}/{repo}
```

**أجزاء صفحة الـ Endpoint**

| الجزء | فيه إيه | في المثال |
|---|---|---|
| Method + Path | الفعل والعنوان. والـ `{…}` = Placeholder تحط مكانه قيمة | `GET /repos/{owner}/{repo}` |
| الوصف | بيعمل إيه، وأي حالة خاصة | "The parent and source objects are present when the repository is a fork" |
| الصلاحيات | محتاج Token؟ بأنهي Scopes أو Permissions؟ | Public repos من غير Token. Private محتاج Permission "Metadata: read" |
| Headers | الـ Headers المطلوبة أو المقترحة | `accept`: يُفضّل `application/vnd.github+json` |
| Path parameters | جوه المسار، **إجبارية دايماً** | `owner` و `repo` (و GitHub بيقول case-insensitive) |
| Query parameters | بعد `?`، غالباً اختيارية وليها Default | مفيش هنا. في `List issues` هتلاقي `state` و `per_page` و `page` |
| Body parameters | في `POST`/`PATCH`: الـ Fields ونوعها وإجباري ولا لأ | في `Update a repository`: `name` و `description`… |
| Responses | كل Status ممكن، ومعاه شكل الـ Body | `200` و `301` (اتنقل) و `403` و `404` |
| Examples | طلب ورد جاهزين بـ curl و JS وغيره | زر Copy |

| الأمر | بيعمل إيه |
|---|---|
| `Path parameter` | جزء من هوية الـ Resource: `/repos/expressjs/express`. لو اتغير، بقى Resource تاني. |
| `Query parameter` | تعديل على **طريقة العرض**: فلترة وترتيب وصفحات. `?state=open&per_page=50`. |
| `Header parameter` | معلومات عن الطلب نفسه مش عن الـ Resource: الـ Auth والنسخة والشكل. |
| `Body parameter` | البيانات اللي بتبعتها علشان تعمل أو تعدّل. JSON غالباً. |

:::caution[خلي بالك: الـ Responses اللي مش مكتوبة]
حتى لو الصفحة كاتبة `200` و`404` بس، كودك لازم يتعامل مع **أي** Status: 401 لو الـ Token انتهى، و429 لو خبطت في الحد، و500 و503 لو السيرفر عنده مشكلة. والـ Helper بتاع فصل 10 بيعمل كده لوحده.
:::

**المصادر الرسمية:** [GitHub · Get a repository](https://docs.github.com/en/rest/repos/repos#get-a-repository) · [GitHub · List repository issues](https://docs.github.com/en/rest/issues/issues#list-repository-issues)

## 11.3 OpenAPI: الدوكيومنتيشن ملف JSON

**القصة**: كل شركة كانت بتكتب الدوكيومنتيشن بإيدها في صفحات HTML. فالصفحات بتبعد عن الكود، ومفيش أداة تقدر "تفهم" الـ API لوحدها. سنة 2011 ظهر مشروع اسمه **Swagger**: ملف JSON/YAML بيوصف الـ API بالكامل، وأداة بتعرضه كصفحة حلوة فيها زر "Try it out". واتبرع بيه سنة 2015 لمؤسسة اسمها OpenAPI Initiative، واتغير اسم المواصفة لـ **OpenAPI**.

#### OpenAPI

**المواصفة نفسها**: إزاي تكتب ملف وصف الـ API. آخر نسخة **3.2.1** (سبتمبر 2026)، و 3.2.0 نزلت سبتمبر 2025، وأغلب الملفات اللي هتشوفها 3.0 أو 3.1.

#### Swagger

النهارده: **اسم مجموعة أدوات** من شركة SmartBear: Swagger UI و Swagger Editor. يعني "ملف Swagger" بالمعنى القديم = ملف OpenAPI 2.0. والناس لسه بتقول الكلمتين مكان بعض.

وأحلى حاجة: كتير من الـ APIs بتنشر الملف ده. Frankfurter (أول API جربناه) بينشره على `/v2/openapi.json`. نزّله واقراه بـ jq:

```sh title="Terminal"
$ curl -s https://api.frankfurter.dev/v2/openapi.json -o fr.json
$ jq -r '.openapi, .info.title, .info.version' fr.json
3.1.2
Frankfurter API
2.1.1
$ jq -c '.servers' fr.json
[{"url":"https://api.frankfurter.dev/v2"}]
$ jq -r '.paths | keys[]' fr.json
/coverage
/currencies
/currency/{code}
/providers
/providers/{provider}
/providers/{provider}/rate/{base}/{quote}
/providers/{provider}/rates
/rate/{base}/{quote}
/rates
```

| الأمر | بيعمل إيه |
|---|---|
| `.openapi` | نسخة **المواصفة** اللي الملف مكتوب بيها (3.1.2). |
| `.info.version` | نسخة **الـ API نفسه** (2.1.1). حاجتين مختلفين خالص، وناس كتير بتلخبط بينهم. |
| `.servers` | الـ Base URL. وكل الـ Paths بتتحط بعده: `https://api.frankfurter.dev/v2` + `/rates`. |
| `.paths` | كل Endpoints الـ API. كل Key مسار، وجواه Method لكل عملية. |

### عملية واحدة من جوه

```sh title="Terminal"
$ jq '.paths["/rates"].get | {summary, operationId, params: [.parameters[]."$ref"], responses: (.responses | keys)}' fr.json
{
  "summary": "Get exchange rates",
  "operationId": "getRates",
  "params": [
    "#/components/parameters/date",
    "#/components/parameters/from",
    "#/components/parameters/to",
    "#/components/parameters/base",
    "#/components/parameters/quotes",
    "#/components/parameters/providers",
    "#/components/parameters/group",
    "#/components/parameters/expand"
  ],
  "responses": [
    "200",
    "404",
    "422",
    "503"
  ]
}
$ jq -c '.components.parameters.base' fr.json
{"name":"base","in":"query","schema":{"type":"string","default":"EUR","example":"USD"}}
```

```json title="بنقرا العقد"
.paths["/rates"].get
"operationId": "getRates"
"$ref": "#/components/parameters/base"
"in": "query"
"default": "EUR"
"responses": ["200", "404", "422", "503"]
```

1. `.paths["/rates"].get`: الـ `["…"]` لأن الـ Key فيه `/`. والـ `get` = العملية بتاعة `GET /rates`.
2. `"operationId": "getRates"`: اسم فريد للعملية. الأدوات اللي بتولّد كود بتعمل منه اسم Function: `client.getRates()`.
3. `"$ref": "#/components/parameters/base"`: نفس `$ref` بتاع JSON Schema (فصل 7): الـ Parameter متعرّف مرة واحدة تحت في `components`، وكل العمليات بتشاور عليه.
4. `"in": "query"`: الـ Parameter ده بيتبعت فين: `query` أو `path` أو `header` أو `cookie`. (الـ Body ليه مكان لوحده اسمه `requestBody`.)
5. `"default": "EUR"`: لو مبعتّوش. وده جواب التحدي الصعب في فصل 1: لو شلت `base`، السعر بيتحسب بالـ EUR.
6. `"responses": ["200", "404", "422", "503"]`: الـ Statuses الموثّقة. و422 = Parameter قيمته غلط: جربنا `base=XYZ` ورجع `422` و`{"status":422,"message":"invalid currency: XYZ"}`.

```sh title="Terminal"
$ jq '.components.schemas.Rate | {required, props: (.properties | keys)}' -c fr.json
{"required":["date","base","quote","rate"],"props":["base","date","providers","quote","rate"]}
```

وده JSON Schema عادي جداً (فصل 7)! بيقولك كل عنصر في الرد فيه 4 حقول مضمونين، و`providers` اختياري. يعني تقدر تكتب كودك وانت متأكد إن `rate` موجود.

**المصادر الرسمية:** [Frankfurter · openapi.json](https://api.frankfurter.dev/v2/openapi.json) · [OpenAPI Specification (latest)](https://spec.openapis.org/oas/latest.html) · [OpenAPI Initiative · What is OpenAPI](https://www.openapis.org/what-is-openapi)

## 11.4 الصفحات اللي بتتولد من الملف

نفس الملف ده بيتحوّل لدوكيومنتيشن تفاعلية بأدوات زي:

**أدوات العرض**

| الأداة | بتعمل |
|---|---|
| Swagger UI | الصفحة الكلاسيكية: كل Endpoint ليه زر **Try it out** يبعت طلب حقيقي من المتصفح. وأي API Express بيستخدم `swagger-ui-express` بيعرضها على `/docs`. |
| Redoc | صفحة دوكيومنتيشن من 3 أعمدة، أشيك للقراية، من غير Try it out في النسخة المجانية. |
| Scalar | أحدث، وفيه API client جوه الصفحة. |
| Bruno / Postman / Insomnia | Import للملف = Collection جاهزة بكل الطلبات (فصل 8). |

:::note[مثال عملي: Petstore]
افتح `https://petstore3.swagger.io/`: ده المثال الرسمي من Swagger، ملفه OpenAPI **3.0.4** فيه 13 Path (`/pet` و `/pet/{petId}` و `/store/order`…). افتح `GET /pet/{petId}` ← Try it out ← حط 1 ← Execute. هتشوف الـ curl اللي اتبعت، والرد، والـ Headers. وبعدين حط `abc` وشوف الـ 400.
:::

:::note[توليد Client و Types من الملف]
لأن الملف دقيق، في أدوات بتكتبلك كود منه: **openapi-typescript** بيطلّع Types لـ TypeScript لكل Request و Response، و**OpenAPI Generator** بيطلّع Client كامل بأكتر من 50 لغة. و GitHub نفسه بينشر ملف OpenAPI للـ REST API كله في Repo اسمه `github/rest-api-description`، ومنه بيتعمل SDK بتاعهم `octokit`. وده اللي هتعمله بعدين في React: Types من ملف الـ API بدل ما تخمّن.
:::

**المصادر الرسمية:** [Swagger UI](https://swagger.io/tools/swagger-ui/) · [Redoc](https://github.com/Redocly/redoc) · [Scalar](https://github.com/scalar/scalar) · [openapi-typescript](https://openapi-ts.dev/) · [github/rest-api-description](https://github.com/github/rest-api-description)

:::tip[ملخص الفصل]
- اقرا بالترتيب: Getting started ← Auth ← Versioning ← Errors ← Rate limits ← Pagination ← Reference ← Changelog.
- صفحة الـ Endpoint: Method + Path، وصلاحيات، و Parameters (path و query و header و body)، و Responses، وأمثلة.
- Path = هوية الـ Resource، و Query = طريقة العرض، و Header = عن الطلب، و Body = البيانات.
- OpenAPI = المواصفة (3.2.1 الأحدث)، و Swagger = أدوات. والملف فيه `openapi` و `info` و `servers` و `paths` و `components`.
- `.openapi` نسخة المواصفة، و`.info.version` نسخة الـ API.
- من الملف: Swagger UI و Redoc و Scalar، و Collections، و Types و Clients.
:::

### صح ولا غلط؟

1. Swagger و OpenAPI حاجتين ملهمش علاقة ببعض.
2. الـ Path parameters عادة اختيارية.
3. الـ `info.version` في ملف OpenAPI هو نسخة مواصفة OpenAPI.

### أسئلة مراجعة

1. ليه تقرا صفحة الـ Errors والـ Rate limits قبل صفحة الـ Endpoint؟
2. إمتى تخلّي حاجة Path parameter وإمتى Query parameter؟ إدّي مثال.
3. إيه فايدة `operationId`؟
4. اكتب أمر jq يطلّع كل الـ `operationId` في ملف `fr.json`.
