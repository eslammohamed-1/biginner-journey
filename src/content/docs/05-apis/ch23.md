<small>المرحلة 7 · الجسر والمشروع</small>

وقت التطبيق كمستخدم. هتاخد API حقيقي متعرفهوش وتمشي عليه بخطوات ثابتة: الـ Docs والـ Spec، وأول طلب، والهيدرز، والـ Auth، والـ Pagination، والأخطاء، والحدود، وبعدين تكتب Script صغير بيعمل حاجة مفيدة، وتسلّم ملف ملاحظات. عملناه مع بعض على GitHub REST API (Repo بتاع Express نفسه)، وبعدين دورك على API تختاره.

:::note[بعد الفصل ده هتكون عارف]
- خطة استكشاف من 8 خطوات تنفع مع أي API
- GitHub: الـ Docs والـ OpenAPI description الرسمي
- أول طلب وقراية كل Header مهم
- Rate limits مختلفة لكل Resource: core و search
- Pagination بـ Link و rel=last
- مفاجأة: Issues endpoint بيرجّع PRs
- Script كامل: report.mjs بـ timeout و Error handling
- ملف الملاحظات اللي هتسلّمه
- APIs بديلة تعمل عليها المشروع
:::

<a id="s23-1"></a>

## 23.1 الخطة: 8 خطوات

1. **الـ Docs والـ Spec**: Base URL، والـ Auth، والـ Versioning، وفي OpenAPI ولا لأ (فصل 11).
2. **أول طلب** بـ `curl -i` أو HTTPie: اقرا الـ Status والهيدرز قبل الـ Body (فصل 3 و 8).
3. **شكل البيانات** بـ jq: إيه الـ Fields المهمة، وأسلوب الأسماء، والتواريخ، والـ null (فصل 6 و 16).
4. **الـ Auth**: من غيره بيحصل إيه، ومعاه بيتغير إيه (فصل 12).
5. **الـ Pagination والفلترة**: Offset ولا Cursor، وفين اللينك (فصل 18).
6. **الأخطاء**: ابعت طلبات غلط عن قصد واقرا الشكل (فصل 16 و 17).
7. **الحدود**: Rate limit، و Versioning، و Deprecation (فصل 19).
8. **Script** صغير بيعمل حاجة مفيدة، بـ Error handling (فصل 10)، و**ملف ملاحظات**.

<a id="s23-2"></a>

## 23.2 الخطوة 1: الـ Docs والـ Spec

GitHub REST API: الـ Base URL `https://api.github.com`، و Versioning بالهيدر (فصل 19)، و Auth بـ Bearer token (فصل 12)، ومن غير توكن 60 طلب في الساعة. وعندهم OpenAPI description رسمي ومفتوح في Repo اسمه `github/rest-api-description`. ده ملف ضخم، بس تقدر تدوّر فيه بـ jq عن أي Endpoint.

**المصادر الرسمية:** [GitHub · REST API docs](https://docs.github.com/en/rest) · [github/rest-api-description (OpenAPI)](https://github.com/github/rest-api-description)

<a id="s23-3"></a>

## 23.3 الخطوات 2 و 3: أول طلب وشكل البيانات

```sh title="Terminal"
$ curl -s -D h1.txt 'https://api.github.com/repos/expressjs/express/releases?per_page=3' \
    -H 'User-Agent: apis-book' | jq -r '.[] | "\(.tag_name)\t\(.published_at)\t\(.author.login)"'
v5.3.0	2026-10-09T12:50:31Z	UlisesGascon
v4.22.2	2026-05-11T18:54:02Z	jonchurch
v5.2.1	2025-12-01T20:54:44Z	jonchurch

$ grep -iE '^(link|x-ratelimit-remaining|etag)' h1.txt
etag: W/"d84dfca22a26a66490a5146176ee8aaed7d2218078b40647e66020153695bcb3"
link: <https://api.github.com/repositories/237159/releases?per_page=3&page=2>; rel="next",
      <https://api.github.com/repositories/237159/releases?per_page=3&page=56>; rel="last"
x-ratelimit-remaining: 56
```

**تشريح الأمر**

```sh
-D h1.txt   \(.tag_name)\t   rel="last"   page=56
```

1. `-D h1.txt`: احفظ الهيدرز في ملف، والـ Body يروح لـ jq. كده عندك الاتنين من طلب واحد (والـ Rate limit غالي).
2. `\(…)`: String interpolation في jq، و`\t` Tab، و`-r` من غير علامات تنصيص (فصل 6).
3. `ملاحظة 1`: الترتيب مش بالنسخة: v4.22.2 نزلت بعد v5.2.1. الـ Releases مترتبة بالتاريخ، و Express بيصلّح الـ 4.x لسه.
4. `ملاحظة 2`: `rel="last"` بـ `page=56` و`per_page=3`: يعني حوالي 166 لـ 168 Release. عرفنا العدد من غير ما نجيبهم كلهم.
5. `ملاحظة 3`: التواريخ RFC 3339 بالـ UTC (`Z`)، والأسماء snake\_case.

## 23.4 الخطوة 7 بدري: الحدود مختلفة

```sh title="Terminal"
$ curl -s 'https://api.github.com/search/issues?q=repo:expressjs/express+is:issue+is:open&per_page=1' \
    -H 'User-Agent: apis-book' | jq '{total_count, incomplete_results}'
{
  "total_count": 112,
  "incomplete_results": false
}
$ curl -s -D h2.txt -o /dev/null 'https://api.github.com/search/issues?q=repo:expressjs/express' -H 'User-Agent: apis-book'
$ grep -i '^x-ratelimit' h2.txt
x-ratelimit-limit: 10
x-ratelimit-remaining: 9
x-ratelimit-used: 1
x-ratelimit-resource: search
x-ratelimit-reset: 1792756774
```

الـ **Search** ليه عدّاد لوحده (`resource: search`): 10 في **الدقيقة** من غير توكن، مش 60 في الساعة زي `core`. والـ Docs بتأكد ده. ده من نوع الحاجات اللي **متعرفهاش غير لما تبص على الهيدرز**.

<a id="s23-5"></a>

## 23.5 مفاجأة: الـ Issues فيها PRs

طلبنا `/repos/expressjs/express/issues?state=open&per_page=50` وجالنا 50. بس الـ Search قال إن الـ Issues المفتوحة 112، فإزاي أول 50 فيهم بس 11 Issue؟ رجعنا للـ Docs:

:::note[من Docs بتاعة GitHub]
"GitHub's REST API considers every pull request an issue, but not every issue is a pull request." يعني الـ Endpoint ده بيرجّع الاتنين، والـ PR بيتعرف بإن فيه `pull_request` key. وده درس تصميم كمان: اسم الـ Endpoint بيوعد بحاجة، والرد فيه حاجة تانية، فلازم يتكتب بوضوح في الـ Docs.
:::

## 23.6 الخطوة 8: الـ Script

```js title="report.mjs"
const [owner = "expressjs", repo = "express"] = process.argv.slice(2);
const API = "https://api.github.com";
const headers = {
  "User-Agent": "apis-book-report",
  Accept: "application/vnd.github+json",
  "X-GitHub-Api-Version": "2026-03-10",
  ...(process.env.GITHUB_TOKEN && { Authorization: `Bearer ${process.env.GITHUB_TOKEN}` }),
};

let lastRemaining = null;
async function gh(path) {
  const res = await fetch(API + path, { headers, signal: AbortSignal.timeout(10_000) });
  lastRemaining = res.headers.get("x-ratelimit-remaining");
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new Error(`${res.status} ${body.message ?? res.statusText} (${path})`);
  }
  return res.json();
}

let r;
try {
  r = await gh(`/repos/${owner}/${repo}`);
} catch (err) {
  console.error(`Cannot read ${owner}/${repo}: ${err.message}`);
  process.exit(1);
}
const releases = await gh(`/repos/${owner}/${repo}/releases?per_page=3`);
const issues = await gh(`/repos/${owner}/${repo}/issues?state=open&per_page=50`);
const onlyIssues = issues.filter((i) => !i.pull_request); // this endpoint also returns PRs
const labels = {};
for (const i of onlyIssues) for (const l of i.labels) labels[l.name] = (labels[l.name] ?? 0) + 1;
// ... console.log the report (see the output)
```

**تشريح الأمر**

```js
...(process.env.GITHUB_TOKEN && { Authorization: ... })
```

1. `...( && {})`: لو في توكن في الـ Environment، زوّد الهيدر. لو مفيش، `...false` مبيزوّدش حاجة. التوكن عمره ما يتكتب في الكود.
2. `X-GitHub-Api-Version`: ثبّتنا النسخة علشان الـ Script ميتغيرش سلوكه لوحده (فصل 19).
3. `AbortSignal.timeout`: متستناش للأبد (فصل 10).
4. `res.json().catch`: لو الـ Error مش JSON، متقعش وانت بتقرا الـ Error.

:::

Docs / Spec: docs.github.com/rest · github/rest-api-description (OpenAPI)

## 23.8 دورك

اعمل نفس الـ 8 خطوات على API تاني (من جدول فصل 9)، وسلّم `notes.md` و Script:

**اقتراحات**

| الـ API | هيعلّمك إيه | فكرة Script |
|---|---|---|
| PokeAPI | Offset pagination، وعلاقات بلينكات | كل Pokémon نوعه Fire وأقوى 5 فيهم |
| Open-Meteo | Query params كتير، و Units، وأخطاء 400 واضحة | تقرير طقس القاهرة لـ 7 أيام بـ jq أو Node |
| Frankfurter v2 | OpenAPI 3.1 جاهز، و 422 | سعر الجنيه مقابل 3 عملات آخر شهر |
| DummyJSON | Auth بـ JWT و Refresh | Login ثم `/auth/me` ثم Refresh لما يخلص |
| Rick and Morty (REST + GraphQL) | نفس البيانات بطريقتين | نفس السؤال بـ REST وبـ GraphQL وقارن عدد الطلبات |

:::tip[ملخص الفصل]
- 8 خطوات ثابتة: Docs، وأول طلب، والشكل، والـ Auth، والـ Pagination، والأخطاء، والحدود، و Script وملاحظات.
- احفظ الهيدرز مع الـ Body (`-D`) لأن الـ Rate limit غالي.
- الحدود ممكن تختلف لكل Resource (core و search).
- الـ Docs بتشرح المفاجآت (Issues فيها PRs)، فارجعلها لما الأرقام متركبش.
- Script بـ Version ثابت، و Timeout، و Token من الـ Environment، و Exit code صح.
:::

### صح ولا غلط؟

1. الـ Search في GitHub بيشارك نفس عدّاد الـ 60 في الساعة.
2. كل عنصر في `/issues` عند GitHub هو Issue مش PR.
3. تثبيت `X-GitHub-Api-Version` في الـ Script فكرة كويسة.

### أسئلة مراجعة

1. إزاي عرفنا عدد الـ Releases التقريبي من غير ما نجيبهم؟
2. ليه الـ Script بيطلع بـ Exit code 1 لما يفشل؟
3. إيه اللي في Errors بتاعة GitHub مختلف عن RFC 9457؟
4. ليه بنقرا الـ Token من `process.env`؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** شغّل `report.mjs` على Repo تاني (`facebook react`) وقارن.
2. **[متوسط]** خلّي الـ Script يمشي على كل صفحات الـ Issues المفتوحة بالـ Link header (فصل 18) ويعدّ الـ Issues الحقيقية بس.
3. **[صعب]** زوّد Cache بالـ ETag: احفظ الرد والـ ETag في ملف، وابعت `If-None-Match` المرة الجاية، واطبع "from cache" لو جالك 304.
