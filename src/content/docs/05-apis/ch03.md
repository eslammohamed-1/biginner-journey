<small>المرحلة 1 · الفكرة</small>

في كتاب الإنترنت شرّحنا طلب HTTP لصفحة ويب. هنا هنعمل نفس الحكاية بس على API حقيقي: GitHub. هنبعت طلب واحد ونقرا كل Header رايح وكل Header راجع، ونفهم ليه الـ API محتاج كل واحد فيهم، ونمشي على الـ JSON اللي رجع Field بـ Field.

:::note[بعد الفصل ده هتكون عارف]
- تقرا ناتج curl -v لـ API سطر سطر
- Accept و Content-Type و User-Agent و Authorization من ناحية الـ API
- Headers خاصة بالـ API: X-GitHub-Api-Version و x-ratelimit-\* و link و etag
- تمشي على JSON كبير وتفهم شكله من غير ما تتوه
- طلب Conditional بـ If-None-Match ورد 304
- خطة التلات أسئلة لأي رد: نجح؟ إيه الشكل؟ فاضلّي قد إيه؟
:::

<a id="s3-1"></a>

## 3.1 فكرة سريعة من كتاب الإنترنت

أي HTTP request فيه: **سطر الطلب** (Method + Path + Version)، و**Headers**، و**Body** اختياري. وأي رد فيه: **سطر الحالة** (Version + Status code)، و**Headers**، و**Body**. ده كله اتشرح بالتفصيل في كتاب الإنترنت (فصول 7 و 8 و 9)، فمش هنعيده. اللي جديد هنا: <strong>إيه اللي بيفرق طلب API عن طلب صفحة؟</strong>

#### طلب صفحة (المتصفح)

- `Accept: text/html,…`
- الرد HTML للعرض.
- Cookies بتتبعت لوحدها.
- بيتبعه عشرات الطلبات (CSS و JS وصور).

#### طلب API (كود)

- `Accept: application/json` أو نوع خاص بالـ API.
- الرد JSON للكود.
- الهوية غالباً في `Authorization` header.
- طلب واحد بيرجّع بيانات وبس، ومعاه Headers بتقولك الحدود والصفحات.

<a id="s3-2"></a>

## 3.2 الطلب: 5 سطور رايحين

GitHub عنده API عام تقدر تجرّبه من غير تسجيل (بحد 60 طلب في الساعة). هنسأله عن Repository بتاع Express، اللي هتشتغل بيه في كورس Maximilian:

```sh title="Terminal"
$ curl -sv -H "Accept: application/vnd.github+json" \
    -H "X-GitHub-Api-Version: 2026-03-10" \
    https://api.github.com/repos/expressjs/express -o repo.json
```

**تشريح الأمر**

```sh
curl -sv -H "Accept: application/vnd.github+json" -H "X-GitHub-Api-Version: 2026-03-10" https://api.github.com/repos/expressjs/express -o repo.json
```

1. `-sv`: اتنين Flags مع بعض: `-s` اسكت عن شريط التقدم، و`-v` "Verbose": اطبع الطلب والرد كاملين بالـ Headers (بـ `>` للرايح و `<` للجاي).
2. `-H "Accept: …"`: بنقول للسيرفر عايزين الرد بأنهي شكل. و GitHub بيطلب في الدوكيومنتيشن `application/vnd.github+json`. والـ `vnd.` = "Vendor": نوع خاص بشركة معينة، والـ `+json` = بس هو في الآخر JSON.
3. `-H "X-GitHub-Api-Version: …"`: نسخة الـ API اللي عايزها، بتاريخ. ولو مبعتّوش، GitHub بيفترض النسخة القديمة `2022-11-28` (فصل 19).
4. `https://api.github.com`: الـ Host بتاع الـ API، منفصل عن `github.com` بتاع الموقع.
5. `/repos/expressjs/express`: الـ Resource: "الـ Repo اللي صاحبه `expressjs` واسمه `express`". اتنين Path parameters ورا بعض.
6. `-o repo.json`: "Output": احفظ الـ Body في ملف بدل ما يتطبع في الشاشة، علشان نشوف الـ Headers لوحدها ونفصّص الـ JSON بعدين بـ jq.

```http title="الرايح (> في ناتج curl -v)"
> GET /repos/expressjs/express HTTP/2
> Host: api.github.com
> User-Agent: curl/8.14.1
> Accept: application/vnd.github+json
> X-GitHub-Api-Version: 2026-03-10
```

| الأمر | بيعمل إيه |
|---|---|
| `GET … HTTP/2` | `GET` = "هات" ومبيغيّرش حاجة. والمسار من غير الـ Host. و HTTP/2 اتفق عليه curl مع السيرفر أثناء TLS (كتاب الإنترنت فصل 11). |
| `Host` | إجباري. السيرفر الواحد ممكن يخدم كذا Domain. |
| `User-Agent` | مين بيكلّم. curl بيحطه لوحده. و**GitHub بيرفض أي طلب من غيره**: جرّبنا نشيله بـ `-H 'User-Agent:'` ورجع **403** ورسالة: <em>"Please make sure your request has a User-Agent header"</em>. وفي اسكريبتاتك حط اسم تطبيقك فيه. |
| `Accept` | الـ Content negotiation: "أنا بفهم الشكل ده". والسيرفر يرد بالشكل ده أو يقولك `406`. |
| `X-GitHub-Api-Version` | Header خاص بـ GitHub (الـ `X-` في الأول عُرف قديم للـ Headers الغير رسمية). |

ومفيش `Authorization` هنا، فاحنا "مجهولين"، وده اللي مخلّي الحد 60 في الساعة. ولو بعتنا Token (فصل 12) الحد بيبقى 5000.

**المصادر الرسمية:** [GitHub · Getting started with the REST API](https://docs.github.com/en/rest/using-the-rest-api/getting-started-with-the-rest-api) · [GitHub · Troubleshooting (User-Agent required)](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api)

## 3.3 الرد: الـ Headers اللي تهم الـ API

```http title="الجاي (< في ناتج curl -v، مختصر)"
< HTTP/2 200
< content-type: application/json; charset=utf-8
< cache-control: public, max-age=60, s-maxage=60
< vary: Accept,Accept-Encoding, Accept, X-Requested-With
< etag: W/"db10cba91645251533a85da8678ac26b20a3aeb72adfc7474f274afeabee7811"
< last-modified: Fri, 23 Oct 2026 10:17:04 GMT
< x-github-api-version-selected: 2026-03-10
< access-control-allow-origin: *
< x-ratelimit-limit: 60
< x-ratelimit-remaining: 47
< x-ratelimit-used: 13
< x-ratelimit-resource: core
< x-ratelimit-reset: 1792754886
< content-length: 6899
< x-github-request-id: 6E3C:2BED:12792C7:3C98199:6ADB436A
```

شلنا Headers الأمان العامة (`strict-transport-security` وأصحابها، كتاب الإنترنت فصل 12). وخلينا نقسم الباقي لـ 4 أسئلة:

**كل Header والسؤال اللي بيجاوبه**

| Header | السؤال | القيمة هنا يعني إيه |
|---|---|---|
| `HTTP/2 200` | نجح؟ | أيوه، والـ Body فيه اللي طلبته. |
| `content-type` | الـ Body إيه؟ | JSON بـ UTF-8. **اقراه قبل ما تعمل parse**: لو جالك `text/html` يبقى غالباً صفحة غلط مش JSON. |
| `content-length` | حجمه؟ | 6899 byte. |
| `cache-control` | أقدر أخزنه؟ | أيوه 60 ثانية (كتاب الإنترنت فصل 15). يعني متسألش أكتر من مرة في الدقيقة على نفس الحاجة. |
| `etag` و `last-modified` | اتغير ولا لأ؟ | "بصمة" النسخة دي. هنستخدمها تحت في طلب Conditional. والـ `W/` = Weak: "نفس المعنى" مش لازم نفس البايتات. |
| `vary` | الرد بيختلف حسب إيه؟ | حسب `Accept` وغيره. فالـ Cache لازم يخزّن نسخة لكل `Accept` مختلف. |
| `x-github-api-version-selected` | اتعاملت بأنهي نسخة؟ | اللي طلبناها. لو مكناش بعتنا كان هيقول `2022-11-28`. |
| `access-control-allow-origin: *` | الـ JS في أي موقع يقدر يقراه؟ | أيوه، أي Origin (CORS، فصل 13). |
| `x-ratelimit-limit` | حدّي كام؟ | 60 طلب في الساعة لـ `core`. |
| `x-ratelimit-remaining` / `used` | فاضل كام؟ | 47 فاضلين، و 13 استخدمناهم (كنا بنجرّب كتير). |
| `x-ratelimit-reset` | الحد هيتصفّر إمتى؟ | رقم ثواني من 1970 (Unix time) = 11:28 UTC = **2:28 م بتوقيت القاهرة**. وتحوّله على الماك بـ `date -r 1792754886`. |
| `x-github-request-id` | لو اشتكيت؟ | رقم الطلب عندهم. ابعته للدعم الفني لو في مشكلة. |

:::note[date على الماك غير Linux]
على الماك: `date -r 1792754886` (الـ `-r` بتاخد ثواني). وعلى Linux نفس الحاجة بـ `date -d @1792754886`. والفرق ده لأن `date` في الماك نسخة BSD، وفي Linux نسخة GNU. ونفس الكلام هيقابلك مع `sed` و `base64`.
:::

:::tip[Best Practice: خطة التلات أسئلة لأي رد]
قبل ما تبص في الـ Body: (1) <strong>نجح؟</strong> بص على الـ Status. (2) <strong>إيه الشكل؟</strong> بص على `content-type`. (3) <strong>فاضلّي قد إيه؟</strong> دوّر على Headers الـ Rate limit. وبعدين بس افتح الـ JSON.
:::

**المصادر الرسمية:** [GitHub · Rate limits for the REST API](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) · [GitHub · Best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api) · [MDN · ETag](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/ETag)

## 3.4 الـ Body: إزاي تمشي في JSON كبير

الملف فيه **85 Field** في أول مستوى. متقراهوش كله. اختار اللي يهمك (الأمر ده بـ jq، وهنشرحه حتة حتة في فصل 6):

```sh title="Terminal"
$ jq '{id, name, full_name, private, owner: {login: .owner.login, type: .owner.type}, description, stargazers_count, open_issues_count, default_branch, topics: .topics[:3], created_at, license: .license.spdx_id}' repo.json
```

```json title="النتيجة"
{
  "id": 237159,
  "name": "express",
  "full_name": "expressjs/express",
  "private": false,
  "owner": {
    "login": "expressjs",
    "type": "Organization"
  },
  "description": "Fast, unopinionated, minimalist web framework for node.",
  "stargazers_count": 69577,
  "open_issues_count": 248,
  "default_branch": "master",
  "topics": [
    "express",
    "javascript",
    "nodejs"
  ],
  "created_at": "2009-06-26T18:56:01Z",
  "license": "MIT"
}
```

```json title="Field بـ Field: إيه اللي تتعلمه من كل واحد كمصمّم"
"id": 237159
"name" / "full_name"
"private": false
"owner": { … }
"stargazers_count": 69577
"topics": [ … ]
"created_at": "2009-06-26T18:56:01Z"
"license": "MIT"
```

1. `"id": 237159`: **رقم ثابت** للـ Repo. الاسم ممكن يتغير (لو حد عمل Rename)، الـ `id` لأ. فلو هتخزّن مرجع في Database، خزّن الـ `id`.
2. `"name" / "full_name"`: نفس المعلومة بشكلين للراحة. الـ `full_name` بيوفّر عليك تركّب `owner/name`.
3. `"private": false`: Boolean حقيقي، مش `"false"` نص ولا `0`.
4. `"owner": { … }`: **Object جوه Object** (Nested). صاحب الـ Repo نفسه Resource تاني، فـ GitHub حاطط ملخص منه هنا علشان متعملش طلب تاني.
5. `"stargazers_count": 69577`: الأسماء بـ `snake_case` (شرطة تحتية). APIs تانية بتستخدم `camelCase`. مفيش صح وغلط، المهم الثبات (فصل 16).
6. `"topics": [ … ]`: Array من Strings. ولو مفيش Topics هترجع `[]` مش `null`: ودي عادة كويسة.
7. `"created_at": "2009-06-26T18:56:01Z"`: التاريخ كـ String بصيغة **ISO 8601 / RFC 3339**. والـ `Z` = UTC. JSON معندوش نوع تاريخ (فصل 4)، فده العرف.
8. `"license": "MIT"`: في الحقيقة دي Object كامل (`.license` فيها `key` و`name` و`spdx_id`…)، واحنا اللي اخترنا `spdx_id` بس. ولو الـ Repo من غير License، القيمة `null`، فخلي كودك جاهز.

**المصادر الرسمية:** [GitHub · Get a repository](https://docs.github.com/en/rest/repos/repos#get-a-repository) · [RFC 3339 · Date and Time on the Internet](https://www.rfc-editor.org/rfc/rfc3339)

## 3.5 طلب Conditional: "اتغير حاجة؟"

قلنا إن الـ `etag` بصمة. لو عايز تسأل كل شوية "الـ Repo اتغير؟"، متنزّلش الـ 6899 byte كل مرة. ابعت البصمة اللي معاك في `If-None-Match`:

```sh title="Terminal"
$ curl -s -i -H 'If-None-Match: W/"7641f364f03df15614e181458c8ebae5a96dac49d08ccd9ddaead72f01911a0d"' \
    https://api.github.com/repos/expressjs/express
HTTP/2 304
x-ratelimit-remaining: 59
```

**304 Not Modified** ومفيش Body خالص: "اللي معاك لسه صح". وده بيوفر عليك وعلى السيرفر. وفي جملة مهمة في دوكيومنتيشن GitHub: الـ 304 **مبيتحسبش من الحد** لو الطلب كان بـ `Authorization`. ومن غيره ممكن يتحسب، فمتعتمدش على ده وانت مجهول.

:::caution[خلي بالك: الـ ETag مربوط بالـ Accept]
أول مرة جربنا، بعتنا ETag جاي من طلب بـ `Accept: application/vnd.github+json` في طلب من غيره، فرجع **200** مش 304. ليه؟ الـ `vary: Accept` بيقول إن الرد بيختلف حسب `Accept`، فكل واحد ليه ETag. فابعت نفس الـ Headers في الطلبين.
:::

::::tip[حاجة مشتركة: نفس الطلب من JS]
كل اللي فوق بالظبط من Console المتصفح أو Node 18+: `const res = await fetch("https://api.github.com/repos/expressjs/express", { headers: { Accept: "application/vnd.github+json" } }); console.log(res.status, res.headers.get("x-ratelimit-remaining")); const repo = await res.json();`. والـ `fetch` هنشرحه بالتفصيل في فصل 10.

:::note[تشغيل JavaScript من الـ Terminal بـ Node]
من هنا ورايح هنشغّل أمثلة كتير بـ **Node**: ده برنامج بيشغّل JavaScript برّه المتصفح، من الـ Terminal (لو مش متسطب عندك، شوف كتاب الـ Terminal فصل 11: `brew install fnm` ثم `fnm install 24`). اللي محتاج تعرفه دلوقتي بس:

- `node file.mjs`: شغّل الملف ده. الامتداد `.mjs` معناه إن الملف **ES Module**، فينفع جواه تكتب `import` وتكتب `await` في أول الملف على طول من غير دالة `async`.
- `import { readFileSync } from "node:fs"`: هات دالة جاهزة من مكتبة. اللي أولها `node:` جاية مع Node نفسه، والباقي محتاج `npm install اسمها` الأول، وبتتحط في `node_modules`.
- `node -e '...'`: شغّل سطر JavaScript واحد من غير ملف.
- `process.env.X`: اقرا متغير بيئة (كتاب الـ Terminal فصل 13).

والـ `await` نفسها اتشرحت في صندوق "Promise و async/await في دقيقة" في كتاب الإنترنت (فصل 7). والـ Modules و npm بالتفصيل في كتاب عالم الفرونت إند (فصول 13 و 17).
:::
::::

:::tip[ملخص الفصل]
- طلب الـ API = نفس HTTP، بس `Accept` بيطلب JSON، والهوية في `Authorization`، والرد بيانات بس.
- GitHub بيرفض أي طلب من غير `User-Agent` بـ 403.
- Headers الـ API المهمة: `content-type` و `etag` و `cache-control` و `x-ratelimit-*` و Header النسخة و Request ID.
- الـ `x-ratelimit-reset` = Unix time، وتحوّله بـ `date -r` على الماك.
- JSON الكبير: اختار الحقول بـ jq، وخزّن الـ `id` مش الاسم، والتواريخ ISO 8601 بـ `Z`.
- `If-None-Match` + ETag = 304 من غير Body لو مفيش تغيير.
:::

### صح ولا غلط؟

1. رد `304` بيبقى فيه نفس الـ Body بتاع 200.
2. `x-ratelimit-reset` بيقولك عدد الثواني الفاضلة لحد ما الحد يتصفّر.
3. الأحسن تخزّن `full_name` كمرجع للـ Repo بدل الـ `id`.

### أسئلة مراجعة

1. إيه الفرق بين `Accept` و `Content-Type`؟ وكل واحد بيتبعت في الطلب ولا الرد؟
2. ليه ممكن تاخد 200 بدل 304 مع إنك باعت ETag صح؟
3. لو `content-type` رجع `text/html` من API المفروض بيرجّع JSON، تتوقع إيه حصل؟
4. إيه فايدة `x-github-request-id`؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** ابعت نفس الطلب لـ `https://api.github.com/users/octocat` واقرا الـ `x-ratelimit-remaining` قبل وبعد.
2. **[متوسط]** اعمل Conditional request بـ ETag للـ `users/octocat` وتأكد إنه رجّع 304.
3. **[صعب]** جرّب `-H "Accept: application/xml"`. GitHub رد بإيه؟ وإيه الـ Status code اللي كنت تتوقعه حسب HTTP؟
