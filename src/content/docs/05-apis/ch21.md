<small>المرحلة 6 · Webhooks و OpenAPI</small>

في فصل 11 قريت OpenAPI بتاع Frankfurter كمستخدم. دلوقتي هتكتبه للـ API بتاعك: نوصف library.js بـ OpenAPI 3.2، وكل جزء بنشرحه سطر بسطر، ونعمل Lint بـ Redocly CLI ونصلّح اللي طلّعه، وبعدين نطلّع منه Docs و TypeScript types، ونستخدمه كـ Contract test يمسك سيرفر بيكدب.

:::note[بعد الفصل ده هتكون عارف]
- Design-first ضد Code-first
- الهيكل: openapi و info و servers و paths و components
- Path و Operation و operationId
- Parameters: query و path و header
- requestBody والـ Content types (merge-patch و problem+json)
- components: schemas و parameters و responses و headers و $ref
- Lint بـ Redocly CLI: 3 تحذيرات وتصليحها
- Docs HTML و TypeScript types من نفس الملف
- Contract test: السيرفر القديم فشل
:::

<a id="s21-1"></a>

## 21.1 Design-first

قبل كده: الفريق يكتب الكود، وبعد ما يخلص حد يكتب Docs في Word أو Wiki. بعد شهرين الكود اتغير والـ Docs لأ، والـ Frontend بيشتغل على معلومات غلط. وكانت المشكلة إن الـ Docs **نسخة تانية** من الحقيقة. فاتطور حل: الـ **Spec** يبقى ملف واحد تقدر الآلة تقراه، ومنه تطلع الـ Docs، والـ Types، والـ Mock server، والـ Tests.

#### Design-first

تكتب الـ Spec الأول، والفريق (وانت والـ Frontend) يتفقوا عليه، وبعدين تكتب الكود. التصميم بيتراجع وهو لسه رخيص يتغير. <strong>ده اللي هنعمله في المشروع (فصل 24).</strong>

#### Code-first

تكتب الكود، ومكتبة بتطلّع الـ Spec منه (من zod مثلاً، أو من Decorators في NestJS). أسرع في الأول، بس التصميم بيتعمل وانت بتكتب كود.

<a id="s21-2"></a>

## 21.2 الهيكل

هنوصف `library.js` (فصل 15 لـ 19). الملف كامل 239 سطر YAML. (YAML = نفس JSON بس بالمسافات بدل الأقواس، وأسهل في الكتابة بإيدك. والاتنين مقبولين في OpenAPI.)

:::note[YAML في صفحة: هتحتاجها في Docker و Kubernetes]
YAML هو JSON بس من غير أقواس ولا Quotes في الغالب. نفس البيانات بالشكلين:

```yaml title="article.yaml"
# comment: Kubernetes and Compose files look exactly like this
title: Hello YAML        # key: value  (string without quotes)
views: 120               # number
published: true          # boolean
tags:                    # a list: every item starts with "- "
  - api
  - json
author:                  # nested object: indent with 2 spaces
  name: Sara
  email: sara@example.com
body: |                  # | = multi-line text, kept as is
  First line.
  Second line.
```

- **المسافات هي القواعد**: اللي متزحزح لجوه تحت مفتاح = جواه. مسافات بس، والـ Tab ممنوع. وأشهر Error هتشوفه سببه مسافة زيادة أو ناقصة.
- `key: value`: لازم مسافة بعد الـ `:`.
- `- `: عنصر في List. ولو العنصر Object، المفاتيح بتاعته تيجي تحت الشرطة بنفس المسافة.
- النص من غير Quotes عادي، بس حط `"..."` لو فيه `:` أو `#`، أو لو عايز `"8080"` يفضل نص مش رقم.

الشكل ده بالظبط هو اللي هتكتبه في `compose.yaml` في كتاب Docker، وفي كل ملفات Kubernetes.
:::

```text title="spec/openapi.yaml: أول جزء"
openapi: 3.2.0
info:
  title: Content Library API
  version: 1.0.0
  license:
    name: MIT
    identifier: MIT
servers:
  - url: http://localhost:3001/v1
security: []
paths:
  /articles:
    get: ...
    post: ...
components:
  schemas: ...
  parameters: ...
  responses: ...
```

1. `openapi: 3.2.0`: نسخة الـ **Spec** نفسه (مش الـ API). 3.2.0 نزلت سبتمبر 2025، وفيه 3.2.1 (سبتمبر 2026) تصليحات. ولو أداة عندك مش بتدعم 3.2 لسه، اكتب 3.1.x.
2. `info:`: نسخة **الـ API بتاعك**. انت اللي بتحددها.
3. `license:`: `identifier` = كود SPDX (من 3.1).
4. `servers:`: الـ Base URL. كل الـ Paths بتتحط بعده.
5. `security: []`: "مفيش Auth" بشكل صريح (هنشوف ليه تحت).
6. `paths:`: كل Path وتحته الـ Methods. كل واحد اسمه **Operation**.
7. `components:`: الحاجات اللي بتتكرر، بتتعرّف مرة وتتشاور عليها بـ `$ref`.

## 21.3 Operation كامل

```text title="POST /articles"
  /articles:
    post:
      operationId: createArticle
      summary: Create an article
      tags: [articles]
      parameters:
        - name: Idempotency-Key
          in: header
          description: A unique key (UUID) so retries do not create duplicates.
          schema: { type: string, maxLength: 255 }
      requestBody:
        required: true
        content:
          application/json:
            schema: { $ref: "#/components/schemas/ArticleInput" }
            example: { title: REST naming, authorId: "2" }
      responses:
        "201":
          description: Created
          headers:
            Location:
              description: URL of the new article
              schema: { type: string }
          content:
            application/json:
              schema: { $ref: "#/components/schemas/Article" }
        "415": { $ref: "#/components/responses/Problem" }
        "422": { $ref: "#/components/responses/ValidationProblem" }
```

**تشريح الأمر**

```text
operationId: createArticle
```

1. `operationId`: اسم فريد للعملية. الأدوات بتعمل منه اسم Function (`api.createArticle()`). اختاره بعناية.
2. `tags`: تجميع في الـ Docs (القسم "articles").
3. `in: header`: مكان الـ Parameter: `query` أو `path` أو `header` أو `cookie` (و 3.2 زوّد `querystring` للـ Query string كلها كـ Schema واحد).
4. `requestBody.content`: مفتاحه الـ Content-Type. والـ PATCH عندنا مفتاحه `application/merge-patch+json` (فصل 15).
5. `"201"`: الـ Status codes بين علامات تنصيص (YAML بيحتاجها علشان متتقريش كرقم).
6. `headers: Location`: هيدرز الرد بتتوصف كمان.
7. `$ref`: JSON Pointer لحتة في نفس الملف. `#` = أول الملف.

### الـ Custom method والـ Path parameters

```text
  /articles/{articleId}:publish:
    parameters:
      - $ref: "#/components/parameters/ArticleId"
    post:
      operationId: publishArticle
      responses:
        "200": ...
        "404": { $ref: "#/components/responses/Problem" }
        "409": { $ref: "#/components/responses/Problem" }
```

`{articleId}` بين أقواس معوجة = Path parameter (في Express كانت `:id`). والـ `:publish` هنا حرفي عادي. والـ Parameters اللي تحت الـ Path نفسه بتتطبق على كل الـ Methods بتاعته.

## 21.4 الـ Components

```text title="components/schemas (جزء)"
    ArticleInput:
      type: object
      required: [title, authorId]
      properties:
        title: { type: string, minLength: 3 }
        status: { $ref: "#/components/schemas/Status", default: draft }
        authorId: { type: string }
        tags: { type: array, items: { type: string }, default: [] }
    Article:
      allOf:
        - $ref: "#/components/schemas/ArticleInput"
        - type: object
          required: [id, createdAt]
          properties:
            id: { type: string, readOnly: true }
            createdAt: { type: string, format: date-time, readOnly: true }
    ArticlePage:
      type: object
      required: [data, nextCursor]
      properties:
        data: { type: array, items: { $ref: "#/components/schemas/Article" } }
        nextCursor: { type: [string, "null"] }
```

**تشريح الأمر**

```text
allOf / readOnly / type: [string, "null"]
```

1. `JSON Schema`: من 3.1، الـ Schemas دي JSON Schema 2020-12 بالظبط (فصل 7). كل اللي اتعلمته هناك شغال هنا.
2. `allOf`: Article = كل حاجة في ArticleInput + `id` و`createdAt`. بنكتب الـ Fields مرة واحدة.
3. `readOnly`: السيرفر بيحطه، والـ Client ميبعتهوش. (الـ Types اللي هتطلع هتعلّمه `readonly`.)
4. `[string, "null"]`: الطريقة الجديدة لـ "String أو null" في 3.1+ (بدل `nullable: true` بتاعة 3.0).

```text title="components/responses: الـ Errors مرة واحدة"
    Problem:
      description: Error (RFC 9457)
      content:
        application/problem+json:
          schema: { $ref: "#/components/schemas/Problem" }
```

وكل Operation بيقول `"404": { $ref: "#/components/responses/Problem" }`. الشكل اللي اتفقنا عليه في فصل 17 بقى مكتوب ومتوثّق في حتة واحدة.

**المصادر الرسمية:** [OpenAPI Specification 3.2.0](https://spec.openapis.org/oas/v3.2.0.html) · [OpenAPI Initiative · Learn OpenAPI](https://learn.openapis.org/)

## 21.5 الـ Lint بـ Redocly CLI

الـ Lint بيقرا الـ Spec ويقولك: ده مش Valid، أو ده Valid بس مش Best practice. Redocly CLI مجاني ومفتوح المصدر، وبيشتغل بـ `npx` من غير تسطيب:

```sh title="Terminal"
$ npx -y @redocly/cli@latest --version
2.70.0
$ npx -y @redocly/cli@latest lint openapi.yaml
No configurations were provided -- using built in recommended configuration by default.

[1] openapi.yaml:11:10 at #/servers/0/url
Server `url` should not point to example.com or localhost.
Warning was generated by the no-server-example.com rule.

[2] openapi.yaml:119:7 at #/paths/~1articles~1{articleId}/delete/responses
Operation must have at least one `4XX` response.
Warning was generated by the operation-4xx-response rule.

Woohoo! Your API description is valid. 🎉
You have 2 warnings.
```

**تشريح الأمر**

```text
at #/paths/~1articles~1{articleId}/delete/responses
```

1. `#/paths/…`: مكان المشكلة كـ JSON Pointer. والـ `/` اللي جوه اسم الـ Path بقت <strong>`~1`</strong> (قاعدة RFC 6901: `~1` = `/`، و`~0` = `~`).
2. `[1] localhost`: تحذير منطقي لـ API حقيقي، بس سيرفرنا فعلاً Local. فقفلنا القاعدة دي في `redocly.yaml` بتعليق بيقول ليه.
3. `[2] 4XX`: الـ DELETE مكانش موثّق ليه أي Error. بس الـ Rate limiter ممكن يرجّع 429 لأي طلب، فزوّدناه.

ولما شيلنا `security` من الـ Spec (لأن `library.js` مفيهوش Auth)، الـ Lint طلّع **6 Errors** جديدة:

```sh title="Terminal"
[1] openapi.yaml:18:5 at #/paths/~1articles/get
Every operation should have security defined on it or on the root level.
Error was generated by the security-defined rule.
...
❌ Validation failed with 6 errors.
```

القاعدة دي بتقول: "لازم تقول صراحة. نسيت الـ Auth ولا قاصد؟". فكتبنا `security: []` (Array فاضية = مفيش Auth، عن قصد):

```sh title="Terminal"
$ npx -y @redocly/cli@latest lint openapi.yaml
validating openapi.yaml...
openapi.yaml: validated in 44ms

Woohoo! Your API description is valid. 🎉
```

```text title="redocly.yaml"
extends:
  - recommended
rules:
  no-server-example.com: off   # our lab server really is on localhost
```

**المصادر الرسمية:** [Redocly CLI · lint](https://redocly.com/docs/cli/commands/lint) · [Redocly · recommended rules](https://redocly.com/docs/cli/rules/recommended)

```sh title="Terminal"
$ npx -y openapi-typescript@latest spec/openapi.yaml -o spec/schema.d.ts
✨ openapi-typescript 7.13.0
🚀 spec/openapi.yaml → spec/schema.d.ts [46.7ms]
```

```js title="جزء من schema.d.ts اللي اتعمل لوحده"
Article: components["schemas"]["ArticleInput"] & {
    readonly id: string;
    /** Format: date-time */
    readonly createdAt: string;
    /** Format: date-time */
    readonly publishedAt?: string;
};
```

لاحظ الـ `allOf` بقى `&`، والـ `readOnly` بقى `readonly`. لما تشتغل React بـ TypeScript، الـ Editor هيكمّل أسماء الـ Fields لوحده ويقولك لو كتبت `createdat` غلط.

## 21.7 Contract test: مين بيكدب؟

الـ Spec وعد. هل السيرفر ملتزم بيه؟ لأن الـ Schemas دي JSON Schema، نقدر نستخدم Ajv (فصل 7) نفسه نقارن ردود حقيقية بيها:

```js title="contract.mjs (الجزء المهم)"
const spec = parse(readFileSync("spec/openapi.yaml", "utf8"));
const ajv = new Ajv2020({ allErrors: true, strict: false });
addFormats(ajv);
ajv.addSchema({ $id: "spec", components: spec.components });
const check = (name) => ajv.getSchema(`spec#/components/schemas/${name}`);

await test("library.js list", "http://localhost:3001/v1/articles?limit=2", "ArticlePage");
await test("library.js one ", "http://localhost:3001/v1/articles/4", "Article");
await test("library.js 404 ", "http://localhost:3001/v1/articles/999", "Problem");
await test("old server.js  ", "http://localhost:3000/v1/articles/2", "Article");
```

```sh title="Terminal"
$ node contract.mjs
PASS  library.js list  (200 vs ArticlePage)
PASS  library.js one   (200 vs Article)
PASS  library.js 404   (404 vs Problem)
FAIL  old server.js    (200 vs Article)
      / must have required property 'authorId'
      / must have required property 'createdAt'
      /id must be string
```

السيرفر القديم بتاع فصل 13 (`server.js`) بيرجّع `"id": 2` Number ومفيش `authorId` ولا `createdAt`. الـ Contract test مسكه في ثانية. وده اللي بيتعمل في الـ CI: أي تغيير في الكود يكسر الوعد، الـ Build يقع قبل ما يوصل للناس.

:::note[لو حابب تتعمق]
أدوات بتعمل ده بشكل أكمل: Schemathesis (بيولّد طلبات من الـ Spec ويدوّر على Bugs)، و Prism (Mock server من الـ Spec علشان الـ Frontend يشتغل قبل ما الـ Backend يخلص). اتأكد من دعمها لـ 3.2 قبل ما تستخدمها، أو اكتب الـ Spec 3.1.
:::

:::tip[ملخص الفصل]
- الـ Spec = مصدر الحقيقة الوحيد. Design-first = تتفق قبل ما تكتب كود.
- `openapi` و`info` و`servers` و`paths` (Operations بـ operationId) و`components` و`$ref`.
- الـ Schemas في 3.1+ = JSON Schema 2020-12: `allOf` و`readOnly` و`[string, "null"]`.
- Redocly lint طلّع 2 تحذير و 6 Errors (security)، وكلهم اتصلّحوا بسبب واضح.
- من نفس الملف: Docs HTML، و TypeScript types، و Contract test مسك السيرفر القديم.
:::

### صح ولا غلط؟

1. `openapi: 3.2.0` هي نسخة الـ API بتاعك.
2. `security: []` معناها إن الـ Auth اتنسى.
3. في JSON Pointer، الـ `/` اللي جوه اسم بتتكتب `~1`.

### أسئلة مراجعة

1. إيه فايدة `operationId`؟
2. ليه `Article` معمول بـ `allOf` بدل ما نكتب كل الـ Fields تاني؟
3. إيه الفرق بين Lint و Contract test؟
4. Design-first ولا Code-first لفريق فيه Frontend مستني؟ وليه؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** زوّد `example` لـ `Article` واعمل `build-docs` وشوفه في الصفحة.
2. **[متوسط]** زوّد `GET /authors/{authorId}` للـ Spec بـ Schema جديد، وخلّي الـ Lint يعدّي.
3. **[صعب]** زوّد `PUT` في الـ Spec، وزوّد على `contract.mjs` اختبار لرد الـ 422 مقابل `ValidationProblem`.
