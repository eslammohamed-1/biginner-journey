<small>المرحلة 3 · إدارة الـ Workloads</small>

فاكر لما قلنا إن Kubernetes بيشتغل بمبدأ الـ Desired State، واللي هي إن دوره يتأكد إن فيه عدد Pods معين شغال وقايم، ولو حصل أي مشكلة وحاجة منهم وقعت هيقوم بدالها؟ هنتكلم عن الحاجة اللي بتعمل كده، ألا وهي الـ ReplicaSets.

:::note[بعد الفصل ده هتكون عارف]
- يعني إيه ReplicaSet ودورها
- ليه بنشغّل كذا نسخة من نفس الـ Pod
- إيه اللي بيحصل لو النسخ زادت أو قلّت
- الـ YAML الصح للـ ReplicaSet
:::

<a id="s8-1"></a>

## 8.1 يعني إيه ReplicaSet؟

هي الحاجة اللي بتتأكد إن فيه عدد معين من الـ Pods شغال، ولكن لاحظ إنها هنا بتتأكد من إن فيه عدد نسخ محدد من **Pod معينة** قايمة. يعني لنتخيل عندنا Pod للـ frontend اسمها `frontend-pod`، لو حطيت إن الـ ReplicaSet بتاعها 3 مثلاً، فكده Kubernetes هيفهم إنه لازم يكون فيه 3 نسخ منها قايمين شغالين.

### طب ليه ممكن نحتاج نقوم كذا نسخة من نفس الـ Pod؟

ببساطة عشان نقدر نستقبل traffic أعلى، وكمان عشان لو واحدة فيهم وقعت يبقى فيه بدالها يستقبل الـ traffic على ما الـ Pod اللي وقعت تقوم تاني. لكن تخيل لو مقومين نسخة واحدة من كل Pod ووقعت.. على ما تقوم تاني الموقع هيفضل واقع. فالهدف إنه يكون فيه نسخ احتياطية عشان لو حصل أي مشاكل زي كده، عقبال ما تتحل، الـ Pods تفضل موجودة وبتستقبل traffic بشكل طبيعي لحد ما المشاكل تتصلح.

![الـ ReplicaSet بتحافظ على العدد المطلوب طول الوقت.](./assets/ch08-fig1.png)

*الـ ReplicaSet بتحافظ على العدد المطلوب طول الوقت.*

:::note[لاحظ]
- لو بطريقة ما بقى فيه نسخ أكتر من المطلوب من نفس الـ Pod، الزيادات هتتمسح.
- لما Pod بيقع وبييجي يقوم بداله، فهو بيقوم Pod زي المكتوب في الـ Configuration (نسخة من الـ template).
- لو زودت أو قللت عدد الـ replicas فجأة، فهيزوّد أو هيقلل النسخ اللي كانت شغالة عشان تبقى زي المكتوب.
:::

<a id="s8-2"></a>

## 8.2 إيه هو Syntax الـ ReplicaSet؟

الفكرة كلها في tag اسمها `replicas` بتحطها جوه الـ tag بتاع الـ `spec`. الشرح الأصلي كتبها كده عشان يوضّح الفكرة:

```yaml title="الفكرة (للتوضيح)"
apiVersion: v1
kind: Pod
metadata:
  name: frontend-pod
spec:
  replicas: 3
  containers:
    ………
```

```yaml title="الشكل العام (للتوضيح)"
apiVersion: v1
kind: Pod
metadata:
  name: name_of_pod_itself
spec:
  replicas: integer_value
  containers:
    ………
```

:::caution[دقة: الـ YAML الحقيقي]
الـ `kind: Pod` مفيهوش حقل اسمه `replicas`، ولو كتبته Kubernetes هيرفض الملف. الـ `replicas` بتتكتب في Object من نوع `ReplicaSet` (أو `Deployment`)، والـ Pod نفسه بيتوصف جواه في `template`، وبيتربطوا ببعض بالـ **Labels والـ Selector** اللي لسه شايفينهم. ده الشكل الصح:
:::

```yaml title="replicaset.yaml"
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: frontend-rs
spec:
  replicas: 3
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
      - name: web
        image: nginx:1.25
```

1. `apiVersion: apps/v1`: الـ ReplicaSet في الـ API group اسمه `apps/v1`.
2. `spec:`: عدد النسخ المطلوب.
3. `selector:`: الـ Pods اللي الـ ReplicaSet مسؤولة عنها.
4. `template:`: الـ template: شكل الـ Pod اللي هيتنسخ. الـ labels هنا لازم تطابق الـ selector.

```sh title="Terminal · توضيح للناتج"
$ kubectl apply -f replicaset.yaml
replicaset.apps/frontend-rs created
$ kubectl get rs
NAME          DESIRED   CURRENT   READY   AGE
frontend-rs   3         3         3       20s
$ kubectl delete pod frontend-rs-7xk2p
pod "frontend-rs-7xk2p" deleted
$ kubectl get pods
NAME                READY   STATUS              RESTARTS   AGE
frontend-rs-4mz9q   1/1     Running             0          40s
frontend-rs-9wq1d   1/1     Running             0          40s
frontend-rs-b8c3t   0/1     ContainerCreating   0          2s
```

**تشريح الأمر**

```sh
kubectl get rs
```

1. `rs`: اختصار `replicasets`. الأعمدة: `DESIRED` العدد المطلوب، `CURRENT` الموجود فعلاً، `READY` الجاهز يستقبل traffic.

ولاحظ إن أسامي الـ Pods بقت **اسم الـ ReplicaSet + كود عشوائي** (زي `frontend-rs-7xk2p`)، لأنها هي اللي بتعملهم من الـ template. والـ Pod الجديدة `b8c3t` اتعملت أوتوماتيك بعد ما مسحنا واحدة.

:::tip[Best Practice]
في الشغل الحقيقي نادراً ما بتكتب ReplicaSet بنفسك. بتكتب **Deployment** وهو اللي بيعمل الـ ReplicaSet ويديرها، وده اللي هنشوفه بعد فصل الـ Namespaces.
:::

:::tip[ملخص الفصل]
- الـ ReplicaSet بتضمن إن فيه عدد ثابت من نسخ نفس الـ Pod شغال طول الوقت.
- النسخ الزيادة بتتمسح، والناقصة بتتعمل من الـ template.
- الـ YAML الصح: `kind: ReplicaSet` فيها `replicas` و `selector` و `template`.
- في الشغل بنستخدم الـ Deployment اللي بيدير الـ ReplicaSet بدالنا.
:::

### أسئلة مراجعة

1. ليه نشغّل 3 نسخ من نفس الـ Pod بدل نسخة واحدة؟
2. مسحت Pod تبع ReplicaSet عددها 3، إيه اللي هيحصل؟
3. إيه علاقة الـ `selector` بالـ `template.metadata.labels`؟

### صح ولا غلط؟

1. ينفع تكتب `replicas` جوه `kind: Pod`.
2. لو بقى فيه Pods أكتر من المطلوب، الـ ReplicaSet بتمسح الزيادة.
3. الـ ReplicaSet بتحدّث الـ Pods القديمة لو غيرت الـ image في الـ template.
