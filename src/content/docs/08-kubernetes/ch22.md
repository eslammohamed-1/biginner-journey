<a id="s22-1"></a>

## 22.1 المشكلة اللي Helm بيحلها

اتعلمنا إزاي تعمل Pods و Deployments و Services بملفات YAML. لاحظت أكيد إن حتى تطبيق بسيط محتاج ملفات كتير، وإدارتهم عبر بيئات مختلفة (dev، staging، production) بتبقى صعبة بسرعة.

الـ **Helm** هو "مدير الحزم" (Package Manager) لـ Kubernetes، زي `apt` في Ubuntu. بدل ما تكتب 10 ملفات YAML لكل بيئة، بتكتبهم مرة واحدة كـ **Templates** فيها متغيرات، وبتغيّر القيم بس لكل بيئة. وكمان تقدر تسطّب تطبيقات جاهزة (زي cert-manager اللي سطبناه في فصل الـ TLS) بأمر واحد.

<a id="s22-2"></a>

## 22.2 المصطلحات الأساسية <small>(إضافة)</small>

#### Chart

الحزمة نفسها: فولدر فيه templates لملفات YAML + ملف قيم افتراضية `values.yaml`.

#### Release

نسخة متسطّبة من Chart في الـ Cluster باسم معين. ممكن تسطب نفس الـ Chart مرتين باسمين مختلفين.

#### Repository

مكان على النت فيه Charts كتير (زي `charts.jetstack.io`). وبتدور فيها على **Artifact Hub**.

<a id="s22-3"></a>

## 22.3 دورة حياة الـ Release <small>(إضافة)</small>

```sh title="Terminal"
helm repo add podinfo https://stefanprodan.github.io/podinfo   # أضف مستودع
helm repo update                                         # حدّث القايمة
helm search repo podinfo                                 # دوّر على Chart
helm install my-web podinfo/podinfo -n web --create-namespace
helm list -A                                             # كل الـ Releases
helm upgrade my-web podinfo/podinfo -n web --set replicaCount=3
helm history my-web -n web                               # النسخ اللي فاتت
helm rollback my-web 1 -n web                            # ارجع للنسخة 1
helm uninstall my-web -n web                             # امسح كل حاجة
```

**تشريح الأمر**

```sh
helm install my-web podinfo/podinfo -n web --create-namespace
```

1. `install`: سطّب Chart كـ Release جديد.
2. `my-web`: اسم الـ Release (من اختيارك)، وبيدخل في أسماء الـ Objects اللي هتتعمل.
3. `podinfo/podinfo`: اسم المستودع/اسم الـ Chart (podinfo تطبيق تجريبي صغير مشهور للتجارب).
4. `-n web`: الـ Namespace اللي هيتسطب فيها، زي kubectl بالظبط.
5. `--create-namespace`: لو الـ Namespace مش موجودة اعملها.

**تشريح الأمر**

```sh
helm upgrade --install my-web ./mychart -f values-prod.yaml --set image.tag=1.2.0
```

1. `upgrade --install`: رقّي الـ Release، ولو مش موجود سطّبه. مثالي في الـ CI/CD لأنه بيشتغل في المرتين.
2. `./mychart`: Chart من فولدر على جهازك بدل مستودع.
3. `-f values-prod.yaml`: ملف قيم بيغطي على القيم الافتراضية (لبيئة الـ production مثلاً).
4. `--set image.tag=1.2.0`: غيّر قيمة واحدة من الأمر. النقطة معناها مستوى أعمق: `image:` جواها `tag:`. وليها الأولوية على `-f`.

:::note[معلومة مهمة]
كل `upgrade` بيعمل Revision جديدة (1، 2، 3 ...). والـ `rollback` نفسه بيعمل Revision جديدة بمحتوى القديمة، فالـ history مش بيضيع.
:::

## 22.4 جوه الـ Chart <small>(إضافة)</small>

```text title="helm create mychart"
mychart/
├── Chart.yaml          # اسم الـ Chart ونسخته (version) ونسخة التطبيق (appVersion)
├── values.yaml         # القيم الافتراضية
├── charts/             # Charts تانية بيعتمد عليها (dependencies)
└── templates/
    ├── deployment.yaml
    ├── service.yaml
    ├── _helpers.tpl    # دوال مساعدة
    └── NOTES.txt       # رسالة بتظهر بعد التسطيب
```

```yaml title="values.yaml"
replicaCount: 2
image:
  repository: nginx
  tag: "1.27"
service:
  port: 80
```

1. `replicaCount: 2`: قيم عادية، وهي اللي بتغيّرها بـ `--set` أو `-f`.

```yaml title="templates/deployment.yaml (جزء)"
metadata:
  name: {{ .Release.Name }}-web
spec:
  replicas: {{ .Values.replicaCount }}
      containers:
      - name: web
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
        {{- if .Values.resources }}
        resources: {{- toYaml .Values.resources | nindent 10 }}
        {{- end }}
```

1. `metadata:`: أي حاجة بين `{{ }}` بتتحسب. `.Release.Name` = اسم الـ Release، فلو `my-web` الاسم يبقى `my-web-web`.
2. `spec:`: `.Values` = محتوى الـ values.yaml بعد دمج `-f` و `--set`.
3. `containers:`: بتطلع `nginx:1.27`.
4. `{{- if .Values.resources }}`: `if` = حط الجزء ده لو القيمة موجودة. `-` جنب الأقواس تشيل المسافات والسطور الفاضية. `toYaml` تحوّل القيمة لـ YAML، و `| nindent 10` (Pipe زي الـ Shell) تبدأ سطر جديد وتزيح 10 مسافات.

**تشريح الأمر**

```sh
helm template my-web ./mychart -f values-prod.yaml > out.yaml
```

1. `template`: اعرض الـ YAML النهائي بعد ما القيم تتحط، **من غير** ما تسطب حاجة. أحسن طريقة تتأكد إن الـ Chart مظبوط.
2. `my-web ./mychart`: اسم Release تجريبي والـ Chart.
3. `-f values-prod.yaml`: بالقيم دي.
4. `> out.yaml`: الـ Redirection: احفظ الناتج في ملف بدل الشاشة (ولو الملف موجود هيتكتب عليه).

:::tip[قبل أي upgrade في Production]
- `helm lint ./mychart` لمراجعة الأخطاء.
- `helm upgrade ... --dry-run` عشان تشوف إيه اللي هيتغير.
- `helm get values my-web` عشان تعرف القيم الحالية قبل ما تغير.
:::

:::tip[ملخص الفصل]
- الـ Helm مدير حزم: Chart = حزمة، Release = نسخة متسطبة، Repository = مكان الـ Charts.
- install / upgrade / rollback / uninstall، و `upgrade --install` للـ CI/CD.
- القيم من `values.yaml` ← `-f` ← `--set` (الأخير هو الأقوى).
- `helm template` بيوريك الـ YAML النهائي من غير تسطيب.
:::

### أسئلة مراجعة

1. إيه الفرق بين الـ Chart والـ Release؟
2. لو حطيت نفس القيمة في `-f` وفي `--set`، مين يكسب؟
3. إزاي ترجع لنسخة قديمة بعد upgrade بايظ؟
4. إيه فايدة `helm template`؟

### صح ولا غلط؟

1. ينفع تسطب نفس الـ Chart مرتين بأسماء Releases مختلفة.
2. `helm rollback` بيمسح الـ history.
3. في `--set image.tag=1.2.0` النقطة معناها مستوى أعمق في الـ values.
