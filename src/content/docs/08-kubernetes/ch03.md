<small>المرحلة 1 · الأساسيات</small>

الـ Pods مهمة جداً في Kubernetes، لأنه مبيتعاملش مع الـ Container لوحده مباشرة، وإنما بيحط الـ Container أو أكتر من Container ليهم علاقة ببعض جوه كبسولة اسمها الـ Pod.

:::note[بعد الفصل ده هتكون عارف]
- يعني إيه Pod وليه هو أصغر وحدة
- الـ Containers اللي جوه نفس الـ Pod بيشاركوا إيه
- ليه الـ Pod مؤقت (Ephemeral)
- الفرق بين Single-Container و Multi-Container Pod
:::

<a id="s3-1"></a>

## 3.1 يعني إيه Pod؟

الـ Pods مهمة شوية في Kubernetes، لأنه مابيتعاملش مع الـ Container لوحده مباشرة، وإنما بيحط الـ Container أو أكتر من Container ليهم علاقة ببعض جوه كبسولة اسمها الـ Pod.

- الـ Pod هو أصغر وأبسط وحدة Kubernetes بيتعامل معاها، وهو بيمثل <strong>"نسخة واحدة شغالة"</strong> (Single instance) من تطبيقك جوه الـ Cluster. لو عايز يعمل Scale ويزود النسخ، هو بيكتّر الـ **Pods** مش الـ Containers الفردية.

<a id="s3-2"></a>

## 3.2 الـ Containers اللي جوه نفس الـ Pod مابينهمش أسرار

لو الـ Pod جواه أكتر من Container، كلهم بيشاركوا بعض في كل حاجة:

![الـ Containers جوه نفس الـ Pod بياخدوا نفس الـ IP، ويكلموا بعض بـ localhost، ويشاركوا نفس الـ Volumes.](./assets/ch03-fig1.png)

*الـ Containers جوه نفس الـ Pod بياخدوا نفس الـ IP، ويكلموا بعض بـ localhost، ويشاركوا نفس الـ Volumes.*

**الـ Containers جوه الـ Pod بيشاركوا في إيه؟**

| بيشاركوا في | يعني إيه؟ |
|---|---|
| <strong>الشبكة (Networking)</strong> | بياخدوا نفس الـ IP address ونفس مساحة المنافذ (Port space)، وبيقدروا يكلموا بعض ببساطة عن طريق `localhost`. |
| <strong>المساحة التخزينية (Storage volumes)</strong> | بيشاركوا نفس وحدات التخزين، يعني لو Container كتب ملف، الـ Container التاني اللي معاه في نفس الـ Pod يقدر يشوفه ويقرأه. |
| <strong>دورة الحياة (Lifecycle)</strong> | بيموتوا ويعيشوا مع بعض. |

:::caution[خلي بالك]
بما إنهم بيشاركوا نفس مساحة المنافذ، مينفعش اتنين Containers في نفس الـ Pod يسمعوا على نفس الـ Port. لو الاتنين عايزين 80 هيحصل تعارض.
:::

<a id="s3-3"></a>

## 3.3 الـ Pod مؤقت (Ephemeral)

الـ Pod بيكون **Ephemeral**، يعني مش عايش للأبد. لو حصلت مشكلة والـ Pod مات، مش بيعمل Restart لنفسه تلقائياً، إلا لو كان مِتدار عن طريق حاجة أكبر منه (**Controller**) زي الـ Deployment، وهو ده اللي بيضمن إن لو Pod مات، يقوم واحد جديد مكانه.

:::note[توضيح مهم]
فيه فرق بين حاجتين: لو **Container** جوه الـ Pod وقع، الـ kubelet بيعمله restart جوه نفس الـ Pod (حسب الـ `restartPolicy` اللي الافتراضي بتاعها `Always`). لكن لو **الـ Pod نفسه** اتمسح أو الـ Node اللي عليها وقعت، الـ Pod ده مش هيرجع تاني لوحده، وهنا بييجي دور الـ Controller (زي الـ Deployment) إنه يعمل Pod جديد بدل منه.
:::

<a id="s3-4"></a>

## 3.4 نوعين Pods على حسب تصميمك

#### Single-Container Pod

وده الشكل الأشهر والأكتر استخداماً، إن كل Pod يكون جواه Container واحد بس، شايل وظيفة واحدة محددة (زي ويب سيرفر، أو API، أو Worker). وده تبعاً لمبدأ <strong>"حاوية واحدة لكل عملية"</strong>.

#### Multi-Container Pod

هنا بقى بنحط حاويتين أو أكتر متصلين ببعض جامد (Tightly coupled) عشان يخدموا على بعض. مثال مشهور: يكون عندك Container أساسي شغال عليه الموقع وبيقدّم الخدمة (Main app)، ومعاه Container مساعد صغير جنبه (**Sidecar**) وظيفته يلم الـ Logs أو يعمل Sync للملفات بس.

- بالشكل ده، الـ Kubernetes بيضمن إن الحاجات اللي لازم تشتغل مع بعض وتخدم على بعض تفضل دايماً في مكان واحد (جوه الـ Pod).
- بالإضافة لكل ده، فـ Kubernetes عنده Services كتيرة بيقدمها بتساعده في تشغيل الـ Structure ده بأفضل شكل.

:::tip[ملخص الفصل]
- الـ Pod أصغر وحدة في Kubernetes، وبيمثل نسخة واحدة من تطبيقك.
- الـ Scaling بيكون بزيادة عدد الـ Pods، مش الـ Containers جوه الـ Pod.
- الـ Containers في نفس الـ Pod بيشاركوا الـ IP والـ Ports والـ Volumes ودورة الحياة.
- الـ Pod مؤقت، واللي بيضمن إن فيه بديل هو Controller زي الـ Deployment.
- أغلب الوقت Pod = Container واحد، والـ Sidecar للحالات المترابطة جامد.
:::

### أسئلة مراجعة

1. لو عايز 3 نسخ من الـ API بتاعك، هتزود Containers جوه الـ Pod ولا Pods؟ وليه؟
2. Container بيكلم التاني في نفس الـ Pod إزاي؟
3. اديني مثال على Sidecar Container.
4. إيه الفرق بين إن Container يقع، وإن Pod يتمسح؟

### صح ولا غلط؟

1. كل Container جوه نفس الـ Pod بياخد IP مختلف.
2. Pod اتعمل لوحده (من غير Controller) واتمسح، Kubernetes هيعمل واحد بداله.
3. الشكل الأشهر هو Pod فيه Container واحد.
