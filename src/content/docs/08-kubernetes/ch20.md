الفصل ده إضافة: الشرح الأصلي اتكلم عن الـ Scaling كفكرة في أول الكتاب (Scale Out و Scale Up)، وهنا بنطبقها أوتوماتيك.

فاكر في أول الكتاب لما قولنا إن Kubernetes بيقدر يزوّد عدد الـ Pods لما الضغط يزيد؟ الأداة اللي بتعمل كده اسمها Horizontal Pod Autoscaler. الفصل ده بيشرح هي بتقرر إزاي، ومحتاجة إيه عشان تشتغل.

:::note[بعد الفصل ده هتكون عارف]
- فكرة الـ HPA ومكانه بين الـ Scaling الأنواع
- ليه الـ metrics-server و الـ requests ضروريين
- المعادلة اللي الـ HPA بيحسب بيها
- إنشاء HPA بالأمر وبالـ YAML (autoscaling/v2)
- اختبار الـ HPA بضغط حقيقي
:::

<a id="s20-1"></a>

## 20.1 يعني إيه HPA؟

الـ <strong>HPA (Horizontal Pod Autoscaler)</strong> بيراقب استهلاك الـ Pods بتاعة Deployment (مثلاً الـ CPU)، ولو الاستهلاك عدّى الهدف اللي حددته، بيزوّد الـ replicas (Scale Out). ولو الضغط قل، بيقللهم تاني لحد الحد الأدنى.

**أنواع الـ Autoscaling في Kubernetes**

| الأداة | بتعمل إيه |
|---|---|
| HPA | بتزوّد/بتقلل **عدد الـ Pods** (Horizontal) |
| VPA | بتعدّل **الـ requests/limits** بتاعة الـ Pod نفسه (Vertical)، add-on منفصل |
| Cluster Autoscaler | بيزوّد/بيقلل **عدد الـ Nodes** لما الـ Pods متلاقيش مكان |

<a id="s20-2"></a>

## 20.2 محتاج إيه عشان يشتغل؟

1. <strong>metrics-server:</strong> هو اللي بيجمع أرقام الـ CPU والـ Memory من الـ kubelet على كل Node. من غيره الـ HPA أعمى. على minikube: `minikube addons enable metrics-server`.
2. <strong>resources.requests:</strong> الـ HPA بيحسب النسبة من الـ **requests** مش من الـ limits. لو مفيش requests للـ CPU، مش هيعرف يحسب، وهيظهر `<unknown>`.

<a id="s20-3"></a>

## 20.3 المعادلة

```text title="معادلة الـ HPA"
desiredReplicas = ceil( currentReplicas × currentUsage / targetUsage )
```

مثال: عندك 2 Pods، والهدف 50% CPU، والاستهلاك الحالي 100%. يبقى `ceil(2 × 100 / 50) = 4` Pods. والـ `ceil` معناها التقريب لفوق.

:::note[معلومة مهمة]
عشان ميفضلش يزوّد ويقلل كل شوية (flapping)، الـ HPA بيستنى فترة استقرار قبل ما يقلل: افتراضياً 5 دقايق.
:::

<a id="s20-4"></a>

## 20.4 إنشاء HPA بالأمر

**تشريح الأمر**

```sh
kubectl autoscale deployment web --cpu-percent=50 --min=2 --max=10
```

1. `autoscale deployment web`: اعمل HPA للـ Deployment اللي اسمه `web`.
2. `--cpu-percent=50`: الهدف: متوسط استهلاك الـ CPU لكل Pod = 50% من الـ request بتاعه.
3. `--min=2`: أقل عدد Pods مهما الضغط قل.
4. `--max=10`: أقصى عدد Pods مهما الضغط زاد (عشان متصرفش موارد الـ Cluster كلها).

<a id="s20-5"></a>

## 20.5 إنشاء HPA بالـ YAML

```yaml title="web-hpa.yaml"
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```

1. `apiVersion: autoscaling/v2`: الإصدار `autoscaling/v2` هو الحالي، وبيدعم أكتر من metric.
2. `spec:`: مين اللي هيتعمله Scale: الـ Deployment `web`.
3. `minReplicas: 2`: الحدود.
4. `metrics:`: راقب الـ CPU، والهدف متوسط 50% من الـ requests. وتقدر تضيف عنصر تاني لـ `memory`.

:::caution[خلي بالك]
لو عامل HPA للـ Deployment، شيل `replicas` من الـ YAML بتاع الـ Deployment أو متعملش له apply تاني بقيمة ثابتة، وإلا كل apply هيرجّع العدد ويتخانق مع الـ HPA.
:::

<a id="s20-6"></a>

## 20.6 تابعه وجرّبه

**تشريح الأمر**

```sh
kubectl get hpa -w
```

1. `get hpa`: اعرض الـ HPAs (`hpa` اختصار `horizontalpodautoscaler`).
2. `-w`: اختصار `--watch`: متقفلش، وكل ما حاجة تتغير اطبع سطر جديد. اخرج بـ `Ctrl+C`.

```sh title="Terminal"
$ kubectl get hpa -w
NAME      REFERENCE        TARGETS        MINPODS   MAXPODS   REPLICAS   AGE
web-hpa   Deployment/web   cpu: 12%/50%   2         10        2          1m
web-hpa   Deployment/web   cpu: 95%/50%   2         10        2          2m
web-hpa   Deployment/web   cpu: 95%/50%   2         10        4          2m
```

ولو عايز تعمل ضغط تجريبي على الـ Service:

**تشريح الأمر**

```sh
kubectl run load --rm -it --image=busybox -- sh -c "while true; do wget -q -O- http://web; done"
```

1. `run load`: شغّل Pod مؤقت اسمه `load`.
2. `--rm`: امسح الـ Pod أوتوماتيك أول ما تخرج منه.
3. `-it`: تفاعلي: `-i` خلي الـ input مفتوح، و `-t` اعمل Terminal.
4. `--image=busybox`: image صغيرة فيها أدوات زي wget.
5. `--`: كل اللي بعدها هو الأمر جوه الـ Container.
6. `sh -c "..."`: شغّل الـ Shell ونفّذ الكلام اللي بين علامات التنصيص.
7. `while true; do ...; done`: Loop مالهاش نهاية، و `;` بتفصل بين الأوامر.
8. `wget -q -O- http://web`: اطلب الصفحة. `-q` من غير رسايل، و `-O-` اطبع الناتج على الشاشة بدل ملف. و `web` اسم الـ Service (DNS).

:::tip[ملخص الفصل]
- الـ HPA بيغير عدد الـ Pods حسب الاستهلاك، بين min و max.
- محتاج metrics-server و requests للـ CPU.
- المعادلة: ceil(الحالي × الاستهلاك / الهدف).
- اعمله بـ `kubectl autoscale` أو YAML بـ `autoscaling/v2`.
:::

### أسئلة مراجعة

1. الـ TARGETS ظاهرة `<unknown>/50%`، إيه السببين المحتملين؟
2. 3 Pods، الهدف 60%، الاستهلاك 90%. الـ HPA هيوصل لكام Pod؟
3. إيه الفرق بين الـ HPA والـ Cluster Autoscaler؟

### صح ولا غلط؟

1. الـ HPA بيحسب النسبة من الـ limits.
2. `--rm` في `kubectl run` بتمسح الـ Pod بعد ما تخرج.
3. الـ HPA بيزوّد عدد الـ Nodes.
