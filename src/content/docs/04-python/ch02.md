<small>المرحلة 1 · التشغيل والقراية</small>

الـ AI كتب لك اسكريبت، ونسخته، وشغّلته… وطلع لك ModuleNotFoundError أو externally-managed-environment. الفصل ده بيحكي ليه المشاكل دي بتحصل، وبيمشّيك خطوة بخطوة من Python اللي على الـ Mac لحد بيئة نضيفة لكل مشروع.

:::note[بعد الفصل ده هتكون عارف]
- ليه فيه أكتر من Python على نفس الـ Mac
- تسطّب Python حديثة بـ Homebrew
- يعني إيه Virtual Environment وليه لازم
- pip و requirements.txt و pip freeze
- الـ Shebang و chmod +x
- يعني إيه if \_\_name\_\_ == "\_\_main\_\_"
:::

<a id="s2-1"></a>

## 2.1 قبل كده: "بيشتغل عندي ومش بيشتغل عندك"

تخيل إن عندك اسكريبتين. الأول اتكتب من سنتين ومحتاج `openai` نسخة قديمة، والتاني جديد ومحتاج أحدث نسخة. لو سطّبت المكتبات "على الجهاز كله"، أول ما تحدّث المكتبة علشان التاني، الأول يبوظ. وكمان الـ Mac نفسه بيستخدم Python في حاجات خاصة بيه، فلو لعبت في مكتباته ممكن تبوّظ حاجة في النظام.

<strong>وهنا كانت المشكلة:</strong> كل المشاريع شايلة نفس "الشنطة" من المكتبات. **فاتطور حل** اسمه **Virtual Environment** (أو venv): فولدر صغير جوه كل مشروع فيه نسخة Python خاصة بيه ومكتباته لوحدها. كل مشروع بشنطته.

![كل مشروع ليه بيئة لوحده فوق نفس Python. اللي تسطّبه جوه venv مشروع مبيأثرش على أي مشروع تاني ولا على الجهاز.](./assets/ch02-fig1.png)

*كل مشروع ليه بيئة لوحده فوق نفس Python. اللي تسطّبه جوه venv مشروع مبيأثرش على أي مشروع تاني ولا على الجهاز.*

<a id="s2-2"></a>

## 2.2 أنهي python3 انت بتشغّل؟

على الـ Mac غالباً هتلاقي أكتر من Python. واحدة بتيجي مع **Xcode Command Line Tools** في `/usr/bin/python3`، ودي قديمة نسبياً (3.9). ولو سطّبت Homebrew هتلاقي واحدة حديثة في `/opt/homebrew/bin/python3`. أول حاجة تعملها: اعرف مين اللي بيرد لما تكتب `python3`.

```sh title="Terminal"
$ which python3
/opt/homebrew/bin/python3
$ python3 --version
Python 3.14.9
```

| الأمر | بيعمل إيه |
|---|---|
| `which python3` | بيطبع مسار البرنامج اللي هيشتغل فعلاً. لو طلع `/usr/bin/python3` يبقى انت على نسخة الـ Xcode. |
| `python3 --version` | النسخة. الـ `--` قبل الكلمة معناها "Option طويل" (Flag). وفي منه نسخة قصيرة: `-V`. |

:::caution[ليه النسخة تفرق؟]
مكتبات كتير بتطلب نسخة Python معينة أو أحدث. مثلاً **pandas 3** محتاجة Python 3.11 أو أحدث، و **google-genai** محتاجة 3.10 أو أحدث. فلو شغّلت على 3.9 بتاعة Xcode، الـ pip هيقولك مفيش نسخة مناسبة، أو هيسطّب نسخة قديمة. علشان كده سطّب Python حديثة.
:::

**تشريح الأمر**

```sh
brew install python@3.14
```

1. `brew`: برنامج Homebrew، مدير البرامج على الـ Mac (زي App Store للـ Terminal).
2. `install`: الأمر الفرعي: "سطّب".
3. `python@3.14`: اسم الحزمة (Formula). الـ `@3.14` بيثبّت السلسلة. في أكتوبر 2026 دي النسخة المستقرة الأساسية في Homebrew (3.14.9)، وفي كمان `python@3.15` لو عايز الأحدث (3.15 نزلت 9 أكتوبر 2026).

**المصادر الرسمية:** [formulae.brew.sh · python@3.14](https://formulae.brew.sh/formula/python@3.14) · [python.org · Downloads](https://www.python.org/downloads/) · [Using Python on macOS](https://docs.python.org/3/using/mac.html)

## 2.3 الـ venv خطوة بخطوة

```sh title="Terminal"
$ mkdir ai-scripts && cd ai-scripts
$ python3 -m venv .venv
$ source .venv/bin/activate
(.venv) $ which python
/Users/you/ai-scripts/.venv/bin/python
(.venv) $ pip install openai google-genai python-dotenv
(.venv) $ deactivate
```

**تشريح الأمر**

```sh
python3 -m venv .venv
```

1. `-m`: "Module": شغّل Module جاهزة من مكتبة Python كأنها برنامج، بدل ما تشغّل ملف. وهنا الـ Module اسمها `venv`.
2. `venv`: الـ Module اللي بتعمل Virtual Environment، وجاية مع Python.
3. `.venv`: اسم الفولدر اللي هيتعمل. النقطة في الأول بتخليه مستخبي في Finder، والاسم ده هو العرف المشهور (و VS Code بيلقطه لوحده).

**تشريح الأمر**

```sh
source .venv/bin/activate
```

1. `source`: نفّذ الملف ده **جوه** الـ Terminal الحالي، مش في Terminal جديد. وده اللي بيخلي التغيير يفضل معاك.
2. `.venv/bin/activate`: اسكريبت صغير بيحط `.venv/bin` أول حاجة في الـ `PATH`. فلما تكتب `python` أو `pip` يتشغّلوا من جوه الـ venv. وعلامة `(.venv)` في أول السطر بتقولك إنك جواه.

:::note[على الـ Mac: activate لكل Terminal جديد]
الـ activate بيشتغل للتابة اللي انت فيها بس. لو فتحت Terminal جديد لازم تعمل `source .venv/bin/activate` تاني. ولو مش عايز تعمل activate خالص، شغّل Python الـ venv بالمسار مباشرة: `.venv/bin/python script.py`.
:::

:::danger[مشكلة: error: externally-managed-environment]
كتبت `pip3 install openai` برّه أي venv، وطلع لك الخطأ ده. ده مش عطل: Python بتاعة Homebrew متعلّم عليها إنها "متدارة من برّه" (PEP 668)، يعني Homebrew هو اللي مسؤول عنها، وهي بتمنعك تسطّب مكتبات عليها علشان متبوظهاش.

<strong>الحل:</strong> اعمل venv وفعّله، وسطّب جواه. ومتستخدمش `--break-system-packages` إلا لو فاهم بالظبط انت بتعمل إيه.
:::

**المصادر الرسمية:** [docs.python.org · venv](https://docs.python.org/3/library/venv.html) · [PEP 668 · externally managed](https://peps.python.org/pep-0668/) · [Installing Packages](https://packaging.python.org/en/latest/tutorials/installing-packages/)

## 2.4 pip و requirements.txt

`pip` هو مدير الحزم بتاع Python: بيروح على موقع اسمه **PyPI** (فيه مئات الآلاف من المكتبات)، ويجيب المكتبة، ويسطّبها جوه الـ venv. وأي اسكريبت محترم هييجي معاه ملف `requirements.txt` فيه أسامي المكتبات اللي محتاجها.

```text title="requirements.txt"
openai>=3.37
google-genai>=2.33
python-dotenv
pandas[excel]
tqdm
```

| الأمر | بيعمل إيه |
|---|---|
| `pip install -r requirements.txt` | `-r` = Read: اقرا أسامي المكتبات من الملف ده وسطّبها كلها. |
| `openai>=3.37` | أي نسخة 3.37 أو أحدث. و`==3.37.0` يعني النسخة دي بالظبط. |
| `pandas[excel]` | الأقواس المربعة اسمها "Extras": سطّب pandas ومعاها المكتبات الإضافية اللي بتقرا وتكتب Excel (زي `openpyxl`). |
| `pip freeze > requirements.txt` | `freeze` بيطبع كل اللي متسطّب بنسخه بالظبط، و`>` بتكتب الناتج في ملف بدل الشاشة. |
| `pip list` | يعرض كل المكتبات المتسطّبة في الـ venv الحالي. |
| `pip show openai` | معلومات عن مكتبة: النسخة، ومكانها، ومحتاجة إيه. |

:::tip[حاجة مشتركة: npm]
`pip install openai` = `npm install openai`. و`requirements.txt` = الـ `dependencies` في `package.json`. والـ `.venv` = `node_modules`: فولدر خاص بالمشروع، مبيترفعش على Git، وتقدر تمسحه وتعمله تاني من الملف.
:::

:::danger[مشكلة: ModuleNotFoundError: No module named 'openai']
أشهر خطأ في الدنيا. معناه إن الـ `python` اللي شغّلت بيه مش شايف المكتبة. يا إما مسطّبتهاش، يا إما سطّبتها في venv وبتشغّل بـ Python تانية.

<strong>الحل:</strong> اتأكد إن `(.venv)` ظاهرة. واعمل `which python`. وسطّب بـ `python -m pip install openai`: الطريقة دي بتضمن إن الـ pip تابع لنفس الـ python.
:::

## 2.5 الـ Shebang و if \_\_name\_\_ == "\_\_main\_\_"

أول سطر في اسكريبتات كتير بيبقى كده، وآخر سطرين كده:

```python title="tool.py"
#!/usr/bin/env python3
def main():
    print("working...")

if __name__ == "__main__":
    main()
```

**تشريح الأمر**

```python
#!/usr/bin/env python3
```

1. `#!`: اسمها **Shebang**. لو شغّلت الملف مباشرة (`./tool.py`)، الـ Mac بيقرا السطر ده علشان يعرف يشغّله بإيه. وبالنسبة لـ Python هو مجرد Comment.
2. `/usr/bin/env python3`: "دوّر على `python3` في الـ PATH وشغّل بيه". فلو الـ venv مفعّل، هيشتغل بـ Python الـ venv.

وعلشان `./tool.py` يشتغل، لازم تدي الملف صلاحية تنفيذ مرة واحدة: `chmod +x tool.py` (`+x` = زوّد صلاحية eXecute).

**تشريح الأمر**

```python
if __name__ == "__main__":
```

1. `__name__`: متغير خاص Python بتعمله لكل ملف لوحدها. الشَرطتين قبل وبعد (اسمهم "dunder" = double underscore) معناهم "حاجة خاصة باللغة".
2. `"__main__"`: لو انت مشغّل الملف ده مباشرة (`python3 tool.py`)، قيمة `__name__` بتبقى `"__main__"`. لكن لو ملف تاني عمل `import tool`، قيمتها بتبقى `"tool"`.
3. `main()`: فالمعنى: "شغّل `main` بس لو أنا الملف الأساسي، لكن لو حد عمل لي import متشغّلش حاجة، اديله الدوال وبس".

:::tip[ده مدخل الاسكريبت]
لما تفتح اسكريبت غريب، دوّر على `if __name__ == "__main__":` في الآخر. اللي جواه هو "نقطة البداية". غالباً هتلاقي `main()`، فتروح تجيب الفانكشن `main` وتبدأ تقرا منها. وده بالظبط اللي هنعمله في الفصل الجاي.
:::

**المصادر الرسمية:** [docs.python.org · __main__](https://docs.python.org/3/library/__main__.html) · [Command line and environment (-m)](https://docs.python.org/3/using/cmdline.html)

:::tip[ملخص الفصل]
- اعرف الـ Python اللي بتشغّلها بـ `which python3`. والـ Xcode بتاعتها قديمة، فسطّب `python@3.14` بـ brew.
- لكل مشروع venv: `python3 -m venv .venv` وبعدين `source .venv/bin/activate`.
- `pip install -r requirements.txt` بيسطّب اللي المشروع محتاجه، و`pip freeze` بيصوّر النسخ.
- الـ `externally-managed-environment` معناها "اعمل venv". والـ `ModuleNotFoundError` معناها "انت مش في الـ Python الصح أو مسطّبتش".
- `if __name__ == "__main__":` هي نقطة دخول الاسكريبت.
:::

### صح ولا غلط؟

1. بعد ما تقفل الـ Terminal وتفتحه تاني، الـ venv بيفضل مفعّل.
2. `python -m pip install x` بيضمن إن المكتبة هتتسطّب لنفس الـ python ده.
3. الكود اللي جوه `if __name__ == "__main__":` بيشتغل لما ملف تاني يعمل import للملف ده.

### أسئلة مراجعة

1. إيه المشكلة اللي الـ venv بيحلّها؟ اشرحها بمثال مشروعين.
2. اشرح كل جزء في `python3 -m venv .venv`.
3. إيه الفرق بين `openai>=3.37` و`openai==3.37.0` في requirements.txt؟
4. ليه `.venv` مبيترفعش على Git؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** اعمل فولدر `ai-scripts` فيه venv، وسطّب `openai` و`google-genai`، واعمل `pip list`.
2. **[متوسط]** اعمل `pip freeze > requirements.txt`، وامسح `.venv`، واعمله من جديد، وسطّب من الملف.
3. **[صعب]** اكتب `tool.py` اللي في الفصل، واعمل ملف تاني فيه `import tool`، وشغّل الاتنين. مين طبع `working...` وليه؟
