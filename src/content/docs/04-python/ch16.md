<small>المرحلة 4 · أساسيات الـ AI</small>

هندخل جوه مكتبة openai: إزاي الـ client بيتعمل وبياخد إعداداته منين، وكل Parameter مهم في responses.create، وشكل الـ Response اللي راجع حتة حتة، والمحادثات، والـ Streaming. وفي الآخر Chat Completions: الطريقة القديمة اللي لسه في كل حتة، ونفسها اللي OpenRouter بيستخدمها.

:::note[بعد الفصل ده هتكون عارف]
- pip install openai و OpenAI() وكل إعدادات الـ client
- responses.create: model و instructions و input و max\_output\_tokens و reasoning و store
- تشريح الـ Response: output و output\_text و usage و status
- input كـ List رسايل بـ Roles و Content parts
- المحادثات بـ previous\_response\_id، والـ Streaming بالـ Events
- chat.completions.create و choices\[0\].message.content
:::

:::note[الـ API اللي OpenAI بتنصح بيه]
الدوكيومنتيشن بتقول إن **Responses API** هو الأساس للمشاريع الجديدة، وإن **Chat Completions** لسه مدعوم. وفي GPT-6 بالذات: Astra و 6.1 Sol بيدعموا Chat Completions، بس الـ Tool calling محتاج Responses. فالكتاب ماشي على Responses، وهنشوف Chat Completions علشان تقراه لما تقابله. (اتأكدنا من الكود ده على `openai` 3.37.0.)
:::

## 16.1 الـ client: الباب لكل حاجة

```python
from openai import OpenAI

client = OpenAI()                                  # الأبسط: كل حاجة من البيئة
client = OpenAI(
    api_key=os.environ["OPENAI_API_KEY"],          # الافتراضي أصلاً
    timeout=60.0,                                  # ثواني لكل Request
    max_retries=3,                                 # الافتراضي 2
)
```

| الأمر | بيعمل إيه |
|---|---|
| `api_key=` | لو مش مكتوب، بيقرا `OPENAI_API_KEY`. ولو مش موجود هناك كمان: `OpenAIError: The api_key client option must be set...` أول ما تعمل الـ client. |
| `base_url=` | عنوان السيرفر. الافتراضي `https://api.openai.com/v1`. ولو غيّرته لسيرفر متوافق، نفس الكود يكلم حد تاني. ده سر OpenRouter (فصل 19). وبيتقري كمان من `OPENAI_BASE_URL`. |
| `timeout=` | أقصى وقت للـ Request. والافتراضي في المكتبة 10 دقايق. |
| `max_retries=` | كام مرة يعيد لوحده لو حصل Connection error أو 408 أو 409 أو 429 أو أي 5xx. الافتراضي 2 (فصل 25). |
| `organization= / project=` | لو حسابك فيه كذا Organization أو Project. أو من `OPENAI_ORG_ID` و`OPENAI_PROJECT_ID`. |

:::tip[Best Practice]
اعمل الـ client **مرة واحدة** في أول الاسكريبت واستخدمه في كل حاجة. متعملوش جوه الـ Loop: كل client جديد بيفتح Connections جديدة.
:::

**المصادر الرسمية:** [github.com/openai/openai-python · README](https://github.com/openai/openai-python) · [OpenAI · Libraries](https://developers.openai.com/api/docs/libraries)

## 16.2 responses.create: كل Parameter مهم

```python title="نداء كامل"
response = client.responses.create(
    model="gpt-6-luna",
    instructions="You are a careful editor. Answer in English.",
    input="Rewrite: 'we was going to the office yesterday'",
    max_output_tokens=300,
    reasoning={"effort": "low"},
    store=False,
)
print(response.output_text)
```

**الـ Parameters اللي هتشوفها في اسكريبتات المحتوى**

| Parameter | بياخد إيه | معناه |
|---|---|---|
| `model` | نص | اسم الموديل. إجباري. |
| `input` | نص أو List رسايل | دور الـ user: الطلب والبيانات. |
| `instructions` | نص | تعليمات الـ system/developer. وليها أولوية على الـ input. ومش بتتنقل لوحدها مع `previous_response_id`. |
| `max_output_tokens` | رقم | سقف الـ Output (شامل الـ Reasoning). |
| `reasoning` | dict | `{"effort": "none" \| "low" \| "medium" \| "high" \| "xhigh" \| "max"}` حسب الموديل. |
| `text` | dict | شكل الرد: نص أو JSON Schema (فصل 21). |
| `tools` | List | دوال أو أدوات الموديل يقدر يطلبها (فصل 22). |
| `store` | True/False | يحفظ الـ Response على سيرفرات OpenAI علشان ترجعله بعدين (الافتراضي `True`). و`False` لو مش محتاج. |
| `previous_response_id` | نص | كمّل محادثة من Response قبلها. |
| `stream` | True/False | ابعت الرد حتة حتة وهو بيتكتب. |
| `service_tier` | نص | مثلاً `"flex"`: أرخص وأبطأ (فصل 27). |
| `prompt_cache_key` | نص | يساعد الـ Caching للـ Prompts المتكررة (فصل 27). |
| `metadata` | dict | علامات بتاعتك (زي اسم الملف) تتحفظ مع الـ Response. |
| `temperature` / `top_p` | رقم | مع GPT-6 يتقبلوا بس لو `effort="none"` (فصل 14). |

## 16.3 تشريح الـ Response

ده شكل الـ Response (مختصر من مثال صفحة الـ API Reference الرسمية). طبعه انت بـ `print(response.model_dump_json(indent=2))`:

```json title="response.model_dump_json(indent=2) — مختصر"
{
  "id": "resp_67ccd3a9da74...",
  "object": "response",
  "status": "completed",
  "incomplete_details": null,
  "model": "gpt-6-luna",
  "output": [
    {
      "type": "message",
      "role": "assistant",
      "content": [
        { "type": "output_text", "text": "We were going to the office yesterday.", "annotations": [] }
      ]
    }
  ],
  "usage": {
    "input_tokens": 328,
    "input_tokens_details": { "cached_tokens": 0, "cache_write_tokens": 0 },
    "output_tokens": 52,
    "output_tokens_details": { "reasoning_tokens": 0 },
    "total_tokens": 380
  }
}
```

```python title="توصل لكل حاجة إزاي"
response.output_text
response.output
response.status
response.usage.input_tokens
response.usage.output_tokens
response.id
```

1. `response.output_text`: أهم سطر: **كل النص** اللي في الـ output ملزوق مع بعض. ده مش حقل في الـ JSON، ده Property الـ SDK بيحسبها لك (علشان كده مش ظاهرة فوق).
2. `response.output`: List فيها "Items". ممكن يبقى فيها أكتر من Item: `reasoning`، و`message`، و`function_call`. علشان كده <strong>متكتبش `response.output[0].content[0].text`</strong>: ممكن أول Item يبقى Reasoning مش Message.
3. `response.status`: `"completed"` تمام. و`"incomplete"` = اتقطع. شوف `response.incomplete_details.reason` (مثلاً `"max_output_tokens"`).
4. `response.usage.input_tokens`: التوكنز اللي دفعت عليها Input. ومنها `usage.input_tokens_details.cached_tokens` اتحسبت بسعر الـ Cache الأرخص.
5. `response.usage.output_tokens`: التوكنز الـ Output، **شاملة** `output_tokens_details.reasoning_tokens`.
6. `response.id`: رقم الـ Response. بتستخدمه في `previous_response_id`، أو تسجّله في الـ log.

:::caution[رد ممكن ميبقاش نص]
لو الموديل رفض الطلب لأسباب أمان، الـ Content بيبقى من نوع `refusal` مش `output_text`. ولو اتقطع، الـ `output_text` هيبقى ناقص أو فاضي. فاسكريبت محترم بيعمل كده:

```python
if response.status == "incomplete":
    log.warning("cut off: %s", response.incomplete_details.reason)
text = response.output_text.strip()
if not text:
    raise RuntimeError(f"empty reply for {path.name}")
```
:::

## 16.4 input كـ List رسايل

الـ `input` ممكن يبقى نص، أو List رسايل لما تحتاج أكتر من دور أو أكتر من حاجة (زي نص + صورة):

```python
response = client.responses.create(
    model="gpt-6-luna",
    input=[
        {"role": "developer", "content": "Classify the review as positive or negative."},
        {"role": "user", "content": "The course was long but really useful."},
    ],
)
```

| الأمر | بيعمل إيه |
|---|---|
| `"role": "developer"` | نفس فكرة `instructions` بس جوه الـ List. (في الموديلات القديمة كانت `"system"`.) |
| `"role": "user"` | الطلب أو البيانات. |
| `"role": "assistant"` | رد قديم للموديل: كده بتبني محادثة بإيدك، أو بتديه أمثلة (Few-shot، فصل 20). |
| `"content": [ {...}, {...} ]` | الـ content ممكن يبقى List "أجزاء": `{"type": "input_text", "text": ...}` و`{"type": "input_image", "image_url": ...}` و`{"type": "input_file", "file_id": ...}` (فصل 23). |

## 16.5 المحادثات: previous\_response\_id

```python
first = client.responses.create(model="gpt-6-luna", input="Suggest 3 titles for an article about tea.")
second = client.responses.create(
    model="gpt-6-luna",
    previous_response_id=first.id,           # "كمّل من هنا"
    input="Make the second one shorter.",
)
```

السيرفر بيجيب المحادثة اللي فاتت لوحده (وده محتاج إن الأول يكون `store=True`، الافتراضي). بس خد بالك: **التوكنز القديمة لسه بتتحسب Input** في كل دور، وإن `instructions` مش بتتنقل، فابعتها تاني لو محتاجها.

**المصادر الرسمية:** [OpenAI · Conversation state](https://developers.openai.com/api/docs/guides/conversation-state)

## 16.6 الـ Streaming: الرد وهو بيتكتب

من غير Streaming، الاسكريبت بيستنى لحد ما الرد كله يخلص. ومع `stream=True` بيوصلك الرد على شكل **Events** (أحداث) أول بأول. مفيد في أداة تفاعلية أو رد طويل، ومالوش لازمة غالباً في Batch ملفات.

```python
stream = client.responses.create(model="gpt-6-luna", input="Write a haiku about Cairo.", stream=True)
for event in stream:
    if event.type == "response.output_text.delta":
        print(event.delta, end="", flush=True)
    elif event.type == "response.completed":
        print("\n", event.response.usage.output_tokens, "tokens")
```

| الأمر | بيعمل إيه |
|---|---|
| `event.type` | نوع الحدث. فيه أنواع كتير: `response.created` و`response.output_text.delta` و`response.completed` و`error`. خد اللي محتاجه وسيب الباقي. |
| `event.delta` | الحتة الجديدة من النص. |
| `end="", flush=True` | `print` من غير سطر جديد، واطبع فوراً من غير ما تستنى. كده النص بيظهر كأنه بيتكتب. |

**المصادر الرسمية:** [OpenAI · Streaming API responses](https://developers.openai.com/api/docs/guides/streaming-responses)

## 16.7 Chat Completions: الشكل القديم اللي لسه في كل حتة

```python
completion = client.chat.completions.create(
    model="gpt-6-luna",
    messages=[
        {"role": "system", "content": "You are an editor."},
        {"role": "user", "content": "Fix: 'we was late'"},
    ],
    max_completion_tokens=200,
)
print(completion.choices[0].message.content)
print(completion.usage.prompt_tokens, completion.usage.completion_tokens)
```

**نفس الحاجة بأسامي مختلفة**

|   | Responses API | Chat Completions |
|---|---|---|
| النداء | `client.responses.create` | `client.chat.completions.create` |
| التعليمات | `instructions=` | رسالة `"system"` أو `"developer"` في `messages` |
| البيانات | `input=` | `messages=[...]` |
| السقف | `max_output_tokens` | `max_completion_tokens` (القديم `max_tokens`) |
| الـ Reasoning | `reasoning={"effort": ...}` | `reasoning_effort=...` |
| النص | `response.output_text` | `completion.choices[0].message.content` |
| التوكنز | `usage.input_tokens` / `output_tokens` | `usage.prompt_tokens` / `completion_tokens` |
| الحالة | `status` / `incomplete_details` | `choices[0].finish_reason` (`"stop"` أو `"length"`) |

:::tip[حاجة مشتركة: نفس المكتبة في JS]
في Node: `import OpenAI from "openai"; const client = new OpenAI();` و`const r = await client.responses.create({ model: "gpt-6-luna", input: "Hi" }); console.log(r.output_text);`. الفرق الأساسي: في JS لازم `await`، وفي Python الـ client العادي بيستنى لوحده (و`AsyncOpenAI` هو اللي محتاج await، فصل 26).
:::

**المصادر الرسمية:** [OpenAI · Migrate to Responses](https://developers.openai.com/api/docs/guides/migrate-to-responses) · [API Reference · Chat Completions](https://developers.openai.com/api/reference/resources/chat)

:::tip[ملخص الفصل]
- `client = OpenAI()` مرة واحدة، وبيقرا `OPENAI_API_KEY`، وفيه `base_url` و`timeout` و`max_retries`.
- `responses.create(model, instructions, input, max_output_tokens, reasoning, store, ...)`.
- `response.output_text` للنص، و`output` List Items (متفترضش `[0]`)، و`status` و`usage`.
- محادثة: `previous_response_id`. Streaming: `stream=True` و`response.output_text.delta`.
- Chat Completions: `messages` و`choices[0].message.content` و`prompt_tokens`.
:::

### صح ولا غلط؟

1. `response.output[0]` دايماً هو رسالة الموديل.
2. `instructions` بتتنقل لوحدها مع `previous_response_id`.
3. في Chat Completions، `finish_reason == "length"` معناها إن الرد اتقطع.

### أسئلة مراجعة

1. اكتب نفس الطلب مرة بـ Responses ومرة بـ Chat Completions.
2. من الـ JSON اللي في الفصل: كام توكن دفعت؟ وكام منهم Reasoning؟
3. ليه تعمل `store=False` في اسكريبت بيعالج ملفات حساسة ومش محتاج يرجعلها؟
