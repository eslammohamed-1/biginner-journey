<small>المرحلة 1 · التشغيل والقراية</small>

الـ AI ادّاك 60 سطر. تبدأ تقرا من السطر الأول للأخير؟ لأ. الاسكريبت مش رواية، ده خريطة. الفصل ده بيديك خطة من 6 خطوات تمشي بيها في أي اسكريبت، وهنطبّقها مع بعض على اسكريبت AI حقيقي قبل ما نكون فاهمين كل تفاصيل اللغة.

:::note[بعد الفصل ده هتكون عارف]
- ليه القراية من فوق لتحت مش أحسن طريقة
- خطة الست خطوات: imports، إعدادات، مدخل، تتبّع، بيانات، خطر
- إزاي تتتبّع فانكشن من مكان استدعائها لمكان تعريفها
- تعلّم على السطور الخطيرة: كتابة ملفات، مسح، فلوس API
- تستخدم VS Code يساعدك في القراية
:::

<a id="s3-1"></a>

## 3.1 ليه محتاج خطة؟

لما بتقرا رواية بتبدأ من أول صفحة. لكن الاسكريبت مكتوب بترتيب "التعريف"، مش بترتيب "التنفيذ". الدوال بتتعرّف فوق، وبتتنادى تحت. ففي الغالب آخر سطرين هما اللي بيشغّلوا كل حاجة. لو قريت من فوق لتحت، هتقرا 40 سطر من تعريفات دوال من غير ما تعرف مين هيستخدمها وليه، وهتتوه.

الحل إنك تقرا زي ما بتقرا خريطة مترو: الأول تعرف المحطات الرئيسية (الـ imports والإعدادات)، وبعدين تدوّر على "محطة البداية" (المدخل)، وبعدين تمشي ورا الخط.

## 3.2 الاسكريبت اللي هنقراه

ده اسكريبت شبه اللي الـ AI بيكتبهولك بالظبط. متحاولش تفهم كل سطر دلوقتي: المرة دي هنقراه بالخطة بس. وكل تفصيلة فيه ليها فصل قدّام.

```python title="summarize_notes.py"
import csv
from pathlib import Path

from dotenv import load_dotenv
from openai import OpenAI

INPUT_DIR = Path("notes")
OUTPUT_CSV = Path("summaries.csv")
MODEL = "gpt-6-luna"

def read_notes(folder):
    return sorted(folder.glob("*.md"))

def summarize(client, text):
    response = client.responses.create(
        model=MODEL,
        instructions="Summarize the note in 2 short sentences.",
        input=text,
    )
    return response.output_text

def main():
    load_dotenv()
    client = OpenAI()
    rows = []
    for path in read_notes(INPUT_DIR):
        text = path.read_text(encoding="utf-8")
        summary = summarize(client, text)
        rows.append({"file": path.name, "summary": summary})
        print(f"done: {path.name}")

    with OUTPUT_CSV.open("w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=["file", "summary"])
        writer.writeheader()
        writer.writerows(rows)

if __name__ == "__main__":
    main()
```

### الخطوة 1: الـ imports… الاسكريبت ده بيستخدم إيه؟

بص على أول 5 سطور بس. دول "قايمة العدة" بتاعة الاسكريبت، ومنهم لوحدهم تقدر تخمّن هو بيعمل إيه:

**القراية من الـ imports بس**

| السطر | معناه | نستنتج إيه |
|---|---|---|
| `import csv` | مكتبة جاية مع Python للـ CSV | هيقرا أو يكتب ملف CSV |
| `from pathlib import Path` | مسارات الملفات | هيلف على ملفات أو فولدرات |
| `from dotenv import load_dotenv` | مكتبة `python-dotenv` | فيه ملف `.env` غالباً فيه API key |
| `from openai import OpenAI` | الـ SDK الرسمي بتاع OpenAI | هيكلم موديل OpenAI، يعني **فلوس** |

:::tip[Best Practice]
لو لقيت import لمكتبة مش عارفها، اكتب اسمها في PyPI أو ابحث عن "\<اسمها\> python docs". وفي VS Code: حط الماوس على اسمها هيطلع لك وصف، أو Cmd+Click هيوديك لكودها.
:::

### الخطوة 2: الإعدادات… الثوابت اللي فوق

بعد الـ imports غالباً تلاقي متغيرات أساميها كلها CAPITAL زي `INPUT_DIR` و`MODEL`. ده عرف في Python معناه "ثابت: متغيّرنيش وانا شغّال". ودي أهم حتة بالنسبالك، لأنها **الأزرار** اللي هتغيّرها: أنهي فولدر، وأنهي ملف نتيجة، وأنهي موديل.

### الخطوة 3: المدخل… هندخل من هنا

انزل لآخر الملف. هتلاقي `if __name__ == "__main__": main()`. يبقى البداية الحقيقية هي `main()`. **هنروح نجيب الفانكشن دي**: دوّر على `def main():`.

### الخطوة 4: التتبّع… امشي ورا الخط

جوه `main` اقرا سطر سطر. ولما تلاقي نداء لفانكشن من تعريفك انت (مش من مكتبة)، زي `read_notes(INPUT_DIR)`، اقفز لتعريفها، افهم بتاخد إيه وبترجّع إيه، وارجع تاني لـ `main`:

```python title="تتبّع main()"
load_dotenv()
client = OpenAI()
for path in read_notes(INPUT_DIR):
    text = path.read_text(encoding="utf-8")
    summary = summarize(client, text)
    rows.append({...})
with OUTPUT_CSV.open("w", ...) as f:
```

1. `load_dotenv()`: بيقرا ملف `.env` ويحط اللي فيه في متغيرات البيئة. كده الـ API key بقى متاح.
2. `client = OpenAI()`: بيعمل "عميل" يكلم OpenAI. ومن غير ما تديله key، هو بيدوّر لوحده على `OPENAI_API_KEY`.
3. `for path in read_notes(INPUT_DIR):`: اقفز لـ `read_notes`: بترجّع كل ملفات `.md` في الفولدر مترتبة. يبقى الـ Loop ده هيلف على كل ملف.
4. `text = path.read_text(encoding="utf-8")`: بيقرا محتوى الملف كله كنص.
5. `summary = summarize(client, text)`: اقفز لـ `summarize`: بتبعت النص للموديل مع تعليمات "لخّص في جملتين"، وترجّع النص اللي الموديل رد بيه. **هنا الفلوس بتتصرف**: Request لكل ملف.
6. `rows.append({...})`: بيضيف صف في List: اسم الملف والملخص.
7. `with OUTPUT_CSV.open("w", ...) as f:`: بعد ما الـ Loop يخلص، بيفتح `summaries.csv` للكتابة ويكتب كل الصفوف.

### الخطوة 5: البيانات… داخل منين وخارج فين؟

دلوقتي تقدر تقول الاسكريبت في جملة: <strong>"بياخد كل ملفات .md من فولدر notes، ويبعت كل واحد لـ gpt-6-luna يلخّصه، ويكتب النتايج في summaries.csv."</strong> لو قدرت تقول الجملة دي، يبقى انت فهمت الاسكريبت. والتفاصيل بعد كده مجرد تفاصيل.

### الخطوة 6: الخطر… إيه اللي ممكن يأذي؟

#### كتابة فوق ملف

`open("w")` بتمسح محتوى `summaries.csv` لو موجود وتكتب من جديد. لو عندك ملف بنفس الاسم مهم، هيروح.

#### فلوس

Request لكل ملف. لو الفولدر فيه 5000 ملف، دي 5000 Request. اعرف التكلفة قبل ما تشغّل (فصل التكلفة).

#### مفيش حماية من الأخطاء

لو ملف واحد في النص فشل (نت فصل، أو 429)، الاسكريبت هيقف، و**كل** الملخصات اللي خلصت هتضيع لأن الكتابة في الآخر.

#### بيانات بتطلع برّه

محتوى ملفاتك بيتبعت لسيرفرات OpenAI. اتأكد إن ده مسموح للبيانات دي.

لاحظ إن خطوة الخطر طلّعت لنا 3 تحسينات حقيقية للاسكريبت: نكتب كل صف أول بأول، ونمسك الأخطاء، ونكمّل من مكان ما وقفنا. وده هيبقى اسكريبت كامل في آخر الكتاب.

## 3.3 VS Code صاحبك في القراية

| الأمر | بيعمل إيه |
|---|---|
| `Cmd + Click` | على اسم فانكشن أو Class: يوديك لتعريفها، حتى لو جوه مكتبة `openai` نفسها. |
| `Hover` | حط الماوس على أي اسم: يطلع لك نوعه والـ Docstring بتاعه (الشرح اللي كاتبه صاحب المكتبة). |
| `Shift + F12` | "Find All References": كل الأماكن اللي الاسم ده متستخدم فيها. |
| `Cmd + Shift + O` | قايمة بكل الدوال والـ Classes في الملف. أسرع طريقة تشوف خريطة الملف. |
| `Python: Select Interpreter` | من Cmd+Shift+P: اختار الـ `.venv` بتاع المشروع علشان VS Code يشوف مكتباته. |

:::tip[حاجة مشتركة: نفس الخطة في JS]
في مشروع Node بتعمل نفس الكلام: الـ `import`/`require` فوق هي العدة، والمدخل في `package.json` (الـ `"main"` أو `"scripts"`)، وبعدين تتتبّع الدوال. الخطة نفسها بتشتغل على أي لغة.
:::

:::tip[ملخص الفصل]
- الاسكريبت مكتوب بترتيب التعريف مش التنفيذ، فمتقراهوش زي رواية.
- الخطة: imports، بعدين إعدادات (CAPITALS)، بعدين المدخل (`__main__`)، بعدين تتبّع الدوال، بعدين البيانات، بعدين الخطر.
- لو قدرت تلخّص الاسكريبت في جملة "بياخد X ويعمل Y ويكتب Z"، يبقى فهمته.
- دوّر دايماً على: كتابة فوق ملفات، ومسح، وعدد الـ Requests المدفوعة، وبيانات بتطلع برّه.
:::

### صح ولا غلط؟

1. أحسن طريقة تقرا اسكريبت إنك تبدأ من أول سطر لآخر سطر.
2. المتغيرات اللي أساميها CAPITAL مينفعش Python تغيّرها.
3. في `summarize_notes.py`، لو حصل خطأ في الملف رقم 90 من 100، النتايج الـ 89 هتتحفظ.

### أسئلة مراجعة

1. رتّب خطوات الخطة الست، وقول فايدة كل واحدة.
2. من الـ imports بس: اسكريبت فيه `import pandas` و`from google import genai` و`import shutil`. خمّن بيعمل إيه، وإيه اللي يقلقك فيه؟
3. ليه `MODEL` أهم سطر بالنسبالك في الإعدادات؟
