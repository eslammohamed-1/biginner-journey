شغّلت الاسكريبت على 500 ملف، وعند الملف 137 وقع بـ 429. الفصل ده بيشرح ليه ده بيحصل (الـ Rate limits بأنواعها)، وإيه اللي الـ SDKs بتعمله لوحدها (OpenAI بيعيد، و Gemini مبيعيدش افتراضياً!)، وإزاي تكتب Exponential backoff with jitter بنفسك، وإمتى متعيدش خالص.

:::note[بعد الفصل ده هتكون عارف]
- RPM و TPM و RPD و TPD: كل واحد بيتحسب إزاي
- الـ Headers: Retry-After و x-ratelimit-\*
- أنهي Errors تتعاد وأنهي لأ
- OpenAI SDK: max\_retries و with\_options و timeout
- Gemini SDK: HttpRetryOptions (مقفولة افتراضياً)
- helper اسمه with\_backoff بنفسك، وليه متعملش Retries جوه Retries
:::

<a id="s25-1"></a>

## 25.1 ليه الـ API بيقولك "استنى"؟

السيرفرات بتاعة OpenAI و Google بتخدم ملايين الناس، فكل مشروع ليه "حصة" في الدقيقة واليوم. ولو عدّيتها، الرد بيبقى **429**، وده مش Bug في كودك، ده "استنى شوية وارجع". والمشكلة إن اسكريبت بسيط بـ `for` بيبعت أسرع ما يقدر، فيخبط في الحد بسرعة. وأول ما يخبط من غير Retry، بيقع، والـ 136 ملف اللي خلصوا ممكن يضيعوا لو مكنتش بتحفظ أول بأول (فصل 26).

**أنواع الحدود (الاتنين بيستخدموا نفس الأسماء)**

| الاختصار | يعني | بتخبط فيه لما |
|---|---|---|
| RPM | Requests per minute | طلبات صغيرة كتير ورا بعض |
| TPM | Tokens per minute | ملفات كبيرة، حتى لو الطلبات قليلة |
| RPD / TPD | في اليوم | شغل طويل. وفي Gemini الـ RPD بيتصفّر **نص الليل بتوقيت Pacific** (يعني 10 أو 11 الصبح بتوقيت القاهرة حسب التوقيت الصيفي) |
| Spend (Gemini) | صرف في كل 10 دقايق | Tier 1: ‏$10، وTier 2: ‏$50، وTier 3: ‏$200، والرد `429 RESOURCE_EXHAUSTED` |

- **OpenAI**: الحدود على مستوى الـ Organization والـ Project، وبتختلف حسب الموديل والـ Tier. وفي موديلات بتتشارك نفس الحد. وتشوف حدودك في صفحة Limits في الـ Settings.
- **Gemini**: الحدود **على الـ Project مش على الـ Key**، فـ 3 Keys في نفس المشروع مش هيدّوك 3 أضعاف. وبتشوفها في AI Studio. والـ Tier بيعلى لوحده مع الصرف.
- الطلبات الفاشلة **بتتحسب** من حصة الدقيقة (OpenAI بتقولها صراحة)، فالـ Retry السريع من غير انتظار بيزوّد المشكلة.

**المصادر الرسمية:** [OpenAI · Rate limits](https://developers.openai.com/api/docs/guides/rate-limits) · [Gemini · Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)

## 25.2 الـ Headers: السيرفر بيقولك فاضلّك قد إيه

```text
HTTP/1.1 429 Too Many Requests
retry-after: 1
x-ratelimit-limit-requests: 60
x-ratelimit-remaining-requests: 0
x-ratelimit-reset-requests: 1s
x-ratelimit-remaining-tokens: 149984
x-ratelimit-reset-tokens: 6m0s
```

| الأمر | بيعمل إيه |
|---|---|
| `retry-after` | أقل عدد ثواني تستناه. OpenAI بتقول: اعتبره **حد أدنى**، وزوّد عليه شوية عشوائي. وممكن ييجي مع 429 ومع 503 (الموديل عليه ضغط). |
| `x-ratelimit-remaining-*` | فاضلّك كام طلب وكام Token قبل الحد. |
| `x-ratelimit-reset-*` | الحد هيتصفّر بعد قد إيه (`1s`، `6m0s`). |

```python
# تقرا الـ Headers من OpenAI SDK
raw = client.responses.with_raw_response.create(model=MODEL, input="hi")
print(raw.headers.get("x-ratelimit-remaining-requests"))
response = raw.parse()          # الـ Response العادي
```

## 25.3 مين يتعاد ومين لأ

**القرار حسب الـ Status**

| Status | يعني | أعيد؟ |
|---|---|---|
| 429 (rate limit) | بسرعة زيادة | **أيوه**، بانتظار |
| 429 (quota / spend limit) | الحصة أو الرصيد خلص | **لأ**. OpenAI: "متعيدش Errors محتاجة منك تصرّف (quota و billing)". وزي ما قلنا في فصل 11: الـ Hard spend limit في OpenAI بيرجّع 429 برضه، فاقرا الرسالة |
| 408 / 409 / 5xx / 503 | مشكلة مؤقتة عندهم | أيوه |
| 400 | الطلب نفسه غلط | لأ، صلّح الكود |
| 401 / 403 | Key غلط أو مفيش صلاحية | لأ |
| 402 (OpenRouter) | الرصيد بالسالب | لأ |

## 25.4 الـ SDKs بتعمل إيه لوحدها

#### OpenAI (openai 3.37)

- بيعيد **تلقائياً مرتين** (`max_retries=2`) على 408 و 409 و 429 و ≥500 وأخطاء الاتصال.
- الـ Timeout الافتراضي 600 ثانية.
- بيحترم `retry-after`.

#### Gemini (google-genai 2.33)

- **مبيعيدش افتراضياً**: محاولة واحدة.
- تفعّلها بـ `HttpRetryOptions`.
- الـ Timeout بالـ **ميلّي ثانية** في `HttpOptions(timeout=...)`.

:::note[جربناها على سيرفر تجريبي]
**OpenAI**: سيرفر بيرجّع 429 مع `retry-after: 1` مرتين وبعدين 200. والـ SDK بالإعدادات الافتراضية بعت 3 طلبات بينهم **ثانية بالظبط** (يعني احترم الـ Header)، وبعت Header اسمه `x-stainless-retry-count` بـ 0 ثم 1 ثم 2، ورجّع الرد بعد 2.1 ثانية من غير أي Error في الكود. ومع `with_options(max_retries=0)` وقع على طول بـ `RateLimitError` و`e.status_code == 429` و`e.response.headers["retry-after"] == "1"`.<br>**Gemini**: سيرفر بيرجّع 429 دايماً. ومن غير Retry options: طلب واحد ووقع. ومع `HttpRetryOptions(attempts=3, initial_delay=0.5)`: وقع بعد ~2.5 ثانية بـ `ClientError` و`e.code == 429` و`e.status == "RESOURCE_EXHAUSTED"`.
:::

```python
# OpenAI: اضبط على الـ Client كله، أو لطلب واحد
client = OpenAI(max_retries=5, timeout=60.0)
client.with_options(max_retries=0).responses.create(...)
client.with_options(timeout=20.0).responses.create(...)

# Gemini: فعّل الـ Retries
from google.genai import types
client = genai.Client(http_options=types.HttpOptions(
    timeout=60_000,                                   # ms
    retry_options=types.HttpRetryOptions(attempts=5),
))
```

| الأمر | بيعمل إيه |
|---|---|
| `with_options(...)` | نسخة من الـ Client بإعدادات مختلفة **لطلب واحد**، والأصلي مبيتغيرش. |
| `timeout=60.0` | OpenAI بالثواني. و600 ثانية افتراضي ده كتير على اسكريبت ملفات، فقلّله. |
| `HttpRetryOptions(attempts=5)` | الباقي بالقيم الافتراضية: `initial_delay=1.0`، و`max_delay=60`، و`exp_base=2`، و`jitter=1`، وعلى الأكواد 408 و 429 و 500 و 502 و 503 و 504. و `attempts` = **إجمالي المحاولات** مش عدد الإعادات. |
| `timeout=60_000` | 60 ثانية بالميلّي. و`_` في الرقم للقراية بس (فصل 4). |

**المصادر الرسمية:** [openai-python · Retries](https://github.com/openai/openai-python#retries) · [openai-python · Timeouts](https://github.com/openai/openai-python#timeouts) · [google-genai SDK docs](https://googleapis.github.io/python-genai/)

## 25.5 Exponential backoff with jitter بإيدك

فكرة الـ Backoff: أول مرة تستنى شوية، ولو فشل تاني استنى الضعف، وبعدين الضعف… لحد سقف. والـ **Jitter**: رقم عشوائي في الانتظار، علشان لو 8 Threads وقعوا مع بعض، ميرجعوش كلهم في نفس اللحظة ويخبطوا تاني. والـ Helper ده بيشتغل مع أي فانكشن (OpenAI أو Gemini أو requests):

```python title="backoff.py"
import logging
import random
import time

log = logging.getLogger("backoff")
RETRYABLE = {408, 409, 429, 500, 502, 503, 504}

def status_of(exc: Exception) -> int | None:
    return getattr(exc, "status_code", None) or getattr(exc, "code", None)

def retry_after_of(exc: Exception) -> float | None:
    headers = getattr(getattr(exc, "response", None), "headers", None) or {}
    value = headers.get("retry-after")
    try:
        return float(value) if value else None
    except ValueError:
        return None

def with_backoff(func, *args, attempts: int = 6, base: float = 1.0, cap: float = 60.0, **kwargs):
    for attempt in range(1, attempts + 1):
        try:
            return func(*args, **kwargs)
        except Exception as exc:
            status = status_of(exc)
            if status not in RETRYABLE or attempt == attempts:
                raise
            delay = min(cap, base * 2 ** (attempt - 1))
            delay = random.uniform(0, delay)
            hint = retry_after_of(exc)
            if hint is not None:
                delay = max(delay, hint) + random.uniform(0, 1)
            log.warning("HTTP %s, attempt %d/%d, sleeping %.1fs", status, attempt, attempts, delay)
            time.sleep(delay)
```

```python title="سطر سطر"
getattr(exc, "status_code", None) or getattr(exc, "code", None)
getattr(getattr(exc, "response", None), "headers", None) or {}
def with_backoff(func, *args, attempts=6, ..., **kwargs)
if status not in RETRYABLE or attempt == attempts: raise
base * 2 ** (attempt - 1)
random.uniform(0, delay)
max(delay, hint) + random.uniform(0, 1)
```

1. `getattr(exc, "status_code", None) or getattr(exc, "code", None)`: OpenAI بتحط الـ Status في `status_code`، و Gemini في `code`. و`getattr(obj, name, default)` بترجّع الـ default لو مش موجود بدل ما تقع.
2. `getattr(getattr(exc, "response", None), "headers", None) or {}`: نفس الفكرة مرتين: لو مفيش response أو مفيش headers، خد dict فاضي، علشان `.get` متقعش.
3. `def with_backoff(func, *args, attempts=6, ..., **kwargs)`: بياخد **الفانكشن نفسها** (من غير أقواس) والـ Arguments بتاعتها، وينادي `func(*args, **kwargs)`. فالـ `attempts` و`base` و`cap` بعد `*args` لازم يتكتبوا بالاسم (فصل 6).
4. `if status not in RETRYABLE or attempt == attempts: raise`: `raise` لوحدها = ارمي نفس الـ Exception تاني زي ما هو. يعني 401 أو 400 بيطلعوا على طول، وآخر محاولة بتطلع الـ Error الحقيقي.
5. `base * 2 ** (attempt - 1)`: 1، 2، 4، 8، 16… و`**` أسبقيتها أعلى من `*`، فده `base × 2^(attempt−1)`. و`min(cap, …)` سقف 60 ثانية.
6. `random.uniform(0, delay)`: "Full jitter": رقم عشوائي من 0 للـ delay.
7. `max(delay, hint) + random.uniform(0, 1)`: لو السيرفر قال `retry-after`، متستناش أقل منه أبداً، وزوّد عشوائي صغير. ودي بالظبط نصيحة OpenAI.

```python
# الاستخدام: اقفل Retries الـ SDK الأول
client = OpenAI(max_retries=0, timeout=60.0)
response = with_backoff(client.responses.create, model=MODEL, input=text)
```

```sh title="Terminal"
WARNING backoff: HTTP 429, attempt 1/6, sleeping 1.2s
WARNING backoff: HTTP 429, attempt 2/6, sleeping 1.6s
done 3.0
```

(ده خرج حقيقي من التجربة على السيرفر التجريبي: `retry-after: 1`، فالانتظار كان دايماً ثانية + عشوائي.)

:::caution[متعملش Retries جوه Retries]
لو الـ SDK بيعيد مرتين، وانت لافف عليه Helper بيعيد 6 مرات، يبقى الطلب الواحد ممكن يتبعت **18 مرة**. وOpenAI بتقولها صراحة: لو بتدير الـ Retries بنفسك، اقفل Retries الـ SDK (`max_retries=0`) أو احسبها. وحط كمان سقف **للوقت الكلي** مش بس لعدد المحاولات.
:::

:::note[tenacity]
OpenAI بتستخدم في أمثلتها مكتبة `tenacity`: `@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(6))`. وهي أصلاً متسطّبة معاك لو عندك `google-genai` (الـ SDK بيستخدمها جواه للـ Retries). بس أمثلة OpenAI **مبتقراش** `Retry-After`، وده مكتوب عندهم، فلو استخدمتها ضيف ده.
:::

## 25.6 أحسن من الـ Retry: متخبطش أصلاً

1. **قلّل التوازي**: 4 Threads بدل 32 (فصل 26).
2. **استنى بين الطلبات**: لو حدك 60 RPM، يبقى `time.sleep(1.1)` بين كل طلب ومش هتخبط.
3. **استخدم Batch API** للشغل اللي مش مستعجل: حدود منفصلة ونص السعر.
4. **OpenAI بتقول**: لما توصل لمليون TPM، متزوّدش أكتر من 50% كل 15 دقيقة (ramp-rate).

:::tip[حاجة مشتركة: JS]
نفس الـ Helper في JS: `async function withBackoff(fn, attempts = 6) { for (let i = 1; i <= attempts; i++) { try { return await fn(); } catch (e) { if (!RETRYABLE.has(e.status) || i === attempts) throw e; await new Promise(r => setTimeout(r, Math.random() * Math.min(60, 2 ** (i - 1)) * 1000)); } } }`. والـ `openai` SDK في JS عنده برضه `maxRetries` (افتراضي 2).
:::

:::tip[ملخص الفصل]
- 429 = استنى، مش Bug. والحدود RPM و TPM و RPD (+ صرف في Gemini)، و Gemini RPD بيتصفّر نص ليل Pacific.
- أعيد على 429 (rate) و 408 و 409 و 5xx. ومتعيدش على 400 و 401 و 403 و quota و billing.
- OpenAI SDK بيعيد مرتين ويحترم `retry-after`. و Gemini SDK مبيعيدش إلا لو فعّلت `HttpRetryOptions`.
- Backoff: ‏`min(cap, base·2^n)` + jitter، ومتنزلش تحت `retry-after`.
- مستوى Retry واحد بس، وسقف للمحاولات والوقت، و Timeout معقول.
:::

### صح ولا غلط؟

1. google-genai بيعيد الطلب تلقائياً على 429 من غير أي إعدادات.
2. الطلبات اللي رجعت 429 مبتتحسبش من حصة الدقيقة.
3. 3 API Keys في نفس مشروع Gemini = 3 أضعاف الـ Rate limit.

### أسئلة مراجعة

1. احسب أقصى انتظار في المحاولة الخامسة بـ `base=1` و`cap=60`.
2. ليه الـ Jitter مهم لما يبقى عندك Threads كتير؟
3. الـ SDK بيعيد مرتين، وانت لافف `with_backoff(attempts=4)`. الطلب ممكن يتبعت كام مرة كحد أقصى؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** اطبع `x-ratelimit-remaining-requests` بعد كل طلب في اسكريبت بـ `with_raw_response`.
2. **[متوسط]** ضيف لـ `with_backoff` باراميتر `max_total=300` ثانية، يوقف لو الوقت الكلي عدّاه.
3. **[صعب]** اعمل سيرفر تجريبي بـ `http.server` بيرجّع 429 كل تاني طلب (زي اللي في الفصل)، واختبر عليه الـ Helper بتاعك.
