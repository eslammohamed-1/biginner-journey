<small>المرحلة 3 · الاسكريبت والدنيا</small>

الاسكريبت شغّال بقاله ساعة ومش طابع حاجة: واقف ولا شغّال؟ وعايز تشغّله على فولدر تاني بموديل تاني، فتفتح الكود وتغيّر سطرين كل مرة. الفصل ده عن الحاجتين: إزاي الاسكريبت يقولك هو فين (print و logging)، وإزاي ياخد إعداداته من الـ Terminal (argparse).

:::note[بعد الفصل ده هتكون عارف]
- إمتى print كفاية وإمتى logging أحسن
- logging.basicConfig و المستويات DEBUG و INFO و WARNING و ERROR
- تسجّل في ملف وتشوف لوجز الـ SDK بـ OPENAI\_LOG
- argparse: Positional و --options و store\_true و type
- تقرا أي --help وتفهمه
- نمط --dry-run و --limit قبل أي تشغيل مكلف
:::

## 13.1 print كفاية… لحد ما متبقاش كفاية

`print(f"done: {path.name}")` ممتازة لاسكريبت صغير. بس لما الاسكريبت يكبر: مش عارف الرسالة دي اتطبعت إمتى، ومش قادر تفصل الرسايل المهمة عن التفاصيل، ولما تقفل الـ Terminal كل حاجة بتروح. <strong>فاتطور الحل:</strong> `logging`، مكتبة في Python بتدّي كل رسالة وقت و"درجة أهمية"، وتقدر تبعتها للشاشة ولملف مع بعض.

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s",
    handlers=[logging.StreamHandler(), logging.FileHandler("run.log", encoding="utf-8")],
)
log = logging.getLogger(__name__)

log.info("start: %d files", len(paths))
log.warning("skip empty file: %s", path.name)
log.error("failed %s: %s", path.name, e)
```

```python title="سطر سطر"
level=logging.INFO
format="%(asctime)s %(levelname)s %(message)s"
handlers=[StreamHandler(), FileHandler("run.log")]
log = logging.getLogger(__name__)
log.info("start: %d files", len(paths))
```

1. `level=logging.INFO`: اطبع من درجة INFO وأعلى. فالـ `log.debug(...)` مش هتظهر. ولو عايز تفاصيل أكتر خليها `logging.DEBUG`.
2. `format="%(asctime)s %(levelname)s %(message)s"`: شكل كل سطر: `%(asctime)s` = الوقت، و`%(levelname)s` = الدرجة، و`%(message)s` = الرسالة. والـ `%(...)s` طريقة تنسيق قديمة في Python، مش f-string.
3. `handlers=[StreamHandler(), FileHandler("run.log")]`: ابعت كل رسالة للشاشة **و** لملف `run.log`. لما الاسكريبت يقع بالليل، تلاقي القصة كلها في الملف.
4. `log = logging.getLogger(__name__)`: Logger باسم الملف الحالي، فتعرف كل رسالة جاية منين في المشاريع اللي من كذا ملف.
5. `log.info("start: %d files", len(paths))`: لاحظ: القيم بتتبعت كـ Arguments منفصلة و`%d` = رقم، و`%s` = نص. ده العرف في logging (f-string برضه شغّالة عادي).

```sh title="Terminal"
2026-10-23 14:02:11,384 INFO start: 120 files
2026-10-23 14:02:13,902 WARNING skip empty file: draft.md
2026-10-23 14:02:40,117 ERROR failed intro.md: RateLimitError: Error code: 429
```

**المستويات: استخدم كل واحد في مكانه**

| المستوى | إمتى |
|---|---|
| `DEBUG` | تفاصيل للتصليح: الـ Prompt كامل، وعدد التوكنز |
| `INFO` | الشغل ماشي: "خلّصت ملف 12" |
| `WARNING` | حاجة غريبة بس مكمّلين: "ملف فاضي، اتساب" |
| `ERROR` | حاجة فشلت: "الملف ده مخلصش" |
| `CRITICAL` | مش هنقدر نكمّل خالص |

:::note[تشوف الـ SDK بيعمل إيه من جوه]
الـ SDK بتاع OpenAI بيستخدم logging برضه. اعمل `export OPENAI_LOG=info` (أو `debug`) قبل ما تشغّل، هتشوف كل Request رايح فين، وكل Retry بيحصل. وفي google-genai، رسايل الـ Retry بتطلع على Logger عادي بدرجة INFO، فهتظهر لو `level=logging.INFO`.
:::

:::caution[خلي بالك]
متسجّلش الـ API key ولا محتوى ملفات حساسة في الـ log. الـ `run.log` ملف عادي ممكن يتبعت أو يترفع بالغلط. وحطه في `.gitignore`.
:::

**المصادر الرسمية:** [docs.python.org · Logging HOWTO](https://docs.python.org/3/howto/logging.html) · [openai-python · Logging](https://github.com/openai/openai-python#logging)

## 13.2 argparse: الاسكريبت ياخد أوامره من الـ Terminal

**قبل كده** كنت هتفتح الاسكريبت كل مرة وتغيّر `INPUT_DIR = "notes"` لـ `"drafts"`. وغلطة واحدة في التعديل، الاسكريبت يبوظ. <strong>فاتطور الحل:</strong> الاسكريبت يقرا إعداداته من الأمر نفسه: `python3 run.py drafts --model gpt-6-luna --limit 5`.

```python title="args.py"
import argparse
from pathlib import Path

parser = argparse.ArgumentParser(description="Summarize every note in a folder.")
parser.add_argument("input_dir", type=Path, help="folder with .md files")
parser.add_argument("--model", default="gpt-6-luna", help="model name")
parser.add_argument("--limit", type=int, default=None, help="only the first N files")
parser.add_argument("-n", "--dry-run", action="store_true", help="show what would run, call nothing")
args = parser.parse_args()
```

**تشريح الأمر**

```python
parser.add_argument("-n", "--dry-run", action="store_true", help="...")
```

1. `add_argument`: عرّف حاجة الاسكريبت يقبلها من الـ Terminal.
2. `"-n"`: الاسم القصير (شَرطة واحدة وحرف).
3. `"--dry-run"`: الاسم الطويل (شَرطتين). وفي الكود بيتقري `args.dry_run`: الـ `-` بتتحوّل لـ `_` لأن الشَرطة مينفعش تبقى في اسم متغير.
4. `action="store_true"`: ده "مفتاح" (Flag) مالوش قيمة: لو كتبته يبقى `True`، ولو مكتبتوش `False`.
5. `help=`: الوصف اللي بيظهر في `--help`.

| الأمر | بيعمل إيه |
|---|---|
| `"input_dir"` | من غير شَرطة = **Positional**: إجباري، وبالترتيب. لو نسيته: `error: the following arguments are required: input_dir`. |
| `type=Path / type=int` | حوّل النص اللي جه من الـ Terminal للنوع ده (كل حاجة في الـ Terminal نص في الأصل). |
| `default=` | القيمة لو مكتبتهوش. |
| `choices=["openai","gemini"]` | قيم مسموحة بس. أي حاجة تانية بتطلّع خطأ واضح. |
| `required=True` | تخلي `--option` إجباري. |

### اقرا الـ --help

```sh title="Terminal"
$ python3 args.py --help
usage: args.py [-h] [--model MODEL] [--limit LIMIT] [-n] input_dir

Summarize every note in a folder.

positional arguments:
  input_dir      folder with .md files

options:
  -h, --help     show this help message and exit
  --model MODEL  model name
  --limit LIMIT  only the first N files
  -n, --dry-run  show what would run, call nothing
$ python3 args.py notes --limit 5 -n
Namespace(input_dir=PosixPath('notes'), model='gpt-6-luna', limit=5, dry_run=True)
```

| الأمر | بيعمل إيه |
|---|---|
| `[ ... ]` | في سطر الـ usage: الأقواس المربعة = اختياري. اللي من غير أقواس (`input_dir`) إجباري. |
| `--model MODEL` | الكلمة الكبيرة بعده = "هنا تكتب قيمة". أما `[-n]` لوحده من غير كلمة بعده = Flag. |
| `Namespace(...)` | الـ `args` نفسه: Object فيه كل قيمة كـ Attribute: `args.limit` و`args.dry_run`. |

:::tip[نمط ذهبي: --dry-run و --limit]
أي اسكريبت بيصرف فلوس API لازم يبقى فيه الاتنين دول. `--dry-run` يطبع "هعمل إيه وعلى كام ملف" من غير ما يكلم أي موديل، و`--limit 3` يجرّب على 3 ملفات بس. اشترط على الـ AI يحطهم وانت بتطلب الاسكريبت (فصل 28).
:::

:::tip[حاجة مشتركة: process.argv]
في Node القيم بتيجي خام في `process.argv`، وبتستخدم مكتبة زي `commander` أو `yargs` علشان تعمل اللي argparse بيعمله. وNode 18.3+ فيه `util.parseArgs` جاهزة.
:::

**المصادر الرسمية:** [docs.python.org · argparse](https://docs.python.org/3/library/argparse.html) · [Argparse Tutorial](https://docs.python.org/3/howto/argparse.html)

:::tip[ملخص الفصل]
- `logging.basicConfig(level, format, handlers)`: وقت ودرجة لكل رسالة، وشاشة + ملف.
- DEBUG للتفاصيل، و INFO للتقدم، و WARNING للغريب، و ERROR للفشل.
- `OPENAI_LOG=info` بيوريك Requests وRetries الـ SDK. ومتسجّلش Keys.
- argparse: Positional إجباري، و`--option` اختياري، و`store_true` Flag، و`--dry-run` بيتقري `args.dry_run`.
- في الـ usage: `[ ]` = اختياري، و`WORD` = قيمة.
:::

### صح ولا غلط؟

1. مع `level=logging.WARNING` رسايل `log.info` هتظهر.
2. `--dry-run` بيتقري في الكود `args.dry-run`.
3. من غير `type=int`، `args.limit` هيبقى نص.

### أسئلة مراجعة

1. اقرا السطر ده واشرحه: `usage: tool.py [-h] [--provider {openai,gemini}] [--out OUT] input`.
2. ليه الـ FileHandler مفيد في اسكريبت بيشتغل ساعة؟
3. إيه فايدة `--dry-run` قبل تشغيل على 2000 ملف؟

### تحديات الفصل

<small>جرّبها بإيدك، والحلول في ملحق الإجابات.</small>

1. **[سهل]** شغّل `args.py` بكذا شكل، ومن غير `input_dir`، واقرا الأخطاء.
2. **[متوسط]** زوّد `--provider` بـ `choices=["openai", "gemini"]`، وجرّب قيمة غلط.
3. **[صعب]** اعمل logging لشاشة وملف، وزوّد Flag `-v` يخلّي المستوى DEBUG لما يتكتب.
